الفصل 21: التنقيح الأصلي (gdb, lldb)

21.1 نظرة عامة

يصف هذا الفصل الدعم الخاص بتنقيح الملفات التنفيذية لـ OCaml المبنية بالمترجم إلى الشيفرة الأصلية ocamlopt، باستخدام المنقّحات الأصلية القياسية مثل GDB أو LLDB. وسنسمّي هذا التنقيح الأصلي، تمييزًا له عن تنقيح الشيفرة البايتية المدعوم عبر ocamldebug (الفصل 20).

التنقيح الأصلي مدعوم على منصّات Linux وmacOS وFreeBSD. أما الدعم على Windows فغير متاح حاليًا.

21.1.1 صيغة DWARF

يستعمل OCaml صيغة التنقيح DWARF لوصف معلومات التنقيح التي يولّدها. وDWARF صيغة لمعلومات التنقيح تستعملها مترجمات ومنقّحات كثيرة لدعم التنقيح على مستوى المصدر. وهي مستعملة في صيغ الملفات التنفيذية ELF وMach-O.

تضمّ معلومات التنقيح مكوّنين أساسيين:

معلومات إطار الاستدعاء (CFI): تصف كيفية فكّ مكدّس الاستدعاءات لتوليد الآثار العكسية. وتمتدّ معلومات CFI في OCaml عبر حدود اللغات، من شيفرة OCaml إلى دوال زمن التشغيل المكتوبة بلغة C، وعبر نداءات واجهة الدوال الأجنبية (FFI) عندما توفّر اللغة الأجنبية بيانات CFI أيضًا.

تعيين أسطر المصدر: يعيد ربط كل تعليمة آلة بموضع المصدر الذي أتت منه، ما يمكّن المنقّحات من عرض شيفرة OCaml المصدرية ودعم التدرّج على مستوى المصدر. مثلًا، قد تُربط التعليمة الموجودة عند عنوان الذاكرة 0xdeadbeef بالموضع myprogram.ml:42.

يعرّف OCaml اصطلاح نداء خاصًا به يبيّن كيفية تمرير الوسائط إلى الدوال، وكيفية إرجاع القيم منها، وكيفية استعمال السجلات. وهذه المعلومات خاصة بكل معمارية، وهي موثّقة في ملفات المصدر asmcomp//proc.ml لكل معمارية.

21.1.2 تشويه الأسماء

عندما يترجم OCaml شيفرة مصدرية، يحوّل بنى اللغة مثل أسماء الدوال والوحدات إلى أسماء مشوَّهة تظهر في الملف التنفيذي النهائي. وتخدم هذه الأسماء المشوَّهة أغراضًا عدّة:

  • تضمن تفرّد الرموز في الملف التنفيذي المُترجَم

  • ترمّز بنية الوحدات ومعلومات فضاء الأسماء

  • تظهر في خَرْج المنقّح مثل الآثار العكسية وقوائم الرموز

  • يمكن استعمالها لضبط نقاط التوقّف عند غياب معلومات ملف المصدر

مخطّط التشويه الحالي ابتداءً من OCaml 5.3:

  • Linux: caml<MODULE_NAME>.<FUNCTION_NAME>_<NNN>

  • macOS وWindows MSVC: caml<MODULE_NAME>$<FUNCTION_NAME>_<NNN>

حيث NNN عدد مولَّد يضمن التفرّد.

مثال: قد تصير الدالة fib في الوحدة MyMath إلى camlMyMath.fib_271 على Linux أو إلى camlMyMath$fib_271 على macOS.

ملاحظة: استعملت إصدارات OCaml السابقة لـ 5.1.1 شرطتين سفليتين متتاليتين: caml<MODULE_NAME>__<FUNCTION_NAME>_<NNN>.

21.1.3 مؤشرات الإطار

توفّر مؤشرات الإطار طريقة بديلة للمنقّحات لاجتياز مكدّس الاستدعاءات. ويدعم OCaml مؤشرات الإطار على منصّتي AMD64 وARM64.

باستعمال مؤشرات الإطار، تحتفظ كل دالة بـمؤشر إطار يشير إلى قاعدة إطار مكدّسها (منطقة الذاكرة المخصّصة لمتغيّرات تلك الدالة المحلية ومعلومات ندائها، وتُعرف أيضًا باسم إطار التنشيط أو سجل التنشيط). وبربط هذه المؤشرات بعضها ببعض مع عناوين العودة، تستطيع المنقّحات إعادة بناء مكدّس الاستدعاءات كاملًا.

مؤشرات الإطار اختيارية (وليست لازمة للتنقيح)، ويجب تمكينها صراحةً أثناء إعداد المترجم (انظر قسم قياس الأداء 22.2.2 للتفاصيل).

21.2 الترجمة من أجل التنقيح

قبل تنقيح برامج OCaml، يجب أن يكون المترجم الأصلي ocamlopt مثبَّتًا مع دعم CFI، وهو كذلك افتراضيًا. ويمكنك أيضًا التحكّم في ذلك صراحةً بخيار الإعداد --enable-cfi عند بناء المترجم.

للقيام بالتنقيح على مستوى المصدر، ترجم كل الشيفرة بالخيار -g؛ فهو يسجّل معلومات DWARF الخاصة بالآثار العكسية للاستثناءات، ويولّد معلومات الأسطر اللازمة للربط بين مواضع التجميع ومواضع المصدر في OCaml. ولا تترتّب على الترجمة بـ-g أي كلفة وقت تشغيل، لكنها تولّد ملفات تنفيذية أكبر لأنها تضمّ أقسامًا لمعلومات التنقيح. لاحظ أن مكتبات OCaml وسائر التبعيات ينبغي أن تكون مترجمة بمعلومات تنقيح DWARF، وإلا فقدت ميزات التنقيح على مستوى المصدر في تلك الأجزاء من الشيفرة.

تحتاج المنقّحات إلى الوصول إلى ملفات المصدر المشار إليها في معلومات DWARF. وبالنسبة إلى التبعيات، فكّر في استعمال حفظ دليل البناء الذي يوفّره opam:

# First tell opam to keep the source code
$ export OPAMKEEPBUILDDIR=1

# Then, reinstall the packages to force redownloading the sources
$ opam switch reinstall

# Source code for packages will appear inside the opam switch
# in a build directory. e.g. _opam/.opam-switch/build/ for a
# local switch or ~/.opam/<switch_name>/.opam-switch/build

توضّح الأقسام التالية تنقيح برامج OCaml باستعمال GDB وLLDB، وتعرض سيرورات العمل الشائعة والمخرجات المتوقّعة.

21.3 استعمال GDB

هنا نمضي في تنقيح برنامج OCaml بسيط باستعمال GDB على Linux، عارضين الأوامر المستعملة والمخرجات المتوقّعة. لاحظ أن هذه الجلسة تستعمل Ubuntu 24.04 LTS على AMD64 مع OCaml 5.4.

تأمّل البرنامج التالي:

(* fib.ml *)
let rec fib n =
  if n = 0 then 0
  else if n = 1 then 1
  else fib (n-1) + fib (n-2)

let main () =
  let r = fib 20 in
  Printf.printf "fib(20) = %d" r

let _ = main ()

ترجم هذا البرنامج بـocamlopt هكذا:

$ ocamlopt -g -o fib.exe fib.ml
$ ./fib.exe 20
fib(20) = 6765

عند تشغيله يطبع هذا البرنامج عدد فيبوناتشي العشرين. واستعمال العودية هنا ذريعة لفحص مكدّس الاستدعاءات. ابدأ جلسة GDB لهذا البرنامج:

$ gdb ./fib.exe

يمكن ضبط نقاط التوقّف إمّا بالأسماء المشوَّهة التي يولّدها المترجم أو بمزيج من اسم الملف ورقم السطر. مثلًا:

(gdb) break camlFib.fib_     # press tab
(gdb) break camlFib.fib_271  # 271 happens to be the unique number generated
Breakpoint 1 at 0x3cd50: file fib.ml, line 2.

(gdb) break fib.ml:7         # breakpoint for main function
Breakpoint 2 at 0x3cdc0: file fib.ml, line 7.

21.3.1 أوامر GDB

ملخّص أوامر GDB المهمة الخاصة بـ OCaml:

break locspec

يضبط نقطة توقّف عند جميع مواضع الشيفرة المطابقة لـlocspec، مثلًا باستعمال الأسماء المشوَّهة لـ OCaml أو بتحديد رقم السطر في ملف المصدر بصيغة filename:linenum.

backtrace

يطبع الأثر العكسي للمكدّس كاملًا. ويضمّ ذلك إشارات إلى مصادر OCaml تحدّد أيّ إطار مكدّس يقابل أيّ موضع مصدر، مثل fib.ml:4.

disassemble addresses

يعرض مجالًا من العناوين على هيئة تعليمات آلة. ويُستعمل عادةً مع الأسماء المشوَّهة لـ OCaml لعرض التجميع الخاص بدالة.

info frame

يطبع هذا الأمر وصفًا مفصّلًا لإطار المكدّس المحدَّد.

list linenum

يطبع أسطرًا حول رقم السطر linenum في ملف المصدر الحالي. ويطبع ذلك الشيفرة المصدرية لـ OCaml وزمن تشغيل OCaml المكتوب بلغة C.

directory dirname

يضيف الدليل dirname إلى مقدّمة مسار المصادر؛ ويمكن تقديم عدّة أسماء أدلّة مفصولة بـ: . وهذا مفيد عندما تتغيّر الأدلّة بين الترجمة وجلسة التنقيح.

انظر وثائق Debugging with GDB لمزيد من التفاصيل. وبوجه عام تعمل الميزات الموصوفة أعلاه مع OCaml، وإذا فشلت يرتدّ GDB إلى تنقيح لغة التجميع. ويُتوقَّع أن يعمل GDB على جميع معماريات Linux المدعومة.

21.4 استعمال LLDB

هنا سنمضي في تنقيح مثال fib السابق باستعمال LLDB على Linux. ابدأ جلسة LLDB باستعمال fib.exe من قبل. لاحظ أن هذه الجلسة تستعمل Ubuntu 24.04 LTS على ARM64 مع OCaml 5.4.

$ lldb ./fib.exe
Current executable set to 'fib.exe' (aarch64).
(lldb)

يمكن ضبط نقاط التوقّف بالأسماء المشوَّهة لـ OCaml أو بمزيج من اسم الملف ورقم السطر. مثلًا:

(lldb) breakpoint set -n camlFib.fib        # press tab for autocomplete
(lldb) breakpoint set -n camlFib.fib_271
Breakpoint 2: where = fib.exe`camlFib.fib_271 + 80, address = 0x0000000000052360
(lldb) breakpoint set -f fib.ml -l 7         # breakpoint for line 7 in fib.ml
Breakpoint 2: where = fib.exe`camlFib.main_272, address = 0x0000000000051088
(lldb)

الآن يمكننا تشغيل البرنامج.

21.4.1 أوامر LLDB

ملخّص أوامر LLDB المهمة الخاصة بـ OCaml:

breakpoint set -n symbol

يضبط نقطة توقّف عند موضع الشيفرة المطابق لـsymbol، مثلًا باستعمال الاسم المشوَّه لـ OCaml.

breakpoint set -f filename -l linenum

يضبط نقطة توقّف عند السطر linenum في filename، مثل fib.ml:7.

breakpoint set -a address

يضبط نقطة توقّف عند عنوان ذاكرة معيّن.

backtrace

يطبع الأثر العكسي للمكدّس كاملًا. ويضمّ ذلك إشارات إلى مصادر OCaml تحدّد أيّ إطار مكدّس يقابل أيّ موضع مصدر.

disassemble

يفكّ تجميع التعليمات المحدَّدة في الهدف الحالي. ومن خياراته المفيدة -n مع الاسم المشوَّه لـ OCaml لفكّ تجميع دالة معيّنة، و-a مع عنوان لفكّ تجميع الدالة التي تضمّ ذلك العنوان.

frame info

يسرد معلومات عن إطار المكدّس الحالي في الخيط الحالي.

source

أوامر لفحص الشيفرة المصدرية التي تصفها معلومات التنقيح لعملية الهدف الحالي.

settings set target.source-map from to

يعيد ربط مسارات المصدر from بمسار مصدر جديد يُستعمل عند تحديد موقع الشيفرة المصدرية لعرضها إلى جانب البرنامج المنقَّح. وتُدعم عدّة أزواج من تعيينات from to.

وبوجه عام تعمل الميزات الموصوفة أعلاه مع OCaml، وإذا فشلت يرتدّ LLDB إلى تنقيح لغة التجميع. ويُتوقَّع أن يعمل LLDB على جميع معماريات Linux المدعومة.
