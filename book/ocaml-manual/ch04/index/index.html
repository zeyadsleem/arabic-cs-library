الفصل 4: الوسائط المُعنونة

كتب هذا الفصل جاك غاريغ

إذا نظرت في الوحدات التي تنتهي بـ Labels في المكتبة القياسية، فسترى أنّ أنواع الدوال تحمل إضافات لم تكن لديك في الدوال التي عرّفتها بنفسك.

# ListLabels.map;;

- : f:('a -> 'b) -> 'a list -> 'b list = <fun>

# StringLabels.sub;;

- : string -> pos:int -> len:int -> string = <fun>

تُسمّى هذه الإضافات من الشكل name: وسومًا. والغرض منها توثيق الشيفرة، والسماح بمزيد من الفحص، وإعطاء مرونة أكبر في تطبيق الدوال. ويمكنك إعطاء مثل هذه الأسماء للوسائط في برامجك بوضع علامة المدّة ~ قبلها.

# let f ~x ~y = x - y;;

val f : x:int -> y:int -> int = <fun>

# let x = 3 and y = 2 in f ~x ~y;;

- : int = 1

وحين تريد استعمال اسمين مختلفين للمتغيّر وللوسم الظاهر في النوع، يمكنك استعمال وسم تسمية من الشكل ~name:. وهذا ينطبق أيضًا حين لا يكون الوسيط متغيّرًا.

# let f ~x:x1 ~y:y1 = x1 - y1;;

val f : x:int -> y:int -> int = <fun>

# f ~x:3 ~y:2;;

- : int = 1

تخضع الوسوم للقواعد نفسها التي تخضع لها المعرّفات الأخرى في OCaml، أي لا يمكنك استعمال كلمة محجوزة (مثل in أو to) وسمًا.

تُقابَل الوسائط الصورية والوسائط الفعلية وفق وسومها، ويُفسَّر غياب الوسم بأنه الوسم الفارغ. وهذا يسمح بتبديل ترتيب الوسائط في التطبيقات. ويمكن أيضًا تطبيق دالة جزئيًا على أي وسيط، فيُنشأ بذلك دالة جديدة بالوسائط المتبقية.

# let f ~x ~y = x - y;;

val f : x:int -> y:int -> int = <fun>

# f ~y:2 ~x:3;;

- : int = 1

# ListLabels.fold_left;;

- : f:('acc -> 'a -> 'acc) -> init:'acc -> 'a list -> 'acc = <fun>

# ListLabels.fold_left [1;2;3] ~init:0 ~f:( + );;

- : int = 6

# ListLabels.fold_left ~init:0;;

- : f:(int -> 'a -> int) -> 'a list -> int = <fun>

وإذا حمل عدّة وسائط للدالة الوسم نفسه (أو لم تحمل وسمًا)، فإنها لا تتبادل المواضع بينها، ويكون الترتيب مهمًّا. لكنها تظلّ قادرة على تبادل المواضع مع وسائط أخرى.

# let hline ~x:x1 ~x:x2 ~y = (x1, x2, y);;

val hline : x:'a -> x:'b -> y:'c -> 'a * 'b * 'c = <fun>

# hline ~x:3 ~y:2 ~x:5;;

- : int * int * int = (3, 5, 2)

4.1 الوسائط الاختيارية

من الميزات المثيرة للانتباه في الوسائط المعنونة إمكان جعلها اختيارية. ففي الوسائط الاختيارية تحلّ علامة الاستفهام ? محلّ علامة المدّة ~ التي في غير الاختيارية، ويُسبق الوسم أيضًا بعلامة ? في نوع الدالة. ويمكن إعطاء قيم افتراضية لمثل هذه الوسائط الاختيارية.

# let bump ?(step = 1) x = x + step;;

val bump : ?step:int -> int -> int = <fun>

# bump 2;;

- : int = 3

# bump ~step:3 2;;

- : int = 5

والدالة التي تأخذ وسائط اختيارية يجب أن تأخذ أيضًا وسيطًا واحدًا غير اختياري على الأقل. والمعيار في الحكم على حذف وسيط اختياري هو التطبيق غير المعنون لوسيط يظهر بعد هذا الوسيط الاختياري في نوع الدالة. لاحظ أنه إذا كان ذلك الوسيط معنونًا، فلن تتمكّن من إزالة الوسائط الاختيارية إلا بتطبيق الدالة تطبيقًا تامًّا، مع حذف كل الوسائط الاختيارية وحذف كل الوسوم من كل الوسائط المتبقية.

# let test ?(x = 0) ?(y = 0) () ?(z = 0) () = (x, y, z);;

val test : ?x:int -> ?y:int -> unit -> ?z:int -> unit -> int * int * int =
  <fun>

# test ();;

- : ?z:int -> unit -> int * int * int = <fun>

# test ~x:2 () ~z:3 ();;

- : int * int * int = (2, 0, 3)

ويمكن أن تتبادل الوسائط الاختيارية مواضعها مع الوسائط غير الاختيارية أو غير المعنونة، ما دامت تُطبَّق في الوقت نفسه. وبحكم طبيعتها، لا تتبادل الوسائط الاختيارية مواضعها مع الوسائط غير المعنونة المطبَّقة مستقلّةً.

# test ~y:2 ~x:3 () ();;

- : int * int * int = (3, 2, 0)

# test () () ~z:1 ~y:2 ~x:3;;

- : int * int * int = (3, 2, 1)

# (test () ()) ~z:1 ;;

Error: This expression has type int * int * int
       This is not a function; it cannot be applied.

فهنا (test () ()) هو (0,0,0) سلفًا، ولا يمكن تطبيقه أكثر.

والوسائط الاختيارية تُنفَّذ في الواقع كأنواع خيارية. فإن لم تعطِ قيمة افتراضية، أمكنك الوصول إلى تمثيلها الداخلي، type 'a option = None | Some of 'a. وحينها يمكنك تقديم سلوكيات مختلفة بحسب حضور الوسيط أو غيابه.

# let bump ?step x =
    match step with
    | None -> x * 2
    | Some y -> x + y
  ;;

val bump : ?step:int -> int -> int = <fun>

وقد يكون مفيدًا أيضًا تمرير وسيط اختياري من استدعاء دالة إلى آخر. ويتم ذلك بوضع علامة ? قبل الوسيط المطبَّق. فعلامة الاستفهام هذه تُعطّل تغليف الوسيط الاختياري في نوع خياري.

# let test2 ?x ?y () = test ?x ?y () ();;

val test2 : ?x:int -> ?y:int -> unit -> int * int * int = <fun>

# test2 ?x:None;;

- : ?y:int -> unit -> int * int * int = <fun>

4.2 الوسوم واستنتاج الأنواع

رغم أنها تزيد الراحة في كتابة تطبيقات الدوال، فإنّ في الوسوم والوسائط الاختيارية مَزلقًا هو أنها لا يمكن استنتاجها استنتاجًا تامًّا كما هي الحال في بقيّة اللغة.

ويمكنك رؤية ذلك في المثالين التاليين.

# let h' g = g ~y:2 ~x:3;;

val h' : (y:int -> x:int -> 'a) -> 'a = <fun>

# h' f ;;

Error: The value f has type x:int -> y:int -> int
       but an expression was expected of type y:int -> x:int -> 'a
       Labels x and y do not match

# let bump_it bump x =
    bump ~step:2 x;;

val bump_it : (step:int -> 'a -> 'b) -> 'a -> 'b = <fun>

# bump_it bump 1 ;;

Error: The value bump has type ?step:int -> int -> int
       but an expression was expected of type step:int -> 'a -> 'b
       The label ?step was expected to not be optional

الحالة الأولى بسيطة: يُمرَّر إلى g الوسم ~y ثم ~x، بينما تتوقّع f الوسم ~x ثم ~y. ويُعالَج هذا معالجة صحيحة إذا عرفنا نوع g سلفًا أنه x:int -> y:int -> int، وإلّا حصل التعارض النوعي المذكور أعلاه. وأبسط حلّ هو تطبيق الوسائط الصورية بترتيب معياري.

أمّا المثال الثاني فأدقّ: فرغم أننا قصدنا أن يكون الوسيط bump من النوع ?step:int -> int -> int، استُنتج أن نوعه step:int -> int -> 'a. ولأنّ هذين النوعين غير متوافقين (فالوسائط العادية والاختيارية مختلفة داخليًا)، يحدث خطأ نوع عند تطبيق bump_it على الدالة bump الحقيقية.

لن نحاول هنا شرح كيفية عمل استنتاج الأنواع بالتفصيل. يكفي أن تفهم أنّ في البرنامج أعلاه معلومات غير كافية لاستنتاج النوع الصحيح لـ g أو لـ bump. أي أنه لا سبيل إلى معرفة ما إذا كان الوسيط اختياريًا أم لا، ولا إلى معرفة الترتيب الصحيح، بالنظر إلى كيفية تطبيق الدالة فقط. والاستراتيجية التي يستعملها المترجم هي افتراض عدم وجود وسائط اختيارية، وأنّ التطبيقات تجري بالترتيب الصحيح.

والطريقة الصحيحة لحلّ هذه المشكلة في الوسائط الاختيارية هي إضافة إضافة نوع إلى الوسيط bump.

# let bump_it (bump : ?step:int -> int -> int) x =
    bump ~step:2 x;;

val bump_it : (?step:int -> int -> int) -> int -> int = <fun>

# bump_it bump 1;;

- : int = 3

وعمليًا، تظهر مثل هذه المشكلات غالبًا عند استعمال كائنات دوالها ذات وسائط اختيارية، لذا فكتابة نوع وسائط الكائنات فكرة حسنة في الغالب.

وبشكل عادي يولّد المترجم خطأ نوع إذا حاولت تمرير وسيط نوعه مختلف عن المتوقّع إلى دالة. غير أنه في الحالة الخاصة التي يكون فيها النوع المتوقّع نوع دالة غير معنون، والوسيط دالة تتوقّع وسائط اختيارية، سيحاول المترجم تحويل الوسيط ليطابق النوع المتوقّع، بتمرير None لكل الوسائط الاختيارية.

# let twice f (x : int) = f(f x);;

val twice : (int -> int) -> int -> int = <fun>

# twice bump 2;;

- : int = 8

وهذا التحويل متّسق مع الدلالة المقصودة، بما في ذلك الآثار الجانبية. أي أنه إذا كان تطبيق الوسائط الاختيارية سيُنتج آثارًا جانبية، فإنّ هذه الآثار تؤجَّل إلى أن تُطبَّق الدالة المستقبِلة فعلًا على وسيط.

4.3 اقتراحات لوضع الوسوم

كما في اختيار الأسماء، ليس اختيار وسوم الدوال مهمّة سهلة. والوسم الجيّد هو الذي

  • يجعل البرامج أكثر قابلية للقراءة،

  • يسهل تذكّره،

  • يسمح، حين أمكن، بتطبيقات جزئية مفيدة.

نشرح هنا القواعد التي طبّقناها عند وضع وسوم مكتبات OCaml.

إذا تحدّثنا بطريقة «كائنية»، يمكن اعتبار أنّ لكل دالة وسيطًا رئيسيًا، هو كائنها، ووسائط أخرى تتعلّق بفعلها، هي المعاملات. وللسماح بتركيب الدوال عبر الدوال العليا في نمط الوسوم المتبادلة، لن يُوسم الكائن. فدوره واضح من الدالة نفسها. أمّا المعاملات فتُوسم بأسماء تُذكِّر بطبيعتها أو بدورها. وأفضل الوسوم ما يجمع بين الطبيعة والدور. وحين يتعذّر ذلك يُفضَّل الدور، لأنّ الطبيعة سيُعطيها النوع نفسه في الغالب. وينبغي تجنّب الاختصارات الغامضة.

ListLabels.map : f:('a -> 'b) -> 'a list -> 'b list
UnixLabels.write : file_descr -> buf:bytes -> pos:int -> len:int -> unit

وحين تكون هناك عدّة كائنات بالطبيعة والدور نفسيهما، تُترك كلها بلا وسم.

ListLabels.iter2 : f:('a -> 'b -> unit) -> 'a list -> 'b list -> unit

وحين لا يوجد كائن مفضَّل، تُوسم كل الوسائط.

BytesLabels.blit :
  src:bytes -> src_pos:int -> dst:bytes -> dst_pos:int -> len:int -> unit

غير أنه حين يكون هناك وسيط واحد فقط، يُترك في الغالب بلا وسم.

BytesLabels.create : int -> bytes

وينطبق هذا المبدأ أيضًا على دوال بعدّة وسائط نوع إرجاعها متغيّر نوع، ما دام دور كل وسيط غير ملتبس. فوضع وسوم على مثل هذه الدوال قد يقود إلى رسائل خطأ رديئة حين تحاول حذف الوسوم في تطبيق ما، كما رأينا مع ListLabels.fold_left.

وفي ما يلي بعض أسماء الوسوم التي ستجدها في أنحاء المكتبات.

الوسم المعنى
f: دالة يُطبَّق عليها
pos: موضع في سلسلة أو مصفوفة أو متتالية بايتات
len: طول
buf: متتالية بايتات أو سلسلة تُستعمل مخزنًا مؤقتًا
src: مصدر العملية
dst: هدف العملية
init: القيمة الابتدائية لمكرِّر
cmp: دالة مقارنة، مثل Stdlib.compare
mode: نمط عملية أو قائمة أعلام

كل هذه مجرّد اقتراحات، لكن تذكّر أنّ اختيار الوسوم أساسي لقابلية القراءة. فالاختيارات الغريبة ستجعل البرنامج أصعب في الصيانة.

وفي الحالة المثالية، ينبغي أن يكفي اسم الدالة الصحيح مع الوسوم الصحيحة لفهم معنى الدالة. ولأنّ هذه المعلومات متاحة في OCamlBrowser أو في المستوى الأعلى ocaml، لا يُستعمل التوثيق إلا عند الحاجة إلى مواصفة أكثر تفصيلًا.
