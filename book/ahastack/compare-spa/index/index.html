مقارنة مع تطبيق SPA

دعنا نقارن حزمة AHA بالمقاربة المعتادة لتطبيق الصفحة الواحدة (SPA)، مثل تطبيق مبنيّ باستخدام React مثلًا:

  • الأمر أبسط في التفكير فيه، فهناك أمور أقلّ ينبغي أن تشغل بالك، فتستطيع التفكير في أمور مهمّة أخرى بدلًا من ذلك. مثلًا «كيف سيجد الناس تطبيقي» أو «دعني أضيف هذه الميزة بسرعة».
  • إنه أكثر وفاءً للمنصّة. فهو يستخدم Web كما قُصد أن تُستخدم.
  • إنه يمنحك مشكلات أداء أقلّ تعقيدًا، لأنك تستخدم Web كما قُصد أن تُستخدم.
  • إنه يتطلّب شيفرة JavaScript أقلّ. ارفع يدك إن كنت قد زرت يومًا موقعًا حيًّا كانت صفحته فارغة تمامًا وفيطر الأخطاء في DevTools مليء بالأخطاء، أو (وهو أسوأ) خطأ JavaScript مطبوع على الصفحة نفسها.
  • إنّه يتطلّب ارتباطًا أضعف بالتقنية. فإذا بنيت تطبيقًا بـ React، فأنت مطوّر React. تستخدم Svelte؟ فأنت مطوّر Svelte. أنت مربوط بذلك، ولن تعيد كتابة التطبيق بإطار أو مكتبة أخرى أبدًا لأنك ستضطر لإعادة كتابة كل شيء من الصفر. أمّا النهج الذي أستخدمه فيعتمد على تبعيات أصغر يمكنك استبدالها في أي وقت ببديل. بل يمكنك حتى كتابة نسختك الخاصة، لأن htmx مجرّد ملف واحد.
  • التحميل الأول أسرع بكثير لأنه لا يكاد يكون سوى بعض HTML مُعرَّض على الخادم، فأنت لا تحتاج أولًا إلى تحميل كمّ هائل من JavaScript ثم التهيئة ثم استدعاء بعض JSON الذي يُعرَّض بعد ذلك…
