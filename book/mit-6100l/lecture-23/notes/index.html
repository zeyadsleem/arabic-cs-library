الشريحة 1: أصناف التعقيد — أمثلة

هذه المحاضرة أمثلة على أصناف التعقيد (Complexity Classes). يُرفق ملف الشرائح وملفات .py للمتابعة الجانبيًا.

الشريحة 2: ثيتا (Θ)

  • نرمز إلى التعقيد الحتمي (asymptotic complexity) بالحرف ثيتا Θ.
  • ننظر إلى حدّ المدخل الذي يهيمن على الدالة.
  • نُسقط الأجزاء الأخرى التي لا تنمو بسرعة، ونُسقط الثوابت الجمعية، ونُسقط الثوابت الضربية.
  • ينتهي الأمر إلى عدد قليل من أصناف الخوارزميات.
  • سننظر اليوم إلى شيفرة تقع في كل واحد من هذه الأصناف.

الشريحة 3: من أين تأتي الدالة؟

بالنظر إلى الشيفرة، ابدأ بمعاملات الإدخال: ما هي؟ ثم صُغ المعادلة التي تربط الإدخال بعدد العمليات.

def f(L, L1, L2):
    inL1 = False
    for i in range(len(L1)):
        if L[i] == L1[i]:
            inL1 = True
    inL2 = False
    for i in range(len(L2)):
        if L[i] == L2[i]:
            inL2 = True
    return inL1 and inL2
f=1+len(L1)∗5+1+len(L2)∗5+2=5∗len(L1)+5∗len(L2)+3f = 1 + len(L1)*5 + 1 + len(L2)*5 + 2 = 5*len(L1) + 5*len(L2) + 3f=1+len(L1)∗5+1+len(L2)∗5+2=5∗len(L1)+5∗len(L2)+3

إذا كان الطولان متساويين، فإن:

f=10∗len(L)+3f = 10*len(L) + 3f=10∗len(L)+3 Θ(f)=Θ(10∗len(L)+3)=Θ(len(L))\Theta(f) = \Theta(10*len(L) + 3) = \Theta(len(L))Θ(f)=Θ(10∗len(L)+3)=Θ(len(L))

الشريحة 4: من أين تأتي الدالة؟ (طريقة أسرع)

لا حاجة لصياغة المعادلة الدقيقة. ابحث عن الحلقات وعن كل ما يتكرّر بدلالة معاملات الإدخال. وكل ما عداه ثابت.

نفس الدالة f(L, L1, L2) السابقة، والحلقتان for i in range(len(L1)) و for i in range(len(L2)) هما كل ما يتكرّر بدلالة الإدخال.

الشريحة 5: أصناف التعقيد

n هو المدخل. نريد تصميم خوارزميات تكون أقرب ما يمكن إلى قمة هذا التسلسل قدر الإمكان.

الرمز الدلالة
Θ(1)\Theta(1)Θ(1) زمن تشغيل ثابت (constant running time)
Θ(log⁡n)\Theta(\log n)Θ(logn) زمن تشغيل لوغاريتمي (logarithmic)
Θ(n)\Theta(n)Θ(n) زمن تشغيل خطّي (linear)
Θ(nlog⁡n)\Theta(n \log n)Θ(nlogn) زمن تشغيل خطّي لوغاريتمي (log-linear)
Θ(nc)\Theta(n^c)Θ(nc) زمن تشغيل متعدّد الحدود (polynomial)، حيث ccc ثابت
Θ(cn)\Theta(c^n)Θ(cn) زمن تشغيل أُسّي (exponential)، حيث ccc ثابت مرفوع إلى قوّة تعتمد على حجم الإدخال

ملاحظة المترجم: الشرائح الأصلية تكتب الحدّين الأخيرين بالإحراف مطبوعًا على هيئة Θ(nc)\Theta(nc)Θ(nc) و Θ(cn)\Theta(cn)Θ(cn)، لكن المقصود هو ncn^cnc و cnc^ncn، وقد ضبطتُهما هنا على الصورة الصحيحة لأن بقية الشرائح تستخدمهما بذلك.

الشريحة 6: التعقيد الثابت

شريحة فاصلة.

الشريحة 7: التعقيد الثابت

  • تعقيد مستقل عن المدخلات.
  • الخوارزميات المثيرة للاهتمام في هذا الصنف قليلة، لكن كثيرًا من الخوارزميات يمكن أن تحتوي أجزاءً تقع في هذا الصنف.
  • يمكن أن توجد حلقات أو استدعاءات ذاتية، لكن عدد التكرارات أو الاستدعاءات لا يعتمد على حجم المدخل.
  • بعض العمليات المدمجة في اللغة ثابتة الزمن:
    • الفهرسة في قائمة في Python: L[i]
    • الإلحاق في قائمة: L.append()
    • البحث في قاموس: d[key]

الشريحة 8: التعقيد الثابت: مثال ١

def add(x, y):
    return x+y

التعقيد بدلالة x أو بدلالة y: Θ(1)\Theta(1)Θ(1).

الشريحة 9: التعقيد الثابت: مثال ٢

def convert_to_km(m):
    return m*1.609

التعقيد بدلالة m: Θ(1)\Theta(1)Θ(1).

الشريحة 10: التعقيد الثابت: مثال ٣

def loop(x):
    y = 100
    total = 0
    for i in range(y):
        total += x
    return total

التعقيد بدلالة x (معامل الإدخال): Θ(1)\Theta(1)Θ(1)، لأن الحدّ الأقصى للتكرارات هو 100 أي عدد ثابت لا علاقة له بـ x.

الشريحة 11: التعقيد الخطّي

شريحة فاصلة.

الشريحة 12: التعقيد الخطّي

  • خوارزميات حلقية تكرارية بسيطة (simple iterative loop algorithms).
  • يجب أن تكون الحلقات دالةً في المدخل.
  • البحث الخطّي عن عنصر في قائمة (linear search): هل العنصر موجود أم لا.
  • دوال ذاتية (recursive functions) فيها استدعاء ذاتي واحد فقط وتكلفة ثابتة للاستدعاء نفسه.
  • بعض العمليات المدمجة خطّية:
    • e in L
    • شريحة من قائمة، مثل L[:len(L)//2]
    • L1 == L2
    • del(L[5])

الشريحة 13: مثال تعقيد صفر (بمفاجأة)

اضرب x في y.

def mul(x, y):
    tot = 0
    for i in range(y):
        tot += x

الشريحة 53: خوارزميات البحث

البحث الخطّي (linear search):

  • بحث بالقوة الغاشمة (brute force).
  • لا يلزم أن تكون القائمة مرتّبة.

البحث بالتنصيف (bisection search):

  • يجب أن تكون القائمة مرتّبة (MUST) حتى تعطي إجابة صحيحة.
  • سنرى تنفيذين مختلفين للخوارزمية.

الشريحة 54: البحث الخطّي على قائمة غير مرتّبة

def linear_search(L, e):
    found = False
    for i in range(len(L)):
        if e == L[i]:
            found = True
    return found
  • يجب أن ننظر في كل العناصر لنقرّر أنه غير موجود.
  • Θ(len(L))\Theta(len(L))Θ(len(L)) للحلقة، مضروبة في Θ(1)\Theta(1)Θ(1) لاختبار e == L[i].
  • التعقيد الإجمالي Θ(n)\Theta(n)Θ(n) حيث n=len(L)n = len(L)n=len(L)، أي Θ(len(L))\Theta(len(L))Θ(len(L)).

الشريحة 55: البحث الخطّي على قائمة غير مرتّبة (نسخة ثانية)

def linear_search(L, e):
    for i in L:
        if e == L[i]:
            return True
    return False
  • نفس التحليل السابق.
  • Θ(len(L))\Theta(len(L))Θ(len(L)) للحلقة، مضروبة في Θ(1)\Theta(1)Θ(1) لاختبار e == L[i].
  • التعقيد الإجمالي Θ(n)\Theta(n)Θ(n) حيث n=len(L)n = len(L)n=len(L)، أي Θ(len(L))\Theta(len(L))Θ(len(L)).

ملاحظة المترجم: الشريحة تحمل النصّ الدقيق للدالة linear_search وعلى يسارها نسختان متتاليتان منها (تُقرأان على أنها found = False ثم for i in L: مع return True/return False). النسخة الأولى تُعيد found بعد الحلقة، والثانية تُعيد True/False مباشرة. تُركت الاثنتان كما تظهران في الشريحة.

الشريحة 56: البحث الخطّي على قائمة مرتّبة

def search(L, e):
    for i in L:
        if i == e:
            return True
        if i > e:
            return False
    return False
  • يجب أن ننظر فقط حتى نصل إلى عدد أكبر من e.
  • Θ(len(L))\Theta(len(L))Θ(len(L)) للحلقة، مضروبة في Θ(1)\Theta(1)Θ(1) لاختبار i == e أو i > e.
  • التعقيد الإجمالي Θ(len(L))\Theta(len(L))Θ(len(L))، أي Θ(n)\Theta(n)Θ(n) حيث n=len(L)n = len(L)n=len(L).

الشريحة 57: البحث بالتنصيف عن عنصر في قائمة مرتّبة

  1. اختر فهرسًا i يقسم القائمة إلى نصفين.
  2. اسأل: هل L[i] == e؟
  3. إن لم يكن كذلك، اسأل: هل L[i] أكبر أم أصغر من e؟
  4. حسب الإجابة، ابحث في النصف الأيسر أو الأيمن من L عن e.
  • هذه نسخة جديدة من «اقسم وانتصر» (divide-and-conquer): إذًا الاستدعاء الذاتي (recursion)!
  • نقسم المشكلة إلى نسخ أصغر منها (قائمة أصغر)،إضافةً إلى عمليات بسيطة.
  • الإجابة عن النسخة الأصغر هي الإجابة عن النسخة الأصلية.

الشريحة 58: تحليل تعقيد البحث بالتنصيف

  • ننتهي من النظر في القائمة عندما:
1=n/2i1 = n/2^i1=n/2i
  • إذن ما العلاقة بين الطول الأصلي للقائمة وعدد مرّات تقسيمها؟
i=log⁡ni = \log ni=logn
  • التعقيد هو Θ(log⁡n)\Theta(\log n)Θ(logn) حيث nnn هو len(L).

ملاحظة المترجم: الشريحة الأصلية تمثّل المساواة 1 = n/2^i بخطّ مستقيم على محور لوغاريتمي بحوارَين «…»، وهذه الأشكال لا تنجو من طبقة النصّ؛ أُعيدت المعادلة بصيغتها الرياضية الصحيحة.

الشريحة 59: الفكرة الكبرى

تنفيذان مختلفان لهما قيمتا Θ\ThetaΘ مختلفتان.

الشريحة 60: البحث بالتنصيف — التنفيذ ١

def bisect_search1(L, e):
    if L == []:
        return False
    elif len(L) == 1:
        return L[0] == e
    else:
        half = len(L)//2
        if L[half] > e:
            return bisect_search1( L[:half], e)
        else:
            return bisect_search1( L[half:], e)

الشريحة 61: تعقيد bisect_search1 (حيث n هو len(L))

  • Θ(log⁡n)\Theta(\log n)Θ(logn) استدعاءات بحث بالتنصيف.
  • كل استدعاء ذاتي يقتطع المدى المطلوب البحث فيه إلى النصف. أسوأ حالة للوصول إلى مدى حجمه 1 من n هي عندما n/2k=1n/2^k = 1n/2k=1، أي عندما k=log⁡nk = \log nk=logn، وبهذا نحصل على تعبير يربط k بـ n.
  • Θ(n)\Theta(n)Θ(n) لكل استدعاء بحث للتنصيف بسبب نسخ القائمة.
  • Θ(log⁡n)∗Θ(n)=Θ(nlog⁡n)\Theta(\log n) * \Theta(n) = \Theta(n \log n)Θ(logn)∗Θ(n)=Θ(nlogn) حيث n=len(L)n = len(L)n=len(L).
    • هذه هي الإجابة في هذا الصف.
  • إن كنت دقيقًا، ستلاحظ أن القائمة أيضًا تُنصَّف عند كل استدعاء ذاتي، فتصير هنالك سلسلة لا نهائية (لا داعي للقلق بشأنها في هذا الصف).
  • Θ(n)\Theta(n)Θ(n) هي حدّ أدقّ (tighter bound) لأن نسخ القائمة يهيمن على log⁡n\log nlogn.

الشريحة 62: تنفيذ بديل للبحث بالتنصيف

  • صغّر حجم المسألة بمعامل 2 في كل خطوة.
  • احتفظ بفهرسي low و high للبحث في القائمة.
  • تجنّب نسخ القائمة.
  • تعقيد الاستدعاء الذاتي هو Θ(log⁡n)\Theta(\log n)Θ(logn) حيث nnn هو len(L).

الشريحة 63: البحث بالتنصيف — التنفيذ ٢

def bisect_search2(L, e):
    def bisect_search_helper(L, e, low, high):
        if high == low:
            return L[low] == e
        mid = (low + high)//2
        if L[mid] == e:
            return True
        elif L[mid] > e:
            if low == mid: #nothing left to search
                return False
            else:
                return bisect_search_helper(L, e, low, mid - 1)
        else:
            return bisect_search_helper(L, e, mid + 1, high)
    if len(L) == 0:
        return False
    else:
        return bisect_search_helper(L, e, 0, len(L) - 1)

الشريحة 64: تعقيد bisect_search2 ودالة المساعِد (حيث n هو len(L))

  • Θ(log⁡n)\Theta(\log n)Θ(logn) استدعاءات بحث بالتنصيف.
  • كل استدعاء ذاتي يقتطع المدى المطلوب البحث فيه إلى النصف. أسوأ حالة للوصول إلى مدى حجمه 1 من n هي عندما n/2k=1n/2^k = 1n/2k=1، أي عندما k=log⁡nk = \log nk=logn.
  • نمرّر القائمة والفهارس كمعاملات. القائمة لا تُنسخ أبدًا، بل تُمرَّر فقط: Θ(1)\Theta(1)Θ(1) عند كل استدعاء ذاتي.
  • Θ(log⁡n)∗Θ(1)=Θ(log⁡n)\Theta(\log n) * \Theta(1) = \Theta(\log n)Θ(logn)∗Θ(1)=Θ(logn) حيث n=len(L)n = len(L)n=len(L).

الشريحة 66: البحث في قائمة مرتّبة — حيث n هو len(L)

  • باستخدام البحث الخطّي، البحث عن عنصر هو Θ(n)\Theta(n)Θ(n).
  • باستخدام البحث الثنائي، يمكننا البحث عن عنصر في Θ(log⁡n)\Theta(\log n)Θ(logn) — بافتراض أن القائمة مرتّبة!
  • متى يكون من المعقول أن نرتب أولًا ثم نبحث؟
SORT+Θ(log⁡n)<Θ(n)⇒SORT<Θ(n)−Θ(log⁡n)SORT + \Theta(\log n) < \Theta(n) \Rightarrow SORT < \Theta(n) - \Theta(\log n)SORT+Θ(logn)<Θ(n)⇒SORT<Θ(n)−Θ(logn)
  • متى يكون الترتيب أصغر من Θ(n)\Theta(n)Θ(n)؟!
    • أبدًا ما دام أنك على الأقل ستحتاج إلى النظر في كل عنصر!

الشريحة 67: التكلفة المُطفَّرة (Amortized Cost) — حيث n هو len(L)

  • لماذا نرتّب أولًا إذن؟
  • رتّب القائمة مرّة واحدة ثم أجرِ عمليات بحث كثيرة.
  • نُطفئ (amortize) كلفة الترتيب على عمليات البحث الكثيرة.
  • SORT+K∗Θ(log⁡n)<K∗Θ(n)SORT + K * \Theta(\log n) < K * \Theta(n)SORT+K∗Θ(logn)<K∗Θ(n)، أي إن كان K كبيرًا فإن زمن الترتيب يصبح غير ذي أثر.
