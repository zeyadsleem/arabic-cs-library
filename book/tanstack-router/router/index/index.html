ماذا سنتعلّم؟

في أول درس من الدورة نستعرض TanStack Router قبل أن نكتب فيه سطرًا واحدًا: ما هو، وما الذي يجعله مختلفًا عن بقية موجّهات React، وما الميزات التي ستراها واحدًا واحدًا في الدروس التالية. تتّضح في هذا الدرس القاعدة التي بُنيت عليها المكتبة: كل ما يتعلّق بالتنقّل مكتوبٌ بأنواع صارمة، فيتحقّق المحرّر من صحّة روابطك ومعاملاتك قبل أن يعمل التطبيق، لا بعد أن يخطئ المستخدم.

الدرس خريطةُ طريق أكثر منه تطبيقًا: نمرّ على الميزات الكبرى — التخطيطات المتداخلة، والتوجيه المبني على الملفات، وتحميل البيانات بالتوازي، والجلب المسبق، والذاكرة المؤقتة — ونترك كل تفصيلٍ منها لدرسٍ مستقل. وفي نهايته ننتقل إلى العمل مباشرةً: إنشاء مشروع جديد وتثبيت الموجّه داخله.

موجّهٌ لا إطارُ عمل

TanStack Router ليس إطار عمل متكامل بمعنى Next.js، بل هو طبقةُ تنقّل تجلس داخل تطبيقك أنت. بنيةُ المشروع وأدواتُ البناء والخادم ملكك أنت، والمكتبة تتكفّل بشجرة المسارات والتنقّل بينها.

وهذا الفرق ليس ترفًا: لو كانت المكتبة إطارًا كاملًا لما استطعتَ نقل مساراتك إلى مشروع قائم دون إعادة كتابةٍ من الصفر. ولهذا صُمّمت لتكون قابلةً للترقية إلى إطار عمل كامل، وهي فعليًا ما يشغّل إطارَ العمل TanStack Start الذي كان في مرحلة تجريبية (بيتا) وقت تصوير الدورة. ومَن أراد تعلّم TanStack Start لاحقًا سيحتاج أوّلًا إلى إتقان موجّه TanStack Router.

ويشير الدرس أيضًا إلى جدولِ مقارنة بين أشهر موجّهات React — TanStack Router وReact Router وموجّه Next.js — قد يساعدك على اختيار الموجّه المناسب لمشروعٍ جديد.

الأمانُ النوعي: ماذا يعني «آمنُ الأنواع بالكامل»؟

الوعدُ الأساسيّ في المكتبة أنّ كل عملية تنقّل — من رابطٍ في الصفحة إلى استدعاءٍ برمجيّ للموجّه — يمرّ على فحصِ TypeScript. فلا يكفي أن يعرف المحرّر اسمَ المسار؛ عليه أن يعرف عنوانه الكامل، ونوع معاملاته، وشكلَ ما يعود من التحقّق.

وأنواعُ المسارات لا تُكتب يدويًّا؛ «دعم TypeScript المُستنتَج» يعني أنّ الأنواع تُشتقّ من شجرة المسارات المولَّدة تلقائيًّا، فتبقى الروابطُ والتطبيقُ متوافقَين لأنّ مصدرَهما واحد. (توضيح من عندي: هذه الآلية تظهر بوضوح في درس التوجيه المبني على الملفات، وهو من الدروس التالية.)

ويمتدّ الأمر إلى معاملات البحث (search params): يمكن جعلها آمنةِ الأنواع، والتحقّق من قيمها قبل أن تصل إلى الصفحة، وتعديلها بسهولة.

الميزاتُ التي سنعود إليها في الدروس التالية

  • التخطيطات المتداخلة ومجموعاتُ التخطيط — تخطيطاتٌ تشارك تبويباتٍ أو أشرطةً بين صفحاتٍ مختلفة.
  • التوجيه المبني على الملفات — شجرةُ مساراتٍ تُولَّد من مجلّد routes، مع ملفّ routeTree.gen.ts مولَّدٍ تلقائيًّا.
  • تحميلُ البيانات بالتوازي والجلبُ المسبق — طلبُ بياناتِ صفحةٍ واحدةٍ معًا بدل واحدةٍ تلو الأخرى.
  • الذاكرةُ المؤقتة المدمجة — تخزينُ نتائج التحقّق وإعادةُ استخدامها.
  • التكامل مع TanStack Query — طبقةُ بياناتٍ فوق طبقة التنقّل.
  • السياق (context) — حالةٌ مشتركةٌ بين عدّة مسارات، تُستعمل مثلًا في المصادقة (authentication) لحماية مساراتٍ معيّنة.
  • دوالُ المُحمِّل (loader) وبثُّ البيانات — تحميلُ بياناتِ المسار ضمن مساره لا خارجه.

الشيفرةُ التي سنبني عليها

الفرع main — وهو الفرع الذي تنطلق منه الدورة — يحتوي هيكل مشروع Vite وReact مع TypeScript، مضافًا إليه موجّهُ TanStack Router وأدواتُه. هذه بعض أجزائه.

في ملفّ الاعتماديات تظهر ثلاثُ حزمٍ لا بدّ منها: @tanstack/react-router وهي المكتبة نفسها، و@tanstack/react-router-devtools وهي أدوات المطوّر، و@tanstack/router-plugin وهي إضافةُ البناء المولِّدة لشجرة المسارات. لاحظ أن الأخيرة تقع في اعتماديات التطوير، فهي لا تُشحن مع التطبيق:

  "dependencies": {
    "@tailwindcss/vite": "^4.1.12",
    "@tanstack/react-router": "^1.131.28",
    "@tanstack/react-router-devtools": "^1.131.28",
    "react": "^19.1.1",
    "react-dom": "^19.1.1",
    "tailwindcss": "^4.1.12"
  },
  "devDependencies": {
    "@eslint/js": "^9.33.0",
    "@tanstack/router-plugin": "^1.131.28",
    "@types/react": "^19.1.10",
    "@types/react-dom": "^19.1.7",
    "@vitejs/plugin-react": "^5.0.0",
    "eslint": "^9.33.0",
    "eslint-plugin-react-hooks": "^5.2.0",
    "eslint-plugin-react-refresh": "^0.4.20",
    "globals": "^16.3.0",
    "typescript": "~5.8.3",
    "typescript-eslint": "^8.39.1",
    "vite": "^7.1.2"
  }
}

وتسجيلُ الإضافة يتمّ في ملفّ إعدادات البناء، داخل مصفوفة plugins. الإضافةُ تسبق إضافةَ React في الترتيب، ومعاملُ target فيها يحدّد إطارَ العمل المستهدَف:

import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";
import tailwindcss from "@tailwindcss/vite";
import { tanstackRouter } from "@tanstack/router-plugin/vite";

// https://vite.dev/config/
export default defineConfig({
  plugins: [
    tanstackRouter({
      target: "react",
    }),
    react(),
    tailwindcss(),
  ],
});

أمّا نقطةُ الدخول فهي كما هي في أيّ مشروع Vite: تُستورد الأنماطُ من index.css، ويُركَّب <App /> داخل StrictMode. وهي الموضع الذي سيُركَّب فيه الموجّه في الدروس القادمة، فكل ما نحتاجه الآن هو أن نعرف أين نقطةُ الانطلاق:

import { StrictMode } from 'react'
import { createRoot } from 'react-dom/client'
import './index.css'
import App from './App.tsx'

createRoot(document.getElementById('root')!).render(
  <StrictMode>
    <App />
  </StrictMode>,
)

وأمّا إعداداتُ TypeScript فهي صارمة: الوضعُ strict مفعّل، والمتغيّراتُ غير المستعملة خطأٌ لا تحذير، والأوامرُ المتشعّبة تكسر البناء. وليست هذه تفاصيلً تجميلية: الأمانُ النوعي الذي تعد به المكتبة لن يكون له أثرٌ حقيقيٌّ إن كان المشروعُ نفسه متساهلاً في فحص الأنواع.

    /* Linting */
    "strict": true,
    "noUnusedLocals": true,
    "noUnusedParameters": true,
    "erasableSyntaxOnly": true,
    "noFallthroughCasesInSwitch": true,
    "noUncheckedSideEffectImports": true
  },
  "include": ["src"]

النتيجة

بعد هذا الدرس صارت الإجابةُ عن سؤال «ما الذي سأستخدمه؟» واضحة: TanStack Router موجّهٌ آمنُ الأنواع بالكامل، يجمع التخطيطات المتداخلة والتوجيه المبني على الملفات والتحميلَ بالتوازي والجلبَ المسبق والذاكرةَ المؤقتة والتكاملَ مع TanStack Query ومعاملاتَ بحثٍ آمنةِ الأنواع وسياقًا مشتركًا ودوالَ مُحمِّل، وهو موجّهٌ لا إطارُ عمل، وقابلٌ للترقية إلى TanStack Start.

والمشروعُ الذي سنعمل عليه صار مهيّأً: إضافةُ Vite مسجّلةٌ في الترتيب الصحيح، وإعداداتُ TypeScript صارمة، ونقطةُ الدخول جاهزةٌ لاستقبال الموجّه. أمّا الخطوةُ التالية — كما في الدرس التالي — فهي إنشاءُ مشروعٍ جديد وتثبيتُ الموجّه فيه من الصفر.

جرّب بنفسك

  1. افتح فرع main من مستودع الدورة وتصفّح vite.config.ts: حدّد إضافةَ الموجّه وموضعَها في ترتيب plugins.
  2. في package.json فرّق بين الحزمِ التي تُشحن مع التطبيق وتلك التي لا تُشحن إلا وقت البناء، وبيّن لماذا يُعدّ @tanstack/router-plugin من الثانية.
  3. في tsconfig.app.json ابحث عن "strict": true وقارن أثرَه بما كنتَ تكتتبه في مشاريعك السابقة.
  4. اكتب قائمةً قصيرة بالميزات التي يحتاجها مشروعك القادم من الميزات المذكورة أعلاه، فستجد في الدروس التالية أين يجد كلٌّ منها مكانَه.
