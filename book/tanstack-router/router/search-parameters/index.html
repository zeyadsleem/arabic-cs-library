ماذا سنتعلّم؟

كثيرٌ من تطبيقات الويب حالةٌ لا تنتهي: تصفيةٌ وترقيمٌ صفحيّ وترتيبٌ للنتائج. وحين تُخزَّن هذه الحالةُ في حالةِ React وحدها، تفقدها في اللحظة التي تبتعد فيها عن الصفحة أو تُحدِّثها. أمّا حين تعيش في عنوان الصفحة، فيمكنك أن تشارك الرابطَ أو تحفظه في المفضّلة أو تفتحه في تبويبٍ جديد، وتجد التطبيقَ بالحالة نفسها.

في هذا الدرس نتعلّم كيف يدير TanStack Router هذه المعاملات: كيف نمرّرها مع الرابط، وكيف تقرأها الصفحة، وكيف نتحقّق منها فنحصل على أمانِ أنواعٍ يكشف أخطاءَ الكتابة قبل أن تصل إلى المتصفّح.

الشرح

صفحةُ المنتجات ومسارُها الجديد

لنتخيّل صفحةَ منتجاتٍ فيها قائمةٌ ومرشّحاتٌ وترقيمٌ صفحيّ، ونضع لها مسارًا جديدًا:

  • src/routes/products.index.tsx

ولاحقةُ index تجعل /products مسارًا مستقلًّا لا أبًا لأحد، على نحو ما تعلّمناه في درس المقاطع الديناميكية. والصفحةُ في فرع الدرس كالتالي:

import { createFileRoute } from "@tanstack/react-router";

export const Route = createFileRoute("/products/")({
  component: RouteComponent,
  validateSearch: (search: Record<string, unknown>) => {
    return {
      sort_by: (search.sort_by as string) || "",
    };
  },
});

function RouteComponent() {
  const search = Route.useSearch();
  console.log(search);
  return <div>Hello "/products/"!</div>;
}

ولاحظ فيها validateSearch: دالّةٌ تستقبل ما في عنوان الصفحة كما هو، بلا أنواعٍ ولا تحقّق، وتُعيد كائنًا مُتحقَّقًا منه ومُمنَحًا أنواعَه. وسنعود إلى ذلك بتفصيلٍ أدناه.

تمريرُ معاملات البحث مع الرابط

كي نصل إلى الصفحة بمعاملات بحثٍ في عنوانها، نضيف إلى Link خاصيةً اسمها search، ونضع فيها المعاملاتَ في كائن. والصفحةُ الرئيسيةُ في فرع الدرس صارت كالتالي:

import { createFileRoute, Link } from "@tanstack/react-router";

export const Route = createFileRoute("/")({
  component: RouteComponent,
});

function RouteComponent() {
  return (
    <div className="p-2 bg-violet-500">
      <h3 className="text-xl font-bold">Home</h3>
      <Link
        to="/{-$locale}/archive/{-$year}/{-$month}/{-$day}"
        params={{
          locale: "fr",
          year: "2009",
        }}
      >
        Go to Archive
      </Link>
      <br />
      <Link
        to="/products"
        search={{
          sort_by: "price",
          // product_type: ["shoes", "t-shirts"],
          // pagination: {
          //   page: 1,
          //   pageSize: 10,
          // },
          // colors: ["red", "blue"],
          // sale: true,
        }}
      >
        Products with Filters
      </Link>
    </div>
  );
}

وفي الشيفرة أمثلةٌ معطَّلةٌ بتعليقاتٍ توضّح ما يمكن أن يحمله search: سلسلةً نصيةً واحدة مثل sort_by، ومصفوفةً مثل product_type، وكائنًا متداخلًا مثل pagination الذي يحوي page وpageSize، ومصفوفةً أخرى مثل colors، وقيمةً منطقيةً مثل sale. وما نُفعّله في هذا الدرس هو sort_by وحدَه.

وكلُّ ما في search يجب أن يكون قابلًا للتسلسل بصيغة JSON. يحوّلُ TanStack Router هذه البنيةَ إلى نصٍّ في عنوان الصفحة، ثم يعيدها إلى كائنٍ بغيرها حين تقرأها الصفحة، فتجد المصفوفاتِ والكائناتِ كما مرّرتها لا نصوصًا.

قراءةُ معاملات البحث في الصفحة

نقرأ معاملات البحث من المسار نفسه عبر Route.useSearch()، وهذه هما السطران المسؤولان عن ذلك في المكوّن:

  const search = Route.useSearch();
  console.log(search);

ما يطبعه console.log هو الكائنُ نفسه الذي رأيناه في أدوات المطوّر: النصوصُ والمصفوفاتُ والكائناتُ كما مرّرناها. وبه نستطيع مثلًا أن نُبرز المرشّحاتِ المختارةَ حاليًا في واجهة الصفحة.

التحقّقُ من معاملات البحث وأمانُ الأنواع

المشكلةُ فيما سبق: حين مرّرنا sort_by من الصفحة الرئيسية لم نحصل على أيّ أمانِ أنواع، فمَن يمرّر قيمةً منطقيةً مكان سلسلةٍ نصيةٍ لا يكتشف الخطأ إلّا في وقت التشغيل. وهنا يأتي دورُ validateSearch، وهي الدالّةُ التي تُمرَّر إلى المسار:

  validateSearch: (search: Record<string, unknown>) => {
    return {
      sort_by: (search.sort_by as string) || "",
    };
  },

ما يدخلُ الدالّةَ هو كلُّ ما في العنوان بلا نوعٍ ولا تحقّق، أي مجموعةُ معاملاتِ البحث كما وصلت، وما تخرجه هو المعاملاتُ المُتحقَّقُ منها. وبتحديد sort_by على أنّه سلسلةٌ نصيةٌ يُصير نوعُه معروفًا للمحرّر: فالقيمةُ الصحيحةُ تُقبل، والقيمةُ المنطقيةُ خطأٌ يُعرض قبل التشغيل. ولاحظ أنّ ما تُعيده الدالّةُ هو كلُّ ما تراه الصفحة، فالمعاملاتُ التي لا تذكرها لا تصل إليها أصلًا.

وإن كانت معاملاتُك كثيرةً فمكتبةُ Zod أسهلُ من كتابة دالّة تحقّقٍ يدويّة، وفي الدورة درسٌ مستقلٌّ لها.

النتيجة

في الصورة صفحةُ /products?sort_by=price: النصُّ الظاهر هو Hello "/products/"! وهو محتوى الصفحة، وفي الزاوية العليا اليمنى تظهر أداةُ المطوّر. ولاحظ أنّ عنوان الصفحة يحوي معاملَ البحث في نهايته، فالعنوانُ وحدَه يصفُّ الحالةَ التي تعرضها الصفحة، ولهذا يمكنُ نسخُه ومشاركةُه فيؤدّي إلى النتيجة نفسها.

جرّب بنفسك

  1. استنسخ مستودعَ الدورة وانتقل إلى فرع search-1.
  2. أنشئ الملف src/routes/products.index.tsx بالاستعانة بالشيفرة أعلاه، وهو في فرع الدرس جاهز.
  3. أضف إلى src/routes/index.tsx رابطًا إلى /products مع search={{ sort_by: "price" }}.
  4. شغّل npm run dev ثم افتح /products وحدَها، وبعدها اضغط الرابطَ «منتجات مع مرشّحات» ولاحظ عنوان الصفحة النهائي.
  5. غيّر sort_by: "price" إلى true ولاحظ خطأ المحرّر الذي يقول إنّ النوعَ المطلوب نصٌّ لا قيمةٌ منطقية.
  6. أضف إلى كائن search معاملًا جديدًا لا تذكره validateSearch، ولاحظ أنّه لا يظهر في عنوان الصفحة.
  7. أزل validateSearch من المسار وأعد تمرير معاملٍ منطقيّ، ولاحظ أنّ الخطأ يختفي لأنّ أحدًا لم يعد يفحص الأنواع.
