13.1 BinaryTrie: شجرة بحث رقمية

يشفّر BinaryTrie مجموعةً من الأعداد الصحيحة بطول w \mathtt{w}w بت في شجرة ثنائية. فجميع الأوراق في الشجرة على العمق w \mathtt{w}w ، ويُشفَّر كلّ عدد صحيح في صورة مسارٍ يمتدّ من الجذر إلى ورقة. ويتّجه مسار العدد الصحيح x \mathtt{x}x إلى اليسار عند المستوى i \mathtt{i}i إذا كان البت i \mathtt{i}i th الأكثر أهميةً في x \mathtt{x}x يساوي 0، وإلى اليمين إذا كان يساوي 1. ويعرض الشكل 13.1 مثالًا للحالة w=4 \ensuremath{\mathtt{w}}=4w=4 ، حيث تخزّن شجرة البادئات (trie) الأعداد الصحيحة 3(0011) و9(1001) و12(1100) و13(1101).

لأنّ مسار البحث عن قيمةٍ ما، x \mathtt{x}x ، يعتمد على بتات x \mathtt{x}x نفسها، من المفيد أن نسمّي أبناء عقدةٍ ما، u \mathtt{u}u ، بالاسمين u.child[0] \mathtt{u.child[0]}u.child[0] ( left \mathtt{left}left ) و u.child[1] \mathtt{u.child[1]}u.child[1] ( right \mathtt{right}right ). وفي الواقع، تخدم مؤشّرات الأبناء هذين غرضين معًا. ولأنّ أوراق شجرة البادئات الثنائية لا أبناء لها، تُستعمل هذه المؤشّرات لوصل الأوراق ببعضها في قائمة مترابطة ثنائية الوصل (doubly-linked list). أمّا الورقة في شجرة البادئات الثنائية، u.child[0] \mathtt{u.child[0]}u.child[0] ( prev \mathtt{prev}prev ) فهي العقدة التي تسبق u \mathtt{u}u في القائمة، و u.child[1] \mathtt{u.child[1]}u.child[1] ( next \mathtt{next}next ) هي العقدة التي تلي u \mathtt{u}u في القائمة. وتُستعمل عقدةٌ خاصة، dummy \mathtt{dummy}dummy ، قبل أوّل عقدةٍ في القائمة وبعد آخر عقدةٍ فيها معًا (انظر القسم 3.2). وتحتوي كلّ عقدة، u \mathtt{u}u ، كذلك على مؤشّرٍ إضافي هو u.jump \mathtt{u.jump}u.jump . فإن كان الابن الأيسر لـ u \mathtt{u}u مفقودًا، فإنّ u.jump \mathtt{u.jump}u.jump يشير إلى أصغر ورقةٍ في الشجرة الفرعية لـ u \mathtt{u}u . وإن كان الابن الأيمن لـ u \mathtt{u}u مفقودًا، فإنّ u.jump \mathtt{u.jump}u.jump يشير إلى أكبر ورقةٍ في الشجرة الفرعية لـ u \mathtt{u}u . ويعرض الشكل 13.2 مثالًا على BinaryTrie يُظهر مؤشّرات jump \mathtt{jump}jump والقائمة المترابطة ثنائية الوصل عند الأوراق.

العملية find(x) \mathtt{find(x)}find(x) في BinaryTrie بسيطةٌ إلى حدٍّ ما. فنحن نحاول اتّباع مسار البحث عن x \mathtt{x}x في شجرة البادئات. فإذا بلغنا ورقة، فقد وجدنا x \mathtt{x}x . وإذا بلغنا عقدةً u \mathtt{u}u لا يمكننا المتابعة عندها (لأنّ u \mathtt{u}u تفتقر إلى ابن)، فإنّنا نتبع u.jump \mathtt{u.jump}u.jump ، الذي ينقلنا إمّا إلى أصغر ورقةٍ أكبر من x \mathtt{x}x أو إلى أكبر ورقةٍ أصغر من x \mathtt{x}x . وأيّ من هاتين الحالتين يقع يتوقّف على ما إذا كانت u \mathtt{u}u تفتقر إلى ابنها الأيسر أم إلى ابنها الأيمن، على التوالي. وفي الحالة الأولى ( u \mathtt{u}u تفتقر إلى ابنها الأيسر) فقد وجدنا العقدة التي نريدها. وفي الحالة الثانية ( u \mathtt{u}u تفتقر إلى ابنها الأيمن) يمكننا استعمال القائمة المترابطة للوصول إلى العقدة التي نريدها. ويوضّح الشكل 13.3 كلَّ واحدةٍ من هاتين الحالتين.

يغلب على زمن تنفيذ الدالة find(x) \mathtt{find(x)}find(x) الزمن اللازم لاتّباع مسارٍ من الجذر إلى ورقة، ولذلك تعمل بزمن O(w) O(\ensuremath{\mathtt{w}})O(w) . أمّا العملية add(x) \mathtt{add(x)}add(x) في BinaryTrie فبسيطةٌ هي الأخرى، لكنّ عليها عملٌ كثير:

  1. يتّبع مسار البحث عن x \mathtt{x}x حتى يبلغ عقدةً u \mathtt{u}u لم يعد في وسعه المتابعة.
  2. ينشئ بقيّة مسار البحث من u \mathtt{u}u إلى ورقةٍ تحوي x \mathtt{x}x .
  3. يضيف العقدةَ u′ \mathtt{u'}u′ ، التي تحوي x \mathtt{x}x ، إلى القائمة المترابطة للأوراق (ويستطيع الوصول إلى السابقة pred \mathtt{pred}pred لـ u′ \mathtt{u'}u′ في القائمة المترابطة من مؤشّر jump \mathtt{jump}jump لآخر عقدٍ، u \mathtt{u}u ، صادفها في الخطوة 1.)
  4. يصعد عائدًا في مسار البحث عن x \mathtt{x}x ، ويعدّل مؤشّرات jump \mathtt{jump}jump عند العقد التي ينبغي أن يشير مؤشّر jump \mathtt{jump}jump فيها الآن إلى x \mathtt{x}x .

ويوضّح الشكل 13.4 مثالًا على إضافة عنصر.

    boolean add(T x) {
        int i, c = 0, ix = it.intValue(x);
        Node u = r;
        // 1 - search for ix until falling out of the trie
        for (i = 0; i < w; i++) {
            c = (ix >>> w-i-1) & 1;
            if (u.child[c] == null) break;
            u = u.child[c];
        }        
        if (i == w) return false; // already contains x - abort
        Node pred = (c == right) ? u.jump : u.jump.child[0];
        u.jump = null;  // u will have two children shortly
        // 2 - add path to ix
        for (; i < w; i++) {
            c = (ix >>> w-i-1) & 1;
            u.child[c] = newNode();
            u.child[c].parent = u;
            u = u.child[c];
        }
        u.x = x;
        // 3 - add u to linked list
        u.child[prev] = pred;
        u.child[next] = pred.child[next];
        u.child[prev].child[next] = u;
        u.child[next].child[prev] = u;
        // 4 - walk back up, updating jump pointers
        Node v = u.parent;
        while (v != null) {
            if ((v.child[left] == null 
                    && (v.jump == null || it.intValue(v.jump.x) > ix))
            || (v.child[right] == null 
                    && (v.jump == null || it.intValue(v.jump.x) < ix)))
                v.jump = u;
            v = v.parent;
        }
        n++;
        return true;
    }

تُجري هذه الدالة نزولًا واحدًا في مسار البحث عن x \mathtt{x}x وصعودًا واحدًا عائدًا. وتستغرق كلّ خطوةٍ من خطوتي الصعود والنزول زمنًا ثابتًا، ولذلك تعمل الدالة add(x) \mathtt{add(x)}add(x) بزمن O(w) O(\ensuremath{\mathtt{w}})O(w) . أمّا العملية remove(x) \mathtt{remove(x)}remove(x) فتلغي عمل add(x) \mathtt{add(x)}add(x) . ومثل add(x) \mathtt{add(x)}add(x) ، عليها عملٌ كثير:

  1. يتّبع مسار البحث عن x \mathtt{x}x حتى يبلغ الورقةَ u \mathtt{u}u ، التي تحوي x \mathtt{x}x .
  2. يزيل u \mathtt{u}u من القائمة المترابطة ثنائية الوصل.
  3. يحذف u \mathtt{u}u ثمّ يصعد عائدًا في مسار البحث عن x \mathtt{x}x ، محذفًا العقد، حتى يبلغ عقدةً v \mathtt{v}v لها ابنٌ ليس على مسار البحث عن x \mathtt{x}x .
  4. يصعد من v \mathtt{v}v إلى الجذر، محدِّثًا أيّ مؤشّرات jump \mathtt{jump}jump التي تشير إلى u \mathtt{u}u .

ويوضّح الشكل 13.5 مثالًا على إزالة عنصر.

    boolean remove(T x) {
        // 1 - find leaf, u, containing x
        int i, c, ix = it.intValue(x);
        Node u = r;
        for (i = 0; i < w; i++) {
            c = (ix >>> w-i-1) & 1;
            if (u.child[c] == null) return false;
            u = u.child[c];
        }
        // 2 - remove u from linked list
        u.child[prev].child[next] = u.child[next];
        u.child[next].child[prev] = u.child[prev];
        Node v = u;
        // 3 - delete nodes on path to u
        for (i = w-1; i >= 0; i--) {
            c = (ix >>> w-i-1) & 1;
            v = v.parent;
            v.child[c] = null;
            if (v.child[1-c] != null) break;
        }
        // 4 - update jump pointers
        c = (ix >>> w-i-1) & 1;
        v.jump = u.child[1-c];
        v = v.parent;
        i--;
        for (; i >= 0; i--) {
            c = (ix >>> w-i-1) & 1;
            if (v.jump == u) 
                v.jump = u.child[1-c];
            v = v.parent;
        }
        n--;
        return true;
    }

13.2 XFastTrie: البحث في زمن لوغاريتمي مزدوج
