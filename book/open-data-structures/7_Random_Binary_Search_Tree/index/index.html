7.2 Treap: شجرة بحث ثنائية عشوائية

المشكلة في الأشجار الثنائية للبحث العشوائية أنّها بطبيعتها غير ديناميكية (dynamic). فهي لا تدعم العمليتَين add(x) و remove(x) اللتين تلزمان لتنفيذ واجهة SSet. وفي هذا القسم نشرح بنية بيانات تُدعى Treap تستخدم الملمة 7.1 لتنفيذ واجهة SSet.7.2 إنّ عقدة في Treap تشبه عقدة في BinarySearchTree من حيث أنّها تحمل قيمة بيانات، x ، كما أنّها تحتوي أيضًا على أولوية (priority) عددية فريدة، p ، تُسنَد عشوائيًا:

    class Node<T> extends BinarySearchTree.BSTNode<Node<T>,T> {
        int p;
    }

إلى جانب كونه شجرة بحث ثنائية، تلتزم عقد الـTreap أيضًا بخاصية الكومة (heap property):

  • (خاصية الكومة) عند كل عقدة u ، باستثناء الجذر، \ensuremath{\mathtt{u.parent.p}} &lt; \ensuremath{\mathtt{u.p}} .

بعبارة أخرى، لكل عقدة أولوية أصغر من أولوية طفليها. ويبيّن الشكل 7.5 مثالًا على ذلك.

والشيفرة التي تطبّق ذلك عليها معالجة الحالتَين أعلاه، فضلًا عن حالةٍ حدّية (boundary case) ينبغي الانتباه لها (عندما يكون u هو الجذر)، ولذلك فإنّ الشيفرة الفعلية أطول قليلًا ممّا يوحي به الشكل 7.6 للقارئ:

    void rotateLeft(Node u) {
        Node w = u.right;
        w.parent = u.parent;
        if (w.parent != nil) {
            if (w.parent.left == u) {
                w.parent.left = w;
            } else {
                w.parent.right = w;
            }
        }
        u.right = w.left;
        if (u.right != nil) {
            u.right.parent = u;
        }
        u.parent = w;
        w.left = u;
        if (u == r) { r = w; r.parent = nil; }
    }    
    void rotateRight(Node u) {
        Node w = u.left;
        w.parent = u.parent;
        if (w.parent != nil) {
            if (w.parent.left == u) {
                w.parent.left = w;
            } else {
                w.parent.right = w;
            }
        }
        u.left = w.right;
        if (u.left != nil) {
            u.left.parent = u;
        }
        u.parent = w;
        w.right = u;
        if (u == r) { r = w; r.parent = nil; }
    }

بالنسبة إلى بنية بيانات الـTreap، أهمّ خاصية للدوران هي أنّ عمق w ينقص بمقدار واحد فيما يزيد عمق u بمقدار واحد. وباستخدام الدورانات يمكننا تنفيذ العملية add(x) على النحو التالي: ننشئ عقدة جديدة، u ، ونُسند u.x=x ، ونختار قيمةً عشوائية لـ u.p . ثم نضيف u باستخدام خوارزمية add(x) المعتادة الخاصة بـ BinarySearchTree، بحيث تصير u الآن ورقةً (leaf) في الـTreap. وعند هذه النقطة يكون الـTreap لدينا ملتزمًا بخاصية شجرة البحث الثنائية، ولكن ليس بالضرورة بخاصية الكومة. وبخاصة، قد يكون \mathtt{u.parent.p &gt; u.p} . وإن كان الأمر كذلك، فإنّنا نجري دورانًا عند العقدة w = u.parent حتّى تصبح u أبًا للعقدة w . وإذا ظلّ u يخالف خاصية الكومة، فلا بدّ لنا من تكرار ذلك، مع إنقاص عمق u بمقدار واحد في كل مرة، إلى أن يصير u إمّا الجذر وإمّا بحيث \ensuremath{\mathtt{u.parent.p}} &lt; \ensuremath{\mathtt{u.p}} .

    boolean add(T x) {
        Node<T> u = newNode();
        u.x = x;
        u.p = rand.nextInt();
        if (super.add(u)) {
            bubbleUp(u);
            return true;
        }
        return false;
    }
    void bubbleUp(Node<T> u) {
        while (u.parent != nil && u.parent.p > u.p) {
            if (u.parent.right == u) {
                rotateLeft(u.parent);
            } else {
                rotateRight(u.parent);
            }
        }
        if (u.parent == nil) {
            r = u;
        }
    }

ويبيّن الشكل 7.7 مثالًا على عملية add(x) .

زمن تشغيل العملية add(x) محدَّدٌ بزمن اتباع مسار البحث عن x مضافًا إليه عدد الدورانات التي أُجريت لنقل العقدة المضافة حديثًا، u ، إلى موضعها الصحيح في الـTreap. وبموجب الملمة 7.2، فإنّ الطول المتوقَّع لمسار البحث يساوي على الأكثر 2ln\ensuremathn+O(1) . وإضافةً إلى ذلك، فإنّ كل دوران يُنقِص عمق u . وهذا يتوقّف إذا صار u هو الجذر، ومن ثمّ لا يمكن أن يتجاوز عدد الدورانات المتوقَّع الطول المتوقَّع لمسار البحث. وبالتالي فإنّ زمن التشغيل المتوقَّع للعملية add(x) في الـTreap هو O(log\ensuremathn) . (يطلب التمرين 7.5 أن تُثبت أنّ عدد الدورانات المتوقَّع أثناء الإضافة ليس في الحقيقة إلا O(1) .) أمّا العملية remove(x) في الـTreap فهي عكس العملية add(x) . فنبحث عن العقدة، u ، التي تحوي x ، ثمّ نجري دورانات لنقل u إلى الأسفل حتى يصير ورقة، ثمّ نفصل u عن الـTreap. ولاحظ أنّه لنقل u إلى الأسفل، يمكننا إجراء دوران أيسر أو أيمن عند u، وهو ما سيستبدل u بـ u.right أو u.left على التوالي. ويُتَّخذ الاختيار وفق أول الشروط التالية المنطبقة:

  1. إذا كان u.left و u.right كلاهما null ، فإنّ u ورقة ولا يُجرى أيّ دوران.
  2. إذا كان u.left (أو u.right ) هو null ، ف أجرِ دورانًا أيمنًا (أو أيسرًا، على التوالي) عند u .
  3. إذا كان \ensuremath{\mathtt{u.left.p}} &lt; \ensuremath{\mathtt{u.right.p}} (أو \ensuremath{\mathtt{u.left.p}} &gt; \ensuremath{\mathtt{u.right.p}}) ، ف أجرِ دورانًا أيمنًا (أو أيسرًا، على التوالي) عند u .

تضمن هذه القواعد الثلاث ألّا ينقطع الـTreap عن بعضه، وأن تُستعاد خاصية الكومة بعد إزالة u .

    boolean remove(T x) {
        Node<T> u = findLast(x);
        if (u != nil && compare(u.x, x) == 0) {
            trickleDown(u);
            splice(u);
            return true;
        }
        return false;
    }
    void trickleDown(Node<T> u) {
        while (u.left != nil || u.right != nil) {
            if (u.left == nil) {
                rotateLeft(u);
            } else if (u.right == nil) {
                rotateRight(u);
            } else if (u.left.p < u.right.p) {
                rotateRight(u);
            } else {
                rotateLeft(u);
            }
            if (r == u) {
                r = u.parent;
            }
        }
    }

ومن تنويعات Treap الأخرى التي لا تخزّن أولويات عند كل عقدة: شجرة البحث الثنائية العشوائية لـ Martínez و Roura [51]. ففي هذا التنويع، تخزّن كل عقدة، u ، الحجم u.size للشجرة الفرعية التي جذورها u . وكلتا خوارزمتَي add(x) و remove(x) عشوائيتان. وتقوم خوارزمية إضافة x إلى الشجرة الفرعية التي جذورها هو u بما يلي: باحتمال 1/(\ensuremathsize(u)+1) ، تُضاف القيمة x بالطريقة المعتادة كورقة، ثمّ تُجرى دورانات لرفع x حتى جذر هذه الشجرة الفرعية. وفي غير ذلك (باحتمال 1−1/(\ensuremathsize(u)+1) )، تُضاف القيمة x secara تكرارية إلى إحدى الشجرتين الفرعيتين الجذور لهما u.left أو u.right، بحسب ما يقتضيه الحال. وتُقابل الحالة الأولى عملية add(x) في Treap تحصل فيها عقدة x على أولوية عشوائية أصغر من أيٍّ من الأولويات size(u) الموجودة في الشجرة الفرعية التي جذورها u . وتحدث هذه الحالة بالاحتمال نفسه بالضبط. وإزالة قيمة x من شجرة بحث ثنائية عشوائية تشبه عملية الإزالة من Treap. فنجد العقدة، u ، التي تحوي x ، ثمّ نجري دورانات ترفع عمق u تكرارًا حتى يصير ورقة، وعندئذٍ يمكننا فصله عن الشجرة. والاختيار بين إجراء دوران أيسر أو أيمن في كل خطوة عشوائي. فباحتمال u.left.size/(u.size−1) ، نجري دورانًا أيمنًا عند u، فتصير u.left جذرًا للشجرة الفرعية التي كان جذورها هو u . وباحتمال u.right.size/(u.size−1) ، نجري دورانًا أيسرًا عند u، فتصير u.right جذرًا للشجرة الفرعية التي كان جذورها هو u . ومرةً أخرى، يسهل التحقّق من أنّ هذه هي بالضبط الاحتمالات عينها التي تجري فيها خوارزمية الإزالة في Treap دورانًا أيسرًا أو أيمنًا للعقدة u . وللأشجار الثنائية للبحث العشوائية عيبٌ مقارنةً بـTreap، إذ إنّها عند إضافة العناصر وإزالتها تجري اختياراتٍ عشوائية كثيرة، وعليها أن تحافظ على أحجام الشجرات الفرعية. وفي المقابل، فإنّ لأشجار البحث الثنائية العشوائية ميزةٌ على Treap، إذ إنّ أحجام الشجرات الفرعية يمكن أن تخدم غرضًا نافعًا آخر، وتحديدًا توفير الوصول حسب الرتبة في زمن متوقَّع قدره O(log\ensuremathn) (راجع التمرين 7.10). وبالمقارنة مع ذلك، فإنّ الأولويات العشوائية المخزَّنة في عقد الـtreap لا فائدة فيها سوى إبقاء الـtreap متوازنًا. التمرين 7..1 بيّن إضافة 4.5 (بأولوية 7) ثمّ 7.5 (بأولوية 20) إلى التمرين 7..12 صمّم ونفّذ نسخةً من Treap تدعم عملية split(x) . وهذه العملية تزيل من الـTreap كلَّ القيم الأكبر من x وتُعيد Treap ثانيةً يحتوي على كل القيم المُزالة. مثال: الشيفرة t2=t.split(x) تزيل من t كل القيم الأكبر من x وتُعيد Treap جديدًا t2 يحتوي على هذه القيم جميعًا. وينبغي أن تعمل عملية split(x) في زمن متوقَّع قدره O(log\ensuremathn) . تحذير: لكي يعمل هذا التعديل على الوجه الصحيح ولا تزال طريقة size() تعمل في زمن ثابت، من الضروري تنفيذ التعديلات الواردة في التمرين 7.10.

التمرين 7..13 صمّم ونفّذ نسخةً من Treap تدعم عملية absorb(t2) ، ويمكن التفكير فيها على أنّها العملية العاكسة لـ split(x) . وهذه العملية تزيل من الـTreap t2 كلَّ القيم وتضيفها إلى الكائن المستقبِل. وتفترض هذه العملية أنّ أصغر قيمة في t2 أكبر من أكبر قيمة في الكائن المستقبِل. وينبغي أن تعمل عملية absorb(t2) في زمن متوقَّع قدره O(log\ensuremathn) .

التمرين 7..14 نفّذ أشجار البحث الثنائية العشوائية لـ Martinez كما نُوقشت في هذا القسم. وقارن بين أداء تنفيذك وأداء تنفيذ الـTreap.
