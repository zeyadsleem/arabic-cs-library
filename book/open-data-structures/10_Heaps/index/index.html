10.1 BinaryHeap: شجرة ثنائية ضمنية

يقوم تنفيذنا الأول لطابور (أولوية) على تقنيةٍ عمرها أكثر من أربعمئة عام. تتيح لنا طريقة Eytzinger تمثيل شجرة ثنائية كاملة بوصفها مصفوفة، بترتيب عقد الشجرة في تسلسلٍ بالعرض (breadth-first order) (انظر القسم 6.1.2). وبهذه الطريقة، يُخزَّن الجذر عند الموضع 0، وتُخزَّن الابنة اليسرى للجذر عند الموضع 1، وتُخزَّن الابنة اليمنى للجذر عند الموضع 2، وتُخزَّن ابنة الابنة اليسرى للجذر عند الموضع 3، وهكذا. انظر الشكل 10.1.

وإذا طبّقنا طريقة Eytzinger على شجرةٍ كبيرة بما يكفي، تظهر بعض الأنماط. فالابنة اليسرى للعقدة ذات الفهرس i \mathtt{i}i تقع عند الفهرس left(i)=2i+1 \ensuremath{\mathtt{left(i)}}=2\ensuremath{\mathtt{i}}+1left(i)=2i+1 ، والابنة اليمنى للعقدة ذات الفهرس i \mathtt{i}i تقع عند الفهرس right(i)=2i+2 \ensuremath{\mathtt{right(i)}}=2\ensuremath{\mathtt{i}}+2right(i)=2i+2 . أمّا الأمّ (parent) للعقدة ذات الفهرس i \mathtt{i}i فتقع عند الفهرس parent(i)=(i−1)/2 \ensuremath{\mathtt{parent(i)}}=(\ensuremath{\mathtt{i}}-1)/2parent(i)=(i−1)/2 .

    int left(int i) {
        return 2*i + 1;
    }
    int right(int i) {
        return 2*i + 2;
    }
    int parent(int i) {
        return (i-1)/2;
    }

يستخدم BinaryHeap هذه التقنيةَ لتمثيل شجرة ثنائية كاملة ضمنيًّا، تكون فيها العناصر مرتّبة ترتيب كومة (heap-ordered): فالقيمة المخزَّنة عند أي فهرس i \mathtt{i}i ليست أصغر من القيمة المخزَّنة عند الفهرس parent(i) \mathtt{parent(i)}parent(i) ، باستثناء قيمة الجذر، i=0 \ensuremath{\mathtt{i}}=0i=0 . ويترتّب على ذلك أنّ أصغر قيمة في طابور الأولوية تُخزَّن عند الموضع 0 (الجذر). أمّا في BinaryHeap، فتُخزَّن العناصر الـ n \mathtt{n}n في مصفوفة a \mathtt{a}a :

    T[] a;
    int n;

وتنفيذ العملية add(x) \mathtt{add(x)}add(x) مباشرٌ إلى حدٍّ كبير. فكما في جميع البنى المعتمدة على المصفوفات، نتحقّق أولًا مما إذا كانت a \mathtt{a}a ممتلئة (بالتحقّق مما إذا كان a.length=n \ensuremath{\mathtt{a.length}}=\ensuremath{\mathtt{n}}a.length=n )، وإذا كانت كذلك فإنّنا نُكبِّر a \mathtt{a}a . ثمّ نضع x \mathtt{x}x عند الموضع a[n] \mathtt{a[n]}a[n] ونزيد n \mathtt{n}n . وفي هذه المرحلة، لم يبقَ سوى ضمان الحفاظ على خاصية الكومة. ونفعل ذلك بتبديل x \mathtt{x}x مع أمّه تكرارًا حتى تصير x \mathtt{x}x ليست أصغر من أمّها. انظر الشكل 10.2.

    boolean add(T x) {
        if (n + 1 > a.length) resize();
        a[n++] = x;
        bubbleUp(n-1);
        return true;
    }
    void bubbleUp(int i) {
        int p = parent(i);
        while (i > 0 && compare(a[i], a[p]) < 0) {
            swap(i,p);
            i = p;
            p = parent(i);
        }
    }

أمّا تنفيذ العملية remove() \mathtt{remove()}remove() ، التي تزيل أصغر قيمة من الكومة، فهو أعقد قليلًا. فنحن نعرف أين تقع أصغر قيمة (عند الجذر)، لكنّنا بحاجة إلى استبدالها بعد إزالتها والحرص على الحفاظ على خاصية الكومة. وأيسر طريقة للقيام بذلك هي استبدال الجذر بالقيمة a[n−1] \mathtt{a[n-1]}a[n−1] ، ثمّ حذف تلك القيمة، وإنقاص n \mathtt{n}n . للأسف، فإنّ عنصر الجذر الجديد على الأرجح ليس أصغر عنصر، لذا يلزم نقله إلى الأسفل. ونفعل ذلك بمقارنة هذا العنصر بابنتيه تكرارًا. فإن كان أصغر الثلاثة فقد انتهينا. وإلّا فبدّلنا هذا العنصر مع أصغر ابنتيه وتابعنا.

    T remove() {
        T x = a[0];
        a[0] = a[--n];
        trickleDown(0);
        if (3*n < a.length) resize();
        return x;
    }
    void trickleDown(int i) {
        do {
            int j = -1;
            int r = right(i);
            if (r < n && compare(a[r], a[i]) < 0) {
                int l = left(i);
                if (compare(a[l], a[r]) < 0) {
                    j = l;
                } else {
                    j = r;
                }
            } else {
                int l = left(i);
                if (l < n && compare(a[l], a[i]) < 0) {
                    j = l;
                }
            }
            if (j >= 0)    swap(i, j);
            i = j;
        } while (i >= 0);
    }

10.2 MeldableHeap: كومة قابلة للدمج عشوائية

نصف في هذا القسم بنية البيانات MeldableHeap، وهي تنفيذٌ لطابور الأولوية تكون فيه البنية الأساسية أيضًا شجرة ثنائية مرتّبة ترتيب كومة (heap-ordered). غير أنّه، بخلاف BinaryHeap الذي تُحدَّد فيه الشجرة الثنائية الأساسية تمامًا بعدد العناصر، لا توجد قيودٍ على شكل الشجرة الثنائية التي تقوم عليها بنية MeldableHeap؛ فأيّ شكلٍ يصاح. أمّا العمليتان add(x) \mathtt{add(x)}add(x) و remove() \mathtt{remove()}remove() في MeldableHeap فتُنفَّذان بدلالة العملية merge(h1,h2) \mathtt{merge(h1,h2)}merge(h1,h2) . تأخذ هذه العملية عقدتَي كومة h1 \mathtt{h1}h1 و h2 \mathtt{h2}h2 وتدمجهما، وتُرجع عقدة كومةٍ تكون جذر كومةٍ تحتوي جميع العناصر في الشجرة الفرعية المجذَّرة عند h1 \mathtt{h1}h1 وجميع العناصر في الشجرة الفرعية المجذَّرة عند h2 \mathtt{h2}h2 . ومن مزايا العملية merge(h1,h2) \mathtt{merge(h1,h2)}merge(h1,h2) أنّه يمكن تعريفها على نحو تعاودي (recursive). انظر الشكل 10.4. فإذا كانت h1 \mathtt{h1}h1 أو h2 \mathtt{h2}h2 على القيمة nil \mathtt{nil}nil ، فإنّنا ندمج مع مجموعةٍ فارغة، فنُرجع h2 \mathtt{h2}h2 أو h1 \mathtt{h1}h1 على التوالي. وإلّا، فافترض h1.x≤h2.x \ensuremath{\mathtt{h1.x}} \le \ensuremath{\mathtt{h2.x}}h1.x≤h2.x ، إذ إنّنا لو كان h1.x>h2.x \ensuremath{\mathtt{h1.x}} > \ensuremath{\mathtt{h2.x}}h1.x>h2.x لاستطعنا تبديل دورَي h1 \mathtt{h1}h1 و h2 \mathtt{h2}h2 . وعندئذٍ نعرف أنّ جذر الكومة المدموجة سيحتوي h1.x \mathtt{h1.x}h1.x ، ويمكننا أن ندمج تعاوديًا h2 \mathtt{h2}h2 مع h1.left \mathtt{h1.left}h1.left أو h1.right \mathtt{h1.right}h1.right ، كيفما شئنا. وهنا يأتي دور العشوائية (randomization): فنقذف عملة (coin) لتقرّر ما إذا كنّا سندمج h2 \mathtt{h2}h2 مع h1.left \mathtt{h1.left}h1.left أم مع h1.right \mathtt{h1.right}h1.right :

    Node<T> merge(Node<T> h1, Node<T> h2) {
        if (h1 == nil) return h2;
        if (h2 == nil) return h1;
        if (compare(h2.x, h1.x) < 0) return merge(h2, h1);
        // now we know h1.x <= h2.x
        if (rand.nextBoolean()) {
            h1.left = merge(h1.left, h2);
            h1.left.parent = h1;
        } else {
            h1.right = merge(h1.right, h2);
            h1.right.parent = h1;
        }
        return h1;
    }

نبيّن في القسم التالي أنّ merge(h1,h2) \mathtt{merge(h1,h2)}merge(h1,h2) تعمل في زمنٍ متوقَّع قدره O(log⁡n) O(\log \ensuremath{\mathtt{n}})O(logn) ، حيث n \mathtt{n}n هو العدد الإجمالي للعناصر في h1 \mathtt{h1}h1 و h2 \mathtt{h2}h2 . ومع توفّر العملية merge(h1,h2) \mathtt{merge(h1,h2)}merge(h1,h2) تصير العملية add(x) \mathtt{add(x)}add(x) سهلة. فننشئ عقدةً جديدة u \mathtt{u}u تحتوي x \mathtt{x}x ثمّ ندمج u \mathtt{u}u مع جذر كومتنا:

    boolean add(T x) {
        Node<T> u = newNode();
        u.x = x;
        r = merge(u, r);
        r.parent = nil;
        n++;
        return true;
    }

وهذا يستغرق زمنًا متوقَّعًا قدره O(log⁡(n+1))=O(log⁡n) O(\log (\ensuremath{\mathtt{n}}+1)) = O(\log \ensuremath{\mathtt{n}})O(log(n+1))=O(logn) . والعملية remove() \mathtt{remove()}remove() سهلةٌ على نحو مماثل. فالعقدة التي نريد إزالتها هي الجذر، لذا ندمج ابنتيها فحسب ونجعل الناتج هو الجذر:

    T remove() {
        T x = r.x;
        r = merge(r.left, r.right);
        if (r != nil) r.parent = nil;
        n--;
        return x;
    }

10.3 مناقشة والتمارين

يبدو أنّ التمثيل الضمني للشجرة الثنائية الكاملة بوصفه مصفوفةً (أو قائمةً) أوّل ما اقترحه Eytzinger [27]. وقد استعمل هذا التمثيل في كتبٍ تحتوي على أشجار نسبية (pedigree) للعائلات النبيلة. وأما بنية البيانات BinaryHeap الموصوفة هنا فقد أدخلها أوّلًا Williams [78]. ويبدو أنّ بنية البيانات العشوائية MeldableHeap الموصوفة هنا أوّل ما اقترحها Gambin وMalinowski [34]. وهناك تنفيذاتٌ أخرى للكومات القابلة للدمج (meldable heaps)، منها الكومات اليسارية (leftist heaps) [16,48, القسم 5.3.2]، والكومات الثنائية (binomial heaps) [75]، وكومات فيبوناتشي (Fibonacci heaps) [30]، وكومات الأزواج (pairing heaps) [29]، والكومات المائلة (skew heaps) [72]، وإنّما لم يكن أيٌّ منها بسيطًا بقدر بنية MeldableHeap. وتدعم بعض البنى المذكورة أعلاه أيضًا عملية decreaseKey(u,y) \mathtt{decreaseKey(u,y)}decreaseKey(u,y) التي تُنقص فيها القيمة المخزَّنة عند العقدة u \mathtt{u}u إلى y \mathtt{y}y . (ويُشترط سلفًا أن يكون y≤u.x \ensuremath{\mathtt{y}}\le\ensuremath{\mathtt{u.x}}y≤u.x .) وفي معظم البنى السابقة، يمكن دعم هذه العملية في زمن O(log⁡n) O(\log \ensuremath{\mathtt{n}})O(logn) بإزالة العقدة u \mathtt{u}u وإضافة y \mathtt{y}y . غير أنّ بعض هذه البنى يمكنها تنفيذ decreaseKey(u,y) \mathtt{decreaseKey(u,y)}decreaseKey(u,y) بكفاءةٍ أعلى. وتحديدًا، تستغرق decreaseKey(u,y) \mathtt{decreaseKey(u,y)}decreaseKey(u,y) زمنًا مُطفَّأ (amortized) قدره O(1) O(1)O(1) في كومات فيبوناتشي، وزمنًا مُطفَّأ قدره O(log⁡log⁡n) O(\log\log \ensuremath{\mathtt{n}})O(loglogn) في نسخةٍ خاصة من كومات الأزواج [25]. ولهذه العملية الأكفأ decreaseKey(u,y) \mathtt{decreaseKey(u,y)}decreaseKey(u,y) تطبيقاتٌ في تسريع عدة خوارزميات رسمٍ بياني (graph)، ومنها خوارزمية أقصر مسار في Dijkstra [30]. التمرين 10.1 بيّن إضافة القيمة 7 ثمّ القيمة 3 إلى BinaryHeap المبيَّن في نهاية الشكل 10.2.
