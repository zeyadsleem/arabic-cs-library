3.1 SLList: قائمة مترابطة أحادية الوصل

إن SLList (قائمة مترابطة أحادية الوصل) هي متسلسلة من عقد Node. وتخزّن كل عقدة u \mathtt{u}u قيمة بيانات u.x \mathtt{u.x}u.x ومرجعًا u.next \mathtt{u.next}u.next إلى العقدة التالية في المتسلسلة. أما العقدة الأخيرة w \mathtt{w}w في المتسلسلة فيكون w.next=null \ensuremath{\mathtt{w.next}} = \ensuremath{\mathtt{null}}w.next=null

    class Node {
        T x;
        Node next;
    }

ولكفاءة التنفيذ، تستخدم SLList المتغيّرات head \mathtt{head}head وtail \mathtt{tail}tail لمتابعة العقدة الأولى والعقدة الأخيرة في المتسلسلة، وكذلك عددًا صحيحًا n \mathtt{n}n لمتابعة طول المتسلسلة:

    Node head;
    Node tail;
    int n;

يوضّح الشكل 3.1 متسلسلة من عمليات Stack وQueue على SLList.

تستطيع SLList تنفيذ عمليتَي Stack، وهما push() \mathtt{push()}push() وpop() \mathtt{pop()}pop()، بكفاءة عبر إضافة العناصر وحذفها عند رأس المتسلسلة. إن عملية push() \mathtt{push()}push() ببساطة تنشئ عقدة جديدة u \mathtt{u}u بقيمة البيانات x \mathtt{x}x ، وتضبط u.next \mathtt{u.next}u.next على الرأس القديم للقائمة، وتجعل u \mathtt{u}u هو الرأس الجديد للقائمة. وأخيرًا هي تزيد n \mathtt{n}n بمقدار واحد لأن حجم SLList قد ازداد بمقدار واحد:

    T push(T x) {
        Node u = new Node();
        u.x = x;
        u.next = head;
        head = u;
        if (n == 0)
            tail = u;
        n++;
        return x;
    }

أما عملية pop() \mathtt{pop()}pop() ، بعد التحقق من أن SLList ليست فارغة، فتزيل الرأس عبر ضبط head=head.next \ensuremath{\mathtt{head=head.next}}head=head.next وإنقاص n \mathtt{n}n . وتحدث حالة خاصة عند إزالة العنصر الأخير، وعندئذ يُضبط tail \mathtt{tail}tail على null \mathtt{null}null :

    T pop() {
        if (n == 0)    return null;
        T x = head.x;
        head = head.next;
        if (--n == 0) tail = null;
        return x;
    }

من الواضح أن عمليتَي push(x) \mathtt{push(x)}push(x) وpop() \mathtt{pop()}pop() تعملان في زمن O(1) O(1)O(1) .

3.1.1 عمليات الطابور

تستطيع SLList كذلك تنفيذ عمليتَي الطابور من نوع FIFO، وهما add(x) \mathtt{add(x)}add(x) وremove() \mathtt{remove()}remove() ، في زمن ثابت. يتم الحذف من رأس القائمة، وهو مطابق تمامًا لعملية pop() \mathtt{pop()}pop() :

    T remove() {
        if (n == 0)    return null;
        T x = head.x;
        head = head.next;
        if (--n == 0) tail = null;
        return x;
    }

أما الإضافة، على النقيض، تتم عند ذيل القائمة. وفي معظم الحالات يتم ذلك عبر ضبط tail.next=u \ensuremath{\mathtt{tail.next}}=\ensuremath{\mathtt{u}}tail.next=u ، حيث u \mathtt{u}u هي العقدة المُنشأة حديثًا التي تحتوي على x \mathtt{x}x . غير أن حالة خاصة تحدث عندما n=0 \ensuremath{\mathtt{n}}=0n=0 ، وعندئذ يكون tail=head=null \ensuremath{\mathtt{tail}}=\ensuremath{\mathtt{head}}=\ensuremath{\mathtt{null}}tail=head=null . في هذه الحالة يُضبط كلٌّ من tail \mathtt{tail}tail وhead \mathtt{head}head على u \mathtt{u}u .

    boolean add(T x) {
        Node u = new Node();
        u.x = x;
        if (n == 0) {
            head = u;
        } else {
            tail.next = u;
        }
        tail = u;
        n++;
        return true;
    }

من الواضح أن كلتا العمليتين add(x) \mathtt{add(x)}add(x) وremove() \mathtt{remove()}remove() تستغرقان زمنًا ثابتًا. 3.1.2 الملخّص تلخّص المبرهنة التالية أداء SLList: مبرهنة 3.1 يطبِّق SLList واجهتَي Stack وQueue (بترتيب FIFO). وتعمل العمليات push(x) \mathtt{push(x)}push(x) وpop() \mathtt{pop()}pop() وadd(x) \mathtt{add(x)}add(x) وremove() \mathtt{remove()}remove() في زمن O(1) O(1)O(1) لكل عملية.

يطبِّق SLList تقريبًا المجموعة الكاملة لعمليات Deque. والعملية الوحيدة المفقودة هي الحذف من ذيل SLList. والحذف من ذيل SLList صعب لأنه يتطلب تحديث قيمة tail \mathtt{tail}tail بحيث يشير إلى العقدة w \mathtt{w}w التي تسبق tail \mathtt{tail}tail في SLList؛ وهذه هي العقدة w \mathtt{w}w بحيث w.next=tail \ensuremath{\mathtt{w.next}}=\ensuremath{\mathtt{tail}}w.next=tail . وللأسف، الطريقة الوحيدة للوصول إلى w \mathtt{w}w هي اجتياز SLList بدءًا من head \mathtt{head}head مع أخذ n−2 \ensuremath{\mathtt{n}}-2n−2 خطوة. opendatastructures.org

3.2 DLList: قائمة مترابطة ثنائية الوصل

إن DLList (قائمة مترابطة ثنائية الوصل) مشابهة جدًا لـ SLList، إلا أن كل عقدة u \mathtt{u}u في DLList لها مراجع إلى العقدة u.next \mathtt{u.next}u.next التي تليها وإلى العقدة u.prev \mathtt{u.prev}u.prev التي تسبقها.

    class Node {
        T x;
        Node prev, next;
    }

وحينما نفّذنا SLList لاحظنا أنه كانت هناك دائمًا عدة حالات خاصة يجب الاهتمام بها. فمثلًا، إزالة العنصر الأخير من SLList أو إضافة عنصر إلى SLList فارغة تتطلب عنايةً لضمان تحديث head \mathtt{head}head وtail \mathtt{tail}tail بشكل صحيح. وفي DLList يزداد عدد هذه الحالات الخاصة بدرجة كبيرة. ولعل أنظف طريقة للاهتمام بكل هذه الحالات الخاصة في DLList هي إدخال عقدة dummy \mathtt{dummy}dummy . وهذه عقدة لا تحتوي على أي بيانات، لكنها تعمل كعنصر نائب (placeholder) بحيث لا توجد عقد خاصة؛ فكل عقدة لديها next \mathtt{next}next وprev \mathtt{prev}prev ، مع كون dummy \mathtt{dummy}dummy هي العقدة التي تلي آخر عقدة في القائمة وتسبق أول عقدة فيها. وبهذه الطريقة تُربط عقد القائمة بترابط ثنائي في دورة (cycle)، كما يوضّح الشكل 3.2.

    int n;
    Node dummy;
    DLList() {
        dummy = new Node();
        dummy.next = dummy;
        dummy.prev = dummy;
        n = 0;
    }

العثور على العقدة ذات الفهرس معيّن في DLList سهل؛ فإما أن نبدأ من رأس القائمة ( dummy.next \mathtt{dummy.next}dummy.next ) ونتقدّم إلى الأمام، أو نبدأ من ذيل القائمة ( dummy.prev \mathtt{dummy.prev}dummy.prev ) ونتراجع إلى الخلف. وهذا يتيح لنا الوصول إلى العقدة i \mathtt{i}i في زمن O(1+min⁡{i,n−i}) O(1+\min\{\ensuremath{\mathtt{i}},\ensuremath{\mathtt{n}}-\ensuremath{\mathtt{i}}\})O(1+min{i,n−i}) :

    Node getNode(int i) {
        Node p = null;
        if (i < n / 2) {
            p = dummy.next;
            for (int j = 0; j < i; j++)
                p = p.next;
        } else {
            p = dummy;
            for (int j = n; j > i; j--)
                p = p.prev;
        }
        return p;
    }

أصبحت العمليتان get(i) \mathtt{get(i)}get(i) وset(i,x) \mathtt{set(i,x)}set(i,x) سهلتين أيضًا. فنبدأ بالعثور على العقدة i \mathtt{i}i ثم نجلب قيمتها x \mathtt{x}x أو نضبطها:

    T get(int i) {
        if (i < 0 || i > n - 1) throw new IndexOutOfBoundsException();
        return getNode(i).x;
    }
    T set(int i, T x) {
        if (i < 0 || i > n - 1) throw new IndexOutOfBoundsException();
        Node u = getNode(i);
        T y = u.x;
        u.x = x;
        return y;
    }

ويُهيمن على زمن تنفيذ هذه العمليات الوقت اللازم للعثور على العقدة i \mathtt{i}i ، ويكون O(1+min⁡{i,n−i}) O(1+\min\{\ensuremath{\mathtt{i}},\ensuremath{\mathtt{n}}-\ensuremath{\mathtt{i}}\})O(1+min{i,n−i}) .

3.2.1 الإضافة والحذف

إذا كان لدينا مرجع إلى عقدة w \mathtt{w}w في DLList أردنا إدراج عقدة u \mathtt{u}u قبل w \mathtt{w}w ، فلا{amsر سوى ضبط u.next=w \ensuremath{\mathtt{u.next}}=\ensuremath{\mathtt{w}}u.next=w وu.prev=w.prev \ensuremath{\mathtt{u.prev}}=\ensuremath{\mathtt{w.prev}}u.prev=w.prev ثم تعديل u.prev.next \mathtt{u.prev.next}u.prev.next وu.next.prev \mathtt{u.next.prev}u.next.prev . (انظر الشكل 3.3.) وبفضل عقدة dummy، لا حاجة للقلق بشأن غياب w.prev \mathtt{w.prev}w.prev أو w.next \mathtt{w.next}w.next .

    Node addBefore(Node w, T x) {
        Node u = new Node();
        u.x = x;
        u.prev = w.prev;
        u.next = w;
        u.next.prev = u;
        u.prev.next = u;
        n++;
        return u;
    }

والآن أصبح تنفيذ عملية القائمة add(i,x) \mathtt{add(i,x)}add(i,x) بسيطًا تامًّا. فنجد العقدة i \mathtt{i}i في DLList ونُدرِج عقدة جديدة u \mathtt{u}u تحتوي على x \mathtt{x}x قبلها مباشرة.

    void add(int i, T x) {
        if (i < 0 || i > n) throw new IndexOutOfBoundsException();
        addBefore(getNode(i), x);
    }

الجزء الوحيد غير الثابت في زمن تنفيذ add(i,x) \mathtt{add(i,x)}add(i,x) هو الوقت اللازم للعثور على العقدة i \mathtt{i}i (باستخدام getNode(i) \mathtt{getNode(i)}getNode(i) ). ولذلك تعمل add(i,x) \mathtt{add(i,x)}add(i,x) في زمن O(1+min⁡{i,n−i}) O(1+\min\{\ensuremath{\mathtt{i}}, \ensuremath{\mathtt{n}}-\ensuremath{\mathtt{i}}\})O(1+min{i,n−i}) . أما حذف عقدة w \mathtt{w}w من DLList فسهل. فنحن بحاجة فقط إلى تعديل المؤشرين عند w.next \mathtt{w.next}w.next وw.prev \mathtt{w.prev}w.prev بحيث يتجاوزان w \mathtt{w}w . ومرة أخرى، يُلغي استخدام عقدة dummy الحاجة إلى اعتبار أي حالات خاصة:

    void remove(Node w) {
        w.prev.next = w.next;
        w.next.prev = w.prev;
        n--;
    }

والآن أصبحت عملية remove(i) \mathtt{remove(i)}remove(i) بسيطة تامًّا. فنجد العقدة ذات الفهرس i \mathtt{i}i ونحذفها:

    T remove(int i) {
        if (i < 0 || i > n - 1) throw new IndexOutOfBoundsException();
        Node w = getNode(i);
        remove(w);
        return w.x;
    }

ومرة أخرى، الجزء الوحيد المكلف في هذه العملية هو العثور على العقدة i \mathtt{i}i باستخدام getNode(i) \mathtt{getNode(i)}getNode(i) ، ولذلك تعمل remove(i) \mathtt{remove(i)}remove(i) في زمن O(1+min⁡{i,n−i}) O(1+\min\{\ensuremath{\mathtt{i}}, \ensuremath{\mathtt{n}}-\ensuremath{\mathtt{i}}\})O(1+min{i,n−i}) . 3.2.2 الملخّص تلخّص المبرهنة التالية أداء DLList: مبرهنة 3.2 يطبِّق DLList واجهة List. وفي هذا التنفيذ، تعمل العمليات get(i) \mathtt{get(i)}get(i) وset(i,x) \mathtt{set(i,x)}set(i,x) وadd(i,x) \mathtt{add(i,x)}add(i,x) وremove(i) \mathtt{remove(i)}remove(i) في زمن O(1+min⁡{i,n−i}) O(1+\min\{\ensuremath{\mathtt{i}},\ensuremath{\mathtt{n}}-\ensuremath{\mathtt{i}}\})O(1+min{i,n−i}) لكل عملية.

من المفيد ملاحظة أنه، إذا تجاهلنا تكلفة عملية getNode(i) \mathtt{getNode(i)}getNode(i) ، فإن جميع العمليات على DLList تستغرق زمنًا ثابتًا. وبالتالي فإن الجزء الوحيد المكلف في العمليات على DLList هو العثور على العقدة المطلوبة. وبمجرد أن نتوفّر لدينا على العقدة المطلوبة، فإن الإضافة أو الحذف أو الوصول إلى البيانات في تلك العقدة لا يستغرق سوى زمن ثابت. وهذا في تناقض حادّ مع تنفيذات List القائمة على المصفوفات في الفصل 2؛ ففي تلك التنفيذات يمكن العثور على عنصر المصفوفة المطلوب في زمن ثابت. غير أن الإضافة أو الحذف تتطلّب إزاحة عناصر داخل المصفوفة، وهي عمومًا تستغرق زمنًا غير ثابت. ولهذا السبب فإن بنى القوائم المترابطة تناسب التطبيقات التي يمكن فيها الحصول على مراجع عقد القائمة بطرق خارجية. ومن أمثلتها بنية بيانات LinkedHashSet الموجودة في Java Collections Framework، حيث تُخزَّن مجموعة عناصر في قائمة مترابطة ثنائية الوصل وتُخزَّن عقد تلك القائمة في جدول تجزئة (hash table) (يُناقش في الفصل 5). وعندما تُزال العناصر من LinkedHashSet، يُستخدم جدول التجزئة للعثور على عقدة القائمة المطلوبة في زمن ثابت ثم تُحذف عقدة القائمة (أيضًا في زمن ثابت). opendatastructures.org

3.3 SEList: قائمة مترابطة موفّرة للمساحة

أحد عيوب القوائم المترابطة (بخلاف الوقت اللازم للوصول إلى العناصر الموجودة في أعماق القائمة) هو استهلاكها للمساحة. تتطلّب كل عقدة في DLList مرجعين إضافيين إلى العقدة التالية والعقدة السابقة في القائمة. وحقلان من حقول Node مخصّصان لصيانة القائمة، ولا يبقى سوى حقل واحد لتخزين البيانات! ويقلّل SEList (قائمة موفّرة للمساحة) هذه المساحة المهدرة باستخدام فكرة بسيطة: فبدلًا من تخزين العناصر المفردة في DLList، نخزّن كتلة (block) تحتوي على عدة عناصر. وبعبارة أدق، يُعاير SEList بحجم الكتلة b \mathtt{b}b . وتخزّن كل عقدة مفردة في SEList كتلة يمكن أن تتّسع حتى b+1 \mathtt{b+1}b+1 عنصرًا. ولأسباب ستتضح لاحقًا، من المفيد أن نتمكّن من تنفيذ عمليات Deque على كل كتلة. وبنية البيانات التي نختارها لهذا هي BDeque (طابور مزدوج مقيَّد)، المشتق من بنية ArrayDeque الموصوفة في القسم 2.4. ويختلف BDeque عن ArrayDeque في فرق بسيط واحد: فعند إنشاء BDeque جديد، يكون حجم المصفوفة a \mathtt{a}a المؤسِّسة ثابتًا عند b+1 \mathtt{b+1}b+1 ولا يتزايد ولا يتناقص أبدًا. والخاصية المهمة في BDeque هي أنها تسمح بإضافة العناصر أو حذفها عند المقدّمة أو المؤخّرة في زمن ثابت. وسيكون هذا مفيدًا عند إزاحة العناصر من كتلة إلى أخرى.

    class BDeque extends ArrayDeque<T> {
        BDeque() {
            super(SEList.this.type());
            a = newArray(b+1);
        }
        void resize() { }
    }

يصبح SEList إذن قائمة مترابطة ثنائية الوصل من الكتل:

    class Node {
        BDeque d;
        Node prev, next;
    }

    int n;
    Node dummy;

3.3.1 متطلبات المساحة يفرض SEList قيودًا شديدة على عدد العناصر في الكتلة: فمالم تكن الكتلة هي الكتلة الأخيرة، فإن تلك الكتلة تحتوي على b−1 \ensuremath{\mathtt{b}}-1b−1 عنصرًا على الأقل وb+1 \ensuremath{\mathtt{b}}+1b+1 عنصرًا على الأكثر. وهذا يعني أنه إذا كان SEList يحتوي على n \mathtt{n}n عنصرًا، فإنه يحتوي على

n/(b−1)+1=O(n/b) \displaystyle \ensuremath{\mathtt{n}}/(\ensuremath{\mathtt{b}}-1) + 1 = O(\ensuremath{\mathtt{n}}/\ensuremath{\mathtt{b}}) n/(b−1)+1=O(n/b)

كتلة كحد أقصى. يحتوي BDeque الخاص بكل كتلة على مصفوفة طولها b+1 \ensuremath{\mathtt{b}}+1b+1 ، لكن في كل كتلة عدا الأخيرة، لا يُهدَر في هذه المصفوفة سوى قدر ثابت من المساحة. والذاكرة المتبقية المستخدَمة بواسطة الكتلة هي أيضًا ثابتة. وهذا يعني أن المساحة المهدرة في SEList هي O(b+n/b) O(\ensuremath{\mathtt{b}}+\ensuremath{\mathtt{n}}/\ensuremath{\mathtt{b}})O(b+n/b) فقط. وباختيار قيمة لـ b \mathtt{b}b ضمن معامل ثابت من n \sqrt{\ensuremath{\mathtt{n}}}n​ ، يمكننا أن نجعل الحمل الزائد للمساحة في SEList يقترب من الحدّ الأدنى n \sqrt{\ensuremath{\mathtt{n}}}n​ المذكور في القسم 2.6.2.

3.3.2 العثور على العناصر

التحدّي الأول الذي نواجهه مع SEList هو العثور على عنصر القائمة ذي الفهرس i \mathtt{i}i . ولاحظ أن موقع العنصر يتكوّن من جزأين:

  1. العقدة u \mathtt{u}u التي تحتوي على الكتلة التي تحتوي على العنصر ذو الفهرس i \mathtt{i}i ؛ و
  2. الفهرس j \mathtt{j}j للعنصر داخل كتلته.
    class Location {
        Node u;
        int j;
        Location(Node u, int j) {
            this.u = u;
            this.j = j;
        }

وللعثور على الكتلة التي تحتوي على عنصر معيّن، نتصرّف بالطريقة نفسها التي نتصرّف بها في DLList. فإما أن نبدأ من مقدّمة القائمة ونجتاز في الاتجاه الأمامي، أو من ذيل القائمة ونجتاز إلى الخلف حتى نصل إلى العقدة التي نريدها. والاختلاف الوحيد هو أنه، كلما انتقلنا من عقدة إلى التي تليها، نتخطى فوق كتلة كاملة من العناصر.

    Location getLocation(int i) {
        if (i < n/2) {
            Node u = dummy.next;
            while (i >= u.d.size()) {
                i -= u.d.size();
                u = u.next;
            }
            return new Location(u, i);
        } else {
            Node u = dummy;
            int idx = n;
            while (i < idx) {
                u = u.prev;
                idx -= u.d.size();
            }
            return new Location(u, i-idx);
        }
    }

تذكّر أن، باستثناء كتلة واحدة على الأكثر، تحتوي كل كتلة على b−1 \ensuremath{\mathtt{b}}-1b−1 عنصرًا على الأقل، لذا تقربنا كل خطوة في بحثنا b−1 \ensuremath{\mathtt{b}}-1b−1 عنصرًا من العنصر الذي نبحث عنه. وإذا كنا نبحث إلى الأمام، فهذا يعني أننا نصل إلى العقدة التي نريدها بعد O(1+i/b) O(1+\ensuremath{\mathtt{i}}/\ensuremath{\mathtt{b}})O(1+i/b) خطوة. وإذا كنا نبحث إلى الخلف، فنصل إلى العقدة التي نريدها بعد O(1+(n−i)/b) O(1+(\ensuremath{\mathtt{n}}-\ensuremath{\mathtt{i}})/\ensuremath{\mathtt{b}})O(1+(n−i)/b) خطوة. وتأخذ الخوارزمية الأصغر من هاتين القيمتين تبعًا لقيمة i \mathtt{i}i ، لذا فإن الزمن اللازم لتحديد موقع العنصر ذي الفهرس i \mathtt{i}i هو O(1+min⁡{i,n−i}/b) O(1+\min\{\ensuremath{\mathtt{i}},\ensuremath{\mathtt{n}}-\ensuremath{\mathtt{i}}\}/\ensuremath{\mathtt{b}})O(1+min{i,n−i}/b) . وبمجرد أن نعرف كيفية تحديد موقع العنصر ذي الفهرس i \mathtt{i}i ، تتحوّل العمليتان get(i) \mathtt{get(i)}get(i) وset(i,x) \mathtt{set(i,x)}set(i,x) إلى جلب فهرس معيّن داخل الكتلة الصحيحة أو ضبطه:

        Location l = getLocation(i);
        return l.u.d.get(l.j);
    }
    T set(int i, T x) {
        if (i < 0 || i > n - 1) throw new IndexOutOfBoundsException();

ويُهيمن على زمن تنفيذ هذه العمليات الوقت اللازم لتحديد موقع العنصر، لذا فهي تعمل أيضًا في زمن O(1+min⁡{i,n−i}/b) O(1+\min\{\ensuremath{\mathtt{i}},\ensuremath{\mathtt{n}}-\ensuremath{\mathtt{i}}\}/\ensuremath{\mathtt{b}})O(1+min{i,n−i}/b) .

3.3.3 إضافة عنصر

إضافة العناصر إلى SEList أعقد قليلًا. وقبل النظر في الحالة العامة، نبحث عن العملية الأسهل، وهي add(x) \mathtt{add(x)}add(x) ، حيث يُضاف x \mathtt{x}x إلى نهاية القائمة. وإذا كانت الكتلة الأخيرة ممتلئة (أو غير موجودة لعدم وجود كتل بعد)، فإننا نخصّص كتلة جديدة أولًا ونُلحقها بقائمة الكتل. وبمجرد أن نتيقّن من وجود الكتلة الأخيرة وعدم امتلائها، نُلحق x \mathtt{x}x بالكتلة الأخيرة.

        Node last = dummy.prev;
        if (last == dummy || last.d.size() == b+1) {

        }
        last.d.add(x);

        return true;

  1. نجد بسرعة (في r+1≤b r+1\le \ensuremath{\mathtt{b}}r+1≤b خطوة) عقدة ur \ensuremath{\mathtt{u}}_rur​ كتلتها ليست ممتلئة. في هذه الحالة، نُجري r rr إزاحة لعنصر من كتلة إلى التي تليها، بحيث تصبح المساحة الحرة في ur \ensuremath{\mathtt{u}}_rur​ مساحة حرة في u0 \ensuremath{\mathtt{u}}_0u0​ . يمكننا بعدها إدراج x \mathtt{x}x في كتلة u0 \ensuremath{\mathtt{u}}_0u0​ .

3.3.4 حذف عنصر

حذف عنصر من SEList شبيه بإضافة عنصر. فنحن أولًا نحدّد موقع العقدة u \mathtt{u}u التي تحتوي على العنصر ذي الفهرس i \mathtt{i}i . والآن علينا الاستعداد للحالة التي لا يمكننا فيها حذف عنصر من u \mathtt{u}u دون أن تصبح كتلة u \mathtt{u}u أصغر من b−1 \ensuremath{\mathtt{b}}-1b−1 . ومرة أخرى، لنرمز بـ u0,u1,u2,… \ensuremath{\mathtt{u}}_0,\ensuremath{\mathtt{u}}_1,\ensuremath{\mathtt{u}}_2,\ldotsu0​,u1​,u2​,… إلى u \mathtt{u}u وu.next \mathtt{u.next}u.next وu.next.next \mathtt{u.next.next}u.next.next وهكذا. ونفحص u0,u1,u2,… \ensuremath{\mathtt{u}}_0,\ensuremath{\mathtt{u}}_1,\ensuremath{\mathtt{u}}_2,\ldotsu0​,u1​,u2​,… بالترتيب بحثًا عن عقدة نستطيع أن نستعير منها عنصرًا لجعل حجم كتلة u0 \ensuremath{\mathtt{u}}_0u0​ على الأقل b−1 \ensuremath{\mathtt{b}}-1b−1 . وهناك ثلاث حالات يجب اعتبارها (انظر الشكل 3.5):
  1. نجد بسرعة (في r+1≤b r+1\le \ensuremath{\mathtt{b}}r+1≤b خطوة) عقدة كتلتها تحتوي على أكثر من b−1 \ensuremath{\mathtt{b}}-1b−1 عنصرًا. في هذه الحالة، نُجري r rr إزاحة لعنصر من كتلة إلى السابقة لها، بحيث يصبح العنصر الزائد في ur \ensuremath{\mathtt{u}}_rur​ عنصرًا زائدًا في u0 \ensuremath{\mathtt{u}}_0u0​ . يمكننا بعدها حذف العنصر المناسب من كتلة u0 \ensuremath{\mathtt{u}}_0u0​ .
  2. نتجاوز بسرعة (في r+1≤b r+1\le \ensuremath{\mathtt{b}}r+1≤b خطوة) نهاية قائمة الكتل. في هذه الحالة، تكون ur \ensuremath{\mathtt{u}}_rur​ هي الكتلة الأخيرة، ولا حاجة لأن تحتوي كتلة ur \ensuremath{\mathtt{u}}_rur​ على b−1 \ensuremath{\mathtt{b}}-1b−1 عنصرًا على الأقل. ولذلك نتصرّف كما سبق، مستعيرين عنصرًا من ur \ensuremath{\mathtt{u}}_rur​ ليكون عنصرًا زائدًا في u0 \ensuremath{\mathtt{u}}_0u0​ . وإذا أدّى هذا إلى أن تصبح كتلة ur \ensuremath{\mathtt{u}}_rur​ فارغة، فإننا نحذفها.
  3. بعد b \mathtt{b}b خطوات، لا نجد أي كتلة تحتوي على أكثر من b−1 \ensuremath{\mathtt{b}}-1b−1 عنصرًا. في هذه الحالة، يكون u0,…,ub−1 \ensuremath{\mathtt{u}}_0,\ldots,\ensuremath{\mathtt{u}}_{\ensuremath{\mathtt{b}}-1}u0​,…,ub−1​ متسلسلة من b \mathtt{b}b كتل تحتوي كل منها على b−1 \ensuremath{\mathtt{b}}-1b−1 عنصرًا. نجمع العناصر الـ b(b−1) \ensuremath{\mathtt{b}}(\ensuremath{\mathtt{b}}-1)b(b−1) هذه في u0,…,ub−2 \ensuremath{\mathtt{u}}_0,\ldots,\ensuremath{\mathtt{u}}_{\ensuremath{\mathtt{b}}-2}u0​,…,ub−2​ بحيث تحتوي كل واحدة من هذه الـ b−1 \ensuremath{\mathtt{b}}-1b−1 كتلة على b \mathtt{b}b عنصرًا بالضبط، ونحذف ub−1 \ensuremath{\mathtt{u}}_{\ensuremath{\mathtt{b}}-1}ub−1​ التي صارت فارغة. والآن كتلة u0 \ensuremath{\mathtt{u}}_0u0​ تحتوي على b \mathtt{b}b عنصرًا، ونتمكن بعدها من حذف العنصر المناسب منها.

3.3.5 التحليل المُلبَّد للتوزيع والجمع

بعد ذلك، نبحث في تكلفة الطريقتين gather(u) \mathtt{gather(u)}gather(u) وspread(u) \mathtt{spread(u)}spread(u) اللتين قد تنفَّذان بواسطة الطريقتين add(i,x) \mathtt{add(i,x)}add(i,x) وremove(i) \mathtt{remove(i)}remove(i) . ولأجل الاكتمال، إليك إياهما:

    void spread(Node u) {
        Node w = u;
        for (int j = 0; j < b; j++) {
            w = w.next;
        }
        w = addBefore(w);
        while (w != u) {
            while (w.d.size() < b)
                w.d.add(0,w.prev.d.remove(w.prev.d.size()-1));
            w = w.prev;
        }
    }

    void gather(Node u) {
        Node w = u;
        for (int j = 0; j < b-1; j++) {
            while (w.d.size() < b)
                w.d.add(w.next.d.remove(0));
            w = w.next;
        }
        remove(w);
    }
