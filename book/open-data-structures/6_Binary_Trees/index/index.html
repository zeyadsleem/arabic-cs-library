يقدّم هذا الفصل أحد أكثر البنى أهمية في علوم الحاسوب: الأشجار الثنائية (binary trees). ويعود سبب تسمية هذه البنى بـ«شجرة» إلى أنّ الرسم الناتج عنها يشبه في كثير من الأحيان الأشجار التي تنبت في الغابة. وهناك طُرق كثيرة لتعريف الأشجار الثنائية. رياضيًا، الشجرة الثنائية رسم بياني (graph) متصل وغير موجّه (undirected) ومنتهٍ (finite) خالٍ من الدورات، لا رأس (vertex) فيه تتجاوز درجته ثلاثة. وفي معظم تطبيقات علوم الحاسوب تكون الأشجار الثنائية مجذّرة (rooted): إذ تُسمّى عقدة خاصة، r \mathtt{r}r ، درجتها لا تتجاوز اثنتين، جذر (root) الشجرة. أمّا لكل عقدة، u≠r \ensuremath{\mathtt{u}}\neq \ensuremath{\mathtt{r}}u=r ، فتُسمّى العقدة الثانية على المسار من u \mathtt{u}u إلى r \mathtt{r}r العقدة الأم (parent) لـ u \mathtt{u}u . وتُسمّى بقية العقد المجاورة لـ u \mathtt{u}u ابنةً (child) لـ u \mathtt{u}u . ومعظم الأشجار الثنائية التي تهمّنا مرتّبة (ordered)، ولذلك نميّز بين الابنة اليسرى والابنة اليمنى لـ u \mathtt{u}u . وفي الرسوم التوضيحية، تُرسم الأشجار الثنائية عادةً من الجذر نزولًا، فيقع الجذر في أعلى الرسم، وتحتل الابنتان اليسرى واليمنى على التوالي موضعي اليسار واليمين فيه (الشكّل 6.1). وعلى سبيل المثال، يعرض الشكّل 6.2.a شجرة ثنائية من تسع عقد.

ولأنّ الأشجار الثنائية ذات أهمية بالغة، فقد ترسّخت لها اصطلاحات خاصة: فعمق (depth) العقدة u \mathtt{u}u في شجرة ثنائية هو طول المسار من u \mathtt{u}u إلى جذر الشجرة. وإذا كانت عقدة، w \mathtt{w}w ، تقع على المسار من u \mathtt{u}u إلى r \mathtt{r}r ، فإن w \mathtt{w}w تُسمّى سلفًا (ancestor) لـ u \mathtt{u}u ، وتُسمّى u \mathtt{u}u ذريةً (descendant) لـ w \mathtt{w}w . أمّا الشجرة الفرعية (subtree) للعقدة u \mathtt{u}u فهي الشجرة الثنائية المجذّرة عند u \mathtt{u}u وتضمّ جميع ذرية u \mathtt{u}u . وارتفاع (height) العقدة u \mathtt{u}u هو طول أطول مسار من u \mathtt{u}u إلى إحدى ذريّاتها، وارتفاع الشجرة هو ارتفاع جذرها. وتُسمّى العقدة u \mathtt{u}u ورقةً (leaf) إذا لم يكن لها أي ابنة. ونفكّر أحيانًا في الشجرة على أنها مُزوَّدة بعقد خارجية (external nodes): فكل عقدة ليس لها ابنة يسرى تكون لها عقدة خارجية بوصفها الابنة اليسرى، وعلى نحو مقابل، كل عقدة ليس لها ابنة يمنى تكون لها عقدة خارجية بوصفها الابنة اليمنى (انظر الشكّل 6.2.b). ومن السهل التحقّق، بالاستدلال (induction)، من أن شجرة ثنائية فيها n≥1 \ensuremath{\mathtt{n}}\ge 1n≥1 عقدة حقيقية تضمّ n+1 \ensuremath{\mathtt{n}}+1n+1 عقدة خارجية.

6.1 BinaryTree: شجرة ثنائية أساسية

أبسط طريقة لتمثيل عقدة، u \mathtt{u}u ، في شجرة ثنائية هي تخزين جارات u \mathtt{u}u — وعددها ثلاثة على الأكثر — صراحةً:

    class BTNode<Node extends BTNode<Node>> {
        Node left;
        Node right;
        Node parent;    
    }

وعند غياب أحد هذه الجارات الثلاثة نُسند إليه القيمة nil \mathtt{nil}nil . وهكذا يتطابق كلٌّ من العقد الخارجية للشجرة والعقدة الأم للجذر مع القيمة nil \mathtt{nil}nil . وعندئذٍ يمكن تمثيل الشجرة الثنائية نفسها بإشارة إلى عقدة جذرها، r \mathtt{r}r :

    Node r;

ويمكننا حساب عمق عقدة، u \mathtt{u}u ، في شجرة ثنائية بعدّ عدد الخطوات على المسار من u \mathtt{u}u إلى الجذر:

    int depth(Node u) {
        int d = 0;
        while (u != r) {
            u = u.parent;
            d++;
        }
        return d;
    }

6.1.1 الخوارزميات التعاودية

تتيح الخوارزميات التعاودية (recursive) حساب خصائص الأشجار الثنائية بسهولة كبيرة. فمثلًا، لحساب حجم (number of nodes) شجرة ثنائية مجذّرة عند العقدة u \mathtt{u}u ، نحسب تعاوديًا حجمَي الشجرتين الفرعيتين المجذّرتين عند ابنتي u \mathtt{u}u ، ثم نجمعهما ونضيف واحدًا:

    int size(Node u) {
        if (u == nil) return 0;
        return 1 + size(u.left) + size(u.right);
    }

ولحساب ارتفاع عقدة u \mathtt{u}u ، نحسب ارتفاع الشجرتين الفرعيتين لـ u \mathtt{u}u ، ثم نأخذ الأكبر منهما ونضيف واحدًا:

    int height(Node u) {
        if (u == nil) return -1;
        return 1 + Math.max(height(u.left), height(u.right));
    }

6.1.2 اجتياز الأشجار الثنائية

تستخدم الخوارزميتان في القسم السابق كلتاهما التعاود (recursion) لزيارة جميع عقد شجرة ثنائية. وكلٌّ منهما يزور عقد الشجرة الثنائية بالترتيب نفسه الذي تمرّ به الشيفرة التالية:

    void traverse(Node u) {
        if (u == nil) return;
        traverse(u.left);
        traverse(u.right);
    }

وينتج عن هذا الأسلوب شيفرة قصيرة جدًّا وبسيطة، لكنه قد يسبّب مشكلات أيضًا. فأقصى عمق للتعاود تحدّده أقصى عمق لأي عقدة في الشجرة الثنائية، أي ارتفاع الشجرة نفسها. وإذا كان ارتفاع الشجرة كبيرًا جدًّا، فقد يستهلك هذا التعاود من مساحة المكدس (stack) أكثر من المتاح، فيتسبّب في انهيار البرنامج. أمّا لاجتياز شجرة ثنائية دون تعاود، فيمكنك استخدام خوارزمية تعتمد على الموضع الذي أتينا منه لتحديد الموضع الذي سنذهب إليه تاليًّا. انظر الشكّل 6.3. فإذا وصلنا إلى عقدة u \mathtt{u}u من u.parent \mathtt{u.parent}u.parent ، فإن الخطوة التالية هي زيارة u.left \mathtt{u.left}u.left . وإذا وصلنا إلى u \mathtt{u}u من u.left \mathtt{u.left}u.left ، فإن الخطوة التالية هي زيارة u.right \mathtt{u.right}u.right . وإذا وصلنا إلى u \mathtt{u}u من u.right \mathtt{u.right}u.right ، فقد انتهينا من زيارة الشجرة الفرعية لـ u \mathtt{u}u ، فنعود إلى u.parent \mathtt{u.parent}u.parent . وتُنفّذ الشيفرة التالية هذه الفكرة، مع تضمين شيفرة تتعامل مع الحالات التي تكون فيها u.left \mathtt{u.left}u.left أو u.right \mathtt{u.right}u.right أو u.parent \mathtt{u.parent}u.parent على القيمة nil \mathtt{nil}nil :

    void traverse2() {
        Node u = r, prev = nil, next;
        while (u != nil) {
            if (prev == u.parent) {
                if (u.left != nil) next = u.left;
                else if (u.right != nil) next = u.right;
                else next = u.parent;
            } else if (prev == u.left) {
                if (u.right != nil) next = u.right;
                else next = u.parent;
            } else {
                next = u.parent;
            }
            prev = u;
            u = next;
        }
    }

والحقائق نفسها التي يمكن حسابها بالخوارزميات التعاودية يمكن حسابها بهذه الطريقة أيضًا، دون تعاود. فمثلًا، لحساب حجم الشجرة نحتفظ بعدّاد، n \mathtt{n}n ، ونزيد n \mathtt{n}n بمقدار واحد كلما زرنا عقدة لأول مرة:

    int size2() {
        Node u = r, prev = nil, next;
        int n = 0;
        while (u != nil) {
            if (prev == u.parent) {
                n++;
                if (u.left != nil) next = u.left;
                else if (u.right != nil) next = u.right;
                else next = u.parent;
            } else if (prev == u.left) {
                if (u.right != nil) next = u.right;
                else next = u.parent;
            } else {
                next = u.parent;
            }
            prev = u;
            u = next;
        }
        return n;
    }

في بعض تنفيذات الأشجار الثنائية لا يُستعمل الحقل parent \mathtt{parent}parent . وفي هذه الحالة يظلّ التنفيذ غير التعاودي ممكنًا، لكنّه يضطر إلى استعمال قائمة (List) أو مكدس (Stack) لتتبّع المسار من العقدة الحالية إلى الجذر. وهناك نوع خاص من الاجتياز لا يندرج ضمن نمط الدوال أعلاه، وهو الاجتياز بالعرض (breadth-first traversal). وفي الاجتياز بالعرض تُزرع العقد مستوىً بعد مستوى، بدءًا من الجذر ثم النزول، وتُزار عقد كل مستوى من اليسار إلى اليمين (انظر الشكّل 6.4). وهذا يشبه الطريقة التي نقرأ بها صفحة من نص إنجليزي. ويُنفَّذ الاجتياز بالعرض باستعمال طابور (queue)، q \mathtt{q}q ، لا يحتوي في البداية سوى الجذر، r \mathtt{r}r . وفي كل خطوة نستخرج العقدة التالية، u \mathtt{u}u ، من q \mathtt{q}q ، ونعالج u \mathtt{u}u ، ثم نضيف u.left \mathtt{u.left}u.left و u.right \mathtt{u.right}u.right (إذا لم يكونا على القيمة nil \mathtt{nil}nil ) إلى q \mathtt{q}q :

    void bfTraverse() {
        Queue<Node> q = new LinkedList<Node>();
        if (r != nil) q.add(r);
        while (!q.isEmpty()) {
            Node u = q.remove();
            if (u.left != nil) q.add(u.left);
            if (u.right != nil) q.add(u.right);
        }
    }

6.2 BinarySearchTree: شجرة بحث ثنائية غير متوازنة

شجرة BinarySearchTree نوع خاص من الأشجار الثنائية، تخزّن فيها كل عقدة، u \mathtt{u}u ، قيمة بيانات، u.x \mathtt{u.x}u.x ، مأخوذة من ترتيب كلي (total order) ما. وتخضع قيم البيانات في شجرة البحث الثنائية لخاصية شجرة البحث الثنائية (binary search tree property): فأمّا العقدة u \mathtt{u}u ، فكل قيمة بيانات مخزّنة في الشجرة الفرعية المجذّرة عند u.left \mathtt{u.left}u.left فهي أصغر من u.x \mathtt{u.x}u.x ، وكل قيمة بيانات مخزّنة في الشجرة الفرعية المجذّرة عند u.right \mathtt{u.right}u.right فهي أكبر من u.x \mathtt{u.x}u.x . ويعرض الشكّل 6.5 مثالًا على BinarySearchTree.

6.2.1 البحث

خاصية شجرة البحث الثنائية مفيدة إلى حدّ بعيد لأنها تتيح لنا تحديد موضع قيمة، x \mathtt{x}x ، في شجرة بحث ثنائية بسرعة. ولهذا نبدأ البحث عن x \mathtt{x}x من الجذر، r \mathtt{r}r . وعند فحص عقدة، u \mathtt{u}u ، تنشأ ثلاث حالات:

  1. إذا كان x<u.x \ensuremath{\mathtt{x}}< \ensuremath{\mathtt{u.x}}x<u.x ، فإن البحث يتقدّم إلى u.left \mathtt{u.left}u.left ؛
  2. إذا كان x>u.x \ensuremath{\mathtt{x}}> \ensuremath{\mathtt{u.x}}x>u.x ، فإن البحث يتقدّم إلى u.right \mathtt{u.right}u.right ؛
  3. إذا كان x=u.x \ensuremath{\mathtt{x}}= \ensuremath{\mathtt{u.x}}x=u.x ، فقد وجدنا العقدة u \mathtt{u}u التي تحتوي x \mathtt{x}x .

وينتهي البحث عند وقوع الحالة 3 أو عند تحقّق u=nil \mathtt{u=nil}u=nil . وفي الحالة الأولى، فقد عثرنا على x \mathtt{x}x . وفي الحالة الثانية، نستنتج أن x \mathtt{x}x غير موجودة في شجرة البحث الثنائية.

    T findEQ(T x) {
        Node u = r;
        while (u != nil) {
            int comp = compare(x, u.x);
            if (comp < 0) 
                u = u.left;
            else if (comp > 0)
                u = u.right;
            else
                return u.x;
        }
        return null;
    }

يعرض الشكّل 6.6 مثالين للبحث في شجرة بحث ثنائية. وكما يبيّن المثال الثاني، حتى وإن لم نجد x \mathtt{x}x في الشجرة فإننا نظفر ببعض المعلومات القيّمة. فإذا نظرنا إلى آخر عقدة، u \mathtt{u}u ، وقعت فيها الحالة 1، رأينا أن u.x \mathtt{u.x}u.x هي أصغر قيمة في الشجرة أكبر من x \mathtt{x}x . وعلى نحو مماثل، فإن آخر عقدة وقعت فيها الحالة 2 تحتوي على أكبر قيمة في الشجرة أصغر من x \mathtt{x}x . وعليه، فإن تتبّع آخر عقدة، z \mathtt{z}z ، تقع فيها الحالة 1، يتيح لـ BinarySearchTree تنفيذ العملية find(x) \mathtt{find(x)}find(x) التي تُرجع أصغر قيمة مخزّنة في الشجرة تكون أكبر من x \mathtt{x}x أو مساوية لها:

    T find(T x) {
        Node w = r, z = nil;
        while (w != nil) {
            int comp = compare(x, w.x);
            if (comp < 0) {
                z = w;
                w = w.left;
            } else if (comp > 0) {
                w = w.right;
            } else {
                return w.x;
            }
        }
        return z == nil ? null : z.x;
    }

6.2.2 الإضافة

لإضافة قيمة جديدة، x \mathtt{x}x ، إلى BinarySearchTree، نبحث عن x \mathtt{x}x أولًا. فإذا عثرنا عليها فلا داعي لإدراجها. وإلّا فسنخزّن x \mathtt{x}x عند ابنةٍ ورقة للعقدة الأخيرة، p \mathtt{p}p ، التي صادفناها أثناء البحث عن x \mathtt{x}x . أمّا كون العقدة الجديدة ابنةً يسرى أو يمنى لـ p \mathtt{p}p فيتوقّف على نتيجة مقارنة x \mathtt{x}x بـ p.x \mathtt{p.x}p.x .

    boolean add(T x) {
        Node p = findLast(x);
        return addChild(p, newNode(x));        
    }

    Node findLast(T x) {
        Node w = r, prev = nil;
        while (w != nil) {
            prev = w;
            int comp = compare(x, w.x);
            if (comp < 0) {
                w = w.left;
            } else if (comp > 0) {
                w = w.right;
            } else {
                return w;
            }
        }
        return prev;
    }

    boolean addChild(Node p, Node u) {
        if (p == nil) {
            r = u;              // inserting into empty tree
        } else {
            int comp = compare(u.x, p.x);
            if (comp < 0) {
                p.left = u;
            } else if (comp > 0) {
                p.right = u;
            } else {
                return false;   // u.x is already in the tree
            }
            u.parent = p;
        }
        n++;
        return true;        
    }

يعرض الشكّل 6.7 مثالًا على ذلك. وأكثَر أجزاء هذه العملية استهلاكًا للوقت هو البحث الأولي عن x \mathtt{x}x ، إذ يستغرق زمنًا متناسبًا مع ارتفاع العقدة المضافة حديثًا u \mathtt{u}u . وفي أسوأ الحالات، يساوي هذا ارتفاع BinarySearchTree.

6.2.3 الحذف

وحذف قيمة مخزّنة في عقدة، u \mathtt{u}u ، من BinarySearchTree أصعب قليلًا. فإذا كانت u \mathtt{u}u ورقةً، يكفي فصل u \mathtt{u}u عن أمّها. والأفضل: إذا كانت u \mathtt{u}u ذات ابنة واحدة، فيمكننا نزع (splice) u \mathtt{u}u من الشجرة بأن تتبنّى u.parent \mathtt{u.parent}u.parent ابنة u \mathtt{u}u (انظر الشكّل 6.8):

    void splice(Node u) {
        Node s, p;
        if (u.left != nil) {
            s = u.left;
        } else {
            s = u.right;
        }
        if (u == r) {
            r = s;
            p = nil;
        } else {
            p = u.parent;
            if (p.left == u) {
                p.left = s;
            } else {
                p.right = s; 
            }
        }
        if (s != nil) {
            s.parent = p;
        }
        n--;
    }
