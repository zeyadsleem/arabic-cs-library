في هذا الفصل، نناقش بنية بيانات (data structure) جميلة: قائمة التخطي (skiplist)، ولها تطبيقات متنوعة. وباستخدام قائمة التخطي يمكننا تنفيذ واجهة List تمتلك تنفيذات بزمن O(log⁡n) O(\log n)O(logn) للدوال get(i) \mathtt{get(i)}get(i) ، set(i,x) \mathtt{set(i,x)}set(i,x) ، add(i,x) \mathtt{add(i,x)}add(i,x) ، و remove(i) \mathtt{remove(i)}remove(i) . ويمكن أيضًا تنفيذ مجموعة SSet تعمل فيها جميع العمليات بزمن متوقع قدره O(log⁡n) O(\log \ensuremath{\mathtt{n}})O(logn) . وتعتمد كفاءة قوائم التخطي على استخدامها للعشوائية. فعندما يُضاف عنصر جديد إلى قائمة تخطٍ، تستخدم قائمة التخطي رميات عملة عشوائية لتحديد ارتفاع العنصر الجديد. ويُعبَّر عن أداء قوائم التخطي في أزمنة التشغيل المتوقعة وأطوال المسارات. ويُؤخذ هذا التوقع على رميات العملة العشوائية التي تستخدمها قائمة التخطي. وفي التنفيذ، تُحاكى رميات العملة العشوائية المستخدمة في قائمة التخطي بواسطة مولّد أرقام (أو بتات) شبه عشوائي.

4.2 SkiplistSSet: مجموعة SSet فعّالة

تستخدم SkiplistSSet بنية قائمة التخطي لتنفيذ واجهة SSet. وعند استخدامها بهذه الطريقة، تخزّن القائمة L0 L_0L0​ عناصر مجموعة SSet مرتبة. وتعمل الدالة find(x) \mathtt{find(x)}find(x) باتباع مسار البحث عن أصغر قيمة y \mathtt{y}y بحيث y≥x \ensuremath{\mathtt{y}}\ge\ensuremath{\mathtt{x}}y≥x :

    Node<T> findPredNode(T x) {
        Node<T> u = sentinel;
        int r = h;
        while (r >= 0) {
            while (u.next[r] != null && compare(u.next[r].x,x) < 0)
                u = u.next[r];   // go right in list r
            r--;               // go down into list r-1
        }
        return u;
    }
    T find(T x) {
        Node<T> u = findPredNode(x);
        return u.next[0] == null ? null : u.next[0].x;
    }

اتباع مسار البحث عن y \mathtt{y}y سهل: عندما نقع عند عقدة ما u \mathtt{u}u في Lr L_{\ensuremath{\mathtt{r}}}Lr​ ، ننظر إلى اليمين إلى u.next[r].x \mathtt{u.next[r].x}u.next[r].x . فإذا كان x>u.next[r].x \ensuremath{\mathtt{x}}>\ensuremath{\mathtt{u.next[r].x}}x>u.next[r].x ، فإننا نتحرك خطوة إلى اليمين في Lr L_{\ensuremath{\mathtt{r}}}Lr​ ؛ وإلا فإننا ننزل إلى Lr−1 L_{\ensuremath{\mathtt{r}}-1}Lr−1​ . وكل خطوة (يمينًا أو هبوطًا) في هذا البحث تستغرق زمنًا ثابتًا فقط؛ وبالتالي، وبموجب المُلم 4.1، فإن زمن التشغيل المتوقع للدالة find(x) \mathtt{find(x)}find(x) هو O(log⁡n) O(\log \ensuremath{\mathtt{n}})O(logn) . وقبل أن نتمكن من إضافة عنصر إلى SkipListSSet، نحتاج إلى دالة تحاكي رمي العملات لتحديد ارتفاع العقدة الجديدة k \mathtt{k}k . ونفعل ذلك باختيار عدد صحيح عشوائي z \mathtt{z}z وعدّ البتات 1 11 المتتابعة في التمثيل الثنائي لـ z \mathtt{z}z :4.1

    int pickHeight() {
        int z = rand.nextInt();
        int k = 0;
        int m = 1;
        while ((z & m) != 0) {
            k++;
            m <<= 1;
        }
        return k;
    }

لتنفيذ الدالة add(x) \mathtt{add(x)}add(x) في SkiplistSSet، نبحث عن x \mathtt{x}x ثم ندرج x \mathtt{x}x (splice) في بضعة قوائم L0 L_0L0​ ,..., Lk L_{\ensuremath{\mathtt{k}}}Lk​ ، حيث يُختار k \mathtt{k}k باستخدام الدالة pickHeight() \mathtt{pickHeight()}pickHeight() . وأبسط طريقة للقيام بذلك هي استخدام مصفوفة stack \mathtt{stack}stack تتابع العقد عندها ينزل مسار البحث من قائمة ما Lr L_{\ensuremath{\mathtt{r}}}Lr​ إلى Lr−1 L_{\ensuremath{\mathtt{r}}-1}Lr−1​ . وبأدق عبارة، stack[r] \mathtt{stack[r]}stack[r] هي العقدة في Lr L_{\ensuremath{\mathtt{r}}}Lr​ عندها نزل مسار البحث إلى Lr−1 L_{\ensuremath{\mathtt{r}}-1}Lr−1​ . والعقد التي نعدّلها لإدراج x \mathtt{x}x هي بالضبط العقد stack[0],…,stack[k] \ensuremath{\mathtt{stack[0]}},\ldots,\ensuremath{\mathtt{stack[k]}}stack[0],…,stack[k] . ويطبّق الشيفرة التالية هذه الخوارزمية على add(x) \mathtt{add(x)}add(x) :

    boolean add(T x) {
        Node<T> u = sentinel;
        int r = h;
        int comp = 0;
        while (r >= 0) {
            while (u.next[r] != null 
                   && (comp = compare(u.next[r].x,x)) < 0)
                u = u.next[r];
            if (u.next[r] != null && comp == 0) return false;
            stack[r--] = u;          // going down, store u
        }
        Node<T> w = new Node<T>(x, pickHeight());
        while (h < w.height())
            stack[++h] = sentinel;   // height increased
        for (int i = 0; i < w.next.length; i++) {
            w.next[i] = stack[i].next[i];
            stack[i].next[i] = w;
        }
        n++;
        return true;
    }

يتم حذف عنصر x \mathtt{x}x بطريقة مماثلة، إلا أنه لا حاجة إلى stack \mathtt{stack}stack لمتابعة مسار البحث. ويمكن إجراء الحذف أثناء اتباع مسار البحث. نبحث عن x \mathtt{x}x، وكلما تحرّك البحث إلى الأسفل من عقدة u \mathtt{u}u،نتحققمماإذاكان ، نتحقق مما إذا كان ،نتحققمماإذاكان \ensuremath{\mathtt{u.next.x}}=\ensuremath{\mathtt{x}}،وإذاكانالأمركذلكفإننانزع ، وإذا كان الأمر كذلك فإننا نزع ،وإذاكانالأمركذلكفإننانزع \mathtt{u}$ من القائمة (splice):

    boolean remove(T x) {
        boolean removed = false;
        Node<T> u = sentinel;
        int r = h;
        int comp = 0;
        while (r >= 0) {
            while (u.next[r] != null 
                   && (comp = compare(u.next[r].x, x)) < 0) {
                u = u.next[r];

            if (u.next[r] != null && comp == 0) {

الخاصية المفيدة لهذا التعريف للطول هي أنه، إذا كنا حاليًا عند عقدة تقع في الموضع j \mathtt{j}j في L0 L_0L0​ واتبعنا حافة طولها ℓ \ellℓ ، فإننا ننتقل إلى عقدة يكون موضعها في L0 L_0L0​ هو j+ℓ \ensuremath{\mathtt{j}}+\ellj+ℓ . وبهذه الطريقة، أثناء اتباع مسار البحث، يمكننا متابعة الموضع j \mathtt{j}j للعقدة الحالية في L0 L_0L0​ . وعندما نقع عند عقدة u \mathtt{u}u في Lr L_{\ensuremath{\mathtt{r}}}Lr​ ، فإننا نتحرك إلى اليمين إذا كان j \mathtt{j}j مضافًا إليه طول الحافة u.next[r] \mathtt{u.next[r]}u.next[r] أصغر من i \mathtt{i}i . وإلا فإننا ننزل إلى Lr−1 L_{\ensuremath{\mathtt{r}}-1}Lr−1​ .

    Node findPred(int i) {
        Node u = sentinel;
        int r = h;
        int j = -1;   // index of the current node in list 0
        while (r >= 0) {
            while (u.next[r] != null && j + u.length[r] < i) {
                j += u.length[r];
                u = u.next[r];

    T get(int i) {

    }
    T set(int i, T x) {
        if (i < 0 || i > n-1) throw new IndexOutOfBoundsException();
        Node u = findPred(i).next[0];
        T y = u.x;
        u.x = x;
        return y;

التمرين 4.13 باستخدام الأفكار من القائمة الموفِّرة للمساحة، SEList، صمّم ونفّذ مجموعة SSet موفِّرة للمساحة، SESSet. ولتحقيق ذلك، خزّن البيانات بالترتيب في SEList، وخزّن كتل هذه SEList في مجموعة SSet. فإذا كان تنفيذ مجموعة SSet الأصلي يستخدم مساحة مقدارها O(n) O(\ensuremath{\mathtt{n}})O(n) لتخزين n \mathtt{n}n عنصرًا، فإن SESSet ستستخدم مساحة كافية لـ n \mathtt{n}n عنصرًا زائدًا O(n/b+b) O(\ensuremath{\mathtt{n}}/\ensuremath{\mathtt{b}}+\ensuremath{\mathtt{b}})O(n/b+b) مساحة مهدورة.

التمرين 4.14 باستخدام مجموعة SSet كبنية أساسية، صمّم ونفّذ تطبيقًا يقرأ ملفًا نصيًا (كبيرًا) ويسمح لك بالبحث، تفاعليًا، عن أي سلسلة جزئية (substring) واردة في النص. ومع أن يكتب المستخدم استعلامه، ينبغي أن يظهر الجزء المطابق من النص (إن وُجد) كنتيجة. تلميح 1: كل سلسلة جزئية هي بادئة لبعض اللاحقة (suffix)، لذا يكفي تخزين جميع لواحق الملف النصي. تلميح 2: يمكن تمثيل أي لاحقة على نحو مضغوط كعدد صحيح واحد يشير إلى موضع بدايتها في النص. اختبر تطبيقك على بعض النصوص الكبيرة، مثل بعض الكتب المتاحة في Project Gutenberg [1]. وإذا نُفِّذ بشكل صحيح، فإن تطبيقك سيكون سريع الاستجابة إلى حد كبير؛ فلا ينبغي أن يكون هناك تأخير ملحوظ بين ضغط ضغطات المفاتيح ورؤية النتائج.
