## لماذا لا يكفي الاستخراج الحالي

`scripts/import-mcs.mjs` يستخرج نص الفصول بـ `pdftotext -layout` ويحوّل كل سطر مُزاح إلى صندوق شيفرة، فيخرج النص على هذه الصورة:

```
Claim 1.1.3. For every nonnegative integer n the value of n2 C n C 41 is prime.
```

وهذه ليست مسألة تنسيق فقط: الصيغ الرياضية تالفة بنيوياً، لأن خطوط الرياضيات في الـ PDF (‏MathTime: `MT2MIT`, `MT2SYT`, `MT2EXA`) بلا جدول تحويل إلى Unicode:

| ما يُستخرج | ما هو في الكتاب |
| --- | --- |
| `n2 C n C 41` | $n^2 + n + 41$ |
| `p.n/` | $p(n)$ |
| `D` | $=$ |
| `WWD` | $\triangleq$ |
| `8n 2 N` | $\forall n \in \mathbb{N}$ |
| `¤` | $\ne$ |
| `: : :` | $\cdots$ |
| `41  41` | $41 \cdot 41$ |

ولأن الاستخراج يفقد حدود السطر الرياضي كاملاً، لا يمكن إصلاح ذلك بتعبير نمطي: يلزم إعادة بناء كل صيغة من الصورة المطبوعة. لذلك لا تُترجم الملفات المستخرجة كما هي، بل تُقرأ الصفحات المطبوعة وتُكتب الصيغ من جديد بترميز KaTeX الذي يفهمه الموقع.

## خط العمل المعتمد

1. **نص مرجعي مقروء.** `node /tmp/opencode/mcs-clean.mjs <file>` يزيل أسطر الصناديق والترويسات الجارية ويعيد لفّ الأسطر فقرات — للقراءة فقط، لا للنشر.
2. **تقسيم الفصل إلى مقاطع.** كل فصل يُقسم حسب عناوينه الفرعية (`1.1`, `1.2`, …) إلى صفحات مستقلة، على نمط `content/discrete-math`، ويُحدَّث `content/mathematics-for-cs-structure.json`.
3. **كتابة عربية.** ترجمة شرح لا نقل حرفي: فصحى، مخاطبة للقارئ، والصيغ الرياضية بـ `\(…\)` للسطرية و`\[…\]` للمعروضة، مع الرموز المتاحة في `scripts/lib/content-math.mjs` (`\N`, `\Z`, `\R`, `\floor{}`, `\card{}` …).
4. **التحقق.** يُرندر كل ملف عبر `installContentMath` للتأكد من سلامة KaTeX قبل النشر، ثم تُبنى الصفحات عبر `pnpm content` (أي `scripts/build-content.mjs`).

## قواعد ثابتة

- لا يُنشر نص إنجليزي ولا صيغة استُخرجت آلياً بلا مراجعة.
- كل صيغة تُكتب بترميز KaTeX صالح؛ لا صناديق شيفرة للنص العادي.
- أرقام المقولات والمبرهنات والمعادلات تُحفَظ كما في الأصل (‏`1.1.3`, `(1.4)` …) حتى يبقى الإحالة بين الفصول ممكنة.
- حالة الكتاب في `content/library.json` هي `translated`؛ وأي تعديل يضيف صفحات ناقصة يوقف `pnpm content` لأن المولّد يرفض كتابًا مترجمًا بملفات غير عربية.
