يقدّم هذا الفصل أحد أكثر البنى أهمية في علوم الحاسوب: الأشجار الثنائية (binary trees). ويعود سبب تسمية هذه البنى بـ«شجرة» إلى أنّ الرسم الناتج عنها يشبه في كثير من الأحيان الأشجار التي تنبت في الغابة. وهناك طُرق كثيرة لتعريف الأشجار الثنائية. رياضيًا، الشجرة الثنائية رسم بياني (graph) متصل وغير موجّه (undirected) ومنتهٍ (finite) خالٍ من الدورات، لا رأس (vertex) فيه تتجاوز درجته ثلاثة. وفي معظم تطبيقات علوم الحاسوب تكون الأشجار الثنائية مجذّرة (rooted): إذ تُسمّى عقدة خاصة، $ \mathtt{r}$ ، درجتها لا تتجاوز اثنتين، جذر (root) الشجرة. أمّا لكل عقدة، $ \ensuremath{\mathtt{u}}\neq \ensuremath{\mathtt{r}}$ ، فتُسمّى العقدة الثانية على المسار من $ \mathtt{u}$ إلى $ \mathtt{r}$ العقدة الأم (parent) لـ $ \mathtt{u}$ . وتُسمّى بقية العقد المجاورة لـ $ \mathtt{u}$ ابنةً (child) لـ $ \mathtt{u}$ . ومعظم الأشجار الثنائية التي تهمّنا مرتّبة (ordered)، ولذلك نميّز بين الابنة اليسرى والابنة اليمنى لـ $ \mathtt{u}$ . وفي الرسوم التوضيحية، تُرسم الأشجار الثنائية عادةً من الجذر نزولًا، فيقع الجذر في أعلى الرسم، وتحتل الابنتان اليسرى واليمنى على التوالي موضعي اليسار واليمين فيه (الشكّل 6.1). وعلى سبيل المثال، يعرض الشكّل 6.2.a شجرة ثنائية من تسع عقد.

ولأنّ الأشجار الثنائية ذات أهمية بالغة، فقد ترسّخت لها اصطلاحات خاصة: فعمق (depth) العقدة $ \mathtt{u}$ في شجرة ثنائية هو طول المسار من $ \mathtt{u}$ إلى جذر الشجرة. وإذا كانت عقدة، $ \mathtt{w}$ ، تقع على المسار من $ \mathtt{u}$ إلى $ \mathtt{r}$ ، فإن $ \mathtt{w}$ تُسمّى سلفًا (ancestor) لـ $ \mathtt{u}$ ، وتُسمّى $ \mathtt{u}$ ذريةً (descendant) لـ $ \mathtt{w}$ . أمّا الشجرة الفرعية (subtree) للعقدة $ \mathtt{u}$ فهي الشجرة الثنائية المجذّرة عند $ \mathtt{u}$ وتضمّ جميع ذرية $ \mathtt{u}$ . وارتفاع (height) العقدة $ \mathtt{u}$ هو طول أطول مسار من $ \mathtt{u}$ إلى إحدى ذريّاتها، وارتفاع الشجرة هو ارتفاع جذرها. وتُسمّى العقدة $ \mathtt{u}$ ورقةً (leaf) إذا لم يكن لها أي ابنة. ونفكّر أحيانًا في الشجرة على أنها مُزوَّدة بعقد خارجية (external nodes): فكل عقدة ليس لها ابنة يسرى تكون لها عقدة خارجية بوصفها الابنة اليسرى، وعلى نحو مقابل، كل عقدة ليس لها ابنة يمنى تكون لها عقدة خارجية بوصفها الابنة اليمنى (انظر الشكّل 6.2.b). ومن السهل التحقّق، بالاستدلال (induction)، من أن شجرة ثنائية فيها $ \ensuremath{\mathtt{n}}\ge 1$ عقدة حقيقية تضمّ $ \ensuremath{\mathtt{n}}+1$ عقدة خارجية.

## 6.1 BinaryTree: شجرة ثنائية أساسية

**الأقسام الفرعية**

# 6.1 BinaryTree: شجرة ثنائية أساسية

أبسط طريقة لتمثيل عقدة، $ \mathtt{u}$ ، في شجرة ثنائية هي تخزين جارات $ \mathtt{u}$ — وعددها ثلاثة على الأكثر — صراحةً:

```
    class BTNode<Node extends BTNode<Node>> {
        Node left;
        Node right;
        Node parent;    
    }
```

وعند غياب أحد هذه الجارات الثلاثة نُسند إليه القيمة $ \mathtt{nil}$ . وهكذا يتطابق كلٌّ من العقد الخارجية للشجرة والعقدة الأم للجذر مع القيمة $ \mathtt{nil}$ . وعندئذٍ يمكن تمثيل الشجرة الثنائية نفسها بإشارة إلى عقدة جذرها، $ \mathtt{r}$ :

```
    Node r;
```

ويمكننا حساب عمق عقدة، $ \mathtt{u}$ ، في شجرة ثنائية بعدّ عدد الخطوات على المسار من $ \mathtt{u}$ إلى الجذر:

```
    int depth(Node u) {
        int d = 0;
        while (u != r) {
            u = u.parent;
            d++;
        }
        return d;
    }
```

## 6.1.1 الخوارزميات التعاودية

تتيح الخوارزميات التعاودية (recursive) حساب خصائص الأشجار الثنائية بسهولة كبيرة. فمثلًا، لحساب حجم (number of nodes) شجرة ثنائية مجذّرة عند العقدة $ \mathtt{u}$ ، نحسب تعاوديًا حجمَي الشجرتين الفرعيتين المجذّرتين عند ابنتي $ \mathtt{u}$ ، ثم نجمعهما ونضيف واحدًا:

```
    int size(Node u) {
        if (u == nil) return 0;
        return 1 + size(u.left) + size(u.right);
    }
```

ولحساب ارتفاع عقدة $ \mathtt{u}$ ، نحسب ارتفاع الشجرتين الفرعيتين لـ $ \mathtt{u}$ ، ثم نأخذ الأكبر منهما ونضيف واحدًا:

```
    int height(Node u) {
        if (u == nil) return -1;
        return 1 + Math.max(height(u.left), height(u.right));
    }
```

## 6.1.2 اجتياز الأشجار الثنائية

تستخدم الخوارزميتان في القسم السابق كلتاهما التعاود (recursion) لزيارة جميع عقد شجرة ثنائية. وكلٌّ منهما يزور عقد الشجرة الثنائية بالترتيب نفسه الذي تمرّ به الشيفرة التالية:

```
    void traverse(Node u) {
        if (u == nil) return;
        traverse(u.left);
        traverse(u.right);
    }
```

وينتج عن هذا الأسلوب شيفرة قصيرة جدًّا وبسيطة، لكنه قد يسبّب مشكلات أيضًا. فأقصى عمق للتعاود تحدّده أقصى عمق لأي عقدة في الشجرة الثنائية، أي ارتفاع الشجرة نفسها. وإذا كان ارتفاع الشجرة كبيرًا جدًّا، فقد يستهلك هذا التعاود من مساحة المكدس (stack) أكثر من المتاح، فيتسبّب في انهيار البرنامج. أمّا لاجتياز شجرة ثنائية دون تعاود، فيمكنك استخدام خوارزمية تعتمد على الموضع الذي أتينا منه لتحديد الموضع الذي سنذهب إليه تاليًّا. انظر الشكّل 6.3. فإذا وصلنا إلى عقدة $ \mathtt{u}$ من $ \mathtt{u.parent}$ ، فإن الخطوة التالية هي زيارة $ \mathtt{u.left}$ . وإذا وصلنا إلى $ \mathtt{u}$ من $ \mathtt{u.left}$ ، فإن الخطوة التالية هي زيارة $ \mathtt{u.right}$ . وإذا وصلنا إلى $ \mathtt{u}$ من $ \mathtt{u.right}$ ، فقد انتهينا من زيارة الشجرة الفرعية لـ $ \mathtt{u}$ ، فنعود إلى $ \mathtt{u.parent}$ . وتُنفّذ الشيفرة التالية هذه الفكرة، مع تضمين شيفرة تتعامل مع الحالات التي تكون فيها $ \mathtt{u.left}$ أو $ \mathtt{u.right}$ أو $ \mathtt{u.parent}$ على القيمة $ \mathtt{nil}$ :

```
    void traverse2() {
        Node u = r, prev = nil, next;
        while (u != nil) {
            if (prev == u.parent) {
                if (u.left != nil) next = u.left;
                else if (u.right != nil) next = u.right;
                else next = u.parent;
            } else if (prev == u.left) {
                if (u.right != nil) next = u.right;
                else next = u.parent;
            } else {
                next = u.parent;
            }
            prev = u;
            u = next;
        }
    }
```

والحقائق نفسها التي يمكن حسابها بالخوارزميات التعاودية يمكن حسابها بهذه الطريقة أيضًا، دون تعاود. فمثلًا، لحساب حجم الشجرة نحتفظ بعدّاد، $ \mathtt{n}$ ، ونزيد $ \mathtt{n}$ بمقدار واحد كلما زرنا عقدة لأول مرة:

```
    int size2() {
        Node u = r, prev = nil, next;
        int n = 0;
        while (u != nil) {
            if (prev == u.parent) {
                n++;
                if (u.left != nil) next = u.left;
                else if (u.right != nil) next = u.right;
                else next = u.parent;
            } else if (prev == u.left) {
                if (u.right != nil) next = u.right;
                else next = u.parent;
            } else {
                next = u.parent;
            }
            prev = u;
            u = next;
        }
        return n;
    }
```

في بعض تنفيذات الأشجار الثنائية لا يُستعمل الحقل $ \mathtt{parent}$ . وفي هذه الحالة يظلّ التنفيذ غير التعاودي ممكنًا، لكنّه يضطر إلى استعمال قائمة (List) أو مكدس (Stack) لتتبّع المسار من العقدة الحالية إلى الجذر. وهناك نوع خاص من الاجتياز لا يندرج ضمن نمط الدوال أعلاه، وهو الاجتياز بالعرض (breadth-first traversal). وفي الاجتياز بالعرض تُزرع العقد مستوىً بعد مستوى، بدءًا من الجذر ثم النزول، وتُزار عقد كل مستوى من اليسار إلى اليمين (انظر الشكّل 6.4). وهذا يشبه الطريقة التي نقرأ بها صفحة من نص إنجليزي. ويُنفَّذ الاجتياز بالعرض باستعمال طابور (queue)، $ \mathtt{q}$ ، لا يحتوي في البداية سوى الجذر، $ \mathtt{r}$ . وفي كل خطوة نستخرج العقدة التالية، $ \mathtt{u}$ ، من $ \mathtt{q}$ ، ونعالج $ \mathtt{u}$ ، ثم نضيف $ \mathtt{u.left}$ و $ \mathtt{u.right}$ (إذا لم يكونا على القيمة $ \mathtt{nil}$ ) إلى $ \mathtt{q}$ :

```
    void bfTraverse() {
        Queue<Node> q = new LinkedList<Node>();
        if (r != nil) q.add(r);
        while (!q.isEmpty()) {
            Node u = q.remove();
            if (u.left != nil) q.add(u.left);
            if (u.right != nil) q.add(u.right);
        }
    }
```

## 6.2 BinarySearchTree: شجرة بحث ثنائية غير متوازنة

**الأقسام الفرعية**

# 6.2 BinarySearchTree: شجرة بحث ثنائية غير متوازنة

شجرة BinarySearchTree نوع خاص من الأشجار الثنائية، تخزّن فيها كل عقدة، $ \mathtt{u}$ ، قيمة بيانات، $ \mathtt{u.x}$ ، مأخوذة من ترتيب كلي (total order) ما. وتخضع قيم البيانات في شجرة البحث الثنائية لخاصية شجرة البحث الثنائية (binary search tree property): فأمّا العقدة $ \mathtt{u}$ ، فكل قيمة بيانات مخزّنة في الشجرة الفرعية المجذّرة عند $ \mathtt{u.left}$ فهي أصغر من $ \mathtt{u.x}$ ، وكل قيمة بيانات مخزّنة في الشجرة الفرعية المجذّرة عند $ \mathtt{u.right}$ فهي أكبر من $ \mathtt{u.x}$ . ويعرض الشكّل 6.5 مثالًا على BinarySearchTree.

## 6.2.1 البحث

خاصية شجرة البحث الثنائية مفيدة إلى حدّ بعيد لأنها تتيح لنا تحديد موضع قيمة، $ \mathtt{x}$ ، في شجرة بحث ثنائية بسرعة. ولهذا نبدأ البحث عن $ \mathtt{x}$ من الجذر، $ \mathtt{r}$ . وعند فحص عقدة، $ \mathtt{u}$ ، تنشأ ثلاث حالات:

1. إذا كان $ \ensuremath{\mathtt{x}}< \ensuremath{\mathtt{u.x}}$ ، فإن البحث يتقدّم إلى $ \mathtt{u.left}$ ؛
2. إذا كان $ \ensuremath{\mathtt{x}}> \ensuremath{\mathtt{u.x}}$ ، فإن البحث يتقدّم إلى $ \mathtt{u.right}$ ؛
3. إذا كان $ \ensuremath{\mathtt{x}}= \ensuremath{\mathtt{u.x}}$ ، فقد وجدنا العقدة $ \mathtt{u}$ التي تحتوي $ \mathtt{x}$ .

وينتهي البحث عند وقوع الحالة 3 أو عند تحقّق $ \mathtt{u=nil}$ . وفي الحالة الأولى، فقد عثرنا على $ \mathtt{x}$ . وفي الحالة الثانية، نستنتج أن $ \mathtt{x}$ غير موجودة في شجرة البحث الثنائية.

```
    T findEQ(T x) {
        Node u = r;
        while (u != nil) {
            int comp = compare(x, u.x);
            if (comp < 0) 
                u = u.left;
            else if (comp > 0)
                u = u.right;
            else
                return u.x;
        }
        return null;
    }
```

يعرض الشكّل 6.6 مثالين للبحث في شجرة بحث ثنائية. وكما يبيّن المثال الثاني، حتى وإن لم نجد $ \mathtt{x}$ في الشجرة فإننا نظفر ببعض المعلومات القيّمة. فإذا نظرنا إلى آخر عقدة، $ \mathtt{u}$ ، وقعت فيها الحالة 1، رأينا أن $ \mathtt{u.x}$ هي أصغر قيمة في الشجرة أكبر من $ \mathtt{x}$ . وعلى نحو مماثل، فإن آخر عقدة وقعت فيها الحالة 2 تحتوي على أكبر قيمة في الشجرة أصغر من $ \mathtt{x}$ . وعليه، فإن تتبّع آخر عقدة، $ \mathtt{z}$ ، تقع فيها الحالة 1، يتيح لـ BinarySearchTree تنفيذ العملية $ \mathtt{find(x)}$ التي تُرجع أصغر قيمة مخزّنة في الشجرة تكون أكبر من $ \mathtt{x}$ أو مساوية لها:

```
    T find(T x) {
        Node w = r, z = nil;
        while (w != nil) {
            int comp = compare(x, w.x);
            if (comp < 0) {
                z = w;
                w = w.left;
            } else if (comp > 0) {
                w = w.right;
            } else {
                return w.x;
            }
        }
        return z == nil ? null : z.x;
    }
```

## 6.2.2 الإضافة

لإضافة قيمة جديدة، $ \mathtt{x}$ ، إلى BinarySearchTree، نبحث عن $ \mathtt{x}$ أولًا. فإذا عثرنا عليها فلا داعي لإدراجها. وإلّا فسنخزّن $ \mathtt{x}$ عند ابنةٍ ورقة للعقدة الأخيرة، $ \mathtt{p}$ ، التي صادفناها أثناء البحث عن $ \mathtt{x}$ . أمّا كون العقدة الجديدة ابنةً يسرى أو يمنى لـ $ \mathtt{p}$ فيتوقّف على نتيجة مقارنة $ \mathtt{x}$ بـ $ \mathtt{p.x}$ .

```
    boolean add(T x) {
        Node p = findLast(x);
        return addChild(p, newNode(x));        
    }
```

```
    Node findLast(T x) {
        Node w = r, prev = nil;
        while (w != nil) {
            prev = w;
            int comp = compare(x, w.x);
            if (comp < 0) {
                w = w.left;
            } else if (comp > 0) {
                w = w.right;
            } else {
                return w;
            }
        }
        return prev;
    }
```

```
    boolean addChild(Node p, Node u) {
        if (p == nil) {
            r = u;              // inserting into empty tree
        } else {
            int comp = compare(u.x, p.x);
            if (comp < 0) {
                p.left = u;
            } else if (comp > 0) {
                p.right = u;
            } else {
                return false;   // u.x is already in the tree
            }
            u.parent = p;
        }
        n++;
        return true;        
    }
```

يعرض الشكّل 6.7 مثالًا على ذلك. وأكثَر أجزاء هذه العملية استهلاكًا للوقت هو البحث الأولي عن $ \mathtt{x}$ ، إذ يستغرق زمنًا متناسبًا مع ارتفاع العقدة المضافة حديثًا $ \mathtt{u}$ . وفي أسوأ الحالات، يساوي هذا ارتفاع BinarySearchTree.

## 6.2.3 الحذف

وحذف قيمة مخزّنة في عقدة، $ \mathtt{u}$ ، من BinarySearchTree أصعب قليلًا. فإذا كانت $ \mathtt{u}$ ورقةً، يكفي فصل $ \mathtt{u}$ عن أمّها. والأفضل: إذا كانت $ \mathtt{u}$ ذات ابنة واحدة، فيمكننا نزع (splice) $ \mathtt{u}$ من الشجرة بأن تتبنّى $ \mathtt{u.parent}$ ابنة $ \mathtt{u}$ (انظر الشكّل 6.8):

```
    void splice(Node u) {
        Node s, p;
        if (u.left != nil) {
            s = u.left;
        } else {
            s = u.right;
        }
        if (u == r) {
            r = s;
            p = nil;
        } else {
            p = u.parent;
            if (p.left == u) {
                p.left = s;
            } else {
                p.right = s; 
            }
        }
        if (s != nil) {
            s.parent = p;
        }
        n--;
    }
```

غير أنّ الأمور تصبح معقّدة عندما تكون $ \mathtt{u}$ ذات ابنتين. وفي هذه الحالة، أبسط ما يمكن فعله هو العثور على عقدة، $ \mathtt{w}$ ، لها أقل من ابنتين، بحيث يمكن لـ $ \mathtt{w.x}$ أن تحلّ محلّ $ \mathtt{u.x}$ . ولأجل الحفاظ على خاصية شجرة البحث الثنائية، ينبغي أن تكون قيمة $ \mathtt{w.x}$ قريبة من قيمة $ \mathtt{u.x}$ . فمثلًا، يكفي اختيار $ \mathtt{w}$ بحيث تكون $ \mathtt{w.x}$ أصغر قيمة أكبر من $ \mathtt{u.x}$ . والعثور على العقدة $ \mathtt{w}$ سهل؛ فهي أصغر قيمة في الشجرة الفرعية المجذّرة عند $ \mathtt{u.right}$ . ويمكن إزالة هذه العقدة بسهولة لأنها لا تملك ابنة يسرى (انظر الشكّل 6.9).

```
    void remove(Node u) {
        if (u.left == nil || u.right == nil) {
            splice(u);
        } else {
            Node w = u.right;
            while (w.left != nil) 
                w = w.left;
            u.x = w.x;
            splice(w);
        }
    }
```

**الشكّل 6.9:** يتضمّن حذف قيمة ( $ 11$ ) من عقدة، $ \mathtt{u}$ ، ذات ابنتين استبدال قيمة $ \mathtt{u}$ بأصغر قيمة في الشجرة الفرعية اليمنى المجذّرة عند $ \mathtt{u}$ . ![\includegraphics[width=\textwidth ]{figs/bst-delete-1}](/images/open-data-structures/6_2_BinarySearchTree_Unbala-img2728.png.webp) ![\includegraphics[width=\textwidth ]{figs/bst-delete-2}](/images/open-data-structures/6_2_BinarySearchTree_Unbala-img2729.png.webp) 6.2.4 خلاصة تنطوي كلٌّ من العمليات $ \mathtt{find(x)}$ و $ \mathtt{add(x)}$ و $ \mathtt{remove(x)}$ في BinarySearchTree على اتباع مسار من جذر الشجرة إلى إحدى عقدها. ومن دون معرفة أكبر عن شكل الشجرة يصعب قول الكثير عن طول هذا المسار، عدا أنه أقل من $ \mathtt{n}$ ، وهو عدد عقد الشجرة. وتُلخّص المبرهنة التالية (وهي غير مُبهرة) أداء بنية البيانات BinarySearchTree: **المبرهنة 6.1** *تنفّذ BinarySearchTree واجهة SSet، وتدعم العمليات $ \mathtt{add(x)}$ و $ \mathtt{remove(x)}$ و $ \mathtt{find(x)}$ في زمن $ O(\ensuremath{\mathtt{n}})$ لكل عملية.*

تقارن المبرهنة 6.1 مقارنةً سيّئة بالمبرهنة 4.1، التي تُظهر أن بنية SkiplistSSet تستطيع تنفيذ واجهة SSet بزمن متوقع قدره $ O(\log \ensuremath{\mathtt{n}})$ لكل عملية. والمشكلة في بنية BinarySearchTree أنها قد تصبح غير متوازنة. فبدلًا من أن تبدو على هيئة الشجرة في الشكّل 6.5، قد تبدو على هيئة سلسلة طويلة من $ \mathtt{n}$ عقد، لكلّها خلا العقد الأخيرة ابنة واحدة بالضبط. وهناك طُرق عديدة لتجنّب أشجار البحث الثنائية غير المتوازنة، وكلّها تؤدّي إلى بنى بيانات عملياتها بزمن $ O(\log \ensuremath{\mathtt{n}})$ . وفي الفصل 7 نبيّن كيف يمكن بلوغ عمليات بزمن متوقع قدره $ O(\log \ensuremath{\mathtt{n}})$ بالاعتماد على العشوائية (randomization). وفي الفصل 8 نبيّن كيف يمكن بلوغ عمليات بزمن مُطفأ (amortized) قدره $ O(\log \ensuremath{\mathtt{n}})$ بعمليات إعادة البناء الجزئي. وفي الفصل 9 نبيّن كيف يمكن بلوغ عمليات بزمن أسوأ حالة قدره $ O(\log \ensuremath{\mathtt{n}})$ عبر محاكاة شجرة غير ثنائية: شجرة يمكن أن تتجاوز عقدُها أربعَ ابنات. ## 6.3 مناقشة والتمارين

استُخدمت الأشجار الثنائية لنمذجة العلاقات منذ آلاف السنين. ومن أسباب ذلك أنّ الأشجار الثنائية تنمذج بصورة طبيعية أشجار العائلة (نسبيّة النسب). فهذه هي أشجار العائلة التي يكون فيها الجذر شخصًا، وتكون الابنتان اليسرى واليمنى والدَيْن الشخص، وهكذا تعاوديًا. وفي القرون الأخيرة استُخدمت الأشجار الثنائية أيضًا لنمذجة أشجار الأنواع في الأحياء، حيث تمثّل أوراق الشجرة الأنواع الحيّة الباقية، وتمثّل العقد الداخلية للشجرة أحداث التمايز (speciation) التي يتطوّر فيها تجمّعان من نوع واحد إلى نوعين منفصلين. ويبدو أن أشجار البحث الثنائية قد اُكتشفت على يد عدّة مجموعات بصورة مستقلّة في الخمسينيات [48, القسم 6.2.2]. وتقدّم الفصول اللاحقة مراجعَ إضافية إلى أنواع محدّدة من أشجار البحث الثنائية. وعند تنفيذ شجرة ثنائية من الصفر، هناك عدّة قرارات تصميمية يجب اتخاذها. ومن بينها ما إذا كانت كل عقدة تخزّن مؤشرًا إلى أمّها. فإذا كانت معظم العمليات تتبع مجرّد مسار من الجذر إلى ورقة، فإنّ مؤشرات الأمّ تصبح غير ضرورية، وتهدر المساحة، وتمثّل مصدرًا محتملًا لأخطاء البرمجة. ومن الجهة الأخرى، يعني غياب مؤشرات الأمّ أن اجتياز الشجرة لا بدّ أن يتمّ تعاوديًا أو باستعمال مكدس صريح (explicit stack). كما أنّ بعض الطرائق الأخرى (مثل الإدراج أو الحذف في بعض أنواع أشجار البحث الثنائية المتوازنة) تتعقّد بسبب غياب مؤشرات الأمّ. أمّا قرار التصميم الآخر فيتعلّق بكيفية تخزين مؤشرات الأمّ والابنة اليسرى والابنة اليمنى عند العقدة. وفي التنفيذ المعروض هنا، تُخزَّن هذه المؤشرات في متغيّرات منفصلة. وخيار آخر هو تخزينها في مصفوفة، $ \mathtt{p}$ ، طولها 3، بحيث تكون $ \mathtt{u.p[0]}$ هي الابنة اليسرى لـ $ \mathtt{u}$ ، و $ \mathtt{u.p[1]}$ هي الابنة اليمنى لـ $ \mathtt{u}$ ، و $ \mathtt{u.p[2]}$ هي الأمّ لـ $ \mathtt{u}$ . واستعمال المصفوفة بهذه الطريقة يعني أنّ بعض السلاسل من جمل $ \mathtt{if}$ يمكن تبسيطها إلى تعبيرات جبرية. ومن أمثلة هذا التبسيط ما يحدث أثناء اجتياز الشجرة. فإذا وصل الاجتياز إلى عقدة، $ \mathtt{u}$ ، من $ \mathtt{u.p[i]}$ ، فإنّ العقدة التالية في الاجتياز هي $ \ensuremath{\mathtt{u.p}}[(\ensuremath{\mathtt{i}}+1)\bmod 3]$ . وتتكاثر الأمثلة المماثلة عند وجود تناظر بين اليسار واليمين. فمثلًا، أخت (sibling) $ \mathtt{u.p[i]}$ هي $ \ensuremath{\mathtt{u.p}}[(\ensuremath{\mathtt{i}}+1)\bmod 2]$ . وتعمل هذه الحيلة سواء كانت $ \mathtt{u.p[i]}$ ابنةً يسرى ( $ \ensuremath{\mathtt{i}}=0$ ) أو ابنةً يمنى ( $ \ensuremath{\mathtt{i}}=1$ ) لـ $ \mathtt{u}$ . وفي بعض الحالات يعني ذلك أنّ شيفرةً معقّدة كانت ستحتاج لولا ذلك إلى نسختين، نسخة لليسار وأخرى لليمين، يمكن كتابتها مرّة واحدة فقط. انظر الدالتين $ \mathtt{rotateLeft(u)}$ و $ \mathtt{rotateRight(u)}$ في صفحة ![*](/images/open-data-structures/6_3_Discussion_Exercises-crossref.png.webp) مثالًا على ذلك. **التمرين 6.1** أثبت أنّ شجرة ثنائية فيها $ \ensuremath{\mathtt{n}}\ge 1$ عقدة لديها $ \ensuremath{\mathtt{n}}-1$ حافة.

**التمرين 6.2** أثبت أنّ شجرة ثنائية ذات $ \ensuremath{\mathtt{n}}\ge 1$ عقدة حقيقية تضمّ $ \ensuremath{\mathtt{n}}+1$ عقدة خارجية.

**التمرين 6.3** أثبت أنّه إذا كانت الشجرة الثنائية $ T$ تملك ورقة واحدة على الأقلّ، فإنّه إمّا (a) أن يكون لجذر $ T$ ابنة واحدة على الأكثر، أو (b) أن تملك $ T$ أكثر من ورقة.

**التمرين 6.4** نفّذ دالة غير تعاودية، $ \mathtt{size2(u)}$ ، تحسب حجم الشجرة الفرعية المجذّرة عند العقدة $ \mathtt{u}$ .

**التمرين 6.6** الشجرة الثنائية متوازنة الحجم (size-balanced) إذا كان، لكل عقدة $ \mathtt{u}$ ، حجمَا الشجرتين الفرعيتين المجذّرتين عند $ \mathtt{u.left}$ و $ \mathtt{u.right}$ يختلفان بواقع واحد على الأكثر. اكتب دالة تعاودية، $ \mathtt{isBalanced()}$ ، تختبر ما إذا كانت شجرة ثنائية متوازنة. وينبغي أن تعمل دالتك في زمن $ O(\ensuremath{\mathtt{n}})$ . (واحرص على اختبار شيفرتك على بعض الأشجار الكبيرة ذات الأشكال المختلفة؛ فمن السهل كتابة دالة تستغرق زمنًا أطول بكثير من $ O(\ensuremath{\mathtt{n}})$ .)

الاجتياز بالترتيب المسبق (pre-order traversal) لشجرة ثنائية هو اجتياز يزور كل عقدة، $ \mathtt{u}$ ، قبل أيٍّ من ابنتَيها. والاجتياز بالترتيب الوسطي (in-order traversal) يزور $ \mathtt{u}$ بعد زيارة جميع عقد الشجرة الفرعية اليسرى لـ $ \mathtt{u}$ وقبل زيارة أيٍّ من عقد الشجرة الفرعية اليمنى لـ $ \mathtt{u}$ . أمّا الاجتياز بالترتيب اللاحق (post-order traversal) فيزور $ \mathtt{u}$ فقط بعد زيارة سائر عقد الشجرة الفرعية لـ $ \mathtt{u}$ . أمّا ترقيم شجرة بترتيب مسبق أو وسطي أو لاحق (pre/in/post-order numbering) فيُسند إلى عقد الشجرة الأعداد الصحيحة $ 0,\ldots,\ensuremath{\mathtt{n}}-1$ بالترتيب الذي تصادفها به اجتيازٌ مسبق أو وسطي أو لاحق. انظر الشكّل 6.10 مثالًا. **الشكّل 6.10:** الترقيم المسبق واللاتح والوسطي لشجرة ثنائية. ![\includegraphics[scale=0.90909]{figs/binarytree-numbering-1}](/images/open-data-structures/6_3_Discussion_Exercises-img2791.png.webp) ![\includegraphics[scale=0.90909]{figs/binarytree-numbering-2}](/images/open-data-structures/6_3_Discussion_Exercises-img2792.png.webp) ![\includegraphics[scale=0.90909]{figs/binarytree-numbering-3}](/images/open-data-structures/6_3_Discussion_Exercises-img2793.png.webp) **التمرين 6.7** أنشئ صنفًا فرعيًا من BinaryTree تكون لعقده حقول لتخزين الأرقام المسبقة واللاتحقة والوسطية. واكتب دوالًا تعاودية $ \mathtt{preOrderNumber()}$ و $ \mathtt{inOrderNumber()}$ و $ \mathtt{postOrderNumbers()}$ تُسند هذه الأرقام على الوجه الصحيح. وينبغي أن تعمل كلٌّ من هذه الدوال في زمن $ O(\ensuremath{\mathtt{n}})$ .

**التمرين 6.8** نفّذ الدوال غير التعاودية $ \mathtt{nextPreOrder(u)}$ و $ \mathtt{nextInOrder(u)}$ و $ \mathtt{nextPostOrder(u)}$ التي تُرجع العقدة التي تلي $ \mathtt{u}$ في اجتيازٍ بالترتيب المسبق أو الوسطي أو اللاحق على التوالي. وينبغي أن تستهلك هذه الدوال زمنًا ثابتًا مُطفأ (amortized constant time)؛ فإذا بدأنا من أي عقدة $ \mathtt{u}$ وكرّرنا استدعاء إحدى هذه الدوال وأسندنا القيمة المُرجعة إلى $ \mathtt{u}$ حتى يبلغ $ \ensuremath{\mathtt{u}}=\ensuremath{\mathtt{null}}$ ، فينبغي أن تكون تكلفة كل هذه الاستدعاءات $ O(\ensuremath{\mathtt{n}})$ .

**التمرين 6.9** نفترض أنّ لدينا شجرة ثنائية أُسند إلى عقدها أرقامٌ بالترتيب المسبق واللاتح والوسطي. بيّن كيف يمكن استعمال هذه الأرقام للإجابة عن كلٍّ من الأسئلة التالية في زمن ثابت: أعطِ عقدة $ \mathtt{u}$ ، فحدّد حجم الشجرة الفرعية المجذّرة عند $ \mathtt{u}$ . وأعطِ عقدة $ \mathtt{u}$ ، فحدّد عمق $ \mathtt{u}$ . وأعطِ عقدتين $ \mathtt{u}$ و $ \mathtt{w}$ ، فحدّد ما إذا كان $ \mathtt{u}$ سلفًا لـ $ \mathtt{w}$
