## الشريحة 2: ثيتا (Θ)

- نرمز إلى التعقيد الحتمي (asymptotic complexity) بالحرف ثيتا Θ.
- ننظر إلى حدّ المدخل الذي يهيمن على الدالة.
- نُسقط الأجزاء الأخرى التي لا تنمو بسرعة، ونُسقط الثوابت الجمعية، ونُسقط الثوابت الضربية.
- ينتهي الأمر إلى عدد قليل من أصناف الخوارزميات.
- سننظر اليوم إلى شيفرة تقع في كل واحد من هذه الأصناف.

## الشريحة 3: من أين تأتي الدالة؟

بالنظر إلى الشيفرة، ابدأ بمعاملات الإدخال: ما هي؟ ثم صُغ المعادلة التي تربط الإدخال بعدد العمليات.

```python
def f(L, L1, L2):
    inL1 = False
    for i in range(len(L1)):
        if L[i] == L1[i]:
            inL1 = True
    inL2 = False
    for i in range(len(L2)):
        if L[i] == L2[i]:
            inL2 = True
    return inL1 and inL2
```

$$f = 1 + len(L1)*5 + 1 + len(L2)*5 + 2 = 5*len(L1) + 5*len(L2) + 3$$

إذا كان الطولان متساويين، فإن:

$$f = 10*len(L) + 3$$

$$\Theta(f) = \Theta(10*len(L) + 3) = \Theta(len(L))$$

## الشريحة 4: من أين تأتي الدالة؟ (طريقة أسرع)

لا حاجة لصياغة المعادلة الدقيقة. ابحث عن الحلقات وعن كل ما يتكرّر بدلالة معاملات الإدخال. وكل ما عداه ثابت.

نفس الدالة `f(L, L1, L2)` السابقة، والحلقتان `for i in range(len(L1))` و `for i in range(len(L2))` هما كل ما يتكرّر بدلالة الإدخال.

## الشريحة 5: أصناف التعقيد

`n` هو المدخل. نريد تصميم خوارزميات تكون أقرب ما يمكن إلى قمة هذا التسلسل قدر الإمكان.

| الرمز | الدلالة |
|---|---|
| $\Theta(1)$ | زمن تشغيل ثابت (constant running time) |
| $\Theta(\log n)$ | زمن تشغيل لوغاريتمي (logarithmic) |
| $\Theta(n)$ | زمن تشغيل خطّي (linear) |
| $\Theta(n \log n)$ | زمن تشغيل خطّي لوغاريتمي (log-linear) |
| $\Theta(n^c)$ | زمن تشغيل متعدّد الحدود (polynomial)، حيث $c$ ثابت |
| $\Theta(c^n)$ | زمن تشغيل أُسّي (exponential)، حيث $c$ ثابت مرفوع إلى قوّة تعتمد على حجم الإدخال |

> **ملاحظة المترجم:** الشرائح الأصلية تكتب الحدّين الأخيرين بالإحراف مطبوعًا على هيئة $\Theta(nc)$ و $\Theta(cn)$، لكن المقصود هو $n^c$ و $c^n$، وقد ضبطتُهما هنا على الصورة الصحيحة لأن بقية الشرائح تستخدمهما بذلك.

## الشريحة 7: التعقيد الثابت

- تعقيد مستقل عن المدخلات.
- الخوارزميات المثيرة للاهتمام في هذا الصنف قليلة، لكن كثيرًا من الخوارزميات يمكن أن تحتوي أجزاءً تقع في هذا الصنف.
- يمكن أن توجد حلقات أو استدعاءات ذاتية، لكن عدد التكرارات أو الاستدعاءات لا يعتمد على حجم المدخل.
- بعض العمليات المدمجة في اللغة ثابتة الزمن:
  - الفهرسة في قائمة في Python: `L[i]`
  - الإلحاق في قائمة: `L.append()`
  - البحث في قاموس: `d[key]`

## الشريحة 12: التعقيد الخطّي

- خوارزميات حلقية تكرارية بسيطة (simple iterative loop algorithms).
- يجب أن تكون الحلقات دالةً في المدخل.
- البحث الخطّي عن عنصر في قائمة (linear search): هل العنصر موجود أم لا.
- دوال ذاتية (recursive functions) فيها استدعاء ذاتي واحد فقط وتكلفة ثابتة للاستدعاء نفسه.
- بعض العمليات المدمجة خطّية:
  - `e in L`
  - شريحة من قائمة، مثل `L[:len(L)//2]`
  - `L1 == L2`
  - `del(L[5])`

## الشريحة 16: التعقيد الخطّي: مثال ٢

حلقة لإيجاد مضروب عدد $\ge 2$ (factorial).

```python
def fact_iter(n):
    prod = 1

        prod *= i

```

- عدد العمليات داخل الحلقة ثابت، ومستقل عن `n`.

## الشريحة 17: مسألة طريفة حول المضروب وPython

- السبب أن Python يزيد حجم الأعداد الصحيحة، مما يجعل العمليات أكثر كلفة.

## الشريحة 18: التعقيد الخطّي: مثال ٣

```python
def fact_recur(n):
    """ assume n >= 0 """
    if n <= 1:
        return 1
    else:
        return n*fact_recur(n – 1)
```

- يحسب المضروب بطريقة ذاتية.
- إن قِست الزمن، ستلاحظ أنه أبطأ قليلًا من النسخة التكرارية بسبب استدعاءات الدوال.
- $\Theta(n)$ لأن عدد استدعاءات الدوال خطّي في `n`.
- تنفيذا المضروب، التكراري والذاتي، لهما ترتيب النمو نفسه.

## الشريحة 19: التعقيد الخطّي: مثال ٤

```python
def compound(invest, interest, n_months):
    total=0
    for i in range(n_months):
        total = total * interest + invest Θ(1)
    return total
```

- $\Theta(1) * \Theta(n\_months) = \Theta(n\_months)$
- $\Theta(n)$ حيث $n = n\_months$
- $\Theta(n\_months)$
- إن كنت دقيقًا إلى حدّ كبير، فلا بد من احتساب جملتي الإسناد والإرجاع:
  $\Theta(1) + 4*\Theta(n) + \Theta(1) = \Theta(1 + 4*n + 1) = \Theta(n)$ حيث $n = n\_months$.

## الشريحة 20: تعقيد فيبوناتشي التكراري

```python
def fib_iter(n):
    if n == 0:
        return 0
    elif n == 1:
        return 1
    else:
        fib_i = 0
        fib_ii = 1
        for i in range(n-1):
            tmp = fib_i
            fib_i = fib_ii
            fib_ii = tmp + fib_ii
        return fib_ii
```

الحساب: $\Theta(1) + \Theta(1) + \Theta(n) * \Theta(1) + \Theta(1) = \Theta(n)$

## الشريحة 22: التعقيد متعدّد الحدود (غالبًا تربيعي)

- أكثر خوارزميات متعدّدة الحدود شيوعًا هي التربيعية، أي أن التعقيد ينمو مع مربّع حجم المدخل.
- يظهر عادةً عندما تكون لدينا حلقات متداخلة (nested loops) أو استدعاءات ذاتية لدوال.

## الشريحة 23: التعقيد التربيعي: مثال ١

```python
def g(n):
    """ assume n >= 0 """
    x = 0
    for i in range(n):
        for j in range(n):
            x += 1
    return x
```

- يحسب $n^2$ بطريقة غير فعّالة جدًّا.
- انظر إلى الحلقات: هل هي بدلالة المُدخل؟
- حلقات متداخلة.
- انظر إلى المدى: `range(n)` لكل منهما.
- كل حلقة تتكرّر $n$ مرّات.
- $\Theta(n) * \Theta(n) * \Theta(1) = \Theta(n^2)$

## الشريحة 24: التعقيد التربيعي: مثال ٢

هل `L1` مجموعة جزئية (subset) من `L2`؟ أي: هل كل عناصر `L1` موجودة في `L2`؟

```python
def is_subset(L1, L2):
    for e1 in L1:
        matched = False
        for e2 in L2:
            if e1 == e2:
                matched = True
                break
        if not matched:
            return False
    return True
```

| الحالة | `L1` | `L2` | النتيجة |
|---|---|---|---|
| نعم | `[3, 5, 2]` | `[2, 3, 5, 9]` | كل عناصر `L1` في `L2` |
| لا | `[3, 5, 2]` | `[2, 5, 9]` | العنصر `3` غير موجود في `L2` |

## الشريحة 25: التعقيد التربيعي: مثال ٢ (التحليل)

نفس الدالة `is_subset`، مع الشرح:

- الحلقة الخارجية تُنفَّذ `len(L1)` مرّة.
- كل تكرار لها يُنفّذ الحلقة الداخلية حتى `len(L2)` مرّة.
- $\Theta(len(L1) * len(L2))$
- إذا كان `L1` و `L2` بالطول نفسه، ولم يكن أيّ عنصر من `L1` في `L2`: $\Theta(len(L1)^2)$

## الشريحة 26: التعقيد التربيعي: مثال ٣

ابحث عن تقاطع قائمتين، وأعِد قائمة فيها كل عنصر يظهر مرّة واحدة فقط.

```python
def intersect(L1, L2):
    tmp = []
    for e1 in L1:
        for e2 in L2:
            if e1 == e2:
                tmp.append(e1)
    unique = []
    for e in tmp:
        if not(e in unique):
            unique.append(e)
    return unique
```

| `L1` | `L2` | النتيجة |
|---|---|---|
| `[3, 5, 2]` | `[2, 3, 5, 9]` | `[2, 3, 5]` |
| `[7, 7, 7]` | `[7, 7, 7]` | `[7]` |

## الشريحة 27: التعقيد التربيعي: مثال ٣ (التحليل)

- الحلقة المتداخلة الأولى تأخذ $\Theta(len(L1) * len(L2))$ خطوة.
- الحلقة الثانية تأخذ على الأكثر $\Theta(len(L1) * len(L2))$ خطوة. وهي عادةً ليست بالسوءة هذه.
  - مثال: `[7,7,7]` و `[7,7,7]` ينتج `tmp=[7,7,7,7,7,7,7,7,7]`.
- الإجمالي $\Theta(len(L1) * len(L2))$

## الشريحة 28: تعقيد القطر (diameter)

```python
def diameter(L):
    farthest_dist = 0
    for i in range(len(L)):
        for j in range(i+1, len(L)):
            p1 = L[i]
            p2 = L[j]
            dist = math.sqrt( (p1[0]-p2[0])**2 + (p1[1]-p2[1])**2 )
            if dist > farthest_dist:
                farthest_dist = dist
    return farthest_dist
```

عدد التكرارات: $len(L) * len(L)/2 = len(L)^2 / 2$، أي $\Theta(len(L)^2)$.

## الشريحة 30: جرّب بنفسك (YOU TRY IT!)

def f(L1, L2, L3):

## الشريحة 32: التعقيد الأُسّي

- دوال ذاتية فيها أكثر من استدعاء ذاتي واحد لكل حجم من أحجام المسألة.
  - فيبوناتشي.
- كثير من المسائل المهمة هي في جوهرها أُسّية.
- هذا أمر محزن، لأن الكلفة قد تكون عالية.
- سيقودنا هذا إلى التفكير في الحلول التقريبية (approximate solutions) بسرعة أكبر.

| التعبير | القراءة |
|---|---|
| $2^{30}$ | $\approx$ مليون |
| $2^{100}$ | أكثر عدد دورات في حاسب than كل الحواسيب في العالم، تعمل طوال التاريخ المسجَّل، يمكن أن تُنجزه |

## الشريحة 33: تعقيد فيبوناتشي الذاتي

```python
def fib_recur(n):
    """ assumes n an int >= 0 """
    if n == 0:
        return 0
    elif n == 1:
        return 1
    else:
        return fib_recur(n-1) + fib_recur(n-2)
```

الحالة الأسوأ: $\Theta(2^n)$

## الشريحة 35: التعقيد الأُسّي: توليد المجموعات الفرعية

المُدخل هو `[1, 2, 3]`، والمُخرج هو كل توليفات العناصر بكل الأطوال:

```text
[[], [1], [2], [3], [1,2], [1,3], [2,3], [1,2,3]]
```

```python
def gen_subsets(L):
    if len(L) == 0:
        return [[]]
    extra = L[-1:]
    smaller = gen_subsets(L[:-1])
    new = []
    for small in smaller:
        new.append(small+extra)
    return smaller+new
```

def linear_search(L, e):

    for i in range(len(L)):
        if e == L[i]:

def linear_search(L, e):

## الشريحة 56: البحث الخطّي على قائمة مرتّبة

```python
def search(L, e):
    for i in L:
        if i == e:
            return True
        if i > e:
            return False
    return False
```

- يجب أن ننظر فقط حتى نصل إلى عدد أكبر من `e`.
- $\Theta(len(L))$ للحلقة، مضروبة في $\Theta(1)$ لاختبار `i == e` أو `i > e`.
- التعقيد الإجمالي $\Theta(len(L))$، أي $\Theta(n)$ حيث $n = len(L)$.

## الشريحة 57: البحث بالتنصيف عن عنصر في قائمة مرتّبة

1. اختر فهرسًا `i` يقسم القائمة إلى نصفين.
2. اسأل: هل `L[i] == e`؟
3. إن لم يكن كذلك، اسأل: هل `L[i]` أكبر أم أصغر من `e`؟
4. حسب الإجابة، ابحث في النصف الأيسر أو الأيمن من `L` عن `e`.

- هذه نسخة جديدة من «اقسم وانتصر» (divide-and-conquer): إذًا الاستدعاء الذاتي (recursion)!
- نقسم المشكلة إلى نسخ أصغر منها (قائمة أصغر)،إضافةً إلى عمليات بسيطة.
- الإجابة عن النسخة الأصغر هي الإجابة عن النسخة الأصلية.

## الشريحة 58: تحليل تعقيد البحث بالتنصيف

- ننتهي من النظر في القائمة عندما:

$$1 = n/2^i$$

- إذن ما العلاقة بين الطول الأصلي للقائمة وعدد مرّات تقسيمها؟

$$i = \log n$$

- التعقيد هو $\Theta(\log n)$ حيث $n$ هو `len(L)`.

> **ملاحظة المترجم:** الشريحة الأصلية تمثّل المساواة `1 = n/2^i` بخطّ مستقيم على محور لوغاريتمي بحوارَين «…»، وهذه الأشكال لا تنجو من طبقة النصّ؛ أُعيدت المعادلة بصيغتها الرياضية الصحيحة.

## الشريحة 60: البحث بالتنصيف — التنفيذ ١

```python
def bisect_search1(L, e):
    if L == []:
        return False
    elif len(L) == 1:
        return L[0] == e
    else:
        half = len(L)//2
        if L[half] > e:
            return bisect_search1( L[:half], e)
        else:
            return bisect_search1( L[half:], e)
```

## الشريحة 61: تعقيد bisect_search1 (حيث `n` هو `len(L)`)

- $\Theta(\log n)$ استدعاءات بحث بالتنصيف.
- كل استدعاء ذاتي يقتطع المدى المطلوب البحث فيه إلى النصف. أسوأ حالة للوصول إلى مدى حجمه 1 من `n` هي عندما $n/2^k = 1$، أي عندما $k = \log n$، وبهذا نحصل على تعبير يربط `k` بـ `n`.
- $\Theta(n)$ لكل استدعاء بحث للتنصيف بسبب نسخ القائمة.
- $\Theta(\log n) * \Theta(n) = \Theta(n \log n)$ حيث $n = len(L)$.
  - هذه هي الإجابة في هذا الصف.
- إن كنت دقيقًا، ستلاحظ أن القائمة أيضًا تُنصَّف عند كل استدعاء ذاتي، فتصير هنالك سلسلة لا نهائية (لا داعي للقلق بشأنها في هذا الصف).
- $\Theta(n)$ هي حدّ أدقّ (tighter bound) لأن نسخ القائمة يهيمن على $\log n$.

## الشريحة 63: البحث بالتنصيف — التنفيذ ٢

```python
def bisect_search2(L, e):
    def bisect_search_helper(L, e, low, high):
        if high == low:
            return L[low] == e
        mid = (low + high)//2
        if L[mid] == e:
            return True
        elif L[mid] > e:
            if low == mid: #nothing left to search
                return False
            else:
                return bisect_search_helper(L, e, low, mid - 1)
        else:
            return bisect_search_helper(L, e, mid + 1, high)
    if len(L) == 0:
        return False
    else:
        return bisect_search_helper(L, e, 0, len(L) - 1)
```

## الشريحة 64: تعقيد bisect_search2 ودالة المساعِد (حيث `n` هو `len(L)`)

- $\Theta(\log n)$ استدعاءات بحث بالتنصيف.
- كل استدعاء ذاتي يقتطع المدى المطلوب البحث فيه إلى النصف. أسوأ حالة للوصول إلى مدى حجمه 1 من `n` هي عندما $n/2^k = 1$، أي عندما $k = \log n$.
- نمرّر القائمة والفهارس كمعاملات. القائمة لا تُنسخ أبدًا، بل تُمرَّر فقط: $\Theta(1)$ عند كل استدعاء ذاتي.
- $\Theta(\log n) * \Theta(1) = \Theta(\log n)$ حيث $n = len(L)$.

## الشريحة 66: البحث في قائمة مرتّبة — حيث `n` هو `len(L)`

- باستخدام البحث الخطّي، البحث عن عنصر هو $\Theta(n)$.
- باستخدام البحث الثنائي، يمكننا البحث عن عنصر في $\Theta(\log n)$ — بافتراض أن القائمة مرتّبة!
- متى يكون من المعقول أن نرتب أولًا ثم نبحث؟

$$SORT + \Theta(\log n) < \Theta(n) \Rightarrow SORT < \Theta(n) - \Theta(\log n)$$

- متى يكون الترتيب أصغر من $\Theta(n)$؟!
  - أبدًا ما دام أنك على الأقل ستحتاج إلى النظر في كل عنصر!

## الشريحة 67: التكلفة المُطفَّرة (Amortized Cost) — حيث `n` هو `len(L)`

- لماذا نرتّب أولًا إذن؟
- رتّب القائمة مرّة واحدة ثم أجرِ عمليات بحث كثيرة.
- نُطفئ (amortize) كلفة الترتيب على عمليات البحث الكثيرة.
- $SORT + K * \Theta(\log n) < K * \Theta(n)$، أي إن كان `K` كبيرًا فإن زمن الترتيب يصبح غير ذي أثر.

> **ملاحظة المترجم:** الكلمة الإنجليزية `Mig` في جملة «رتّب القائمة مرّة واحدة ثمMig كم مرة…» هي خطأ في استخراج نصّ PDF الأصلي (للتجزئة `many`)، وأصلحتها هنا إلى «كثير من المرّات».
