# الفصل 23: الربط البيني مع لغة C

يشرح هذا الفصل كيف يمكن ربط العمليات الأوّلية التي يعرّفها المستخدم، والمكتوبة بلغة C، بشيفرة OCaml واستدعاؤها من دوال OCaml، وكيف يمكن لهذه الدوال المكتوبة بلغة C أن تعود فتنادي شيفرة OCaml.

## 23.1 نظرة عامة ومعلومات الترجمة

### 23.1.1 تعريف العمليات الأوّلية

```text
definition::= ... ∣ external value-name : typexpr = external-declaration external-declaration::= string-literal [ string-literal [ string-literal ] ]
```

تُعرَّف العمليات الأوّلية التي يكتبها المستخدم في ملف تنفيذ أو في تعبير وحدة من الشكل `struct`…`end` باستعمال الكلمة المفتاحية `external`:

```text
        external name : type = C-function-name
```

يعرّف هذا السطر القيمة المسماة *name* على أنها دالة من النوع *type* تُنفَّذ باستدعاء دالة C المعطاة. وعلى سبيل المثال، هكذا تُعرَّف العملية الأوّلية `seek_in` في وحدة المكتبة القياسية `Stdlib`:

```text
        external seek_in : in_channel -> int -> unit = "caml_ml_seek_in"
```

العمليات الأوّلية ذات الوسائط المتعدّدة مُكَرْيَنة دائمًا. وليس من الضروري أن تحمل دالة C الاسم نفسه الذي تحمله دالة ML.

ويمكن تحديد الدوال الخارجية المعرَّفة بهذه الطريقة في ملفات الواجهة أو في توقيعات `sig`…`end`، إمّا كقيم عادية

```text
        val name : type
```

فنُخفي بذلك تنفيذها كدوال C، وإمّا صراحةً كدوال خارجية «ظاهرة»

```text
        external name : type = C-function-name
```

الصيغة الأخيرة أكفأ قليلًا، لأنها تتيح لعملاء الوحدة استدعاء دالة C مباشرة بدلًا من المرور عبر دالة OCaml المقابلة. في المقابل، لا ينبغي استعمالها في وحدات المكتبات إذا كانت لها آثار جانبية على المستوى الأعلى، لأن هذا الاستدعاء المباشر يتعارض مع خوارزمية الرابط التي تحذف الوحدات غير المستعملة من المكتبات عند الربط.

تُحدَّد رتبة العملية الأوّلية (أي عدد وسائطها) تلقائيًا من نوعها في OCaml في تعريف `external`، عن طريق عدّ عدد أسهم الدوال في النوع. فمثلًا رتبة `seek_in` أعلاه هي 2، وتُستدعى دالة C المسماة `caml_ml_seek_in` بوسيطين. وعلى المنوال نفسه،

```text
    external seek_in_pair: in_channel * int -> unit = "caml_ml_seek_in_pair"
```

رتبتها 1، وتتلقّى دالة C المسماة `caml_ml_seek_in_pair` وسيطًا واحدًا (هو زوج من قيم OCaml).

لا تُبسَّط اختصارات الأنواع عند تحديد رتبة العملية الأوّلية. فمثلًا،

```text
        type int_endo = int -> int
        external f : int_endo -> int_endo = "f"
        external g : (int -> int) -> (int -> int) = "f"
```

رتبة `f` هي 1، أما رتبة `g` فهي 2. وهذا يتيح للعملية الأوّلية أن تُعيد قيمة دالية (كما في مثال `f` أعلاه): يكفي أن تتذكّر تسمية نوع الإرجاع الدالي في اختصار نوع.

تقبل اللغة تعريفات خارجية تحمل سلسلة أو سلسلتين إضافيتين من الأعلام إلى جانب اسم دالة C. وهذه الأعلام محجوزة لتنفيذ المكتبة القياسية.

### 23.1.2 تنفيذ العمليات الأوّلية

العمليات الأوّلية التي يكتبها المستخدم ورتبتها *n* ≤ 5 تُنفَّذ بدوال C تأخذ *n* وسيطًا من النوع `value` وتُعيد نتيجة من النوع `value`. والنوع `value` هو نوع تمثيلات قيم OCaml. وهو يرمّز كائنات من أنواع أساسية عدة (الأعداد الصحيحة، وأعداد الفاصلة العائمة، والسلاسل، …) فضلًا عن بنى بيانات OCaml. وسيُوصف النوع `value` وما يرتبط به من دوال تحويل ووحدات ماكرو بالتفصيل أدناه. فمثلًا، هذا هو تعريف دالة C التي تنفّذ العملية الأوّلية `In_channel.input`، وهي تأخذ 4 وسائط:

```text
CAMLprim value input(value channel, value buffer, value offset, value length)
{
  ...
}
```

عندما تُطبَّق الدالة الأوّلية في برنامج OCaml، تُستدعى دالة C بقيم التعابير التي طُبِّقت عليها العملية الأوّلية كوسائط. وتُعاد القيمة التي تُرجعها الدالة إلى برنامج OCaml كنتيجة لتطبيق الدالة.

أما العمليات الأوّلية التي يكتبها المستخدم ورتبتها أكبر من 5 فينبغي تنفيذها بدالتَي C. الدالة الأولى، التي تُستعمل مع مترجم الشيفرة البايتية `ocamlc`، تتلقّى وسيطين: مؤشرًا إلى مصفوفة من قيم OCaml (قيم الوسائط)، وعددًا صحيحًا هو عدد الوسائط المقدَّمة. والدالة الأخرى، التي تُستعمل مع مترجم الشيفرة الأصلية `ocamlopt`، تأخذ وسائطها مباشرة. فمثلًا، هاتان هما دالتا C الخاصتان بالعملية الأوّلية `Nat.add_nat` ذات الوسائط السبعة:

```text
CAMLprim value add_nat_native(value nat1, value ofs1, value len1,
                              value nat2, value ofs2, value len2,
                              value carry_in)
{
  ...
}
CAMLprim value add_nat_bytecode(value * argv, int argn)
{
  return add_nat_native(argv[0], argv[1], argv[2], argv[3],
                        argv[4], argv[5], argv[6]);
}
```

ويجب إعطاء اسمَي دالتَي C في تعريف العملية الأوّلية كما يلي:

```text
        external name : type =
                 bytecode-C-function-name native-code-C-function-name
```

فمثلًا، في حالة `add_nat`، يكون التعريف كالتالي:

```text
        external add_nat: nat -> int -> int -> nat -> int -> int -> int -> int
                        = "add_nat_bytecode" "add_nat_native"
```

تنفيذ عملية أوّلية يكتبها المستخدم هو في الحقيقة مهمتان منفصلتان: فمن جهة، فكّ ترميز الوسائط لاستخراج قيم C من قيم OCaml المعطاة، وترميز قيمة الإرجاع على هيئة قيمة OCaml؛ ومن جهة أخرى، حساب النتيجة فعليًا انطلاقًا من الوسائط. وفيما عدا العمليات الأوّلية البسيطة جدًا، يُستحسن غالبًا أن تكون هناك دالتا C متمايزتان للقيام بهاتين المهمتين. فالدالة الأولى تنفّذ العملية الأوّلية فعليًا، فتأخذ قيم C أصلية وسائطَ وتُعيد قيمة C أصلية. والدالة الثانية، التي تُسمّى غالبًا «شيفرة الوصلة»، هي غلاف بسيط حول الدالة الأولى يحوّل وسائطها من قيم OCaml إلى قيم C، ويستدعي الدالة الأولى، ويحوّل قيمة C المُعادة إلى قيمة OCaml. فمثلًا، هذه هي شيفرة الوصلة الخاصة بالعملية الأوّلية `Int64.float_of_bits`:

```text
CAMLprim value caml_int64_float_of_bits(value vi)
{
  return caml_copy_double(caml_int64_float_of_bits_unboxed(Int64_val(vi)));
}
```

(هنا `caml_copy_double` و`Int64_val` دوال تحويل ووحدات ماكرو خاصة بالنوع `value`، وستُوصف لاحقًا. أما الوحدة الماكرو `CAMLprim` فتتوسّع إلى توجيهات المترجم اللازمة لضمان تصدير الدالة وإمكانية الوصول إليها من OCaml.) والعمل الشاق تؤدّيه الدالة `caml_int64_float_of_bits_unboxed`، المعرَّفة كما يلي:

```text
double caml_int64_float_of_bits_unboxed(int64_t i)
{
  ...
}
```

ولكتابة شيفرة C تتعامل مع قيم OCaml، تُوفَّر ملفات التضمين التالية:

| **ملف التضمين** | **ما يوفّره** |
| --- | --- |
| `<caml/mlvalues.h>` | تعريف النوع `value` ووحدات الماكرو الخاصة بالتحويل |
| `<caml/alloc.h>` | دوال التخصيص (لإنشاء كائنات OCaml بنيوية) |
| `<caml/memory.h>` | دوال ووحدات ماكرو متفرّقة متعلقة بالذاكرة (لواجهة جامع القمامة، والتعديل في المكان للبنى، وما إلى ذلك). |
| `<caml/fail.h>` | دوال إطلاق الاستثناءات (انظر القسم 23.4.5) |
| `<caml/callback.h>` | النداء العكسي من C إلى OCaml (انظر القسم 23.7). |
| `<caml/custom.h>` | عمليات على الكتل المخصّصة (انظر القسم 23.9). |
| `<caml/intext.h>` | عمليات لكتابة دوال تسلسل وإلغاء تسلسل يكتبها المستخدم للكتل المخصّصة (انظر القسم 23.9). |
| `<caml/threads.h>` | عمليات للربط البيني في وجود خيوط متعددة (انظر القسم 23.12). |

تقع هذه الملفات في الدليل الفرعي `caml/` من دليل المكتبة القياسية لـ OCaml، وهو الدليل الذي يرجعه الأمر `ocamlc -where` (وهو عادةً `/usr/local/lib/ocaml` أو `/usr/lib/ocaml`).

### 23.1.3 الربط الساكن لشيفرة C بشيفرة OCaml

يتألف نظام تشغيل OCaml من ثلاثة أجزاء رئيسية: مفسّر الشيفرة البايتية، ومدير الذاكرة، ومجموعة دوال C تنفّذ العمليات الأوّلية. وقد وُضعت بعض تعليمات الشيفرة البايتية لاستدعاء دوال C هذه، وتُشار إليها بإزاحتها في جدول الدوال (جدول العمليات الأوّلية).

في النمط الافتراضي، يولّد رابط OCaml شيفرة بايتية لنظام التشغيل القياسي، مع مجموعة قياسية من العمليات الأوّلية. وأي إشارة إلى عملية أوّلية ليست في هذه المجموعة القياسية تؤدي إلى الخطأ «عملية C أوّلية غير متاحة». (إلا إذا كان التحميل الدينامي لمكتبات C مدعومًا – انظر القسم 23.1.4 أدناه.)

في نمط «نظام التشغيل المخصّص»، يمسح رابط OCaml ملفات الكائنات ويحدّد مجموعة العمليات الأوّلية المطلوبة. ثم يبني نظام تشغيل مناسبًا باستدعاء رابط الشيفرة الأصلية بـ:

- جدول العمليات الأوّلية المطلوبة؛

- مكتبة توفّر مفسّر الشيفرة البايتية ومدير الذاكرة والعمليات الأوّلية القياسية؛

- مكتبات وملفات شيفرة كائنات (ملفات `.o`) مذكورة على سطر أوامر رابط OCaml، وتوفّر تنفيذات لعمليات المستخدم الأوّلية.

فتبني هذه الخطوات نظام تشغيل يحوي العمليات الأوّلية المطلوبة. ويولّد رابط OCaml شيفرة بايتية لهذا النظام المخصّص. وتُلحق الشيفرة البايتية بنهاية نظام التشغيل المخصّص، بحيث تُنفَّذ تلقائيًا عند تشغيل ملف الخَرْج (نظام التشغيل المخصّص + الشيفرة البايتية).

وللربط في نمط «نظام التشغيل المخصّص»، نفّذ الأمر `ocamlc` مع:

- الخيار `-custom`؛

- أسماء ملفات كائنات OCaml المطلوبة (ملفات `.cmo` و`.cma`)؛

- أسماء ملفات كائنات C والمكتبات (ملفات `.o` و`.a`) التي تنفّذ العمليات الأوّلية المطلوبة. وفي Unix وWindows، يمكن أيضًا تحديد مكتبة باسم `lib`*name*`.a` (أو `.lib` على التوالي) تقع في أحد أدلة المكتبة القياسية، وذلك بصيغة `-cclib -l`*name*.

وإذا كنت تستعمل مترجم الشيفرة الأصلية `ocamlopt`، فلا حاجة إلى العلم `-custom`، لأن طور الربط الأخير في `ocamlopt` يبني دائمًا ملفًا تنفيذيًا مستقلًا. ولبناء ملف تنفيذي مختلط بين OCaml وC، نفّذ الأمر `ocamlopt` مع:

- أسماء ملفات كائنات OCaml الأصلية المطلوبة (ملفات `.cmx` و`.cmxa`)؛

- أسماء ملفات كائنات C والمكتبات (ملفات `.o` و`.a` و`.so` أو `.dll`) التي تنفّذ العمليات الأوّلية المطلوبة.

وابتداءً من Objective Caml 3.00، أصبح من الممكن تسجيل خيار `-custom` فضلًا عن أسماء مكتبات C في ملف مكتبة OCaml من النوع `.cma` أو `.cmxa`. فمثلًا، اعتبر مكتبة OCaml اسمها `mylib.cma`، بُنيت من ملفَّي كائنات OCaml هما `a.cmo` و`b.cmo`، وهما يشيران إلى شيفرة C في `libmylib.a`. فإذا بُنيت المكتبة كما يلي:

```text
        ocamlc -a -o mylib.cma -custom a.cmo b.cmo -cclib -lmylib
```

أمكن لمستعملي المكتبة أن يربطوا ببساطة مع `mylib.cma`:

```text
        ocamlc -o myprog mylib.cma ...
```

فيضيف النظام تلقائيًا الخيارين `-custom` و`-cclib -lmylib`، محقّقًا الأثر نفسه الذي يحقّقه

```text
        ocamlc -o myprog -custom a.cmo b.cmo ... -cclib -lmylib
```

والبديل هو بالطبع بناء المكتبة دون خيارات إضافية:

```text
        ocamlc -a -o mylib.cma a.cmo b.cmo
```

ثم مطالبة المستعملين بتقديم الخيارين `-custom` و`-cclib -lmylib` بأنفسهم عند الربط:

```text
        ocamlc -o myprog -custom mylib.cma ... -cclib -lmylib
```

غير أن البديل الأول أيسر على المستعملين النهائيين للمكتبة.

### 23.1.4 الربط الدينامي لشيفرة C بشيفرة OCaml

ابتداءً من Objective Caml 3.03، تُوفَّر بدائل للربط الساكن لشيفرة C باستعمال الخيار `-custom`. في هذا النمط، يولّد رابط OCaml ملفًا تنفيذيًا من الشيفرة البايتية الخالصة (دون نظام تشغيل مخصّص مضمَّن فيه) يسجّل ببساطة أسماء المكتبات المحمّلة ديناميًا التي تحوي شيفرة C. ثم يحمّل نظام تشغيل OCaml القياسي `ocamlrun` هذه المكتبات ديناميًا، ويحلّ الإشارات إلى العمليات الأوّلية المطلوبة، قبل تنفيذ الشيفرة البايتية.

هذه الإمكانية متاحة حاليًا على جميع المنصّات التي يدعمها OCaml باستثناء Cygwin 64 bits.

ولربط شيفرة C بشيفرة OCaml ديناميًا، يجب أولًا ترجمة شيفرة C إلى مكتبة مشتركة (في Unix) أو DLL (في Windows). ويشمل ذلك 1- ترجمة ملفات C بأعلام مترجم C المناسبة لإنتاج شيفرة مستقلة عن الموضع (عندما يتطلب نظام التشغيل ذلك)، و2- بناء مكتبة مشتركة من ملفات الكائنات الناتجة. ويجب تثبيت ملف المكتبة المشتركة أو DLL الناتج في موضع يستطيع `ocamlrun` أن يجده لاحقًا عند بدء تشغيل البرنامج (انظر القسم 15.3). وأخيرًا (الخطوة 3)، نفّذ الأمر `ocamlc` مع

- أسماء ملفات كائنات OCaml المطلوبة (ملفات `.cmo` و`.cma`)؛

- أسماء مكتبات C المشتركة (ملفات `.so` أو `.dll`) التي تنفّذ العمليات الأوّلية المطلوبة. وفي Unix وWindows، يمكن أيضًا تحديد مكتبة باسم `dll`*name*`.so` (أو `.dll` على التوالي) تقع في أحد أدلة المكتبة القياسية، وذلك بصيغة `-dllib -l`*name*.

و*لا* تضبط العلم `-custom`، وإلا عدت إلى الربط الساكن كما وُصف في القسم 23.1.3. والأداة `ocamlmklib` (انظر القسم 23.14) تؤتمت الخطوتين 2 و3.

وكما في حالة الربط الساكن، من الممكن (ويُستحسن) تسجيل أسماء مكتبات C في أرشيف مكتبة OCaml من النوع `.cma`. اعتبر مرة أخرى مكتبة OCaml اسمها `mylib.cma`، بُنيت من ملفَّي كائنات OCaml هما `a.cmo` و`b.cmo`، وهما يشيران إلى شيفرة C في `dllmylib.so`. فإذا بُنيت المكتبة كما يلي:

```text
        ocamlc -a -o mylib.cma a.cmo b.cmo -dllib -lmylib
```

أمكن لمستعملي المكتبة أن يربطوا ببساطة مع `mylib.cma`:

```text
        ocamlc -o myprog mylib.cma ...
```

فيضيف النظام تلقائيًا الخيار `-dllib -lmylib`، محقّقًا الأثر نفسه الذي يحقّقه

```text
        ocamlc -o myprog a.cmo b.cmo ... -dllib -lmylib
```

وبهذه الآلية، لا يحتاج مستعملو المكتبة `mylib.cma` إلى معرفة أنها تشير إلى شيفرة C، ولا إلى معرفة ما إذا كانت شيفرة C هذه يجب أن تُربط ساكنًا (باستعمال `-custom`) أو ديناميًا.

### 23.1.5 الاختيار بين الربط الساكن والربط الدينامي

بعد وصف طريقتين مختلفتين لربط شيفرة C بشيفرة OCaml، نستعرض الآن محاسن كل منهما ومساوئها، لمساعدة مطوّري مكتبات OCaml/C المختلطة على الاختيار.

الميزة الأساسية للربط الدينامي هي أنه يحافظ على استقلال الملفات التنفيذية للشيفرة البايتية عن المنصّة. أي إن الملف التنفيذي للشيفرة البايتية لا يحوي شيفرة آلة، ويمكن لذلك أن يُترجم على المنصّة *A* ويُنفَّذ على منصّات أخرى *B* و*C* و…، ما دامت المكتبات المشتركة المطلوبة متاحة على جميع هذه المنصّات. في المقابل، فإن الملفات التنفيذية التي يولّدها `ocamlc -custom` لا تعمل إلا على المنصّة التي أُنشئت عليها، لأنها تحمل نظام تشغيل مخصّصًا مفصّلًا لتلك المنصّة. وفضلًا عن ذلك، ينتج عن الربط الدينامي ملفات تنفيذية أصغر.

وثمة ميزة أخرى للربط الدينامي، هي أن المستعملين النهائيين للمكتبة لا يحتاجون إلى مترجم C ولا إلى رابط C ولا إلى مكتبات تشغيل C مثبَّتة على أجهزتهم. وهذا ليس أمرًا ذا بال في Unix وCygwin، لكن كثيرًا من مستعملي Windows يتحرّجون من تثبيت Microsoft Visual C لمجرد القدرة على تنفيذ `ocamlc -custom`.

وللربط الدينامي مساوئ اثنان. الأول أن الملف التنفيذي الناتج ليس مستقلًا: فهو يحتاج إلى المكتبات المشتركة، وإلى `ocamlrun`، مثبَّتين على الجهاز الذي ينفّذ الشيفرة. فإن أردت توزيع ملف تنفيذي مستقل، فالأفضل ربطه ساكنًا باستعمال `ocamlc -custom -ccopt -static` أو `ocamlopt -ccopt -static`. كما يثير الربط الدينامي مشكلة «جحيم DLL»: إذ يجب الحرص على أن تُوجد النسخ الصحيحة من المكتبات المشتركة عند بدء التشغيل.

والعيب الثاني للربط الدينامي أنه يعقّد بناء المكتبة. فأعلام مترجم C ورابطه اللازمة للترجمة إلى شيفرة مستقلة عن الموضع ولبناء مكتبة مشتركة تتفاوت تفاوتًا كبيرًا بين أنظمة Unix المختلفة. كذلك، الربط الدينامي غير مدعوم على جميع أنظمة Unix، ما يستلزم حالة ارتداد إلى الربط الساكن في ملف Makefile الخاص بالمكتبة. ويحاول الأمر `ocamlmklib` (انظر القسم 23.14) إخفاء بعض هذه التبعيات النظامية.

وخلاصة القول: يُوصى بشدة بالربط الدينامي في المنفذ الأصلي إلى Windows، لأنه لا يطرح مشكلات قابلية نقل وهو أيسر بكثير على المستعملين النهائيين. أما في Unix، فينبغي النظر في الربط الدينامي للمكتبات الناضجة كثيرة الاستعمال، لأنه يعزّز استقلال الملفات التنفيذية للشيفرة البايتية عن المنصّة. أما المكتبات الجديدة أو قليلة الاستعمال، فالربط الساكن أبسط بكثير في إعداده على نحو قابل للنقل.

### 23.1.6 بناء أنظمة تشغيل مخصّصة مستقلة

يُزعج أحيانًا بناء نظام تشغيل مخصّص في كل مرة تُربط فيها شيفرة OCaml بمكتبات C، كما يفعل `ocamlc -custom`. فأولًا، بناء نظام التشغيل بطيء على بعض الأنظمة (التي تكون فيها الروابط سيئة أو أنظمة الملفات البعيدة بطيئة)؛ وثانيًا، يُفقد استقلال ملفات الشيفرة البايتية عن المنصّة، ما يفرض تنفيذ ربط واحد بـ `ocamlc -custom` لكل منصّة معنيّة.

والبديل عن `ocamlc -custom` هو بناء نظام تشغيل مخصّص يدمج مكتبات C المطلوبة على نحو منفصل، ثم توليد ملفات تنفيذية «خالصة» من الشيفرة البايتية (لا تحوي نظام تشغيلها الخاص) يمكنها العمل على نظام التشغيل المخصّص هذا. ويتحقّق ذلك بالعلمين `-make-runtime` و`-use-runtime` في `ocamlc`. فمثلًا، لبناء نظام تشغيل مخصّص يدمج الأجزاء المكتوبة بلغة C من مكتبتَي «Unix» و«Threads»، نفّذ:

```text
        ocamlc -make-runtime -o /home/me/ocamlunixrun unix.cma threads.cma
```

ولتوليد ملف تنفيذي من الشيفرة البايتية يعمل على نظام التشغيل هذا، نفّذ:

```text
        ocamlc -use-runtime /home/me/ocamlunixrun -o myprog \
                unix.cma threads.cma your .cmo and .cma files
```

وبعد ذلك يمكن تشغيل الملف التنفيذي `myprog` كالمعتاد: `myprog` *args* أو `/home/me/ocamlunixrun myprog` *args*.

لاحظ أنه يجب تقديم مكتبتَي الشيفرة البايتية `unix.cma` و`threads.cma` مرتين: عند بناء نظام التشغيل (حتى يعرف `ocamlc` العمليات الأوّلية المكتوبة بلغة C المطلوبة) وأيضًا عند بناء الملف التنفيذي من الشيفرة البايتية (حتى تُربط الشيفرة البايتية من `unix.cma` و`threads.cma` بالفعل).

## 23.2 نوع القيمة

تُمثَّل جميع كائنات OCaml بالنوع `value` في C، المعرَّف في ملف التضمين `<caml/mlvalues.h>`، مع وحدات ماكرو للتعامل مع قيم ذلك النوع. وكائن النوع `value` هو إمّا:

- عدد صحيح غير مُعلَّب؛

- أو مؤشر إلى كتلة داخل الكومة، مخصَّصة بإحدى دوال `caml_alloc_*` الموصوفة في القسم 23.4.4.

### 23.2.1 قيم الأعداد الصحيحة

تشفّر قيم الأعداد الصحيحة أعدادًا صحيحة موقَّعة من 63 بتًا (ومن 31 بتًا على المعماريات ذات 32 بتًا). وهي غير معلَّبة (غير مخصَّصة).

### 23.2.2 الكتل

تُجمَع كتل الكومة ضمن القمامة، ولذلك تخضع لقيود بنيوية صارمة. وكل كتلة تحوي ترويسة تحوي حجم الكتلة (بكلمات) ووسم الكتلة. والوسم يحكم كيفية بناء محتويات الكتل. فالوسم الأصغر من `No_scan_tag` يدلّ على كتلة بنيوية تحوي قيمًا سليمة البنية، ويجتازها جامع القمامة تكراريًا. والوسم الأكبر من `No_scan_tag` أو المساوي له يدلّ على كتلة خام لا يمسح جامع القمامة محتوياتها. ولمصلحة العمليات الأوّلية المتعدّدة الأشكال على نحو مخصّص، مثل المساواة والإدخال والإخراج البنيوي، تُصنَّف الكتل البنيوية والخام أيضًا بحسب وسومها كما يلي:

| **الوسم** | **محتويات الكتلة** |
| --- | --- |
| من 0 إلى `No_scan_tag`−1 | كتلة بنيوية (مصفوفة من كائنات OCaml). وكل حقل فيها قيمة من النوع `value`. |
| `Closure_tag` | إغلاق يمثّل قيمة دالية. الكلمة الأولى مؤشر إلى قطعة شيفرة، والكلمات الباقية قيم من النوع `value` تحوي البيئة. |
| `String_tag` | سلسلة محارف أو متتالية بايتية. |
| `Double_tag` | عدد ذو فاصلة عائمة بدقة مضاعفة. |
| `Double_array_tag` | مصفوفة أو سجل من أعداد ذات فاصلة عائمة بدقة مضاعفة. |
| `Abstract_tag` | كتلة تمثّل نوع بيانات مجرّدًا. |
| `Custom_tag` | كتلة تمثّل نوع بيانات مجرّدًا مع دوال إنهاء ومقارنة وتجزئة وتسلسل وإلغاء تسلسل يكتبها المستخدم. |

### 23.2.3 المؤشرات خارج الكومة

في النسخ الأقدم من OCaml، كان من الممكن استعمال مؤشرات موافقة للكلمات إلى عناوين خارج الكومة بوصفها قيم OCaml، بمجرد تحويل المؤشر إلى النوع `value`. وهذا الاستعمال لم يبق مدعومًا منذ OCaml 5.0.

والطريقة الصحيحة للتعامل مع مؤشرات إلى كتل خارج الكومة من OCaml هي تخزين هذه المؤشرات في كتل OCaml ذات وسم `Abstract_tag` أو `Custom_tag`، ثم استعمال الكتل بوصفها قيم OCaml.

وفيما يلي مثال على تغليف مؤشرات خارج الكومة من النوع `ty *` في C داخل كتل ذات وسم `Abstract_tag`. ويعطي القسم 23.6 مثالًا أكمل يستعمل كتلًا ذات وسم `Custom_tag`.

```text
/* Create an OCaml value encapsulating the pointer p */
static value val_of_typtr(ty * p)
{
  value v = caml_alloc(1, Abstract_tag);
  *((ty **) Data_abstract_val(v)) = p;
  return v;
}

/* Extract the pointer encapsulated in the given OCaml value */
static ty * typtr_of_val(value v)
{
  return *((ty **) Data_abstract_val(v));
}
```

وبديلًا من ذلك، يمكن معاملة المؤشرات خارج الكومة كأعداد صحيحة «أصلية»، أي أعداد صحيحة مُعلَّبة من 32 بتًا على منصّة 32 بتًا ومن 64 بتًا على منصّة 64 بتًا.

```text
/* Create an OCaml value encapsulating the pointer p */
static value val_of_typtr(ty * p)
{
  return caml_copy_nativeint((intnat) p);
}

/* Extract the pointer encapsulated in the given OCaml value */
static ty * typtr_of_val(value v)
{
  return (ty *) Nativeint_val(v);
}
```

أما المؤشرات المحاذاة لمضاعفات 2 على الأقل (أي التي يُضمن أن بتّها الأدنى صفر)، فلدينا لها تمثيل صالح آخر بوصفها عددًا صحيحًا موسومًا في OCaml.

```text
/* Create an OCaml value encapsulating the pointer p */
static value val_of_typtr(ty * p)
{
  assert (((uintptr_t) p & 1) == 0);  /* check correct alignment */
  return (value) p | 1;
}

/* Extract the pointer encapsulated in the given OCaml value */
static ty * typtr_of_val(value v)
{
  return (ty *) (v & ~1);
}
```
## 23.3 تمثيل أنواع بيانات OCaml

يصف هذا القسم كيف ترمَّز أنواع بيانات OCaml في النوع `value`.

### 23.3.1 الأنواع الذرّية

| **نوع OCaml** | **الترميز** |
| --- | --- |
| `int` | قيم أعداد صحيحة غير معلَّبة. |
| `char` | قيم أعداد صحيحة غير معلَّبة (رمز ASCII). |
| `float` | كتل ذات وسم `Double_tag`. |
| `bytes` | كتل ذات وسم `String_tag`. |
| `string` | كتل ذات وسم `String_tag`. |
| `int32` | كتل ذات وسم `Custom_tag`. |
| `int64` | كتل ذات وسم `Custom_tag`. |
| `nativeint` | كتل ذات وسم `Custom_tag`. |

### 23.3.2 الصفوف والسجلات

تُمثَّل الصفوف بمؤشرات إلى كتل ذات وسم 0.

وتُمثَّل السجلات أيضًا بكتل موسومة بالوسم صفر. وترتيب الوسوم في تعريف نوع السجل هو الذي يحدّد تخطيط حقول السجل: فالقيمة المرتبطة بالوسم المعرَّف أولًا تُخزَّن في الحقل 0 من الكتلة، والقيمة المرتبطة بالوسم الثاني تذهب إلى الحقل 1، وهكذا.

وكتحسين، تُمثَّل السجلات التي تكون جميع حقولها من النوع الساكن `float` كمصفوفات من أعداد ذات فاصلة عائمة، بوسم `Double_array_tag`. (انظر القسم التالي عن المصفوفات.)

وكتحسين آخر، تُمثَّل أنواع السجلات القابلة لإزالة التعلّب تمثيلًا خاصًا؛ وأنواع السجلات القابلة لإزالة التعلّب هي أنواع السجلات غير القابلة للتغيير التي لها حقل واحد فقط. ويُمثَّل النوع القابل لإزالة التعلّب بإحدى طريقتين: مُعلَّبًا أو غير مُعلَّب. أما أنواع السجلات المُعلَّبة فتُمثَّل كما وُصف أعلاه (بكتلة ذات وسم 0 أو `Double_array_tag`). وأما نوع السجل غير المُعلَّب فيُمثَّل مباشرة بقيمة حقله (أي لا توجد كتلة تمثّل السجل نفسه).

ويُختار التمثيل وفق ما يلي، بترتيب أولوية تنازلي:

- سمة (`[@@boxed]` أو `[@@unboxed]`) على تعريف النوع.

- خيار مترجم (`-unboxed-types` أو `-no-unboxed-types`).

- التمثيل الافتراضي. وفي النسخة الحالية من OCaml، الافتراضي هو التمثيل المُعلَّب.

### 23.3.3 المصفوفات

تُمثَّل مصفوفات الأعداد الصحيحة والمؤشرات مثل الصفوف والسجلات، أي كمؤشرات إلى كتل موسومة بالوسم 0. ويُوصل إليها بوحدة الماكرو `Field` للقراءة وبالدالة `caml_modify` للكتابة.

وقيم النوع `floatarray` (كما تتعامل معها الوحدة `Float.Array`)، فضلًا عن السجلات التي لا يحوي تعريفها إلا حقولًا من نوع `float`، تستعمل تمثيلًا غير معلَّب كفؤًا: كتلًا ذات وسم `Double_array_tag` تتألف محتوياتها من قيم مضاعفة خامة ليست بحد ذاتها قيم OCaml صالحة. وينبغي الوصول إليها باستعمال وحدتَي الماكرو `Double_flat_field` و`Store_double_flat_field`.

وأخيرًا، قد تستعمل مصفوفات النوع `float array` التمثيل المُعلَّب أو غير المُعلَّب بحسب إعداد المترجم. وهي تستعمل حاليًا التمثيل غير المُعلَّب افتراضيًا، لكن يمكن جعلها تستعمل التمثيل المُعلَّب بتمرير العلم `--disable-flat-float-array` إلى سكربت «configure». وينبغي الوصول إليها باستعمال وحدتَي الماكرو `Double_array_field` و`Store_double_array_field`، وهما تعملان على نحو صحيح في النمطين كليهما.

### 23.3.4 أنواع البيانات الملموسة

تُمثَّل الحدود المبنيّة إمّا بأعداد صحيحة غير معلَّبة (للبواني الثابتة) وإمّا بكتل يشفّر وسمها الباني (للبواني غير الثابتة). وتُرقَّم البواني الثابتة والبواني غير الثابتة لنوع ملموس معيّن ترقيمًا منفصلًا يبدأ من 0، بحسب ترتيب ظهورها في تعريف النوع الملموس. ويُمثَّل الباني الثابت بعدد صحيح غير معلَّب يساوي رقم بانيه. ويُمثَّل الباني غير الثابت المعرَّف بـ *n* وسيطًا بكتلة حجمها *n*، موسومة برقم الباني؛ وتحوي الحقول *n* وسائطه. مثال:

| **الحد المبنيّ** | **التمثيل** |
| --- | --- |
| `()` | `Val_int(0)` |
| `false` | `Val_int(0)` |
| `true` | `Val_int(1)` |
| `[]` | `Val_int(0)` |
| `h::t` | كتلة حجمها 2 ووسمها 0؛ الحقل الأول يحوي `h` والثاني `t`. |

وتسهيلًا، يعرّف الملف `<caml/mlvalues.h>` وحدات الماكرو `Val_unit` و`Val_false` و`Val_true` و`Val_emptylist` للإشارة إلى `()` و`false` و`true` و`[]`.

ويوضّح المثال التالي إسناد الأعداد الصحيحة ووسوم الكتل إلى البواني:

```text
type t =
  | A             (* First constant constructor -> integer "Val_int(0)" *)
  | B of string   (* First non-constant constructor -> block with tag 0 *)
  | C             (* Second constant constructor -> integer "Val_int(1)" *)
  | D of bool     (* Second non-constant constructor -> block with tag 1 *)
  | E of t * t    (* Third non-constant constructor -> block with tag 2 *)
```

وكتحسين، تُمثَّل أنواع البيانات الملموسة القابلة لإزالة التعلّب تمثيلًا خاصًا؛ ونوع البيانات الملموس يكون قابلًا لإزالة التعلّب إذا كان له بانٍ واحد بعينه، وكان لهذا الباني وسيط واحد بعينه. وتُمثَّل أنواع البيانات الملموسة القابلة لإزالة التعلّب بالطريقتين نفسهما اللتين تُمثَّل بهما أنواع السجلات القابلة لإزالة التعلّب: انظر الوصف في القسم 23.3.2.

### 23.3.5 الكائنات

تُمثَّل الكائنات بكتل ذات وسم `Object_tag`. والحقل الأول من الكتلة يشير إلى صنف الكائن ومجموعة دواله المرتبطة به، وذلك بصيغة لا يمكن استغلالها من C بسهولة. والحقل الثاني يحوي معرّفًا فريدًا للكائن، يُستعمل في المقارنات. أما الحقول الباقية من الكائن فتحوي قيم متغيّرات النسخة الخاصة به. ومن غير الآمن الوصول مباشرة إلى متغيّرات النسخة، لأن نظام الأنواع لا يقدّم أي ضمانة بشأن متغيّرات النسخة التي يحويها كائن.

ويمكن استخراج دالة عمومية من كائن باستعمال دالة C المسماة `caml_get_public_method` (المعرَّفة في `<caml/mlvalues.h>`.) وبما أن وسوم الدوال العمومية تُجزَّأ بالطريقة نفسها التي تُجزَّأ بها وسوم المتغيّرات، وبما أن الدوال هي دوال تأخذ الذات وسيطًا أول، فإنك إن أردت تنفيذ استدعاء الدالة `foo#bar` من جهة C، فينبغي أن تستدعي:

```text
  callback(caml_get_public_method(foo, caml_hash_variant("bar")), foo);
```

### 23.3.6 المتغيّرات متعدّدة الأشكال

مثل الحدود المبنيّة، تُمثَّل قيم المتغيّرات متعدّدة الأشكال إمّا كأعداد صحيحة (للمتغيّرات متعدّدة الأشكال بلا وسيط)، وإمّا ككتل (للمتغيّرات متعدّدة الأشكال بوسيط). وبخلاف الحدود المبنيّة، لا تُرقَّم بواني المتغيّرات بدءًا من 0، بل تُعرَّف بقيمة تجزئة (عدد صحيح في OCaml) تحسبها دالة C المسماة `caml_hash_variant` (المعرَّفة في `<caml/mlvalues.h>`): فقيمة التجزئة لباني متغيّر اسمه مثلًا `VConstr` هي `caml_hash_variant("VConstr")`.

وتُمثَّل قيمة المتغيّر `` `VConstr `` بـ `caml_hash_variant("VConstr")`. أما قيمة المتغيّر `` `VConstr(`*v*`) `` فتُمثَّل بكتلة حجمها 2 ووسمها 0، يحوي حقلها رقم 0 القيمة `caml_hash_variant("VConstr")` ويحوي حقلها رقم 1 القيمة *v*.

وبخلاف القيم المبنيّة، لا تُسطَّح قيم المتغيّرات متعدّدة الأشكال التي تأخذ عدة وسائط. أي إن `` `VConstr(`*v*`,`*w*`) `` تُمثَّل بكتلة حجمها 2 يحوي حقلها رقم 1 تمثيل الزوج `(`*v*`,`*w*`)`، لا بكتلة حجمها 3 تحوي *v* و*w* في الحقلين 1 و2.

## 23.4 عمليات على القيم

### 23.4.1 فحوص النوع

- `Is_long(`*v*`)` صحيحة إذا كانت القيمة *v* عددًا صحيحًا مباشرًا، وخاطئة فيما عدا ذلك

- `Is_block(`*v*`)` صحيحة إذا كانت القيمة *v* مؤشرًا إلى كتلة، وخاطئة إذا كانت عددًا صحيحًا مباشرًا.

- `Is_none(`*v*`)` صحيحة إذا كانت القيمة *v* هي `None`.

- `Is_some(`*v*`)` صحيحة إذا كانت القيمة *v* (المفترض أنها من نوع option) تقابل الباني `Some`.

### 23.4.2 عمليات على الأعداد الصحيحة

يعرّف الملف `<caml/config.h>` نوعًا صحيحًا في C اسمه `intnat` يمثّل أعدادًا صحيحة موقَّعة من 64 بتًا (ومن 32 بتًا على المعماريات ذات 32 بتًا). ويُستعمل هذا النوع لتمثيل العدد الصحيح الذي تشفّره قيمة `value` تقابل عددًا صحيحًا غير معلَّب، دون اقتطاع.

- `Val_long(`*n*`)` ترجع القيمة التي تشفّر العدد `intnat` المسمّى *n*.

- `Long_val(`*v*`)` ترجع العدد `intnat` المشفَّر في القيمة *v*.

- `Val_int(`*i*`)` ترجع القيمة التي تشفّر العدد `int` المسمّى *i*.

- `Int_val(`*v*`)` ترجع العدد `int` المشفَّر في القيمة *v*. لاحظ أن هذه العملية قد ينتج عنها قيمة مقتطعة، لأن `int` عرضه 32 بتًا على المعماريات ذات 64 بتًا.

- `Val_bool(`*x*`)` ترجع القيمة المنطقية في OCaml الممثّلة لقيمة الصدق للعدد الصحيح *x* في C.

- `Bool_val(`*v*`)` ترجع 0 إذا كانت *v* هي القيمة المنطقية `false` في OCaml، و1 إذا كانت `true`.

- `Val_true` و`Val_false` تمثّلان القيمتين المنطقيتين `true` و`false` في OCaml.

- `Val_emptylist` تمثّل القائمة الفارغة.

- `Val_none` تمثّل القيمة `None` في OCaml.

### 23.4.3 الوصول إلى الكتل

- `Wosize_val(`*v*`)` ترجع حجم الكتلة *v* بالكلمات، دون احتساب الترويسة.

- `Tag_val(`*v*`)` ترجع وسم الكتلة *v*.

- `Field(`*v*`,`*n*`)` ترجع القيمة التي يحويها الحقل رقم *n* من الكتلة البنيوية *v*. والحقول مرقَّمة من 0 إلى `Wosize_val`(*v*)−1.

- `Store_field(`*b*`,`*n*`,`*v*`)` تخزّن القيمة *v* في الحقل رقم *n* من القيمة *b*، التي يجب أن تكون كتلة بنيوية.

- `Code_val(`*v*`)` ترجع جزء الشيفرة من الإغلاق *v*.

- `caml_string_length(`*v*`)` ترجع طول السلسلة أو المتتالية البايتية *v* (عدد بايتاتها).

- `Byte(`*v*`,`*n*`)` ترجع البايت رقم *n* من السلسلة أو المتتالية البايتية *v*، بنوع `char`. والبايتات مرقَّمة من 0 إلى `string_length`(*v*)−1.

- `Byte_u(`*v*`,`*n*`)` ترجع البايت رقم *n* من السلسلة أو المتتالية البايتية *v*، بنوع `unsigned char`. والبايتات مرقَّمة من 0 إلى `string_length`(*v*)−1.

- `String_val(`*v*`)` ترجع مؤشرًا إلى البايت الأول من السلسلة *v*، بنوع `const char *`. وهذا المؤشر سلسلة C صالحة: فهناك بايت صفري بعد البايت الأخير في السلسلة. غير أن سلاسل OCaml قد تحوي بايتات صفرية مضمَّنة، وهي تُربك الدوال المعتادة في C الخاصة بالسلاسل. والدالة `caml_string_is_c_safe(`*v*`)` ترجع `true` إذا كانت سلسلة OCaml المسمّاة *v* لا تحوي أي بايت صفري مضمَّن.

- `Bytes_val(`*v*`)` ترجع مؤشرًا إلى البايت الأول من المتتالية البايتية *v*، بنوع `unsigned char *`.

- `Double_val(`*v*`)` ترجع عدد الفاصلة العائمة الذي تحويه القيمة *v*، بنوع `double`.

- `Double_array_field(`*v*`,`*n*`)` ترجع العنصر رقم *n* من المصفوفة `float array` المسمّاة *v*.

- `Store_double_array_field(`*v*`,`*n*`,`*d*`)` تخزّن عدد الفاصلة العائمة ذا الدقة المضاعفة *d* في العنصر رقم *n* من المصفوفة `float array` المسمّاة *v*.

- `Double_flat_field(`*v*`,`*n*`)` ترجع العنصر رقم *n* من القيمة `floatarray` أو سجل العوائم *v* (كتلة غير معلَّبة موسومة بـ `Double_array_tag`).

- `Store_double_flat_field(`*v*`,`*n*`,`*d*`)` تخزّن عدد الفاصلة العائمة ذا الدقة المضاعفة *d* في العنصر رقم *n* من القيمة `floatarray` أو سجل العوائم *v*.

- `Data_custom_val(`*v*`)` ترجع مؤشرًا إلى جزء البيانات من الكتلة المخصّصة *v*. وهذا المؤشر نوعه `void *` ويجب تحويله إلى نوع البيانات التي تحويها الكتلة المخصّصة.

- `Int32_val(`*v*`)` ترجع العدد الصحيح ذا 32 بتًا الذي تحويه القيمة `int32` المسمّاة *v*.

- `Int64_val(`*v*`)` ترجع العدد الصحيح ذا 64 بتًا الذي تحويه القيمة `int64` المسمّاة *v*.

- `Nativeint_val(`*v*`)` ترجع العدد الصحيح الطويل الذي تحويه القيمة `nativeint` المسمّاة *v*.

- `caml_field_unboxed(`*v*`)` ترجع قيمة حقل القيمة *v* من أي نوع غير معلَّب (سجل أو نوع بيانات ملموس).

- `caml_field_boxed(`*v*`)` ترجع قيمة حقل القيمة *v* من أي نوع معلَّب (سجل أو نوع بيانات ملموس).

- `caml_field_unboxable(`*v*`)` تستدعي `caml_field_unboxed` أو `caml_field_boxed` بحسب التمثيل الافتراضي للأنواع القابلة لإزالة التعلّب في النسخة الحالية من OCaml.

- `Some_val(`*v*`)` ترجع الوسيط *x* للقيمة *v* من الشكل `Some(`*x*`)`.

التعابير `Field(`*v*`,`*n*`)` و`Byte(`*v*`,`*n*`)` و`Byte_u(`*v*`,`*n*`)` قيم يسارية صالحة. ومن ثم يمكن الإسناد إليها، فينتج عن ذلك تعديل في المكان للقيمة *v*. ويجب أن يتمّ الإسناد المباشر إلى `Field(`*v*`,`*n*`)` بحرص لتجنّب إرباك جامع القمامة (انظر أدناه).

### 23.4.4 تخصيص الكتل

#### الواجهة البسيطة

- `Atom(`*t*`)` ترجع «ذرّة» (كتلة حجمها صفر) بوسم *t*. والكتل ذات الحجم صفر مخصَّصة مسبقًا خارج الكومة. ومن غير الصحيح محاولة تخصيص كتلة حجمها صفر باستعمال الدوال أدناه. فمثلًا `Atom(0)` تمثّل المصفوفة الفارغة.

- `caml_alloc(`*n*`,`*t*`)` ترجع كتلة جديدة حجمها *n* ووسمها *t*. وإذا كان *t* أصغر من `No_scan_tag`، فإن حقول الكتلة تُهيَّأ بقيمة صالحة لتلبية قيود جامع القمامة.

- `caml_alloc_tuple(`*n*`)` ترجع كتلة جديدة حجمها *n* كلمة، بوسم 0.

- `caml_alloc_string(`*n*`)` ترجع قيمة متتالية بايتية (أو سلسلة) طولها *n* بايت. وتحتوي المتتالية في البداية بايتات غير مهيَّأة.

- `caml_alloc_initialized_string(`*n*`,`*p*`)` ترجع قيمة متتالية بايتية (أو سلسلة) طولها *n* بايت. وتُهيَّأ القيمة من البايتات *n* التي تبدأ عند العنوان *p*.

- `caml_copy_string(`*s*`)` ترجع قيمة سلسلة أو متتالية بايتية تحوي نسخة من سلسلة C المنتهية بالبايت الصفري *s* (وهي من نوع `char *`).

- `caml_copy_double(`*d*`)` ترجع قيمة فاصلة عائمة مهيَّأة بالقيمة المضاعفة *d*.

- `caml_copy_int32(`*i*`)` و`caml_copy_int64(`*i*`)` و`caml_copy_nativeint(`*i*`)` ترجع قيمة من النوع `int32` أو `int64` أو `nativeint` في OCaml على التوالي، مهيَّأة بالعدد الصحيح *i*.

- `caml_alloc_array(`*f*`,`*a*`)` تخصّص مصفوفة من القيم، فتستدعي الدالة *f* على كل عنصر من مصفوفة الدخل *a* لتحويله إلى قيمة. والمصفوفة *a* مصفوفة مؤشرات تنتهي بالمؤشر الصفري. وتتلقّى الدالة *f* كل مؤشر وسيطًا، وترجع قيمة. وتُملأ الكتلة الموسومة بالوسم صفر التي ترجعها `alloc_array(`*f*`,`*a*`)` بالقيم التي ترجعها الاستدعاءات المتتالية للدالة *f*. (ولا يجوز استعمال هذه الدالة لبناء مصفوفة من أعداد الفاصلة العائمة.)

- `caml_copy_string_array(`*p*`)` تخصّص مصفوفة من السلاسل أو المتتاليات البايتية، منسوخة من المؤشر إلى مصفوفة السلاسل *p* (وهو من النوع `char **`). ويجب أن تكون *p* منتهية بـ NULL.

- `caml_alloc_float_array(`*n*`)` تخصّص مصفوفة من أعداد الفاصلة العائمة حجمها *n*. وتحتوي المصفوفة في البداية قيمًا غير مهيَّأة.

- `caml_alloc_unboxed(`*v*`)` ترجع القيمة (من أي نوع غير معلَّب) التي حقلها القيمة *v*.

- `caml_alloc_boxed(`*v*`)` تخصّص وترجع قيمة (من أي نوع معلَّب) حقلها القيمة *v*.

- `caml_alloc_unboxable(`*v*`)` تستدعي `caml_alloc_unboxed` أو `caml_alloc_boxed` بحسب التمثيل الافتراضي للأنواع القابلة لإزالة التعلّب في النسخة الحالية من OCaml.

- `caml_alloc_some(`*v*`)` تخصّص كتلة تمثّل `Some(`*v*`)`.

#### الواجهة المنخفضة المستوى

الدوال التالية أكفأ قليلًا من `caml_alloc`، لكنها أصعب استعمالًا بكثير.

من وجهة نظر دوال التخصيص، تُقسَّم الكتل بحسب حجمها إلى كتل حجمها صفر، وكتل صغيرة (حجمها أصغر من `Max_young_wosize` أو مساوٍ له)، وكتل كبيرة (حجمها أكبر من `Max_young_wosize`). والثابت `Max_young_wosize` معرَّف في ملف التضمين `<caml/mlvalues.h>`. وهو مضمون بأن يكون 64 (كلمة) على الأقل، بحيث يمكن افتراض أن أي كتلة حجمها الثابت أصغر من 64 أو مساوٍ له هي كتلة صغيرة. أما الكتل التي يُحسب حجمها وقت التشغيل، فيجب مقارنة حجمها بـ `Max_young_wosize` لتحديد إجراء التخصيص الصحيح.

- `caml_alloc_small(`*n*`,`*t*`)` ترجع كتلة صغيرة جديدة حجمها *n* ≤ `Max_young_wosize` كلمة، بوسم *t*. وإذا كانت هذه الكتلة بنيوية (أي إذا كان *t* < `No_scan_tag`)، فإن حقولها (التي تحوي في البداية قمامة) يجب أن تُهيَّأ بقيم مشروعة (بالإسناد المباشر إلى حقول الكتلة) قبل التخصيص التالي.

- `caml_alloc_shr(`*n*`,`*t*`)` ترجع كتلة جديدة حجمها *n*، بوسم *t*. ويمكن أن يكون حجم الكتلة أكبر من `Max_young_wosize`. (ويمكن أن يكون أصغر أيضًا، لكن في هذه الحالة يكون استدعاء `caml_alloc_small` بدلًا من `caml_alloc_shr` أكفأ.) وإذا كانت هذه الكتلة بنيوية (أي إذا كان *t* < `No_scan_tag`)، فإن حقولها (التي تحوي في البداية قمامة) يجب أن تُهيَّأ بقيم مشروعة (باستعمال الدالة `caml_initialize` الموصوفة أدناه) قبل التخصيص التالي.

### 23.4.5 إطلاق الاستثناءات

تُوفَّر دالتان لإطلاق استثنائين قياسيين:

- `caml_failwith(`*s*`)`، حيث *s* سلسلة C منتهية بالبايت الصفري (من النوع `char *`)، تطلق الاستثناء `Failure` بوسيط *s*.

- `caml_invalid_argument(`*s*`)`، حيث *s* سلسلة C منتهية بالبايت الصفري (من النوع `char *`)، تطلق الاستثناء `Invalid_argument` بوسيط *s*.

أما إطلاق استثناءات اعتباطية من C فأمر أدقّ: فباني الاستثناء يُخصَّص ديناميًا بواسطة برنامج OCaml، ولذلك يجب إبلاغه إلى دالة C باستعمال آلية التسجيل الموصوفة أدناه في القسم 23.7.4. وبمجرد استعادة باني الاستثناء في C، تطلق الدوال التالية الاستثناء فعليًا:

- `caml_raise_constant(`*id*`)` تطلق الاستثناء *id* بلا وسيط؛

- `caml_raise_with_arg(`*id*`,`*v*`)` تطلق الاستثناء *id* بوسيط هو القيمة *v* في OCaml؛

- `caml_raise_with_args(`*id*`,`*n*`,`*v*`)` تطلق الاستثناء *id* بوسائط هي القيم *v*`[0]`، …، *v*`[`*n*`-1]` في OCaml؛

- `caml_raise_with_string(`*id*`,`*s*`)`، حيث *s* سلسلة C منتهية بالبايت الصفري، تطلق الاستثناء *id* بوسيط هو نسخة من سلسلة C المسمّاة *s*.

وأحيانًا يلزم تنظيف الحالة وتحرير الموارد قبل إطلاق الاستثناء فعلًا إلى OCaml. وتحقيقًا لذلك، تُوفَّر دوال بديلة ترجع الاستثناء بدلًا من إطلاقه مباشرة (`caml_exception_failure` و`caml_exception_invalid_argument` وغيرهما). والنوع `caml_result` يمثّل إمّا قيمة OCaml وإمّا استثناءً؛ انظر القسم 23.7.2.

## 23.5 التعايش مع جامع القمامة

تُستعاد الكتل غير المستعملة في الكومة تلقائيًا بواسطة جامع القمامة. ويستلزم ذلك بعض التعاون من شيفرة C التي تتعامل مع كتل مخصَّصة في الكومة.

### 23.5.1 الواجهة البسيطة

بوجه عام، يجب أن يكون كل متغيّر في شيفرة C يشير إلى قيمة OCaml مخصَّصة في الكومة معروفًا لنظام التشغيل عندما يعمل جامع القمامة، لأن الإشارات إلى أي كائنات ينقلها جامع القمامة تحتاج إلى تحديث. كما يجب أن يتابع جامع القمامة تعديلات الحقول القابلة للتغيير لأجل الصحة. وفيما يلي قواعد بسيطة لتحقيق ذلك. وفي بعض الحالات، تفرض هذه القواعد تسجيل متغيّرات قد لا تكون لازمة تقنيًا (مثلًا لأن قيمة OCaml المشار إليها مباشرة، أو لأن جامع القمامة مضمون بأن لا يُستدعى خلال عمر المتغيّر). غير أن محاولة تحسين تسجيل الجذور مصدر شائع لأخطاء السلامة، ولذلك يُوصى بشدة باتباع القواعد أدناه في معظم الحالات. فتنفيذ آلية تسجيل الجذور كفؤ ولا يؤدي عادةً إلى أي إبطاء في الأداء.

جميع وحدات الماكرو الموصوفة في هذا القسم معرَّفة في ملف الترويسة `<caml/memory.h>`.

**القاعدة 1** *الدالة التي لها وسائط أو متغيّرات محلية من النوع `value` يجب أن تبدأ باستدعاء إحدى وحدات الماكرو `CAMLparam` وأن ترجع بـ `CAMLreturn` أو `CAMLreturn0` أو `CAMLreturnT`.*

هناك ست وحدات ماكرو من نوع `CAMLparam`: من `CAMLparam0` إلى `CAMLparam5`، وهي تأخذ من صفر إلى خمس وسائط على التوالي. فإذا لم يكن لدالتك أكثر من 5 وسائط من النوع `value`، فاستعمل الوحدة المقابلة بهذه الوسائط. وإذا كان لدالتك أكثر من 5 وسائط من النوع `value`، فاستعمل `CAMLparam5` مع خمسٍ من هذه الوسائط، واستعمل استدعاءً واحدًا أو أكثر لوحدات الماكرو `CAMLxparam` للوسائط الباقية (من `CAMLxparam1` إلى `CAMLxparam5`). وإذا كان للدالة وسيط `x` هو مصفوفة من قيم `value` طولها `n`، فاستعمل `CAMLparamN (x, n)` لتعريفه (أو `CAMLxparamN (x, n)` إذا كان لديك سلفًا استدعاء لـ `CAMLparam` لوسائط أخرى).

ووحدات الماكرو `CAMLreturn` و`CAMLreturn0` و`CAMLreturnT` تُستعمل بدلًا من الكلمة المفتاحية `return` في C؛ وأي دالة تستعمل وحدة ماكرو `CAMLparam` عند الدخول ينبغي أن تستعمل `CAMLreturn` في جميع نقاط الخروج. والدوال المكتوبة بلغة C والمصدَّرة كدوال OCaml خارجية يجب أن ترجع `value`، وينبغي أن تستعمل `CAMLreturn (x)` بدلًا من `return x`. وقد تتعامل بعض الدوال المساعدة مع قيم OCaml ومع ذلك ترجع `void` أو نوع بيانات آخر. والإجراءات التي ترجع `void` ينبغي أن تستعمل `CAMLreturn0` صراحةً، وألا يكون لها أي إرجاع ضمني. والدوال المساعدة التي ترجع بيانات C من نوع ما `t` ينبغي أن تستعمل `CAMLreturnT (t, x)` بدلًا من `return x`.

##### ملاحظة:

بعض مترجمات C تعطي تحذيرات باطلة بشأن متغيّرات غير مستعملة `caml__dummy_xxx` عند كل استعمال لـ `CAMLparam` و`CAMLlocal`. وينبغي أن تتجاهلها.

أمثلة:

```text
CAMLprim value my_external (value v1, value v2, value v3)
{
  CAMLparam3 (v1, v2, v3);
  ...
  CAMLreturn (Val_unit);
}

static void helper_procedure (value v1, value v2)
{
  CAMLparam2 (v1, v2);
  ...
  CAMLreturn0;
}

static int helper_function (value v1, value v2)
{
  CAMLparam2 (v1, v2);
  ...
  CAMLreturnT (int, 0);
}
```

##### ملاحظة:

إذا كانت دالتك عملية أوّلية لها أكثر من 5 وسائط للاستعمال مع نظام تشغيل الشيفرة البايتية، فإن وسائطها ليست من النوع `value` ولا يجوز تعريفها (فهي من النوعين `value *` و`int`).

##### تحذير:

ينبغي ألا تُستعمل `CAMLreturn0` إلا للإجراءات الداخلية التي ترجع void. وينبغي أن تُستعمل `CAMLreturn(Val_unit)` للدوال التي ترجع قيمة وحدة في OCaml. أما العمليات الأوّلية (دوال C التي يمكن استدعاؤها من OCaml) فينبغي ألا ترجع void أبدًا.

**القاعدة 2** *المتغيّرات المحلية من النوع `value` يجب أن تُعرَّف بإحدى وحدات الماكرو `CAMLlocal`. ومصفوفات قيم `value` تُعرَّف بـ `CAMLlocalN`. ويجب استعمال وحدات الماكرو هذه في بداية الدالة، لا في كتلة متداخلة. والقيم المؤقتة تكافئ المتغيّرات المحلية، لكن لا يمكن تسجيلها لدى جامع القمامة، ولذلك يجب ألا تكون قيمة مؤقتة من النوع `value` حيّة عند احتمال حدوث جمع للقمامة.*

وحدات الماكرو من `CAMLlocal1` إلى `CAMLlocal5` تعرّف وتهيّئ من متغيّر محلي واحد إلى خمسة متغيّرات محلية من النوع `value`. وتُعطى أسماء المتغيّرات وسائطَ لوحدات الماكرو. أما `CAMLlocalN(`*x*`,`*n*`)` فتعريف وتهيّئ متغيّرًا محليًا من النوع `value [`*n*`]`. ويمكنك استعمال عدة استدعاءات لهذه الوحدات إذا كان لديك أكثر من 5 متغيّرات محلية.

مثال:

```text
CAMLprim value bar (value v1, value v2, value v3)
{
  CAMLparam3 (v1, v2, v3);
  CAMLlocal1 (result);
  result = caml_alloc (3, 0);
  ...
  CAMLreturn (result);
}
```

##### تحذير:

لا يمكن استدعاء `CAMLlocal` (و`CAMLxparam`) إلا *بعد* `CAMLparam`. وإذا كانت دالة تعرّف قيمًا محلية لكنها لا تأخذ وسيطًا من النوع `value`، فينبغي أن تبدأ بـ `CAMLparam0 ()`.

```text
static value foo (int n)
{
  CAMLparam0 ();;
  CAMLlocal (result);
  ...
  CAMLreturn (result);
}
```

**القاعدة 3** *الإسنادات إلى حقول الكتل البنيوية يجب أن تُنفَّذ بوحدة الماكرو `Store_field` (للكتل العادية)، أو وحدة الماكرو `Store_double_array_field` (لقيم `float array`)، أو `Store_double_flat_field` (لقيم `floatarray` وسجلات أعداد الفاصلة العائمة). أما الإسنادات الأخرى فيجب ألا تستعمل `Store_field` ولا `Store_double_array_field` ولا `Store_double_flat_field`.*

`Store_field (`*b*`,`*n*`,`*v*`)` تخزّن القيمة *v* في الحقل رقم *n* من القيمة *b*، التي يجب أن تكون كتلة (أي يجب أن تكون `Is_block(`*b*`)` صحيحة).

مثال:

```text
CAMLprim value bar (value v1, value v2, value v3)
{
  CAMLparam3 (v1, v2, v3);
  CAMLlocal1 (result);
  result = caml_alloc (3, 0);
  Store_field (result, 0, v1);
  Store_field (result, 1, v2);
  Store_field (result, 2, v3);
  CAMLreturn (result);
}
```

##### تحذير:

يجب أن تكون الوسيطة الأولى لـ `Store_field` و`Store_double_field` متغيّرًا معرَّفًا بـ `CAMLparam*` أو وسيطًا معرَّفًا بـ `CAMLlocal*`، لضمان ألا يبطل جمعُ القمامة الذي يستدعيه تقييم الوسائط الأخرى الوسيطةَ الأولى بعد حسابها.

##### الاستعمال مع CAMLlocalN:

المصفوفات من القيم المعرَّفة باستعمال `CAMLlocalN` يجب ألا يُكتب فيها باستعمال `Store_field`. بل تُستعمل صيغة المصفوفات العادية في C.
**القاعدة 4** *المتغيّرات العامة التي تحوي قيمًا يجب تسجيلها لدى جامع القمامة باستعمال الدالة `caml_register_global_root`، باستثناء المتغيّرات العامة والمواقع التي لن تحوي أبدًا إلا أعدادًا صحيحة في OCaml (ولن تحوي مؤشرات). وينطبق الأمر نفسه على أي موقع في الذاكرة خارج كومة OCaml يحوي قيمة وليس مضمونًا أن يكون قابلًا للوصول — ما دام يحوي تلك القيمة — من متغيّر عام أو موقع آخر مسجَّل، أو متغيّر محلي معرَّف بـ `CAMLlocal`، أو وسيط دالة معرَّف بـ `CAMLparam`.*

ويُسجَّل المتغيّر العام `v` باستدعاء `caml_register_global_root(&v)` قبل تخزين قيمة صالحة في `v` للمرة الأولى أو بعدها بقليل؛ وعلى المنوال نفسه، يُسجَّل موقع اعتباطي `p` باستدعاء `caml_register_global_root(p)`.

ويجب ألا تستدعي أيًا من دوال نظام تشغيل OCaml أو وحدات ماكروها بين التسجيل وتخزين القيمة. كما يجب ألا تخزّن في المتغيّر `v` (وكذلك في الموقع `p`) أي شيء ليس قيمة صالحة.

ويسوّغ التسجيل أن تُحدَّث محتويات المتغيّر أو موقع الذاكرة بواسطة جامع القمامة كلما نُقلت القيمة الموجودة في ذلك المتغيّر أو الموقع داخل كومة OCaml. وفي وجود الخيوط يجب الحرص على ضمان المزامنة المناسبة مع نظام تشغيل OCaml لتفادي حالة تسابق مع جامع القمامة عند قراءة القيمة أو كتابتها. (انظر القسم 23.12.2.)

ويمكن إلغاء تسجيل متغيّر عام مسجَّل `v` باستدعاء `caml_remove_global_root(&v)`.

وإذا كانت محتويات المتغيّر العام `v` نادرًا ما تُعدَّل بعد التسجيل، أمكن تحقيق أداء أفضل باستدعاء `caml_register_generational_global_root(&v)` لتسجيل `v` (بعد تهيئته بقيمة صالحة، لكن قبل أي تخصيص أو استدعاء لدوال جامع القمامة)، و`caml_remove_generational_global_root(&v)` لإلغاء تسجيله. وفي هذه الحالة، يجب ألا تعدّل قيمة `v` مباشرة، بل يجب أن تستعمل `caml_modify_generational_global_root(&v,x)` لضبطها على `x`. ويستفيد جامع القمامة من ضمانة أن `v` لا يُعدَّل بين استدعاءات `caml_modify_generational_global_root` فيمسحه أقل تكرارًا. وهذا يحسّن الأداء إذا كانت تعديلات `v` تحدث أقل تكرارًا من عمليات الجمع الصغرى.

##### ملاحظة:

تستعمل وحدات ماكرو `CAML` معرّفات (متغيّرات محلية، ومعرّفات أنواع، ووسوم بنى) تبدأ بـ `caml__`. فلا تستعمل أي معرّف يبدأ بـ `caml__` في برامجك.

### 23.5.2 الواجهة المنخفضة المستوى

نعطي الآن قواعد جامع القمامة المقابلة لدالتي التخصيص المنخفضتَي المستوى `caml_alloc_small` و`caml_alloc_shr`. ويمكنك تجاهل هذه القواعد إذا اكتفيت بدالة التخصيص المبسّطة `caml_alloc`.

**القاعدة 5** *بعد تخصيص كتلة بنيوية (كتلة وسمها أصغر من `No_scan_tag`) بالدوال المنخفضة المستوى، يجب أن تُملأ جميع حقول هذه الكتلة بقيم سليمة البنية قبل عملية التخصيص التالية. وإذا كانت الكتلة قد خُصِّصت بـ `caml_alloc_small`، فالتعبئة تُنفَّذ بالإسناد المباشر إلى حقول الكتلة، أي `Field(`*v*`,`*n*`) =` *v*ₙ. وإذا كانت الكتلة قد خُصِّصت بـ `caml_alloc_shr`، فالتعبئة تُنفَّذ عبر الدالة `caml_initialize`، أي `caml_initialize(&Field(`*v*`,`*n*`), `*v*ₙ`)`.*

والتخصيص التالي قد يستدعي جمعًا للقمامة. ويفترض جامع القمامة أن جميع الكتل البنيوية تحوي قيمًا سليمة البنية. أما الكتل المنشأة حديثًا فتحوي بيانات عشوائية، وهي لا تمثّل عادةً قيمًا سليمة البنية.

وإذا كنت تحتاج فعلًا إلى التخصيص قبل أن تتلقّى الحقول قيمتها النهائية، فهيّئها أولًا بقيمة ثابتة (مثل `Val_unit`)، ثم خصّص، ثم عدّل الحقول بالقيمة الصحيحة (انظر القاعدة 6).

**القاعدة 6** *الإسناد المباشر إلى حقل من كتلة، كما في `Field(`*v*`,`*n*`) =` *w*، آمن فقط إذا كانت *v* كتلة مخصَّصة حديثًا بـ `caml_alloc_small`؛ أي إذا لم يحدث أي تخصيص بين تخصيص *v* والإسناد إلى الحقل. وفي جميع الحالات الأخرى، لا تُسند مباشرة أبدًا. وإذا كانت الكتلة قد خُصِّصت للتوّ بـ `caml_alloc_shr`، فاستعمل `caml_initialize` لإسناد قيمة إلى حقل للمرة الأولى، أي `caml_initialize(&Field(`*v*`,`*n*`), `*w*`)`. وفيما عدا ذلك، فأنت تحدّث حقلًا كان يحوي سلفًا قيمة سليمة البنية؛ فاستدعِ الدالة `caml_modify`، أي `caml_modify(&Field(`*v*`,`*n*`), `*w*`)`.*

ولتوضيح القواعد أعلاه، هذه دالة في C تبني وترجع قائمة تحوي العددين الصحيحين المعطيين وسيطين. نكتبها أولًا باستعمال دوال التخصيص المبسّطة:

```text
value alloc_list_int(int i1, int i2)
{
  CAMLparam0 ();
  CAMLlocal2 (result, r);

  r = caml_alloc(2, 0);                   /* Allocate a cons cell */
  Store_field(r, 0, Val_int(i2));         /* car = the integer i2 */
  Store_field(r, 1, Val_emptylist);       /* cdr = the empty list [] */
  result = caml_alloc(2, 0);              /* Allocate the other cons cell */
  Store_field(result, 0, Val_int(i1));    /* car = the integer i1 */
  Store_field(result, 1, r);              /* cdr = the first cons cell */
  CAMLreturn (result);
}
```

هنا، تسجيل `result` ليس لازمًا لزومًا صارمًا، لأنه لا يحدث أي تخصيص بعد أن تتلقى قيمتها، لكن تسجيل جميع المتغيّرات المحلية من النوع `value` أيسر وأكثر أمانًا.

وهذه الدالة نفسها مكتوبة بدوال التخصيص المنخفضة المستوى. ونلاحظ أن خلايا cons كتل صغيرة ويمكن تخصيصها بـ `caml_alloc_small`، وملؤها بالإسناد المباشر إلى حقولها.

```text
value alloc_list_int(int i1, int i2)
{
  CAMLparam0 ();
  CAMLlocal2 (result, r);

  r = caml_alloc_small(2, 0);             /* Allocate a cons cell */
  Field(r, 0) = Val_int(i2);              /* car = the integer i2 */
  Field(r, 1) = Val_emptylist;            /* cdr = the empty list [] */
  result = caml_alloc_small(2, 0);        /* Allocate the other cons cell */
  Field(result, 0) = Val_int(i1);         /* car = the integer i1 */
  Field(result, 1) = r;                   /* cdr = the first cons cell */
  CAMLreturn (result);
}
```

في المثالين أعلاه، تُبنى القائمة من الأسفل إلى الأعلى. وهذه طريقة بديلة تسير من الأعلى إلى الأسفل. وهي أقل كفاءة، لكنها توضّح استعمال `caml_modify`.

```text
value alloc_list_int(int i1, int i2)
{
  CAMLparam0 ();
  CAMLlocal2 (tail, r);

  r = caml_alloc_small(2, 0);             /* Allocate a cons cell */
  Field(r, 0) = Val_int(i1);              /* car = the integer i1 */
  Field(r, 1) = Val_int(0);               /* A dummy value
  tail = caml_alloc_small(2, 0);          /* Allocate the other cons cell */
  Field(tail, 0) = Val_int(i2);           /* car = the integer i2 */
  Field(tail, 1) = Val_emptylist;         /* cdr = the empty list [] */
  caml_modify(&Field(r, 1), tail);        /* cdr of the result = tail */
  CAMLreturn (r);
}
```

سيكون من غير الصحيح تنفيذ `Field(r, 1) = tail` مباشرة، لأن تخصيص `tail` حدث بعد تخصيص `r`.

### 23.5.3 الإجراءات المعلّقة والاستثناءات غير المتزامنة

منذ 4.10، دوال التخصيص مضمونة بأن لا تنفّذ أي شيفرة OCaml، بما في ذلك دوال الإنهاء ومعالجات الإشارات والخيوط الأخرى العاملة على النطاق نفسه. بل يُؤجَّل تنفيذها إلى نقطة آمنة لاحقة.

والدالة `caml_process_pending_actions` من `<caml/signals.h>` تنفّذ أي معالجات إشارات ودوال إنهاء معلّقة، ونداءات Memprof، والتبديل الاستباقي للخيوط النظامية، وعمليات جمع القمامة الصغرى والكبرى المطلوبة. وبوجه خاص، يمكنها إطلاق استثناءات غير متزامنة وإحداث تغييرات على كومة OCaml من النطاق نفسه. ويُوصى باستدعائها بانتظام عند نقاط آمنة داخل شيفرة C الطويلة غير الحاجبة.

والدالة `caml_process_pending_actions_res` ترجع الاستثناء بدلًا من إطلاقه مباشرة إلى شيفرة OCaml. ويُمثَّل ذلك بنوع C مختلف، هو `caml_result` لا `value`. ويمكن اختبار النتيجة باستعمال `caml_result_is_exception`، ثم تنفيذ بعض منطق التنظيف، وأخيرًا `caml_get_value_or_raise` التي ترجع القيمة (وهي هنا مجرد قيمة وحدة مهملة) أو تطلق الاستثناء.

```text
    CAMLlocalresult(res);
    ...
    res = caml_process_pending_actions_res();
    if(caml_result_is_exception(res)) {
      ...cleanup...
      (void)caml_get_value_or_raise(res);
    }
```

ولمزيد من التفاصيل عن `caml_result`، انظر القسم 23.7.2.

## 23.6 مثال كامل

يوجز هذا القسم كيف يمكن إتاحة دوال مكتبة `curses` في Unix لبرامج OCaml. أولًا، هذه هي الواجهة `curses.ml` التي تعرّف العمليات الأوّلية وأنواع البيانات الخاصة بـ `curses`:

```text
(* File curses.ml -- declaration of primitives and data types *)
type window                   (* The type "window" remains abstract *)
external initscr: unit -> window = "caml_curses_initscr"
external endwin: unit -> unit = "caml_curses_endwin"
external refresh: unit -> unit = "caml_curses_refresh"
external wrefresh : window -> unit = "caml_curses_wrefresh"
external newwin: int -> int -> int -> int -> window = "caml_curses_newwin"
external addch: char -> unit = "caml_curses_addch"
external mvwaddch: window -> int -> int -> char -> unit = "caml_curses_mvwaddch"
external addstr: string -> unit = "caml_curses_addstr"
external mvwaddstr: window -> int -> int -> string -> unit
         = "caml_curses_mvwaddstr"
(* lots more omitted *)
```

ولترجمة هذه الواجهة:

```text
        ocamlc -c curses.ml
```

ولتنفيذ هذه الدوال، لا يلزمنا إلا توفير شيفرة الوصلة؛ فالدوال الجوهرية منفَّذة سلفًا في مكتبة `curses`. وملف شيفرة الوصلة، `curses_stubs.c`، يبدو كما يلي:

```text
/* File curses_stubs.c -- stub code for curses */
#include <curses.h>
#include <caml/mlvalues.h>
#include <caml/memory.h>
#include <caml/alloc.h>
#include <caml/custom.h>

/* Encapsulation of opaque window handles (of type WINDOW *)
   as OCaml custom blocks. */

static struct custom_operations curses_window_ops = {
  "fr.inria.caml.curses_windows",
  custom_finalize_default,
  custom_compare_default,
  custom_hash_default,
  custom_serialize_default,
  custom_deserialize_default,
  custom_compare_ext_default,
  custom_fixed_length_default
};

/* Accessing the WINDOW * part of an OCaml custom block */
#define Window_val(v) (*((WINDOW **) Data_custom_val(v)))

/* Allocating an OCaml custom block to hold the given WINDOW * */
static value alloc_window(WINDOW * w)
{
  value v = caml_alloc_custom(&curses_window_ops, sizeof(WINDOW *), 0, 1);
  Window_val(v) = w;
  return v;
}

CAMLprim value caml_curses_initscr(value unit)
{
```

## 23.7 موضوع متقدّم: النداءات العكسية من C إلى OCaml

وصفنا حتى الآن كيف تُستدعى دوال C من OCaml. ونوضّح في هذا القسم كيف يمكن لدوال C أن تستدعي دوال OCaml، إمّا كنداءات عكسية (فيستدعي OCaml دالة C التي تستدعي بدورها OCaml)، وإمّا ببرنامج رئيسي مكتوب بلغة C.

### 23.7.1 تطبيق إغلاقات OCaml من C

يمكن لدوال C أن تطبّق قيم دوال OCaml (أي الإغلاقات) على قيم OCaml. وتُوفَّر الدوال التالية لتنفيذ هذه التطبيقات:

- `caml_callback(`*f, a*`)` تطبّق القيمة الدالية *f* على القيمة *a* وترجع القيمة التي ترجعها *f*.

- `caml_callback2(`*f, a, b*`)` تطبّق القيمة الدالية *f* (المفترض أنها دالة OCaml مكَرْيَنة بوسيطين) على *a* و*b*.

- `caml_callback3(`*f, a, b, c*`)` تطبّق القيمة الدالية *f* (وهي دالة OCaml مكَرْيَنة بثلاثة وسائط) على *a* و*b* و*c*.

- `caml_callbackN(`*f, n, args*`)` تطبّق القيمة الدالية *f* على الوسائط *n* الموجودة في مصفوفة القيم *args* في C.

وإذا كانت الدالة *f* لا ترجع، بل تطلق استثناءً يفلت من نطاق التطبيق، فإن هذا الاستثناء يُنشر إلى شيفرة OCaml المحيطة التالية، متجاوزًا شيفرة C. أي إنه إذا استدعت دالة OCaml اسمها *f* دالة C اسمها *g* استدعت بدورها دالة OCaml اسمها *h* أطلقت استثناءً شاردًا، فإن تنفيذ *g* ينقطع ويُنشر الاستثناء عائدًا إلى *f*.

### 23.7.2 caml_result: تنظيف الموارد عند استثناءات OCaml

إذا أطلقت دالة OCaml المستدعاة بـ `caml_callback` (أو بـ `caml_process_pending_actions` كما ذُكر في القسم 23.5.3) استثناءً، فإن المستدعي في C يُقطع فورًا ليعود إلى أقرب معالج استثناءات في OCaml. وهذا غالبًا سلوك خاطئ إذا كان المستدعي في C يحتاج إلى تنفيذ بعض منطق تنظيف الموارد لينتهي على نحو آمن.

وتوفّر واجهة OCaml للأدوات الأجنبية واجهة برمجية بديلة لاستدعاء شيفرة OCaml من C ترجع قيمة من النوع `caml_result` بدلًا من `value`. وقيمة C من النوع `caml_result` هي إمّا قيمة OCaml أرجعتها دالة OCaml على نحو صحيح، وإمّا استثناء OCaml أطلقته دالة OCaml. ويستطيع المستدعي في C تنفيذ أي منطق تنظيف قبل إعادة إطلاق الاستثناء (إن وُجد) أو متابعة الحساب.

ويمكن التعامل مع قيم `caml_result` بالدوال ووحدات الماكرو التالية:

- `value caml_get_value_or_raise(caml_result`*res*`)` (في `<caml/fail.h>`) ترجع القيمة التي تحويها *res* أو تعيد إطلاق الاستثناء الذي تحويه. وبوجه خاص، يمكن استعمال `(void)caml_get_value_or_raise(res)` لتجاهل نتيجة OCaml من النوع `unit` مع نشر الاستثناءات إلى المستدعي.

- `Result_value(value`*v*`)` (في `<caml/mlvalues.h>`) هي النتيجة التي تمثّل إرجاع القيمة *v*.

- `Result_exception(value`*exn*`)` (في `<caml/mlvalues.h>`) هي النتيجة التي تمثّل إطلاق الاستثناء *exn*.

- `int caml_result_is_exception(caml_result`*res*`)` (في `<caml/mlvalues.h>`) صحيحة إذا كانت *res* تمثّل استثناءً.

- وحدة الماكرو `CAMLlocalresult(foo)` (في `<caml/memory.h>`) هي النظير `caml_result` لـ `CAMLlocal1`: فهي تعرّف متغيّرًا محليًا من النوع `caml_result` يتتبّع جامع القمامة في OCaml محتواه. ومثل `CAMLlocal1` تمامًا، لا يمكن استعمالها إلا بين وحدة ماكرو `CAMLparam` ووحدتي الماكرو `CAMLreturn` أو `CAMLreturnT`. ولا يوجد نظير لـ `CAMLlocal2` و`CAMLlocal3` وغيرهما، لكن يمكن استعمال الوحدة عدة مرات.

وتسهيلًا، عُرِّفت `Result_unit` بأنها `Result_value(Val_unit)`.

واصطلاحًا، تُلحق بدوال C التي ترجع نتائج لاحقة `_res` في أسمائها، مثل `caml_callback2_res` و`caml_process_pending_actions_res`.

بعض الأمثلة:
```text
#include <caml/mlvalues.h> // for the caml_result type, caml_result_is_exception
#include <caml/memory.h>   // CAMLlocalresult
#include <caml/callback.h> // caml_callback_res
#include <caml/fail.h>     // caml_get_value_or_raise
#include <caml/alloc.h>    // caml_alloc_2

/* This function calls an OCaml callback,
   and returns the value or reraises the exception. */
value logging_callback(value f, value arg) {
  CAMLparam2(f, arg);
  CAMLlocalresult(res);
  printf("Start callback.\n");
  res = caml_callback_res(f, arg);
  printf("End callback.\n");
  CAMLreturn (caml_get_value_or_raise(res));
}

/* This function assumes that the callback returns
   a 'unit' value and ignores it -- or reraises
   its exception. It must be called by C, as it
   does not return a value, but the caller cannot
   handle exceptions as they are raised directly. */
void logging_unit_callback(value f, value arg) {
  CAMLparam2(f, arg);
  CAMLlocalresult(res);
  printf("Start unit callback.\n");
  res = caml_callback_res(f, arg);
  printf("End callback.\n");
  (void)caml_get_value_or_raise(res);
  CAMLreturn0;
}

/* This function calls a callback on two arguments in turn,
   and returns the pair of values;
   it does not reraise exceptions, but returns a caml_result instead, letting
   its own C caller perform its own cleanup. */
caml_result two_callbacks_res(value f, value arg1, value arg2) {
  CAMLparam3(f, arg1, arg2);
  CAMLlocalresult(res);
  CAMLlocal3(v1, v2, pair);

  res = caml_callback_res(f, arg1);
  // early exit on exception
  if (caml_result_is_exception(res))
    CAMLreturnT(caml_result, res);
  v1 = caml_get_value_or_raise(res);

  res = caml_callback_res(f, arg2);
  if (caml_result_is_exception(res))
    CAMLreturnT(caml_result, res);
  v2 = caml_get_value_or_raise(res);

  // build the pair of values, and
  // wrap it in a caml_result
  pair = caml_alloc_2(0, v1, v2);
  res = Result_value(pair);
  CAMLreturnT(caml_result, res);
}
```

##### التوافق:

النوع `caml_result` متوفّر منذ OCaml 5.3. أمّا الإصدارات الأقدم من OCaml فتستعمل مفهومًا غير آمن هو «الاستثناءات المُرمَّزة» (`encoded exceptions`: لاحقة `_exn`، وعمليتا `Is_exception_result` و`Extract_exception`)، وهي من النوع `value` لكنها ليست قيم OCaml صحيحة، وقد تُسقط جامع القمامة إذا لم يستخرجها المستدعي فورًا. نوصي بشدّة باستعمال `caml_result` بدلًا منها، لفصل القيم الصحيحة عن الاستثناءات المتجسّدة بأنواع C متمايزة، لكن المقاربة الأقدم تبقى متاحة للتوافق العكسي.

### 23.7.3 الحصول على إغلاقات OCaml أو تسجيلها لاستعمالها في دوال C

هناك طريقتان للحصول على قيم دوال OCaml (الإغلاقات) لتمريرها إلى دوال `callback` الموصوفة أعلاه. إحداهما تمرير دالة OCaml وسيطًا إلى عملية أوّلية. فمثلًا، إذا كان الشيفرة OCaml تحتوي التصريح

```text
    external apply : ('a -> 'b) -> 'a -> 'b = "caml_apply"
```

فيمكن كتابة وصلة C المقابلة على النحو التالي:

```text
    CAMLprim value caml_apply(value vf, value vx)
    {
      CAMLparam2(vf, vx);
      CAMLlocal1(vy);
      vy = caml_callback(vf, vx);
      CAMLreturn(vy);
    }
```

والاحتمال الآخر هو استعمال آلية التسجيل التي يوفّرها OCaml. تمكّن آلية التسجيل هذه شيفرة OCaml من تسجيل دوال OCaml تحت اسم عام، وشيفرة C من استرجاع الإغلاق المقابل بهذا الاسم العام.

في جانب OCaml، يتم التسجيل بتقييم `Callback.register` *n* *v*. هنا *n* هو الاسم العام (سلسلة اعتباطية) و*v* قيمة OCaml. فمثلًا:

```text
    let f x = print_string "f is applied to "; print_int x; print_newline()
    let _ = Callback.register "test function" f
```

وفي جانب C، يُحصل على مؤشّر إلى القيمة المسجَّلة تحت الاسم *n* باستدعاء `caml_named_value(`*n*`)`. ثم يجب إلغاء إشارة المؤشّر المُعاد لاسترداد قيمة OCaml الفعلية. وإذا لم تكن هناك قيمة مسجَّلة تحت الاسم *n*، يُعاد المؤشّر الفارغ. فمثلًا، هذا غلاف C يستدعي دالة OCaml `f` أعلاه:

```text
    void call_caml_f(int arg)
    {
        caml_callback(*caml_named_value("test function"), Val_int(arg));
    }
```

المؤشّر الذي يعيده `caml_named_value` ثابت ويمكن تخزينه بأمان في متغيّر C لتفادي تكرار البحث بالاسم. أمّا القيمة التي يشير إليها فلا يمكن تغييرها من C. لكنها قد تتغيّر أثناء جمع القمامة، لذا يجب إعادة حسابها دائمًا عند موضع الاستعمال. وهذا البديل الأكثر كفاءة من `call_caml_f` أعلاه يستدعي `caml_named_value` مرّة واحدة فقط:

```text
    void call_caml_f(int arg)
    {
        static const value * closure_f = NULL;
        if (closure_f == NULL) {
            /* First time around, look up by name */
            closure_f = caml_named_value("test function");
        }
        caml_callback(*closure_f, Val_int(arg));
    }
```

### 23.7.4 تسجيل استثناءات OCaml لاستعمالها في دوال C

يمكن أيضًا استعمال آلية التسجيل الموصوفة أعلاه لنقل بواني الاستثناءات من OCaml إلى C. فشيفرة OCaml تسجّل باني الاستثناء بتقييم `Callback.register_exception` *n* *exn*، حيث *n* اسم اعتباطي و*exn* قيمة استثناء تحمل باني الاستثناء المطلوب تسجيله. فمثلًا:

```text
    exception Error of string
    let _ = Callback.register_exception "test exception" (Error "any string")
```

ثم تستطيع شيفرة C استرداد باني الاستثناء باستعمال `caml_named_value` وتمريره وسيطًا أوّلًا إلى الدوال `raise_constant` و`raise_with_arg` و`raise_with_string` (الموصوفة في القسم 23.4.5) لرفع الاستثناء فعلًا. فمثلًا، هذه دالة C ترفع الاستثناء `Error` بالوسيط المعطى:

```text
    void raise_error(char * msg)
    {
        caml_raise_with_string(*caml_named_value("test exception"), msg);
    }
```

### 23.7.5 البرنامج الرئيسي في C

في التشغيل العادي، يبدأ برنامج مختلط من OCaml وC بتنفيذ شيفرة تهيئة OCaml، التي قد تنتقل بعدها إلى استدعاء دوال C. نقول إنّ البرنامج الرئيسي هو شيفرة OCaml. وفي بعض التطبيقات، يُستحسن أن تؤدّي شيفرة C دور البرنامج الرئيسي، ف تستدعي دوال OCaml عند الحاجة. ويمكن تحقيق ذلك على النحو التالي:

- يجب أن يوفّر الجزء المكتوب بـ C دالة `main`، فتحلّ محلّ دالة `main` الافتراضية التي يوفّرها نظام تشغيل OCaml. يبدأ التنفيذ في دالة `main` التي يعرّفها المستخدم، تمامًا كما في برنامج C عادي.

- في مرحلة ما، يجب أن تستدعي شيفرة C الدالة `caml_main(argv)` لتهيئة شيفرة OCaml. والوسيط `argv` مصفوفة C من السلاسل (من النوع `char **`)، تنتهي بمؤشّر `NULL`، وتمثّل وسائط سطر الأوامر كما تُمرَّر وسيطًا ثانيًا إلى `main`. وستُهيَّأ مصفوفة OCaml المسماة `Sys.argv` من هذا الوسيط. وفي حالة مترجم الشيفرة البايتية، يُراجع أيضًا `argv[0]` و`argv[1]` للعثور على الملف الذي يحتوي الشيفرة البايتية.

- يستدعي `caml_main` تهيئة نظام تشغيل OCaml، ويحمّل الشيفرة البايتية (في حالة مترجم الشيفرة البايتية)، وينفّذ شيفرة التهيئة في برنامج OCaml. وتلك الشيفرة، في العادة، تسجّل دوال الاستدعاء الراجع باستعمال `Callback.register`. وبمجرّد انتهاء شيفرة تهيئة OCaml، تعود السيطرة إلى شيفرة C التي استدعت `caml_main`.

- بعد ذلك يمكن لشيفرة C أن تستدعي دوال OCaml بآلية الاستدعاء الراجع (انظر القسم 23.7.1).

### 23.7.6 تضمين شيفرة OCaml في شيفرة C

مترجم الشيفرة البايتية في نمط نظام التشغيل المخصّص (`ocamlc -custom`) يُلحق الشيفرة البايتية عادةً بالملف التنفيذي الذي يحتوي نظام التشغيل المخصّص. ولهذا نتيجتان. الأولى أنّ خطوة الربط النهائية يجب أن ينفّذها `ocamlc`. والثانية أنّ مكتبة تشغيل OCaml يجب أن تستطيع العثور على اسم الملف التنفيذي من وسائط سطر الأوامر. وعند استعمال `caml_main(argv)` كما في القسم 23.7.5، يعني ذلك أنّ `argv[0]` أو `argv[1]` يجب أن يحتوي اسم الملف التنفيذي.

وثمّة بديل هو تضمين الشيفرة البايتية في شيفرة C. وقد وُضع الخياران `-output-obj` و`-output-complete-obj` في `ocamlc` لهذا الغرض. فهما يجعلان مترجم `ocamlc` يُخرج ملف كائن C (ملف `.o`، و`.obj` في ويندوز) يحتوي الشيفرة البايتية للجزء المكتوب بـ OCaml من البرنامج، إضافةً إلى دالة `caml_startup`. أمّا ملف كائن C الذي ينتجه `ocamlc -output-complete-obj` فيحتوي كذلك نظام التشغيل ومكتبات الربط التلقائي. ثم يمكن ربط ملف كائن C الذي ينتجه `ocamlc -output-obj` أو `ocamlc -output-complete-obj` بشيفرة C باستعمال مترجم C المعتاد، أو تخزينه في مكتبة C.

ويجب استدعاء الدالة `caml_startup` من برنامج C الرئيسي لتهيئة نظام تشغيل OCaml وتنفيذ شيفرة تهيئة OCaml. ومثل `caml_main`، تأخذ وسيطًا واحدًا هو `argv` يحتوي وسائط سطر الأوامر. وعلى خلاف `caml_main`، لا يُستعمل هذا الوسيط `argv` إلا لتهيئة `Sys.argv`، لا للعثور على اسم الملف التنفيذي.

وإذا نجم استثناء عن مهيّئ وحدة من المستوى الأعلى، ف إنّ `caml_startup` تستدعي معالج الاستثناءات غير الملتقَطة (أو تدخل المنقّح، إذا كان التشغيل تحت ocamldebug). ويمكن التقاط تلك الاستثناءات في شيفرة C باستعمال الدالة `caml_startup_exn` بدلًا منها وفحص النتيجة بـ `Is_exception_result` (متبوعةً بـ `Extract_exception` عند الاقتضاء).

ويمكن استعمال الخيارين `-output-obj` و`-output-complete-obj` للحصول على ملف مصدر C أيضًا. والأهمّ من ذلك أنّ هذين الخيارين يستطيعان إنتاج مكتبة مشتركة (ملف `.so`، و`.dll` في ويندوز) تحتوي شيفرة OCaml ونظام تشغيل OCaml وأيّ شيفرة C ساكنة أخرى تُعطى إلى `ocamlc` (`.o` و`.a`، أو `.obj` و`.lib` على الترتيب). وهذا الاستعمال للخيارين شبيه جدًّا بخطوة ربط عادية، لكنه بدلًا من إنتاج برنامج رئيسي يشغّل شيفرة OCaml تلقائيًا، ينتج مكتبة مشتركة تستطيع تشغيل شيفرة OCaml عند الطلب. والسلوكات الثلاثة الممكنة للخيارين (إنتاج مصدر C بامتداد `.c`، أو ملف كائن C بامتداد `.o`، أو مكتبة مشتركة بامتداد `.so`) تُختار حسب امتداد الملف الناتج (المعطى بـ `-o`).

ويدعم مترجم الشيفرة الأصلية `ocamlopt` الخيارين `-output-obj` و`-output-complete-obj` أيضًا، فيُخرج ملف كائن C أو مكتبة مشتركة تحتوي الشيفرة الأصلية لكل وحدات OCaml المذكورة في سطر الأوامر، إضافةً إلى شيفرة بدء OCaml. ويتم التهيئة باستدعاء `caml_startup` (أو `caml_startup_exn`) كما في حالة مترجم الشيفرة البايتية. والملف الذي ينتجه `ocamlopt -output-complete-obj` يحتوي كذلك نظام التشغيل ومكتبات الربط التلقائي.

ولخطوة الربط النهائية، إضافةً إلى ملف الكائن الذي ينتجه `-output-obj`، ستحتاج إلى توفير مكتبة تشغيل OCaml (`libcamlrun.a` للشيفرة البايتية، و`libasmrun.a` للشيفرة الأصلية)، وكل مكتبات C التي تتطلّبها مكتبات OCaml المستعملة. فمثلًا، افترض أنّ الجزء المكتوب بـ OCaml من برنامجك يستعمل مكتبة Unix. مع `ocamlc` ينبغي أن تفعل:

```text
        ocamlc -output-obj -o camlcode.o unix.cma other .cmo and .cma files
        cc -o myprog C objects and libraries \
           camlcode.o -L‘ocamlc -where‘ -lunix -lcamlrun
```

ومع `ocamlopt` ينبغي أن تفعل:

```text
        ocamlopt -output-obj -o camlcode.o unix.cmxa other .cmx and .cmxa files
        cc -o myprog C objects and libraries \
           camlcode.o -L‘ocamlc -where‘ -lunix -lasmrun
```

ولخطوة الربط النهائية، إضافةً إلى ملف الكائن الذي ينتجه `-output-complete-obj`، لن يبقى عليك إلا توفير مكتبات C التي يتطلّبها نظام تشغيل OCaml.

فمثلًا، افترض أنّ الجزء المكتوب بـ OCaml من برنامجك يستعمل مكتبة Unix. مع `ocamlc` ينبغي أن تفعل:

```text
        ocamlc -output-complete-obj -o camlcode.o unix.cma other .cmo and .cma files
        cc -o myprog C objects and libraries \
           camlcode.o C libraries required by the runtime, eg -lm  -ldl -lcurses -lpthread
```

ومع `ocamlopt` ينبغي أن تفعل:

```text
        ocamlopt -output-complete-obj -o camlcode.o unix.cmxa other .cmx and .cmxa files
        cc -o myprog C objects and libraries \
           camlcode.o C libraries required by the runtime, eg -lm -ldl
```

##### تحذير:

في بعض المنافذ، تُشترط خيارات خاصة في خطوة الربط النهائية التي تربط ملف الكائن الناتج عن الخيارين `-output-obj` و`-output-complete-obj` بباقي البرنامج. وتُعرض تلك الخيارات في ملف التهيئة `Makefile.config` الذي يولّده بناء OCaml، في المتغيّر `OC_LDFLAGS`.

- ويندوز مع مترجم MSVC: ملفّات الكائن التي ينتجها OCaml مُترجمة بالعلم `/MD`، لذا يجب أن تُترجم كل ملفات الكائن الأخرى المربوطة معها بالعلم `/MD` أيضًا.

- سائر الأنظمة: قد تحتاج إلى إضافة `-lm` أو `-ldl` أو كليهما، حسب نظام تشغيلك ومترجم C لديك.

##### آثار المكدّس العكسية.

حين تُضمَّن شيفرة OCaml البايتية الناتجة عن `ocamlc -g` في برنامج C، لا تُضمَّن معلومات تنقيح، فيستحيل لذلك طباعة آثار المكدّس العكسية عند الاستثناءات غير الملتقَطة. وهذا لا ينطبق حين تُضمَّن الشيفرة الأصلية الناتجة عن `ocamlopt -g` في برنامج C: فمعلومات الآثار العكسية متوفّرة، لكنّ آلية الأثر العكسي يجب تشغيلها برمجيًا. ويمكن تحقيق ذلك من جانب OCaml باستدعاء `Printexc.record_backtrace true` في تهيئة إحدى وحدات OCaml. ويمكن أيضًا تحقيقه من جانب C باستدعاء `caml_record_backtraces(1);` في شيفرة الوصل بين OCaml وC. (والدالة `caml_record_backtraces` مصرَّح بها في `<caml/backtrace.h>`)

##### تفريغ نظام التشغيل من الذاكرة.

إذا كانت المكتبة المشتركة الناتجة عن `-output-obj` ستُحمَّل وتُفرَّغ مرارًا في عملية واحدة، فيجب الحرص على تفريغ نظام تشغيل OCaml صراحةً، لتفادي تسرّبات متنوّعة في موارد النظام.

ومنذ الإصدار 4.05، يمكن استعمال الدالة `caml_shutdown` لإيقاف نظام التشغيل على نحو رشيق، وهو ما يعادل ما يلي:

- تشغيل الدوال المسجَّلة بـ `Stdlib.at_exit`.

- إطلاق إنهاء الكتل المخصّصة المخصَّصة (انظر القسم 23.9). فمثلًا، تمثّل `Stdlib.in_channel` و`Stdlib.out_channel` كتلتين مخصّصتين تُغلِّفان واصفات ملفات يجب تحريرها.

- تفريغ المكتبات المشتركة التابعة التي حمّلها نظام التشغيل، بما فيها إضافات `dynlink`.

- تحرير كتل الذاكرة التي خصّصها نظام التشغيل بـ `malloc`. وداخل عمليات C الأوّلية، يُنصح باستعمال دوال `caml_stat_*` من `<caml/memory.h>` لإدارة الكتل الساكنة (أي غير المتحرّكة) من ذاكرة الكومة، لأنّ كل الكتل المخصَّصة بهذه الدوال يحرّرها `caml_shutdown` تلقائيًا. ولضمان التوافق مع وصلات C قديمة استعملت `caml_stat_*` استعمالًا خاطئًا، لا يُفعَّل هذا السلوك إلا إذا بدأ نظام التشغيل بالدالة المخصّصة `caml_startup_pooled`.

ولأنّ المكتبة المشتركة قد يكون لها عدّة عملاء في الوقت نفسه، فقد جُعل `caml_startup` (و`caml_startup_pooled`) قابلًا للاستدعاء عدّة مرّات، بشرط أن يقترن كل استدعاء منها باستدعاء مقابل لـ `caml_shutdown` (على نحو متداخل). ويُفرَّغ نظام التشغيل بمجرّد ألّا تبقى استدعاءات معلّقة لـ `caml_startup`.

وبمجرّد تفريغ نظام التشغيل، لا يمكن تشغيله مرّة أخرى دون إعادة تحميل المكتبة المشتركة وإعادة تهيئة بياناتها الساكنة. ولذلك فإنّ هذه الميزة، في الوقت الحالي، لا تُفيد إلا في بناء مكتبات مشتركة قابلة لإعادة التحميل.

##### معالجة إشارات Unix.

حسب منصّة الهدف ونظام التشغيل، قد يثبّت نظام التشغيل للشيفرة الأصلية معالجات لإشارة واحدة أو أكثر من الإشارات `SIGSEGV` و`SIGTRAP` و`SIGFPE` عند استدعاء `caml_startup`، ويعيد هذه الإشارات إلى سلوكاتها الافتراضية عند استدعاء `caml_shutdown`. وعلى البرنامج الرئيسي المكتوب بـ C ألّا يحاول معالجة هذه الإشارات بنفسه.

## 23.8 مثال متقدّم بالاستدعاءات الراجعة

يوضّح هذا القسم تسهيلات الاستدعاء الراجع الموصوفة في القسم 23.7. سنُغلِّف بعض دوال OCaml بحيث يمكن ربطها بشيفرة C واستدعاؤها من C كأيّ دالة C أخرى. والدوال المذكورة معرَّفة في المصدر OCaml التالي `mod.ml`:

```text
(* File mod.ml -- some "useful" OCaml functions *)

let rec fib n = if n < 2 then n else fib(n-1) + fib(n-2)

let format_result n = Printf.sprintf "Result is: %d\n" n

(* Export those two functions to C *)

let _ = Callback.register "fib" fib
let _ = Callback.register "format_result" format_result
```

وهذه شيفرة وصلة C لاستدعاء تلك الدوال من C:

```text
/* File modwrap.c -- wrappers around the OCaml functions */

#include <stdio.h>
#include <string.h>
#include <caml/mlvalues.h>
#include <caml/callback.h>

int fib(int n)
{
  static const value * fib_closure = NULL;
  if (fib_closure == NULL) fib_closure = caml_named_value("fib");
  return Int_val(caml_callback(*fib_closure, Val_int(n)));
}

char * format_result(int n)
{
  static const value * format_result_closure = NULL;
  if (format_result_closure == NULL)
    format_result_closure = caml_named_value("format_result");
  return strdup(String_val(caml_callback(*format_result_closure, Val_int(n))));
  /* We copy the C string returned by String_val to the C heap
     so that it remains valid after garbage collection. */
}
```

نترجم الآن شيفرة OCaml إلى ملف كائن C ونضعه في مكتبة C مع شيفرة الوصلة في `modwrap.c` ونظام تشغيل OCaml:

```text
        ocamlc -custom -output-obj -o modcaml.o mod.ml
        ocamlc -c modwrap.c
        cp `ocamlc -where`/libcamlrun.a mod.a && chmod +w mod.a
        ar r mod.a modcaml.o modwrap.o
```

(يمكن أيضًا استعمال `ocamlopt -output-obj` بدلًا من `ocamlc -custom -output-obj`. وفي هذه الحالة، استبدل `libcamlrun.a` (مكتبة تشغيل الشيفرة البايتية) بـ `libasmrun.a` (مكتبة تشغيل الشيفرة الأصلية).)

والآن يمكننا استعمال الدالتين `fib` و`format_result` في أيّ برنامج C، كأيّ دالتين C عاديتين. تذكّر فقط أن تستدعي `caml_startup` (أو `caml_startup_exn`) مرّة واحدة قبل ذلك.

```text
/* File main.c -- a sample client for the OCaml functions */

#include <stdio.h>
#include <caml/callback.h>

extern int fib(int n);
extern char * format_result(int n);

int main(int argc, char ** argv)
{
  int result;

  /* Initialize OCaml code */
  caml_startup(argv);
  /* Do some computation */
  result = fib(10);
  printf("fib(10) = %s\n", format_result(result));
  return 0;
}
```

ولبناء البرنامج كلّه، ما عليك إلا استدعاء مترجم C على النحو التالي:

```text
        cc -o prog -I `ocamlc -where` main.c mod.a -lcurses
```

(في بعض الأجهزة، قد تحتاج إلى وضع `-ltermcap` أو `-lcurses -ltermcap` بدلًا من `-lcurses`.)
## 23.9 موضوع متقدّم: الكتل المخصّصة

تبدأ الكتل ذات الوسم `Custom_tag` بمؤشّر إلى `struct` في C من النوع `struct custom_operations`، يربط دوال إنهاء ومقارنة وتجزئة وتسلسل وفكّ تسلسل يوفّرها المستخدم لهذه الكتلة.

وبعد هذا المؤشّر إلى العمليات المخصّصة، يمكن أن توجد بيانات اعتباطية من صفر أو واحد أو أكثر من الكلمات، يحدّد المستخدم دلالتها (فمثلًا قد تكون مجرّد مؤشّر إلى `struct` في C، أو `struct` في C نفسه). استعمل `Data_custom_val` على قيمة الكتلة للحصول على مؤشّر إلى بداية هذه البيانات الاعتباطية.

### 23.9.1 البنية struct custom_operations

البنية `struct custom_operations` معرَّفة في `<caml/custom.h>` وتحتوي الحقول التالية:

- `char *identifier` سلسلة محارف منتهية بالصفر، تُستعمل معرّفًا لعمليات التسلسل وفكّ التسلسل.

- `void (*finalize)(value v)` يحتوي الحقل `finalize` مؤشّرًا إلى دالة C تُستدعى حين تصبح الكتلة غير قابلة للوصول وتوشك على الاسترجاع. وتُمرَّر الكتلة وسيطًا أوّلًا إلى الدالة. ويمكن أيضًا أن يكون الحقل `finalize` مساويًا لـ `custom_finalize_default` للإشارة إلى عدم ربط أيّ دالة إنهاء بالكتلة. لاحظ التنبيه أدناه: فهناك قيود كثيرة على سلوك دوال الإنهاء هذه للكتل المخصّصة. ولمزيد من القوّة والمرونة في الإنهاء، استعمل `Gc.finalise` (انظر `Gc`).

- `int (*compare)(value v1, value v2)` يحتوي الحقل `compare` مؤشّرًا إلى دالة C تُستدعى كلّما قُورنت كتلتان مخصّصتان بمعاملات المقارنة العامة في OCaml (`=` و`<>` و`<=` و`>=` و`<` و`>` و`compare`). وينبغي أن تعيد دالة C القيمة 0 إذا كانت البيانات في الكتلتين متساوية بنيويًا، وعددًا صحيحًا سالبًا إذا كانت بيانات الكتلة الأولى أصغر من بيانات الثانية، وعددًا صحيحًا موجبًا إذا كانت بيانات الأولى أكبر من الثانية.

ويمكن ضبط الحقل `compare` على `custom_compare_default`؛ ودالة المقارنة الافتراضية هذه ترفع `Failure` فحسب.

- `int (*compare_ext)(value v1, value v2)` (منذ 3.12.1) يحتوي الحقل `compare_ext` مؤشّرًا إلى دالة C تُستدعى كلّما قُورنت كتلة مخصّصة وعدد صحيح غير معلَّب بمعاملات المقارنة العامة في OCaml (`=` و`<>` و`<=` و`>=` و`<` و`>` و`compare`). وكما في حالة الحقل `compare`، ينبغي أن تعيد دالة C القيمة 0 إذا كان الوسيطان متساويين بنيويًا، وعددًا صحيحًا سالبًا إذا كان الوسيط الأول أصغر من الثاني، وعددًا صحيحًا موجبًا إذا كان الأول أكبر من الثاني.

ويمكن ضبط الحقل `compare_ext` على `custom_compare_ext_default`؛ ودالة المقارنة الافتراضية هذه ترفع `Failure` فحسب.

- `intnat (*hash)(value v)` يحتوي الحقل `hash` مؤشّرًا إلى دالة C تُستدعى كلّما طُبِّق معامل التجزئة العام في OCaml (انظر الوحدة `Hashtbl`) على كتلة مخصّصة. ويمكن لدالة C أن تعيد عددًا صحيحًا اعتباطيًا يمثّل قيمة تجزئة البيانات في الكتلة المخصّصة المعطاة. ويجب أن تكون قيمة التجزئة متوافقة مع دالة `compare`، بمعنى أنّ بياناتين متساويتين بنيويًا (أي كتلتين مخصّصتين تعيد `compare` لهما 0) يجب أن تكون لهما قيمة التجزئة نفسها.

ويمكن ضبط الحقل `hash` على `custom_hash_default`، وفي هذه الحالة تُهمَل الكتلة المخصّصة أثناء حساب التجزئة.

- `void (*serialize)(value v, uintnat * bsize_32, uintnat * bsize_64)` يحتوي الحقل `serialize` مؤشّرًا إلى دالة C تُستدعى كلّما احتاجت الكتلة المخصّصة إلى تسلسل (تصريف) باستعمال الدالتين `output_value` أو `Marshal.to_...`. فبالنسبة إلى كتلة مخصّصة، تكتب تلك الدوال أوّلًا معرّف الكتلة (كما يعطيه الحقل `identifier`) في مجرى الخَرْج، ثم تستدعي دالة `serialize` التي يوفّرها المستخدم. وتلك الدالة مسؤولة عن كتابة البيانات في الكتلة المخصّصة، باستعمال دوال `serialize_...` المعرَّفة في `<caml/intext.h>` والمذكورة في القسم 23.9.4. ثم يجب على دالة `serialize` التي يوفّرها المستخدم أن تخزّن في وسيطيها `bsize_32` و`bsize_64` حجمي الجزء الخاص بالبيانات في الكتلة المخصّصة بالبايت، على معمارية 32 بت وعلى معمارية 64 بت على التوالي.

ويمكن ضبط الحقل `serialize` على `custom_serialize_default`، وفي هذه الحالة يُرفع الاستثناء `Failure` عند محاولة تسلسل الكتلة المخصّصة.

- `uintnat (*deserialize)(void * dst)` يحتوي الحقل `deserialize` مؤشّرًا إلى دالة C تُستدعى كلّما احتاجت كتلة مخصّصة ذات المعرّف `identifier` إلى فكّ تسلسل (إلغاء تصريف) باستعمال الدالتين `input_value` أو `Marshal.from_...`. وهذه الدالة التي يوفّرها المستخدم مسؤولة عن قراءة البيانات التي كتبتها عملية `serialize`، باستعمال دوال `deserialize_...` المعرَّفة في `<caml/intext.h>` والمذكورة في القسم 23.9.4. ثم يجب عليها إعادة بناء الجزء الخاص بالبيانات في الكتلة المخصّصة وتخزينه في المؤشّر المعطى في الوسيط `dst`. وأخيرًا، تعيد حجم الجزء الخاص بالبيانات في الكتلة المخصّصة بالبايت. ويجب أن يكون هذا الحجم مطابقًا للنتيجة `bsize_32` لعملية `serialize` إذا كانت المعمارية 32 بت، أو لـ `bsize_64` إذا كانت 64 بت.

ويمكن ضبط الحقل `deserialize` على `custom_deserialize_default` للإشارة إلى أنّ فكّ التسلسل غير مدعوم. وفي هذه الحالة، لا تسجّل `struct custom_operations` عند مفكّك التسلسل باستعمال `register_custom_operations` (انظر أدناه).

- `const struct custom_fixed_length* fixed_length` (منذ 4.08.0) يُحجز عادةً في الخَرْج المسلسَل فراغ لكتابة الحقلين `bsize_32` و`bsize_64` اللذين تعيدهما `serialize`. لكن بالنسبة إلى الكتل المخصّصة القصيرة جدًّا، قد يكون هذا الفراغ أكبر من البيانات نفسها! وكتحسين للمساحة، إذا كانت `serialize` تعيد دائمًا القيمتين نفسيهما لـ `bsize_32` و`bsize_64`، فيمكن تحديد هاتين القيمتين في البنية `fixed_length`، فلا تستهلكان مساحة في الخَرْج المسلسَل.

*تنبيه*: الدوال `finalize` و`compare` و`hash` و`serialize` و`deserialize` المرتبطة بوصفات الكتل المخصّصة لا يُسمح لها إلا بتفاعل محدود مع نظام تشغيل OCaml. فلا تستدعِ داخلها أيًّا من دوال التخصيص في OCaml، ولا تنفّذ أيّ استدعاء راجع إلى شيفرة OCaml أو تسمح بذلك (فمثلًا لا تستدعِ `caml_release_runtime_system()`). ولا تستعمل `CAMLparam` لتسجيل وسائط تلك الدوال، ولا `CAMLlocal` لتسجيل متغيّراتها المحلية، ولا `CAMLreturn` لإعادة النتيجة. ولا ترفع استثناءات. وللإبلاغ عن خطأ أثناء فكّ التسلسل، استعمل `caml_deserialize_error`، ويجوز لدالتي `serialize` و`deserialize` أن تستعملا بحرّية الدوال من القسم 23.9.4. وهناك قيود صارمة خصوصًا على سلوك دوال الإنهاء الخاصة بالكتل المخصّصة. فإضافةً إلى القيود أعلاه، يجب على دوال الإنهاء ألّا تصل إلى كومة OCaml، ولا تغيّر الكومة أو أيّ ذاكرة يمكن الوصول إليها من جذور جامع القمامة في OCaml. لكن لاحظ أنّ دوال `finalize` يجوز لها أن تستعمل بحرّية `caml_remove_global_root` و`caml_remove_generational_global_root`. وباختصار، إذا فعلت دالة إنهاء كتلة مخصّصة أيّ شيء بالقيمة التي تتلقّاها غير استدعاء `Data_custom_val` عليها، فمن المحتمل جدًّا أنها غير آمنة. وعند الشكّ، اختر الحذر.

### 23.9.2 تخصيص الكتل المخصّصة

يجب تخصيص الكتل المخصّصة عبر `caml_alloc_custom` أو `caml_alloc_custom_mem`:

تستدعى `caml_alloc_custom(`*ops*`,` *size*`,` *used*`,` *max*`)` وتعيد كتلة مخصّصة جديدة فيها متّسع لـ *size* بايت من بيانات المستخدم، وعملياتها المرتبطة معطاة بـ *ops* (مؤشّر إلى `struct custom_operations`، يُخصَّص عادةً ساكنًا كمتغيّر عام في C).

ويُستعمل الوسيطان *used* و*max* للتحكّم في سرعة جمع القمامة حين يحتوي الكائن المنهى مؤشّرات إلى موارد خارج الكومة. وبوجه عام، يعدّل جامع القمامة الرئيسي التدريجي في OCaml سرعته بحسب معدّل التخصيص في البرنامج. فكلّما أسرع البرنامج في التخصيص، اشتدّ عمل جامع القمامة ليستعيد سريعًا الكتل غير القابلة للوصول ويتفادى تراكم كمّ كبير من «القمامة الطافية» (أي الكائنات غير المشار إليها التي لم يجمعها جامع القمامة بعد).

ويُقاس معدّل التخصيص عادةً بعدّ الحجم داخل الكومة للكتل المخصَّصة. لكن يحدث كثيرًا أن تحتوي الكائنات المنهى مؤشّرات إلى كتل ذاكرة خارج الكومة وموارد أخرى (كواصفات الملفات وصور X Windows النقطية وغيرها). وبالنسبة إلى تلك الكتل، ليس الحجم داخل الكومة مقياسًا جيدًا لكمّ الموارد التي خصّصها البرنامج.

والوسيطان *used* و*max* يعطيان جامع القمامة فكرة عن كمّ الموارد خارج الكومة التي تستهلكها الكتلة المنهى الجاري تخصيصها: فتعطي كمّ الموارد المخصَّصة لهذا الكائن في الوسيط *used*، وأقصى كمّ تريد رؤيته في القمامة الطافية في الوسيط *max*. والوحدات اعتباطية: فلا يهمّ جامع القمامة إلا النسبة *used* / *max*.

فمثلًا، إذا كنت تخصّص كتلة منهى تحمل صورة X Windows نقطية بأبعاد *w* في *h* بكسل، وكنت تفضّل ألّا يتجاوز عدد الصور غير المستعادة مليون بكسل، فحدّد *used* = *w* × *h* و*max* = 1000000.

وثمّة طريقة أخرى لوصف أثر الوسيطين *used* و*max* بدلالة دورات جمع القمامة الكاملة. فإذا خصّصت كثيرًا من الكتل المخصّصة بنسبة *used* / *max* = 1 / *N*، فسيقوم جامع القمامة بدورة كاملة واحدة (يفحص فيها كل كائن في الكومة ويستدعي دوال الإنهاء على غير القابلة للوصول) كلّ *N* عملية تخصيص. فمثلًا، إذا كان *used* = 1 و*max* = 1000، فسيقوم جامع القمامة بدورة كاملة كل 1000 عملية تخصيص للكتل المخصّصة على الأقل.

وإذا كانت كتلك المنهى لا تحتوي مؤشّرات إلى موارد خارج الكومة، أو إذا لم يكن ممّا سبق معنى كبير بالنسبة إليك، فاختر ببساطة *used* = 0 و*max* = 1. أمّا إذا وجدت لاحقًا أنّ دوال الإنهاء لا تُستدعى «بما يكفي»، ففكّر في زيادة النسبة *used* / *max*.

وتستدعى `caml_alloc_custom_mem(`*ops*`,` *size*`,` *used*`)` حين لا تحمل كتلتك المخصّصة إلا ذاكرة خارج الكومة (ذاكرة مخصَّصة بـ `malloc` أو `caml_stat_alloc`) ولا أيّ موارد أخرى. وينبغي أن يكون *used* عدد بايتات الذاكرة خارج الكومة التي تحملها كتلتك المخصّصة. وتعمل هذه الدالة مثل `caml_alloc_custom`، إلا أنّ الوسيط *max* يتحكّم فيه المستخدم (عبر الوسائط `custom_major_ratio` و`custom_minor_ratio` و`custom_minor_max_size`) وهو متناسب مع أحجام الكومة. وهي متاحة منذ OCaml 4.08.0.

### 23.9.3 الوصول إلى الكتل المخصّصة

يمكن الوصول إلى الجزء الخاص بالبيانات في كتلة مخصّصة *v* عبر المؤشّر `Data_custom_val(`*v*`)`. وهذا المؤشّر من النوع `void *`، وينبغي تحويله إلى النوع الفعلي للبيانات المخزّنة في الكتلة المخصّصة.

ولا يفحص جامع القمامة محتويات الكتل المخصّصة، لذا يجب ألّا تحتوي أيّ مؤشّر إلى داخل كومة OCaml. بعبارة أخرى، لا تخزّن أبدًا قيمة OCaml من النوع `value` في كتلة مخصّصة، ولا تستعمل `Field` أو `Store_field` أو `caml_modify` للوصول إلى الجزء الخاص بالبيانات. وبالمقابل، يمكن تخزين أيّ بنية بيانات C (لا تحتوي مؤشّرات إلى الكومة) في كتلة مخصّصة.

### 23.9.5 اختيار المعرّفات

يجب اختيار المعرّفات في `struct custom_operations` بعناية، لأنها يجب أن تميّز بنية البيانات تمييزًا فريدًا في عمليات التسلسل وفكّ التسلسل. وفكّر خصوصًا في تضمين رقم إصدار في المعرّف؛ فبهذا يمكن تغيير صيغة البيانات لاحقًا، مع توفير دوال فكّ تسلسل متوافقة عكسيًا.

والمعرّفات التي تبدأ بـ `_` (محرف الشرطة السفلية) محجوزة لنظام تشغيل OCaml؛ فلا تستعملها لبياناتك المخصّصة. ونوصي باستعمال مسار URL (مثل `http://mymachine.mydomain.com/mylibrary/version-number`) أو اسم حزمة على النمط الجاوي (مثل `com.mydomain.mymachine.mylibrary.version-number`) معرّفاتٍ، لتقليل خطر تعارض المعرّفات.

### 23.9.6 الكتل المنهى

تُعمّم الكتل المخصّصة الكتل المنهى التي كانت موجودة في OCaml قبل الإصدار 3.00. وللتوافق العكسي، فصيغة الكتل المخصّصة متوافقة مع صيغة الكتل المنهى، والدالة `caml_alloc_final` لا تزال متاحة لتخصيص كتلة مخصّصة بدالة إنهاء معطاة، مع دوال مقارنة وتجزئة وتسلسل افتراضية. (وعلى وجه الخصوص، يجب ألّا تصل دالة الإنهاء إلى نظام تشغيل OCaml.)

وتعيد `caml_alloc_final(`*n*`,`*f*`,`*used*`,`*max*`)` كتلة مخصّصة جديدة بحجم *n*+1 كلمة، بدالة إنهاء *f*. والكلمة الأولى محجوزة لتخزين العمليات المخصّصة؛ والكلمات *n* الأخرى متاحة لبياناتك. ويُستعمل الوسيطان *used* و*max* للتحكّم في سرعة جمع القمامة، كما وُصف بالنسبة إلى `caml_alloc_custom`.
## 23.10 موضوع متقدّم: المصفوفات الكبيرة والواجهة بين OCaml وC

يوضّح هذا القسم كيف يمكن لشيفرة وصلة C التي تربط شيفرة C أو Fortran بشيفرة OCaml أن تستعمل المصفوفات الكبيرة (Bigarrays).

### 23.10.1 ملف التضمين

يجب تضمين ملف التضمين `<caml/bigarray.h>` في ملف وصلة C. فهو يصرّح بالدوال والثوابت والماكروات التي نناقشها أدناه.

### 23.10.2 الوصول إلى مصفوفة كبيرة في OCaml من C أو Fortran

إذا كانت *v* قيمة OCaml تمثّل مصفوفة كبيرة، فإنّ التعبير `Caml_ba_data_val(`*v*`)` يعيد مؤشّرًا إلى الجزء الخاص بالبيانات في المصفوفة. وهذا المؤشّر من النوع `void *`، ويمكن تحويله إلى نوع C المناسب للمصفوفة (مثل `double []` أو `char [][10]` أو غير ذلك).

ويمكن استشارة خصائص متنوّعة للمصفوفة الكبيرة في OCaml من C على النحو التالي:

| **تعبير C** | **ما يعيده** |
| --- | --- |
| `Caml_ba_array_val(`*v*`)->num_dims` | عدد الأبعاد |
| `Caml_ba_array_val(`*v*`)->dim[`*i*`]` | البُعد رقم *i* |
| `Caml_ba_array_val(`*v*`)->flags & CAML_BA_KIND_MASK` | نوع عناصر المصفوفة |

ونوع عناصر المصفوفة واحد من الثوابت التالية:

| **الثابت** | **نوع العنصر** |
| --- | --- |
| `CAML_BA_FLOAT16` | أعداد عائمة نصف دقيقة من 16 بت |
| `CAML_BA_FLOAT32` | أعداد عائمة أحادية الدقّة من 32 بت |
| `CAML_BA_FLOAT64` | أعداد عائمة مزدوجة الدقّة من 64 بت |
| `CAML_BA_SINT8` | أعداد صحيحة مؤشَّرة من 8 بت |
| `CAML_BA_UINT8` | أعداد صحيحة غير مؤشَّرة من 8 بت |
| `CAML_BA_SINT16` | أعداد صحيحة مؤشَّرة من 16 بت |
| `CAML_BA_UINT16` | أعداد صحيحة غير مؤشَّرة من 16 بت |
| `CAML_BA_INT32` | أعداد صحيحة مؤشَّرة من 32 بت |
| `CAML_BA_INT64` | أعداد صحيحة مؤشَّرة من 64 بت |
| `CAML_BA_CAML_INT` | أعداد صحيحة مؤشَّرة من 31 أو 63 بت |
| `CAML_BA_NATIVE_INT` | أعداد صحيحة من 32 أو 64 بت (أصلية في المنصّة) |
| `CAML_BA_COMPLEX32` | أعداد مركّبة أحادية الدقّة من 32 بت |
| `CAML_BA_COMPLEX64` | أعداد مركّبة مزدوجة الدقّة من 64 بت |
| `CAML_BA_CHAR` | محارف من 8 بت |

##### تحذير:

يجب دائمًا إلغاء إشارة `Caml_ba_array_val(`*v*`)` فورًا وعدم تخزينه في أيّ مكان، بما في ذلك المتغيّرات المحلية. فهو يُحلّ إلى مؤشّر مشتقّ: ليس قيمة OCaml صحيحة، لكنه يشير إلى منطقة ذاكرة يديرها جامع القمامة. ولهذا السبب يجب ألّا تُخزَّن هذه القيمة في أيّ موضع ذاكرة قد يبقى حيًّا عبر عملية جمع قمامة.

يوضّح المثال التالي تمرير مصفوفة كبيرة ثنائية الأبعاد إلى دالة C ودالة Fortran.

```text
    extern void my_c_function(double * data, int dimx, int dimy);
    extern void my_fortran_function_(double * data, int * dimx, int * dimy);

    CAMLprim value caml_stub(value bigarray)
    {
      int dimx = Caml_ba_array_val(bigarray)->dim[0];
      int dimy = Caml_ba_array_val(bigarray)->dim[1];
      /* C passes scalar parameters by value */
      my_c_function(Caml_ba_data_val(bigarray), dimx, dimy);
      /* Fortran passes all parameters by reference */
      my_fortran_function_(Caml_ba_data_val(bigarray), &dimx, &dimy);
      return Val_unit;
    }
```

### 23.10.3 تغليف مصفوفة C أو Fortran في صورة مصفوفة كبيرة في OCaml

يمكن تغليف مؤشّر *p* إلى مصفوفة C أو Fortran مخصَّصة سابقًا وإعادته إلى OCaml في صورة مصفوفة كبيرة باستعمال الدالتين `caml_ba_alloc` أو `caml_ba_alloc_dims`.

- `caml_ba_alloc(`*kind* `|` *layout*, *numdims*, *p*, *dims*`)`

تعيد مصفوفة كبيرة في OCaml تغلّف البيانات التي يشير إليها *p*. و*kind* نوع عناصر المصفوفة (أحد ثوابت `CAML_BA_` أعلاه). و*layout* هو `CAML_BA_C_LAYOUT` لمصفوفة بتخطيط C و`CAML_BA_FORTRAN_LAYOUT` لمصفوفة بتخطيط Fortran. و*numdims* عدد أبعاد المصفوفة. و*dims* مصفوفة من *numdims* عددًا صحيحًا طويلًا، تعطي أحجام المصفوفة في كل بُعد.

- `caml_ba_alloc_dims(`*kind* `|` *layout*, *numdims*, *p*, `(long)`*dim*₁, `(long)`*dim*₂, …, `(long)`*dim**numdims*`)`

مثل `caml_ba_alloc`، لكن أحجام المصفوفة في كل بُعد تُدرَج وسائط إضافية في استدعاء الدالة، بدلًا من تمريرها مصفوفةً.

يوضّح المثال التالي كيف يمكن إتاحة مصفوفات C وFortran المخصَّصة ساكنًا لـ OCaml.

```text
    extern long my_c_array[100][200];
    extern float my_fortran_array_[300][400];

    CAMLprim value caml_get_c_array(value unit)
    {
      long dims[2];
      dims[0] = 100; dims[1] = 200;
      return caml_ba_alloc(CAML_BA_NATIVE_INT | CAML_BA_C_LAYOUT,
                           2, my_c_array, dims);
    }

    CAMLprim value caml_get_fortran_array(value unit)
    {
      return caml_ba_alloc_dims(CAML_BA_FLOAT32 | CAML_BA_FORTRAN_LAYOUT,
                                2, my_fortran_array_, 300L, 400L);
    }
```

## 23.11 موضوع متقدّم: استدعاء C أرخص

يوضّح هذا القسم كيف نجعل استدعاء دوال C أرخص.

**ملاحظة:** لا ينطبق هذا إلا على المترجم الأصلي. فكلّما استعملت إحدى هذه الطرق، وجب أن توفّر وصلة شيفرة بايتية بديلة تُهمل كل التعليقات الخاصة.

### 23.11.1 تمرير قيم غير معلَّبة

قلنا سابقًا إنّ كل كائنات OCaml تمثّلها في C القيمة من النوع `value`، وعلى المرء أن يستعمل ماكروات مثل `Int_val` لفكّ ترميز البيانات من النوع `value`. لكن يمكن أن نطلب من مترجم الشيفرة الأصلية في OCaml أن يفعل ذلك عنّا ويمرّر الوسائط غير معلَّبة إلى دالة C. وبالمثل يمكن أن نطلب من OCaml أن يتوقّع النتيجة غير معلَّبة وأن يعلّبها لنا.

والدافع هو أنّ إيكال التعليب إلى `ocamlopt` يمكّنه غالبًا من إلغائه كلّيًا.

فمثلًا، لننظر في هذا المثال:

```text
external foo : float -> float -> float = "foo"

let f a b =
  let len = Array.length a in
  assert (Array.length b = len);
  let res = Array.make len 0. in
  for i = 0 to len - 1 do
    res.(i) <- foo a.(i) b.(i)
  done
```

المصفوفات العائمة غير معلَّبة في OCaml، لكن دالة C `foo` تتوقّع وسيطيها عددين عائمين معلَّبين وتعيد عددًا عائمًا معلَّبًا. لذا لا يملك مترجم OCaml بدًّا من تعليب `a.(i)` و`b.(i)` وفكّ تعليب نتيجة `foo`. وينتج عن ذلك تخصيص `3 * len` قيمة عائمة مؤقّتة.

والآن إذا علّمنا الوسائط والنتيجة بـ `[@unboxed]`، أمكن لمترجم الشيفرة الأصلية تجنّب كل هذه التخصيصات:

```text
external foo
  :  (float [@unboxed])
  -> (float [@unboxed])
  -> (float [@unboxed])
  = "foo_byte" "foo"
```

وفي هذه الحالة يجب أن تكون دوال C على النحو التالي:

```text
CAMLprim double foo(double a, double b)
{
  ...
}

CAMLprim value foo_byte(value a, value b)
{
  return caml_copy_double(foo(Double_val(a), Double_val(b)))
}
```

وللتسهيل، حين تُعلَّم كل الوسائط والنتيجة بـ `[@unboxed]`، يمكن وضع السمة مرّة واحدة على التصريح نفسه. فيمكن أن نكتب إذن:

```text
external foo : float -> float -> float = "foo_byte" "foo" [@@unboxed]
```

يلخّص الجدول التالي أنواع OCaml التي يمكن فكّ تعليبها، وأنواع C التي يجب استعمالها مقابلًا لها:

| **نوع OCaml** | **نوع C** |
| --- | --- |
| `float` | `double` |
| `int32` | `int32_t` |
| `int64` | `int64_t` |
| `nativeint` | `intnat` |

وبالمثل، يمكن تمرير أعداد صحيحة OCaml غير موسومة بين OCaml وC. ويُفعل ذلك بتعليم الوسائط و/أو النتيجة بـ `[@untagged]`:

```text
external f : string -> (int [@untagged]) = "f_byte" "f"
```

ويجب أن يكون نوع C المقابل `intnat`.

**ملاحظة:** لا تستعمل النوع `int` في C مقابلًا لـ `(int [@untagged])`. فالفرق بينهما في الحجم كبير في الغالب.

ويمكن تعليم أيّ نوع فوري بـ `[@untagged]`، أي أنواع تمثّل مثل `int`. ويشمل ذلك `bool` و`char` وأيّ نوع متغيّر لا يحتوي إلا بواني ثابتة. وملاحظة: لا يشمل ذلك `Unix.file_descr`، فهو لا يمثّل عددًا صحيحًا على كل المنصّات.

### 23.11.2 استدعاء C مباشر

ليتسنّى تشغيل جامع القمامة في وسط دالة C، يولّد مترجم الشيفرة الأصلية في OCaml شيفرة تدبير حول استدعاءات C. وتقنيًا، يغلّف كل استدعاء C بالدالة `caml_c_call` من نظام تشغيل OCaml.

وبالنسبة إلى الدوال الصغيرة التي تُستدعى مرارًا، قد يكون لهذا التحويل غير المباشر أثر كبير في الأداء. لكنه غير لازم إذا علمنا أنّ دالة C لا تخصّص ولا ترفع استثناءات ولا تحرّر قفل النطاق (انظر القسم 23.12.2). ويمكن إبلاغ مترجم الشيفرة الأصلية بذلك بتعليم التصريح الخارجي بالسمة `[@@noalloc]`:

```text
external bar : int -> int -> int = "foo" [@@noalloc]
```

وفي هذه الحالة يكون استدعاء `bar` من OCaml رخيصًا كاستدعاء أيّ دالة OCaml أخرى، إلا أنّ مترجم OCaml لا يستطيع تضمين دوال C…

### 23.11.3 مثال: استدعاء دوال مكتبة C بلا تحويل غير مباشر

باستعمال هذه السمات، يمكن استدعاء دوال مكتبات C بلا تحويل غير مباشر. فمثلًا، تُعرَّف كثير من الدوال الرياضية بهذه الطريقة في المكتبة القياسية لـ OCaml:

```text
external sqrt : float -> float = "caml_sqrt_float" "sqrt"
  [@@unboxed] [@@noalloc]
(** Square root. *)

external exp : float -> float = "caml_exp_float" "exp" [@@unboxed] [@@noalloc]
(** Exponential. *)

external log : float -> float = "caml_log_float" "log" [@@unboxed] [@@noalloc]
(** Natural logarithm. *)
```

## 23.12 موضوع متقدّم: تعدّد الخيوط

يتطلّب استعمال عدّة خيوط (تزامن بالذاكرة المشتركة) في تطبيق مختلط من OCaml وC احتياطات خاصة يوضّحها هذا القسم.

### 23.12.1 تسجيل الخيوط المنشأة من C

لا يمكن الاستدعاء الراجع من C إلى OCaml إلا إذا كان الخيط المستدعي معروفًا لنظام تشغيل OCaml. والخيوط المنشأة من OCaml (عبر الدالة `Thread.create` في مكتبة الخيوط النظامية) معروفة تلقائيًا لنظام التشغيل. وإذا أنشأ التطبيق خيوطًا إضافية من C وأراد أن يستدعي منها شيفرة OCaml، وجب أن يسجّلها أوّلًا عند نظام التشغيل. والدوال التالية مصرَّح بها في ملف التضمين `<caml/threads.h>`.

- `caml_c_thread_register()` تسجّل الخيط المستدعي عند نظام تشغيل OCaml. وتعيد 1 عند النجاح و0 عند الخطأ. وتسجيل خيط مسجَّل سابقًا لا يفعل شيئًا ويعيد 0.

- `caml_c_thread_register_in_domain(uintnat dom_unique_id)` تسجّل الخيط المستدعي عند نظام تشغيل OCaml في النطاق ذي المعرّف `dom_unique_id` كما يعطيه `Domain.self` و`Domain.get_id`. ويجب أن يكون النطاق قيد التشغيل عند استدعاء هذه الدالة. وتسجيل خيط مسجَّل سابقًا لا يفعل شيئًا ويعيد 0، حتى لو كان مسجَّلًا قبل ذلك في نطاق آخر. ولا يُدعم تسجيل خيط في نطاق، ثم إلغاء تسجيله، ثم تسجيله لاحقًا في نطاق مختلف.

- `caml_c_thread_unregister()` يجب استدعاؤها قبل إنهاء الخيط، لإلغاء تسجيله من نظام تشغيل OCaml. وتعيد 1 عند النجاح و0 عند الخطأ. وإذا لم يكن الخيط المستدعي مسجَّلًا سابقًا، فلا تفعل شيئًا وتعيدة 0.

### 23.12.2 التنفيذ المتوازي لشيفرة C الطويلة باستعمال الخيوط النظامية

النطاقات هي وحدة التوازي في برامج OCaml. وعند استعمال مكتبة الخيوط النظامية، قد تُربط عدّة خيوط بالنطاق نفسه. لكن في أيّ لحظة، لا يجوز أن ينفّذ إلا خيط واحد من تلك الخيوط شيفرة OCaml أو شيفرة C تستعمل نظام تشغيل OCaml، في كل نطاق. وتقنيًا، يفرض ذلك «قفل النطاق» الذي يجب أن يحمله أيّ خيط أثناء تنفيذ تلك الشيفرة داخل نطاق.

وحين يستدعي OCaml شيفرة C المنفّذة لعملية أوّلية، يكون قفل النطاق محمولًا، فتكون لشيفرة C سيطرة كاملة على تسهيلات نظام التشغيل. لكن لا يمكن لأيّ خيط آخر في النطاق نفسه أن ينفّذ شيفرة OCaml بالتوازي مع شيفرة C للعملية الأوّلية. انظر أيضًا الفصل 9.6 لسلوكه مع نطاقات متعدّدة.

وإذا استمرّت عملية C أوّلية وقتًا طويلًا أو نفّذت عمليات إدخال وإخراج قد تحجب، فيمكنها تحرير قفل النطاق صراحةً، فتمكّن خيوط OCaml الأخرى في النطاق نفسه من العمل بالتوازي مع عملياتها. ويجب على شيفرة C أن تعيد اكتساب قفل النطاق قبل العودة إلى OCaml. ويُحقَّق ذلك بالدالتين التاليتين، المصرَّح بهما في ملف التضمين `<caml/threads.h>`.

- `caml_release_runtime_system()` يحرّر الخيط المستدعي قفل النطاق وموارد OCaml الأخرى، فيمكّن الخيوط الأخرى من تنفيذ شيفرة OCaml بالتوازي مع تنفيذ الخيط المستدعي.

- `caml_acquire_runtime_system()` يعيد الخيط المستدعي اكتساب قفل النطاق وموارد OCaml الأخرى. وقد يحجب حتى لا يبقى خيط آخر في النطاق نفسه يستعمل نظام تشغيل OCaml.

تستطلع هاتان الدالتان الإشارات المعلّقة باستدعاء ردود راجعة غير متزامنة (القسم 23.5.3) قبل تحرير القفل وبعد اكتسابه. ولذا يمكنهما تنفيذ شيفرة OCaml اعتباطية، بما في ذلك رفع استثناء غير متزامن.

وبعد استدعاء `caml_release_runtime_system()` وحتى استدعاء `caml_acquire_runtime_system()`، يجب ألّا تصل شيفرة C إلى أيّ بيانات OCaml، ولا تستدعي أيّ دالة من نظام التشغيل، ولا تستدعي شيفرة OCaml. وبالتالي يجب نسخ الوسائط التي يعطيها OCaml للعملية الأوّلية إلى بنى بيانات C قبل استدعاء `caml_release_runtime_system()`، ويجب ترميز النتائج التي ستُعاد إلى OCaml كقيم OCaml بعد عودة `caml_acquire_runtime_system()`.

مثال: العملية الأوّلية التالية في C تستدعي `rmdir` لحذف دليل. وقد تحجب الدالة `rmdir` بعض الوقت، لذا نختار تحرير نظام تشغيل OCaml أثناء عملها.

```text
#include <caml/memory.h>
#include <caml/threads.h>
#include <caml/unixsupport.h>

CAMLprim value stub_rmdir(value vpath)
{
  CAMLparam1(vpath);

  /* Raise Unix.Unix_error(Unix.ENOENT, ...) if the OCaml string
     contains embedded null bytes */
  caml_unix_check_path(vpath, "rmdir");

  /* Copy the string argument to a C string, allocated outside the
     OCaml heap. */
  char_os *path = caml_stat_strdup_to_os(String_val(vpath));
  /* Release the OCaml run-time system */
  caml_release_runtime_system();

  /* Delete the directory */
#ifdef _WIN32
  int ret = _wrmdir(path);
#else
  int ret = rmdir(path);
#endif

  /* Free the copy of the string, which we might as well do before
     acquiring the runtime system to benefit from parallelism. */
  caml_stat_free(path);
  /* Re-acquire the OCaml run-time system */
  caml_acquire_runtime_system();

  /* Raise Unix.Unix_error(...) if rmdir failed */
  if (ret == -1) caml_uerror("rmdir", vpath);

  /* Return to OCaml */
  CAMLreturn(Val_unit);
}
```

تُقيَّم الماكرو `Caml_state` إلى متغيّر حالة النطاق، وتتحقّق في نمط التنقيح من أنّ قفل النطاق محمول. ويوضع تحقّق كهذا أيضًا في النمط العادي عند نقاط دخول أساسية في واجهة C؛ ولهذا قد يؤدّي استدعاء بعض دوال نظام التشغيل وماكرواته دون امتلاك قفل النطاق امتلاكًا صحيحًا إلى خطأ قاتل: `no domain lock held`. أمّا البديل `Caml_state_opt` فلا يجري أيّ تحقّق، بل يُقيَّم إلى `NULL` حين لا يكون قفل النطاق محمولًا. وهذا يتيح لك تحديد ما إذا كان خيط ينتمي إلى نطاق يحمل قفله حاليًا، لأغراض متنوّعة.

ويجب تنفيذ الاستدعاءات الراجعة من C إلى OCaml وهي تحمل قفل النطاق عند نظام تشغيل OCaml. وهذا هو الحال طبيعيًا إذا نفّذ الاستدعاء الراجع عملية C أوّلية لم تحرّر نظام التشغيل. أمّا إذا حرّرت العملية الأوّلية نظام التشغيل سابقًا، أو كان الاستدعاء الراجع يُنفَّذ من شيفرة C أخرى لم تُستدعَ من OCaml (مثل حلقة أحداث في تطبيق ذي واجهة رسومية)، فيجب اكتساب نظام التشغيل قبل الاستدعاء الراجع وتحريره بعده:

```text
  caml_acquire_runtime_system();
  /* Resolve OCaml function vfun to be invoked */
  /* Build OCaml argument varg to the callback */
  vres = callback(vfun, varg);
  /* Copy relevant parts of result vres to C data structures */
  caml_release_runtime_system();
```

ملاحظة: أُدخلت الدالتان `acquire` و`release` الموصوفتان أعلاه في OCaml 3.12. وتستعمل الشيفرة الأقدم الأسماء التاريخية التالية، المصرَّح بها في `<caml/signals.h>`:

- `caml_enter_blocking_section` بديلًا عن `caml_release_runtime_system`

- `caml_leave_blocking_section` بديلًا عن `caml_acquire_runtime_system`

والإلهام في ذلك أنّ «القسم الحاجب» قطعة من شيفرة C لا تستعمل نظام تشغيل OCaml، وهي في العادة عملية إدخال وإخراج حاجبة.

## 23.13 موضوع متقدّم: الربط البيني مع واجهات Unicode في ويندوز

يحتوي هذا القسم بعض الإرشادات العامة لكتابة وصلات C تستعمل واجهات Unicode في ويندوز.

ويمكن ضبط نظام OCaml في ويندوز، عند البناء، في أحد نمطين:

- **النمط القديم:** يُفترض أنّ كل أسماء المسارات ومتغيّرات البيئة ووسائط سطر الأوامر وغيرها، في جانب OCaml، مرمّزة بصفحة الشيفرة ذات 8 بتات الحالية للنظام.

- **نمط Unicode:** يُفترض أنّ كل أسماء المسارات ومتغيّرات البيئة ووسائط سطر الأوامر وغيرها، في جانب OCaml، مرمّزة بـ UTF-8.

وفي ما يلي، نقول إنّ سلسلة لها *ترميز OCaml* إذا كانت مرمّزة بـ UTF-8 في نمط Unicode، أو بصفحة الشيفرة الحالية في النمط القديم، أو كانت سلسلة اعتباطية تحت Unix. ونقول إنّ لها *ترميز المنصّة* إذا كانت مرمّزة بـ UTF-16 تحت ويندوز، أو سلسلة اعتباطية تحت Unix.

ومن وجهة نظر كاتب وصلات C، تحدّيان في التفاعل مع واجهات Unicode في ويندوز:

- تستعمل واجهة ويندوز ترميز UTF-16 لدعم Unicode. ويجري نظام التشغيل التحويلات اللازمة كي لا يتعامل مبرمج OCaml إلا مع ترميز OCaml. أمّا وصلات C التي تستدعي واجهات Unicode في ويندوز فتحتاج إلى دوال نظام تشغيل خاصة لإجراء التحويلات اللازمة على نحو متوافق.

- عند كتابة وصلات يجب ترجمتها تحت ويندوز وUnix معًا، يجب كتابتها على نحو يسمح بالتحويلات اللازمة تحت ويندوز ويعمل أيضًا تحت Unix، حيث لا يلزم عادةً شيء خاص لدعم Unicode.

نوع المحرف الأصلي في C تحت ويندوز هو `WCHAR`، بعرض بايتين، أما تحت Unix فهو `char`، بعرض بايت واحد. وقد عُرِّف نوع `char_os` في `<caml/misc.h>` ليدلّ على نوع المحرف الفعلي في C لكل منصّة. والسلاسل بترميز المنصّة من النوع `char_os *`.

وتُعرض الدوال التالية للمساعدة في كتابة وصلات C متوافقة. ولاستعمالها، تحتاج إلى تضمين `<caml/misc.h>` و`<caml/osdeps.h>` معًا.

- `char_os* caml_stat_strdup_to_os(const char *)` تنسخ الوسيط مع التحويل من ترميز OCaml إلى ترميز المنصّة. وتُستعمل هذه الدالة عادةً لتحويل `char *` الكامن وراء سلسلة OCaml قبل تمريره إلى واجهة نظام تشغيل تأخذ وسيطًا من نوع Unicode. وتكافئ تحت Unix الدالة `caml_stat_strdup`.

**ملاحظة:** لأقصى توافق عكسي في نمط Unicode، إذا لم يكن الوسيط سلسلة UTF-8 صحيحة، ستعود هذه الدالة إلى افتراض أنه مرمّز بصفحة الشيفرة الحالية.

- `char* caml_stat_strdup_of_os(const char_os *)` تنسخ الوسيط مع التحويل من ترميز المنصّة إلى ترميز OCaml. وهي عكس `caml_stat_strdup_to_os`. وتُستعمل هذه الدالة عادةً لتحويل سلسلة حصلت عليها من نظام التشغيل قبل تمريرها إلى شيفرة OCaml. وتكافئ تحت Unix الدالة `caml_stat_strdup`.

- `value caml_copy_string_of_os(char_os *)` تخصّص سلسلة OCaml محتواها يساوي وسيط السلسلة محوَّلًا إلى ترميز OCaml. وتكافئ هذه الدالة، في جوهرها، `caml_stat_strdup_of_os` متبوعةً بـ `caml_copy_string`، إلا أنها تتفادى تخصيص السلسلة الوسيطة التي تعيدها `caml_stat_strdup_of_os`. وتكافئ تحت Unix الدالة `caml_copy_string`.

**ملاحظة:** السلاسل التي تعيدها `caml_stat_strdup_to_os` و`caml_stat_strdup_of_os` مخصَّصة بـ `caml_stat_alloc`، لذا يجب تحريرها بـ `caml_stat_free` حين لا تبقى حاجة إليها.

##### مثال

نريد ربط الدالة `getenv` على نحو يعمل تحت Unix وويندوز معًا. وتحت Unix لهذه الدالة النموذج الأوّلي:

```text
    char *getenv(const char *);
```

أمّا نسخة Unicode تحت ويندوز فنموذجها الأوّلي:

```text
    WCHAR *_wgetenv(const WCHAR *);
```

وبدلالة `char_os`، تأخذ الدالتان وسيطًا من النوع `char_os *` وتعيدان نتيجة من النوع نفسه. نبدأ باختيار التنفيذ الصحيح للدالة المراد ربطها:

```text
#ifdef _WIN32
#define getenv_os _wgetenv
#else
#define getenv_os getenv
#endif
```

وباقي الربط هو نفسه في المنصّتين:

```text
#include <caml/mlvalues.h>
#include <caml/misc.h>
#include <caml/alloc.h>
#include <caml/fail.h>
#include <caml/osdeps.h>
#include <stdlib.h>

CAMLprim value stub_getenv(value var_name)
{
  CAMLparam1(var_name);
  CAMLlocal1(var_value);
  char_os *var_name_os, *var_value_os;

  var_name_os = caml_stat_strdup_to_os(String_val(var_name));
  var_value_os = getenv_os(var_name_os);
  caml_stat_free(var_name_os);

  if (var_value_os == NULL)
    caml_raise_not_found();

  var_value = caml_copy_string_of_os(var_value_os);

  CAMLreturn(var_value);
}
```
## 23.14 بناء مكتبات مختلطة من C وOCaml: ocamlmklib

يسهّل الأمر `ocamlmklib` بناء مكتبات تحتوي شيفرة OCaml وشيفرة C معًا، وتصلح للربط الساكن والربط الدينامي معًا. وهذا الأمر متاح تحت ويندوز منذ Objective Caml 3.11، وتحت أنظمة التشغيل الأخرى منذ Objective Caml 3.03.

ويأخذ الأمر `ocamlmklib` ثلاثة أنواع من الوسائط:

- ملفات مصدر OCaml وملفات كائن OCaml (`.cmo` و`.cmx` و`.ml`) التي تشكّل الجزء المكتوب بـ OCaml من المكتبة؛

- ملفات كائن C (`.o` و`.a`، أو `.obj` و`.lib` على الترتيب) التي تشكّل الجزء المكتوب بـ C من المكتبة؛

- مكتبات الدعم للجزء المكتوب بـ C (`-l`*lib*).

ويولّد الخَرْجات التالية:

- مكتبة شيفرة بايتية في OCaml باسم `.cma` تضمّ ملفات OCaml من نوع `.cmo` و`.ml` المعطاة وسائطَ، وتشير تلقائيًا إلى مكتبة C المولَّدة من ملفات كائن C.

- مكتبة شيفرة أصلية في OCaml باسم `.cmxa` تضمّ ملفات OCaml من نوع `.cmx` و`.ml` المعطاة وسائطَ، وتشير تلقائيًا إلى مكتبة C المولَّدة من ملفات كائن C.

- إذا كان الربط الدينامي مدعومًا على منصّة الهدف، مكتبة مشتركة باسم `.so` (أو `.dll` على الترتيب) مبنية من ملفات كائن C المعطاة وسائطَ، وتشير تلقائيًا إلى مكتبات الدعم.

- مكتبة C ساكنة باسم `.a` (أو `.lib` على الترتيب) مبنية من ملفات كائن C.

وإضافةً إلى ذلك، تُعرَف الخيارات التالية:

**`-cclib`، `-ccopt`، `-I`، `-linkall`**

تُمرَّر هذه الخيارات كما هي إلى `ocamlc` أو `ocamlopt`. انظر توثيق هذين الأمرين.

**`-rpath`، `-R`، `-Wl,-rpath`، `-Wl,-R`**

تُمرَّر هذه الخيارات كما هي إلى مترجم C. راجع توثيق مترجم C.

**`-custom`**

تفرض بناء مكتبة مربوطة ربطًا ساكنًا فقط، حتى لو كان الربط الدينامي مدعومًا.

**`-failsafe`**

ترجع إلى بناء مكتبة مربوطة ربطًا ساكنًا إذا حدثت مشكلة أثناء بناء المكتبة المشتركة (مثلًا إذا لم تكن بعض مكتبات الدعم متاحة مكتباتٍ مشتركة).

**`-L`*dir***

تضيف *dir* إلى مسار البحث عن مكتبات الدعم (`-l`*lib*).

**`-ocamlc` *cmd***

تستعمل *cmd* بدلًا من `ocamlc` لاستدعاء مترجم الشيفرة البايتية.

**`-ocamlopt` *cmd***

تستعمل *cmd* بدلًا من `ocamlopt` لاستدعاء مترجم الشيفرة الأصلية.

**`-o` *output***

تضبط اسم مكتبة OCaml المولَّدة. وسيولّد `ocamlmklib` الملف *output*`.cma` و/أو الملف *output*`.cmxa`. وإذا لم يُحدَّد، فالقيمة الافتراضية `a`.

**`-oc` *outputc***

تضبط اسم مكتبة C المولَّدة. وسيولّد `ocamlmklib` الملف `lib`*outputc*`.so` (إذا كانت المكتبات المشتركة مدعومة) والملف `lib`*outputc*`.a`. وإذا لم يُحدَّد، فالقيمة الافتراضية اسم الخَرْج المعطى بـ `-o`.

##### مثال

لننظر في واجهة OCaml للمكتبة القياسية `libz` في C لقراءة الملفات المضغوطة وكتابتها. افترض أنّ هذه المكتبة تقيم في `/usr/local/zlib`. وتتكوّن هذه الواجهة من جزء OCaml هو `zip.cmo`/`zip.cmx` وجزء C هو `zipstubs.o` يحتوي شيفرة الوصلة حول نقاط دخول `libz`. ويبني الأمر التالي مكتبتي OCaml باسم `zip.cma` و`zip.cmxa`، ومعهما مكتبتي C المرافقتين `dllzip.so` و`libzip.a`:

```text
ocamlmklib -o zip zip.cmo zip.cmx zipstubs.o -lz -L/usr/local/zlib
```

وإذا كانت المكتبات المشتركة مدعومة، نفّذ هذا الأمر الأوامر التالية:

```text
ocamlc -a -o zip.cma zip.cmo -dllib -lzip \
        -cclib -lzip -cclib -lz -ccopt -L/usr/local/zlib
ocamlopt -a -o zip.cmxa zip.cmx -cclib -lzip \
        -cclib -lzip -cclib -lz -ccopt -L/usr/local/zlib
gcc -shared -o dllzip.so zipstubs.o -lz -L/usr/local/zlib
ar rc libzip.a zipstubs.o
```

ملاحظة: هذا المثال على نظام Unix. وقد تختلف سطور الأوامر الدقيقة على أنظمة أخرى.

وإذا لم تكن المكتبات المشتركة مدعومة، نُفّذت الأوامر التالية بدلًا من ذلك:

```text
ocamlc -a -custom -o zip.cma zip.cmo -cclib -lzip \
        -cclib -lz -ccopt -L/usr/local/zlib
ocamlopt -a -o zip.cmxa zip.cmx -lzip \
        -cclib -lz -ccopt -L/usr/local/zlib
ar rc libzip.a zipstubs.o
```

وبدلًا من بناء مكتبة الشيفرة البايتية ومكتبة الشيفرة الأصلية ومكتبتي C في الوقت نفسه، يمكن استدعاء `ocamlmklib` ثلاث مرّات لبناء كل منها على حدة. فيبني الأمر

```text
ocamlmklib -o zip zip.cmo -lz -L/usr/local/zlib
```

مكتبة الشيفرة البايتية `zip.cma`، ويبني الأمر

```text
ocamlmklib -o zip zip.cmx -lz -L/usr/local/zlib
```

مكتبة الشيفرة الأصلية `zip.cmxa`، ويبني الأمر

```text
ocamlmklib -o zip zipstubs.o -lz -L/usr/local/zlib
```

مكتبتي C باسم `dllzip.so` و`libzip.a`. ولاحظ أنّ مكتبات الدعم (`-lz`) والخيارات المقابلة (`-L/usr/local/zlib`) يجب إعطاؤها في الاستدعاءات الثلاثة كلّها لـ `ocamlmklib`، لأنّ الحاجة إليها تقع في أوقات مختلفة بحسب ما إذا كانت المكتبات المشتركة مدعومة.

## 23.15 كلمة تحذير: واجهة نظام التشغيل الداخلية

لم تُوصف في الأقسام السابقة كل ملفات الترويسة المتاحة في الدليل `caml/`. وكل تلك الملفات غير المذكورة جزء من واجهة نظام التشغيل الداخلية، التي *لا* ضمانة لاستقرارها. وإذا كنت تحتاج فعلًا إلى الوصول إلى هذه الواجهة الداخلية، فيوفّر هذا القسم بعض الإرشادات التي قد تساعدك على كتابة شيفرة قد لا تنكسر مع كل إصدار جديد من OCaml.

##### ملاحظة

يُشجَّع المبرمجون الذين يعتمدون على الواجهة الداخلية في حالة استعمال يجدونها واقعية ومفيدة على فتح طلب تحسين في متتبّع العلل.

### 23.15.1 المتغيّرات الداخلية وCAML_INTERNALS

منذ OCaml 4.04، يمكن الوصول إلى كل جزء من واجهة نظام التشغيل الداخلية بتعريف الماكرو `CAML_INTERNALS` قبل تحميل ملفات ترويسة caml. وإذا لم يُعرَّف هذا الماكرو، فتُخفى أجزاء من الواجهة الداخلية.

وإذا كنت تستعمل متغيّرات C داخلية، فلا تعد تعريفها يدويًا. بل استوردها بتضمين ملفات الترويسة المقابلة. فقد تغيّر تمثيل تلك المتغيّرات مرّة واحدة في OCaml 4.10، وهو لا يزال يتطوّر. وإذا اعتمدت شيفرتك على خصائص داخلية هشّة كهذه، فستنكسر في لحظة ما.

فمثلًا، بدلًا من إعادة تعريف `caml_young_limit`:

```text
extern int caml_young_limit;
```

وهو ما ينكسر في OCaml ≥ 4.10، ينبغي أن تضمّن ترويسة `minor_gc`:

```text
#include <caml/minor_gc.h>
```

### 23.15.2 ماكروات إصدار OCaml

وأخيرًا، إذا لم يكن تضمين الترويسات الصحيحة كافيًا، أو إذا احتجت إلى دعم إصدارات أقدم من OCaml 4.04، فينبغي أن يساعدك ملف الترويسة `<caml/version.h>` على تعريف طبقة توافق خاصة بك. ويوفّر هذا الملف ماكروات قليلة تحدّد إصدار OCaml الحالي. وعلى وجه الخصوص، يصفّ الماكرو `OCAML_VERSION` الإصدار الحالي، وصيغته `MmmPP`. فمثلًا، إذا احتجت معالجة خاصة للإصدارات الأقدم من 4.10.0، يمكنك أن تكتب

```text
#include <caml/version.h>
#if OCAML_VERSION >= 41000
...
#else
...
#endif
```
