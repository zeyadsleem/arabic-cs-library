# الفصل 11: لغة OCaml

### تصدير

هذه الوثيقة مرجعٌ للغة OCaml. تسرد تراكيب اللغة، وتعطي صياغتها الدقيقة ودلالتها غير الرسمية. وليست بأيّ حال مقدّمة تعليمية إلى اللغة؛ بل يُفترض وجود معرفة عملية جيدة بـ OCaml.

لم يُسعَ إلى الصرامة الرياضية: تُستعمل الكلمات بمعناها الحدسي دون تعريف إضافي. ونتيجة لذلك، تُركت قواعد التنميط خارج النص لغياب الإطار الرياضي اللازم للتعبير عنها، مع أنها جزء لا شك فيه من تعريف رسمي كامل للغة.

### الاصطلاحات

تُعطى صياغة اللغة بترميز شبيه بترميز BNF. تُكتب الرموز الطرفية بخط الآلة الكاتبة (`like` `this`). وتُكتب الرموز غير الطرفية بخط مائل (*like* *that*). وتدلّ الأقواس المربعة […] على مكوّنات اختيارية. وتدلّ الأقواس المعقوفة {…} على تكرار صفر أو واحد أو عدة مرات للمكوّنات المحصورة بينها. وتدلّ الأقواس المعقوفة المتبوعة بعلامة زائد {…}⁺ على تكرار واحد أو عدة مرات للمكوّنات المحصورة بينها. وتدلّ الأقواس الهلالية (…) على التجميع.

## 11.1 الاصطلاحات المعجمية

#### ترميز ملف المصدر

يُفترض أن تكون ملفات مصدر OCaml نصًّا يونيكوديًا صحيحًا بترميز UTF-8. وتفسير ملفات المصدر غير المشفّرة بـ UTF-8 غير محدَّد، وقد تُرفض هذه الملفات في المستقبل.

#### الفراغات

تُعدّ الأحرف التالية فراغات: المسافة، والجدولة الأفقية، وإرجاع العربة، وتغذية السطر، وتغذية النموذج. وتُهمَل الفراغات، لكنها تفصل المعرّفات والمكوّنات الحرفية والكلمات المحجوزة المتجاورة التي كان يمكن أن تُخلَط معًا في معرّف واحد أو مكوّن حرفي واحد أو كلمة محجوزة واحدة.

#### التعليقات

تُفتتح التعليقات بالحرفين `(*` دون فراغات فاصلة، وتُغلق بالحرفين `*)` دون فراغات فاصلة. وتُعامَل التعليقات معاملة أحرف الفراغ. ولا تظهر التعليقات داخل المكوّنات الحرفية للسّلاسل أو المحارف. وتُعالَج التعليقات المتشابكة على نحو صحيح.

```ocaml
(* single line comment *)

(* multiple line comment, commenting out part of a program, and containing a
nested comment:
let f = function
  | 'A'..'Z' -> "Uppercase"
    (* Add other cases later... *)
*)
```

#### المعرّفات

```text
ident::= (letter ∣ _) { letter ∣ 0…9 ∣ _ ∣ ' } capitalized-ident::= uppercase-letter { letter ∣ 0…9 ∣ _ ∣ ' } lowercase-ident::= (\#)? (lowercase-letter ∣ _) { letter ∣ 0…9 ∣ _ ∣ ' } letter::= uppercase-letter ∣ lowercase-letter lowercase-letter::= a…z ∣ U+00DF … U+00F6 ∣ U+00F8 … U+00FF ∣ U+0153 ∣ U+0161 ∣ U+017E uppercase-letter::= A…Z ∣ U+00C0 … U+00D6 ∣ U+00D8 … U+00DE ∣ U+0152 ∣ U+0160 ∣ U+017D ∣ U+0178 ∣ U+1E9E
```

المعرّفات متتاليات من الحروف والأرقام والشرطة السفلية `_` والفاصلة العليا `'`، تبدأ بحرف أو بشرطة سفلية. وتشمل الحروف 52 حرفًا كبيرًا وصغيرًا من مجموعة ASCII، والحروف `ÀÁÂÃÄÅÆÇÈÉÊËÌÍÎÏÐÑÒÓÔÕÖØÙÚÛÜÝÞßàáâãäåæçèéêëìíîïðñòóôõöøùúûüýþÿ` من كتلة الملحق اللاتيني-1، والحروف `ŠšŽžŒœŸ` من كتلة اللاتينية الممتدّة-A، والحرف الكبير ẞ (`U+189E`). وتُدعَم أيضًا أي متتالية بايتات مكافئة لأحد هذه المحارف اليونيكودية وفق NFC[^1].

جميع المحارف في المعرّف ذات دلالة. ويقبل التنفيذ الحالي معرّفات يصل طولها إلى 16000000 محرف.

يميّز OCaml في مواضع كثيرة بين المعرّفات التي تبدأ بحرف كبير والمعرّفات التي تبدأ بحرف صغير. وتُعدّ الشرطة السفلية حرفًا صغيرًا لهذا الغرض.

ويُسمّى المعرّف الذي يبدأ بـ `\#` *معرّفًا خامًا*، وهو مكافئ للمعرّف الناتج عن حذف البادئة `\#`، إلا أن النتيجة لا تُفسَّر قطّ ككلمة محجوزة (انظر القسم 11.1).

#### المكوّنات الحرفية للأعداد الصحيحة

```text
integer-literal::= [-] (0…9) { 0…9 ∣ _ } ∣ [-] (0x ∣ 0X) (0…9 ∣ A…F ∣ a…f) { 0…9 ∣ A…F ∣ a…f ∣ _ } ∣ [-] (0o ∣ 0O) (0…7) { 0…7 ∣ _ } ∣ [-] (0b ∣ 0B) (0…1) { 0…1 ∣ _ } int32-literal::= integer-literal l int64-literal::= integer-literal L nativeint-literal::= integer-literal n
```

المكوّن الحرفي الصحيح متتالية من رقم واحد أو أكثر، قد تسبقه علامة ناقص. وتكون المكوّنات الحرفية الصحيحة بالأساس العشري (الأساس 10) افتراضيًا. وتختار البادئات التالية أساسًا مختلفًا:

| **البادئة** | **الأساس** |
| --- | --- |
| `0x`، `0X` | ست عشري (الأساس 16) |
| `0o`، `0O` | ثماني (الأساس 8) |
| `0b`، `0B` | ثنائي (الأساس 2) |

(الصفر الأولي هو الرقم صفر؛ أما `O` في النظام الثماني فهو الحرف O.) ويمكن أن يتبع المكوّن الحرفي الصحيح أحد الحروف `l` أو `L` أو `n` للدلالة على أن هذا العدد الصحيح من النوع `int32` أو `int64` أو `nativeint` على الترتيب، بدلًا من النوع الافتراضي `int` للمكوّنات الحرفية الصحيحة. وتفسير المكوّنات الحرفية الصحيحة التي تقع خارج مدى قيم الأعداد الصحيحة القابلة للتمثيل غير محدَّد.

للتيسير والوضوح، تُقبل أحرف الشرطة السفلية (`_`) داخل المكوّنات الحرفية الصحيحة (وتُهمَل).

```ocaml
# let house_number = 37
  let million = 1_000_000
  let copyright = 0x00A9
  let counter64bit = ref 0L;;

val house_number : int = 37
val million : int = 1000000
val copyright : int = 169
val counter64bit : int64 ref = {contents = 0L}
```

#### المكوّنات الحرفية للفاصلة العائمة

```text
float-literal::= [-] (0…9) { 0…9 ∣ _ } [. { 0…9 ∣ _ }] [(e ∣ E) [+ ∣ -] (0…9) { 0…9 ∣ _ }] ∣ [-] (0x ∣ 0X) (0…9 ∣ A…F ∣ a…f) { 0…9 ∣ A…F ∣ a…f ∣ _ } [. { 0…9 ∣ A…F ∣ a…f ∣ _ }] [(p ∣ P) [+ ∣ -] (0…9) { 0…9 ∣ _ }]
```

تتكوّن المكوّنات الحرفية العشرية للفاصلة العائمة من جزء صحيح وجزء كسري وجزء أُسّي. والجزء الصحيح متتالية من رقم واحد أو أكثر، قد تسبقه علامة ناقص. والجزء الكسري نقطة عشرية تتبعها صفر أو واحد أو أكثر من الأرقام. والجزء الأُسّي هو المحرف `e` أو `E` متبوعًا بإشارة `+` أو `-` اختيارية، متبوعة برقم واحد أو أكثر، ويُفسَّر كقوة للعدد 10. ويمكن إهمال الجزء الكسري أو الجزء الأُسّي، لكن لا يجوز إهمالهما معًا تجنّبًا للالتباس مع المكوّنات الحرفية الصحيحة. وتفسير المكوّنات الحرفية للفاصلة العائمة التي تقع خارج مدى قيم الفاصلة العائمة القابلة للتمثيل غير محدَّد.

وتُكتب المكوّنات الحرفية الست عشرية للفاصلة العائمة بالبادئة `0x` أو `0X`. والصياغة شبيهة بصياغة المكوّنات العشرية، مع الفروق التالية: يستعمل الجزء الصحيح والجزء الكسري أرقامًا ست عشرية، ويبدأ الجزء الأُسّي بالمحرف `p` أو `P`، ويُكتب بالتدوين العشري ويُفسَّر كقوة للعدد 2.

وللتيسير والوضوح، تُقبل أحرف الشرطة السفلية (`_`) داخل المكوّنات الحرفية للفاصلة العائمة (وتُهمَل).

```ocaml
# let pi = 3.141_592_653_589_793_12
  let small_negative = -1e-5
  let machine_epsilon = 0x1p-52;;

val pi : float = 3.14159265358979312
val small_negative : float = -1e-05
val machine_epsilon : float = 2.22044604925031308e-16
```

#### المكوّنات الحرفية للمحارف

```text
char-literal::= ' regular-char ' ∣ ' escape-sequence ' escape-sequence::= \ (\ ∣ " ∣ ' ∣ n ∣ t ∣ b ∣ r ∣ space) ∣ \ (0…9) (0…9) (0…9) ∣ \x (0…9 ∣ A…F ∣ a…f) (0…9 ∣ A…F ∣ a…f) ∣ \o (0…3) (0…7) (0…7)
```

تُحدَّد المكوّنات الحرفية للمحارف بعلامتي `'` (الفاصلة العليا). وتحيط العلامتان إمّا بمحرف واحد مختلف عن `'` و`\`، وإمّا بإحدى متتاليات الهروب أدناه:

| **المتتالية** | **المحرف المدلول عليه** |
| --- | --- |
| `\\` | الخط المائل العكسي (`\`) |
| `\"` | علامة التنصيص (`"`) |
| `\'` | الفاصلة العليا (`'`) |
| `\n` | تغذية السطر (LF) |
| `\r` | إرجاع العربة (CR) |
| `\t` | الجدولة الأفقية (TAB) |
| `\b` | مسافة الرجوع (BS) |
| `\`*space* | المسافة (SPC) |
| `\`*ddd* | المحرف ذو رمز ASCII *ddd* بالتدوين العشري |
| `\x`*hh* | المحرف ذو رمز ASCII *hh* بالتدوين الست عشري |
| `\o`*ooo* | المحرف ذو رمز ASCII *ooo* بالتدوين الثماني |

```ocaml
# let a = 'a'
  let single_quote = '\''
  let copyright = '\xA9';;

val a : char = 'a'
val single_quote : char = '\''
val copyright : char = '\169'
```

#### المكوّنات الحرفية للسّلاسل

```text
string-literal::= " { string-character } " ∣ { quoted-string-id | { newline ∣ any-char } | quoted-string-id } quoted-string-id::= { lowercase-letter ∣ _ } string-character::= regular-string-char ∣ escape-sequence ∣ \u{ { 0…9 ∣ A…F ∣ a…f }⁺ } ∣ newline ∣ \ newline { space ∣ tab }
```

تُحدَّد المكوّنات الحرفية للسّلاسل بعلامتي `"` (التنصيص). وتحيط العلامتان متتالية من المحارف المختلفة عن `"` و`\`، أو متتاليات هروب من الجدول المعطى أعلاه للمكوّنات الحرفية للمحارف، أو متتالية هروب لمحرف يونيكودي.

وتُستبدل متتالية هروب المحرف اليونيكودي بترميز UTF-8 لقيمة يونيكود العددية المحدَّدة. وتُعرَّف القيمة العددية اليونيكودية، وهي عدد صحيح في المدى 0x0000...0xD7FF أو 0xE000...0x10FFFF، باستعمال 1 إلى 6 أرقام ست عشرية، ويُسمح بالأصفار البادئة.

```ocaml
# let greeting = "Hello, World!\n"
  let superscript_plus = "\u{207A}";;

val greeting : string = "Hello, World!\n"
val superscript_plus : string = "⁺"
```

ومتتالية السطر الجديد هي تغذية سطر قد تسبقها علامة إرجاع عربة. ومنذ OCaml 5.2، تُسوّى متتالية السطر الجديد الواقعة في مكوّن حرفي سلسلي إلى محرف تغذية سطر واحد.

وللسماح بتقسيم المكوّنات الحرفية للسّلاسل الطويلة على عدة أسطر، تُهمَل المتتالية `\`*newline* *spaces-or-tabs* (خط مائل عكسي في نهاية سطر متبوعًا بأي عدد من المسافات والجدولات الأفقية في بداية السطر التالي) داخل المكوّنات الحرفية للسّلاسل.

```ocaml
# let longstr =
    "Call me Ishmael. Some years ago — never mind how long \
    precisely — having little or no money in my purse, and \
    nothing particular to interest me on shore, I thought I\
    \ would sail about a little and see the watery part of t\
    he world.";;

val longstr : string =
  "Call me Ishmael. Some years ago — never mind how long precisely — having little or no money in my purse, and nothing particular to interest me on shore, I thought I would sail about a little and see the watery part of the world."
```

توفّر الأسطر الجديدة المهروبة سلوكًا أيسر من الأسطر الجديدة غير المهروبة، إذ لا يُعدّ الإزاحة جزءًا من المكوّن الحرفي السلسلي.

```ocaml
# let contains_unexpected_spaces =
    "This multiline literal
     contains three consecutive spaces."

  let no_unexpected_spaces =
    "This multiline literal \n\
     uses a single space between all words.";;

val contains_unexpected_spaces : string =
  "This multiline literal\n   contains three consecutive spaces."
val no_unexpected_spaces : string =
  "This multiline literal \nuses a single space between all words."
```

توفّر المكوّنات الحرفية للسّلاسل المُقتبسة صياغة معجمية بديلة للمكوّنات الحرفية للسّلاسل، وهي مفيدة لتمثيل سلاسل ذات محتوى اعتباطي دون هروب. وتُحدَّد السّلاسل المُقتبسة بزوج متطابق من `{` *quoted-string-id* `|` و`|` *quoted-string-id* `}` له المعرّف *quoted-string-id* نفسه على الجانبين. ولا تفسّر السّلاسل المُقتبسة أي محرف تفسيرًا خاصًّا[^2]، لكنها تشترط ألّا تظهر المتتالية `|` *quoted-string-id* `}` في السلسلة نفسها. والمعرّف *quoted-string-id* متتالية (قد تكون فارغة) من الحروف الصغيرة والشرطات السفلية، ويمكن اختيارها بحرّية لتجنّب هذه المشكلة.

```ocaml
# let quoted_greeting = {|"Hello, World!"|}
  let nested = {ext|hello {|world|}|ext};;

val quoted_greeting : string = "\"Hello, World!\""
val nested : string = "hello {|world|}"
```

ولا يفرض التنفيذ الحالي عمليًا أي قيود على طول المكوّنات الحرفية للسّلاسل.

#### تسمية الوسوم

تجنّبًا للالتباسات، لا يمكن تعريف وسوم التسمية في التعابير صياغيًا بوصفها متتالية الرموز الثلاثة `~` و*ident* و`:` فحسب، بل يجب تعريفها على المستوى المعجمي.

```text
label-name::= lowercase-ident label::= ~ label-name : optlabel::= ? label-name :
```

تأتي وسوم التسمية على شكلين: *label* للوسائط العادية و*optlabel* للوسائط الاختيارية، ويُميَّز بينهما ببساطة بمحرفهما الأول، `~` أو `?`.

ومع أن *label* و*optlabel* كيانان معجميان في التعابير، فستُستعمل توسيعاتهما `~` *label-name* `:` و`?` *label-name* `:` في القواعد النحوية، لأجل الوضوح. ولاحظ أيضًا أن هذا التوسيع يمكن أخذه حرفيًا داخل تعابير الأنواع، أي أن هناك فعلًا 3 رموز مع فراغات اختيارية بينها.

#### رموز البادئة والوسيطة

```text
infix-symbol::= (core-operator-char ∣ % ∣ <) { operator-char } ∣ # { operator-char }⁺ prefix-symbol::= ! { operator-char } ∣ (? ∣ ~) { operator-char }⁺ operator-char::= ~ ∣ ! ∣ ? ∣ core-operator-char ∣ % ∣ < ∣ : ∣ . core-operator-char::= $ ∣ & ∣ * ∣ + ∣ - ∣ / ∣ = ∣ > ∣ @ ∣ ^ ∣ |
```

انظر أيضًا امتدادات اللغة التالية: عمليات الامتداد، وعمليات الفهرسة الممتدة، وعمليات الربط.

تُقرأ متتاليات «محارف العمليات»، مثل `<=>` أو `!!`، كرمز واحد من صنف *infix-symbol* أو *prefix-symbol*. وتُحلَّل هذه الرموز كعمليات بادئة ووسيطة داخل التعابير، لكنها تتصرّف فيما عدا ذلك كمعرّفات عادية.

#### الكلمات المحجوزة

المعرّفات أدناه محجوزة ككلمات محجوزة، ويجب تسبيقها بـ `\#` لاستعمالها على غير ذلك (انظر القسم 11.1):

```text
      and         as          assert      asr         begin       class
      constraint  do          done        downto      effect      else
      end         exception   external    false       for         fun
      function    functor     if          in          include     inherit
      initializer land        lazy        let         lor         lsl
      lsr         lxor        match       method      mod         module
      mutable     new         nonrec      object      of          open
      or          private     rec         sig         struct      then
      to          true        try         type        val         virtual
      when        while       with
```

المتتاليات المحرفية التالية كلمات محجوزة أيضًا، وهي خلافًا للمعرّفات أعلاه محجوزة دائمًا:

```text
    !=    #     &     &&    '     (     )     *     +     ,     -
    -.    ->    .     ..    .~    :     ::    :=    :>    ;     ;;
    <     <-    =     >     >]    >}    ?     [     [<    [>    [|
    ]     _     `     {     {<    |     |]    ||    }     ~
```

لاحظ أن المجموعة الدقيقة للكلمات المحجوزة يمكن تعديلها باستعمال العلم `-keywords` في سطر أوامر المترجم (انظر القسم 13.2). وأخيرًا، لاحظ أن المعرّفات التالية كلمات محجوزة في نظام Camlp4 الذي لم يبقَ مُصانًا، وينبغي تجنّبها لأسباب التوافقية الخلفية.

```text
    parser    value    $     $$    $:    <:    <<    >>    ??
```

#### الالتباسات

تُحلّ الالتباسات المعجمية وفق قاعدة «أطول مطابقة»: فعندما يمكن تفكيك متتالية محرفية إلى رمزين بطرق مختلفة، يُحتفظ بالتفكيك ذي الرمز الأول الأطول.

#### توجيهات أرقام الأسطر

```text
linenum-directive::= # { 0…9 }⁺ " { string-character } "
```

يمكن للمعالجات المسبقة التي تولّد شيفرة مصدر OCaml أن تدرج توجيهات أرقام الأسطر في مخرجاتها، حتى تحمل رسائل الخطأ التي ينتجها المترجم أرقام أسطر وأسماء ملفات تشير إلى ملف المصدر قبل المعالجة المسبقة لا بعدها. ويبدأ توجيه رقم السطر في بداية سطر، ويتكوّن من `#` (علامة الشباك) متبوعة بعدد صحيح موجب (رقم سطر المصدر) متبوعًا بسلسلة محارف (اسم ملف المصدر). وتُعامَل توجيهات أرقام الأسطر معاملة الفراغات أثناء التحليل المعجمي.

## 11.2 القيم

يصف هذا القسم أصناف القيم التي تتعامل معها برامج OCaml.

### 11.2.1 القيم الأساسية

#### الأعداد الصحيحة

قيم الأعداد الصحيحة أعداد صحيحة من −2³⁰ إلى 2³⁰−1، أي من −1073741824 إلى 1073741823. وقد يدعم التنفيذ مدى أوسع من قيم الأعداد الصحيحة: فالتنفيذ الحالي يدعم على المنصّات 64 بت أعدادًا صحيحة من −2⁶² إلى 2⁶²−1.

#### أعداد الفاصلة العائمة

قيم الفاصلة العائمة أعداد بتمثيل الفاصلة العائمة. ويستعمل التنفيذ الحالي أعداد الفاصلة العائمة مزدوجة الدقّة المطابقة لمعيار IEEE 754، بطول 53 بت للعاتق وأُسّ يتراوح بين −1022 و1023.

#### المحارف

تُمثَّل قيم المحارف كأعداد صحيحة بطول 8 بت بين 0 و255. وتُفسَّر رموز المحارف بين 0 و127 وفق معيار ASCII، ويفسّر التنفيذ الحالي رموز المحارف بين 128 و255 وفق معيار ISO 8859-1.

#### سلاسل المحارف

قيم السّلاسل متتاليات منتهية من المحارف. ويدعم التنفيذ الحالي سلاسل تحوي حتى 2²⁴ − 5 محرفًا (16777211 محرفًا)؛ وتكون الحدود على المنصّات 64 بت 2⁵⁷ − 9.

### 11.2.2 الصفوف

تُكتب صفوف القيم `(`*v*₁`،` …`،` *v**n*`)`، وتدلّ على الصف ذي الرتبة *n* من القيم *v*₁ إلى *v**n*. ويدعم التنفيذ الحالي صفوفًا تحوي حتى 2²² − 1 عنصرًا (4194303 عنصرًا).

### 11.2.3 السجلات

قيم السجلات صفوف موسومة من القيم. وقيمة السجل المكتوبة `{` *field*₁ `=` *v*₁`;` …`;` *field**n* `=` *v**n* `}` تربط القيمة *v**i* بحقل السجل *field**i*، حيث *i* = 1 … *n*. ويدعم التنفيذ الحالي سجلات تحوي حتى 2²² − 1 حقلًا (4194303 حقلًا).

### 11.2.4 المصفوفات

المصفوفات متتاليات منتهية متغيّرة الحجم من قيم من النوع نفسه. ويدعم التنفيذ الحالي مصفوفات تحوي حتى 2²² − 1 عنصرًا (4194303 عنصرًا) إلا إذا كانت العناصر أعداد فاصلة عائمة (2097151 عنصرًا في هذه الحالة)؛ وتكون الحدود على المنصّات 64 بت 2⁵⁴ − 1 لجميع المصفوفات.

### 11.2.5 قيم المتغيّرات

قيم المتغيّرات إمّا بانٍ ثابت، وإمّا بانٍ غير ثابت مطبَّق على عدد من القيم. وتُكتب الحالة الأولى *constr*، وتُكتب الحالة الثانية *constr* `(`*v*₁`،` ... `،` *v**n* `)`، حيث يقال عن القيم *v**i* إنها وسائط الباني غير الثابت *constr*. ويمكن إهمال الأقواس إذا كان هناك وسيط واحد فقط.

وتُعامَل الثوابت التالية كبوانٍ ثابتة مدمجة:

| **الثابت** | **الباني** |
| --- | --- |
| `false` | القيمة المنطقية false |
| `true` | القيمة المنطقية true |
| `()` | قيمة «الوحدة» |
| `[]` | القائمة الفارغة |

ويحدّ التنفيذ الحالي كل نوع متغيّر بأن يكون فيه على الأكثر 246 بانيًا غير ثابت و2³⁰−1 بانيًا ثابتًا.

### 11.2.6 المتغيّرات متعدّدة الأشكال

المتغيّرات متعدّدة الأشكال شكل بديل من قيم المتغيّرات، لا ينتمي صراحةً إلى نوع متغيّر معرَّف مسبقًا، ويتبع قواعد تنميط خاصة. ويمكن أن تكون ثابتة، وتُكتب `````*tag-name*، أو غير ثابتة، وتُكتب `````*tag-name*`(`*v*`)`.

### 11.2.7 الدوال

قيم الدوال تطبيقات من قيم إلى قيم.

### 11.2.8 الكائنات

تتكوّن الكائنات من حالة داخلية مخفيّة هي سجل من متغيّرات النسخة، ومن مجموعة دوال للوصول إلى هذه المتغيّرات وتعديلها. ويوصف بنيان الكائن بالصنف الأعلى الذي أنشأه.

## 11.3 الأسماء

تُستعمل المعرّفات لإعطاء أسماء لعدة أصناف من كائنات اللغة وللإشارة إلى هذه الكائنات بالاسم لاحقًا. وهذه الأصناف هي:

- أسماء القيم (الصنف الصياغي *value-name*)،

- بواني القيم وبواني الاستثناءات (الصنف *constr-name*)،

- الوسوم (*label-name*، معرَّفة في القسم 11.1)،

- وسوم المتغيّرات متعدّدة الأشكال (*tag-name*)،

- بواني الأنواع (*typeconstr-name*)،

- حقول السجلات (*field-name*)،

- أسماء الأصناف (*class-name*)،

- أسماء الدوال (*method-name*)،

- أسماء متغيّرات النسخة (*inst-var-name*)،

- أسماء الوحدات (*module-name*)،

- أسماء أنواع الوحدات (*modtype-name*).

وتُميَّز فضاءات الأسماء الأحد عشر هذه بالسياق وبحالة أحرف المعرّف: هل حرفه الأول صغير (يُكتب *lowercase-ident* أدناه) أم كبير (يُكتب *capitalized-ident*)؛ وتُعدّ الشرطة السفلية حرفًا صغيرًا لهذا الغرض.

#### تسمية الكائنات

```text
value-name::= lowercase-ident ∣ ( operator-name ) operator-name::= prefix-symbol ∣ infix-op infix-op::= infix-symbol ∣ * ∣ + ∣ - ∣ -. ∣ = ∣ != ∣ < ∣ > ∣ or ∣ || ∣ & ∣ && ∣ := ∣ mod ∣ land ∣ lor ∣ lxor ∣ lsl ∣ lsr ∣ asr constr-name::= capitalized-ident tag-name::= capitalized-ident typeconstr-name::= lowercase-ident field-name::= lowercase-ident module-name::= capitalized-ident modtype-name::= ident class-name::= lowercase-ident inst-var-name::= lowercase-ident method-name::= lowercase-ident
```

انظر أيضًا امتداد اللغة التالي: عمليات الفهرسة الممتدة.

كما يظهر أعلاه، يمكن استعمال رموز البادئة والوسيطة وبعض الكلمات المحجوزة كأسماء قيم، بشرط كتابتها بين قوسين. وتُلخَّص قواعد حالة الأحرف في الجدول أدناه.

| **فضاء الأسماء** | **حالة الحرف الأول** |
| --- | --- |
| القيم | صغير |
| البواني | كبير |
| الوسوم | صغير |
| وسوم المتغيّرات متعدّدة الأشكال | كبير |
| الاستثناءات | كبير |
| بواني الأنواع | صغير |
| حقول السجلات | صغير |
| الأصناف | صغير |
| متغيّرات النسخة | صغير |
| الدوال | صغير |
| الوحدات | كبير |
| أنواع الوحدات | أي حالة |

*ملاحظة على وسوم المتغيّرات متعدّدة الأشكال:* يقبل التنفيذ الحالي الوسوم الصغيرة إضافة إلى الوسوم الكبيرة، لكننا ننصح بتجنّب الوسوم الصغيرة لأسباب قابلية النقل والتوافقية مع إصدارات OCaml المستقبلية.

#### الإشارة إلى الكائنات المسمّاة

```text
value-path::= [ module-path . ] value-name constr::= [ module-path . ] constr-name typeconstr::= [ extended-module-path . ] typeconstr-name field::= [ module-path . ] field-name modtype-path::= [ extended-module-path . ] modtype-name class-path::= [ module-path . ] class-name classtype-path::= [ extended-module-path . ] class-name module-path::= module-name { . module-name } extended-module-path::= extended-module-name { . extended-module-name } extended-module-name::= module-name { ( extended-module-path ) }
```

يمكن الإشارة إلى كائن مسمّى إمّا باسمه (وفق قواعد النطاق الساكن المعتادة للأسماء)، وإمّا بمسار وصول *prefix* `.` *name*، حيث يدلّ *prefix* على وحدة و*name* على اسم كائن معرَّف في تلك الوحدة. والمكوّن الأول من المسار، *prefix*، إمّا اسم وحدة بسيط وإمّا مسار وصول *name*₁ `.` *name*₂ …، إذا كانت الوحدة المعرِّفة متداخلة هي نفسها داخل وحدات أخرى. وللإشارة إلى بواني الأنواع أو أنواع الوحدات أو أنواع الأصناف، يمكن أن يحوي *prefix* أيضًا تطبيقات موصِّلات بسيطة (كما في الصنف الصياغي *extended-module-path* أعلاه)، إذا كانت الوحدة المعرِّفة ناتجة عن تطبيق موصِّل.

ولا تحتاج أسماء الوسوم وأسماء العلامات وأسماء الدوال وأسماء متغيّرات النسخة إلى التأهيل: فالأولان عالميان، والأخيران محليان في الصنف.

## 11.4 تعابير الأنواع

```text
typexpr::= ' ident ∣ _ ∣ ( typexpr ) ∣ [[?]label-name:] typexpr -> typexpr ∣ typexpr { * typexpr }⁺ ∣ typeconstr ∣ typexpr typeconstr ∣ ( typexpr { , typexpr } ) typeconstr ∣ typexpr as ' ident ∣ polymorphic-variant-type ∣ < [..] > ∣ < method-type { ; method-type } [; ∣ ; ..] > ∣ # classtype-path ∣ typexpr # class-path ∣ ( typexpr { , typexpr } ) # class-path poly-typexpr::= typexpr ∣ { ' ident }⁺ . typexpr method-type::= method-name : poly-typexpr
```

انظر أيضًا امتدادات اللغة التالية: وحدات من الدرجة الأولى، والسمات، وعقد الامتداد، والصفوف الموسومة.

يبيّن الجدول أدناه الأولويات النسبية والترابط لعمليات البناء غير المغلقة للأنواع والعمليات عليها. وتأتي البنى ذات الأولوية الأعلى أولًا.

| **العملية** | **الترابط** |
| --- | --- |
| تطبيق باني نوع | – |
| `#` | – |
| `*` | – |
| `->` | يميني |
| `as` | – |

تدلّ تعابير الأنواع على أنواع في تعريفات أنواع البيانات كما في قيود الأنواع على الأنماط والتعابير.

#### متغيّرات الأنواع

يدلّ تعبير النوع `'` *ident* على متغيّر النوع المسمّى *ident*. ويدلّ تعبير النوع `_` على متغيّر نوع مجهول أو على معاملات نوع مجهولة. وفي تعريفات أنواع البيانات، تكون متغيّرات الأنواع أسماء لمعاملات نوع البيانات. وفي قيود الأنواع، تمثّل أنواعًا غير محدَّدة يمكن أن يُجزَّأ عليها أيّ نوع لتحقيق قيد النوع. وبوجه عام، نطاق متغيّر نوع مسمّى هو العبارة العليا كلها التي يظهر فيها، ولا يمكن تعميمه إلا عند مغادرة هذا النطاق. أما المتغيّرات المجهولة فليس عليها هذا القيد. وفي الحالات التالية يُقصَر نطاق متغيّرات الأنواع المسمّاة على تعبير النوع الذي تظهر فيه: 1) متغيّرات الأنواع الكلّية (متعدّدة الأشكال صراحةً)؛ 2) متغيّرات الأنواع التي تظهر فقط في مواصفات الدوال العمومية (إذ ستُجعل هذه المتغيّرات كلّية، كما هو موصوف في القسم 11.9.1)؛ 3) المتغيّرات المستعملة كأسماء بديلة، عندما يكون النوع الذي يُكنّى به غير صالح في نطاق التعريف المحيط (أي عندما يحوي متغيّرات أنواع كلّية حرّة أو أنواعًا معرَّفة محليًا).

#### الأنواع بين قوسين

يدلّ تعبير النوع `(` *typexpr* `)` على النوع نفسه الذي يدلّ عليه *typexpr*.

#### أنواع الدوال

يدلّ تعبير النوع *typexpr*₁ `->` *typexpr*₂ على نوع الدوال التي تطابق وسائط من النوع *typexpr*₁ إلى نتائج من النوع *typexpr*₂.

ويدلّ *label-name* `:` *typexpr*₁ `->` *typexpr*₂ على نوع الدالة نفسه، لكن الوسيط موسوم بـ *label*.

ويدلّ `?` *label-name* `:` *typexpr*₁ `->` *typexpr*₂ على نوع الدوال التي تطابق وسيطًا موسومًا اختياريًا من النوع *typexpr*₁ إلى نتائج من النوع *typexpr*₂. أي إن النوع الفيزيائي للدالة سيكون *typexpr*₁ `option` `->` *typexpr*₂.

#### أنواع الصفوف

يدلّ تعبير النوع *typexpr*₁ `*` … `*` *typexpr**n* على نوع الصفوف التي تنتمي عناصرها إلى الأنواع *typexpr*₁ … *typexpr**n* على الترتيب.

#### الأنواع المبنيّة

بواني الأنواع التي لا معامل لها، كما في *typeconstr*، تعابير أنواع.

ويدلّ تعبير النوع *typexpr* *typeconstr*، حيث *typeconstr* باني نوع ذو معامل واحد، على تطبيق باني النوع الأحادي *typeconstr* على النوع *typexpr*.

ويدلّ تعبير النوع (*typexpr*₁،…،*typexpr**n*) *typeconstr*، حيث *typeconstr* باني نوع ذو *n* من المعاملات، على تطبيق باني النوع ذي الرتبة *n* على الأنواع *typexpr*₁ حتى *typexpr**n*.

وفي تعبير النوع `_` *typeconstr*، يقوم تعبير النوع المجهول `_` مقام معاملات نوع مجهولة، وهو مكافئ لـ (`_`، …،`_`) بعدد تكرارات لـ `_` يساوي رتبة *typeconstr*.

#### الأنواع المكنّاة والعودية

يدلّ تعبير النوع *typexpr* `as` `'` *ident* على النوع نفسه الذي يدلّ عليه *typexpr*، ويربط أيضًا متغيّر النوع *ident* بالنوع *typexpr* في *typexpr* وفي أنواع أخرى. وبوجه عام، نطاق الكنية هو نطاق متغيّر نوع مسمّى، ويغطّي التعريف المحيط كله. وإذا ظهر متغيّر النوع *ident* فعلًا في *typexpr*، نشأ نوع عودي. وتُرفض الأنواع العودية التي يوجد لها مسار عودي لا يحوي باني نوع كائن أو متغيّر متعدّد الأشكال، إلا عند اختيار النمط `-rectypes`.

وإذا دلّ `'` *ident* على متغيّر متعدّد الأشكال صريح، ودلّ *typexpr* على نوع كائن أو متغيّر متعدّد الأشكال، أُسر متغيّر الصف في *typexpr* بـ `'` *ident* وكُمّم عليه.

#### أنواع المتغيّرات متعدّدة الأشكال

```text
polymorphic-variant-type::= [ tag-spec-first { | tag-spec } ] ∣ [> [ tag-spec ] { | tag-spec } ] ∣ [< [|] tag-spec-full { | tag-spec-full } [ > { `tag-name }⁺ ] ] tag-spec-first::= `tag-name [ of typexpr ] ∣ [ typexpr ] | tag-spec tag-spec::= `tag-name [ of typexpr ] ∣ typexpr tag-spec-full::= `tag-name [ of [&] typexpr { & typexpr } ] ∣ typexpr
```

توصف أنواع المتغيّرات متعدّدة الأشكال القيم التي قد يأخذها المتغيّر متعدّد الأشكال.

الحالة الأولى نوع متغيّر تام: جميع الوسوم الممكنة معروفة، مع أنواعها المرتبطة، ويمكن أن تكون كلها حاضرة. وبنيانه معروف تمامًا.

والحالة الثانية نوع متغيّر مفتوح، يصف قيمة متغيّر متعدّد الأشكال: فهو يعطي قائمة جميع الوسوم التي قد تأخذها القيمة، مع أنواعها المرتبطة. ولا يزال هذا النوع متوافقًا مع نوع متغيّر يحوي وسومًا أكثر. والحالة الخاصة هي النوع المجهول، الذي لا يعرّف أيّ وسم ويكون متوافقًا مع أيّ نوع متغيّر.

والحالة الثالثة نوع متغيّر مغلق. فهو يعطي معلومات عن جميع الوسوم الممكنة وأنواعها المرتبطة، وعن الوسوم المعروفة التي قد تظهر في القيم. والنوع المتغيّر التام (الحالة الأولى) ليس إلا اختصارًا لنوع متغيّر مغلق تكون فيه جميع الوسوم الممكنة حاضرة أيضًا.

وفي الحالات الثلاث، يمكن تحديد الوسوم مباشرةً في الصيغة `````*tag-name* [`of` *typexpr*]، أو بشكل غير مباشر عبر تعبير نوع يجب أن يتمدّد إلى نوع متغيّر تام تُدرَج مواصفات وسومه في مكانه.

ولا تُستعمل المواصفات الكاملة لوسوم المتغيّرات إلا في الأنواع المغلقة غير التامة. ويمكن فهمها كنوع عطفي للوسيط: يُراد بها أن تكون جميع الأنواع المذكورة في المواصفة.

وقد تكون هذه القيود العطفية غير قابلة للإرضاء. وفي هذه الحالة قد لا يمكن استعمال الوسم المقابل في قيمة من هذا النوع. ولا يعني ذلك أن النوع كُلّه غير صالح: فما زال بإمكان المرء استعمال وسوم أخرى متاحة. والقيود العطفية مخصَّصة أساسًا لأن تكون مخرجات من مدقّق الأنواع؛ وعندما تُستعمل في برامج مصدرية، قد تسبّب القيود غير القابلة للحلّ إخفاقات مبكّرة.

#### أنواع الكائنات

نوع كائن `<` [*method-type* { `;` *method-type* }] `>` هو سجل من أنواع الدوال.

ويمكن أن يكون لكل دالة نوع متعدّد الأشكال صريح: { `'` *ident* }⁺ `.` *typexpr*. ولمتغيّرات الأنواع الصريحة نطاق محلي، ولا يمكن توحيد نوع متعدّد الأشكال صريح إلا مع نوع مكافئ، حيث لا يتغيّر إلا ترتيب متغيّرات الأنواع وأسماؤها.

والنوع `<` { *method-type* `;` } `..` `>` هو نوع كائن توصف أسماء دواله وأنواعها بـ *method-type*₁ … *method-type**n*، وربما بدوال أخرى تمثّلها القطع. وهذه القطع في الحقيقة نوع خاص من متغيّرات الأنواع (يُسمّى *متغيّر صف* في الأدبيات) يقوم مقام أي عدد من أنواع الدوال الإضافية.

#### أنواع `#`

النوع `#` *classtype-path* نوع خاص من الاختصارات. وهو يتوحّد مع نوع أي كائن ينتمي إلى صنف فرعي من نوع الصنف *classtype-path*. ويُعالَج على نحو خاص لأنه عادةً يخفي متغيّر نوع (قطعة تمثّل الدوال التي قد تُضاف في صنف فرعي). وعلى وجه الخصوص، يتلاشى عندما يُجزَّأ عليه. وكل تعبير نوع `#` *classtype-path* يعرّف متغيّر نوع جديدًا، لذا فالنوع `#` *classtype-path* `->` `#` *classtype-path* ليس عادةً النوع نفسه (`#` *classtype-path* `as` `'` *ident*) `->` `'` *ident*.

#### أنواع المتغيّرات وأنواع السجلات

لا توجد تعابير أنواع تصف أنواع المتغيّرات (المعرَّفة) ولا أنواع السجلات، لأنها دائمًا مسمّاة، أي معرَّفة قبل الاستعمال ويُشار إليها بالاسم. وتُوصف تعريفات الأنواع في القسم 11.8.1.

## 11.5 الثوابت

```text
constant::= integer-literal ∣ int32-literal ∣ int64-literal ∣ nativeint-literal ∣ float-literal ∣ char-literal ∣ string-literal ∣ constr ∣ false ∣ true ∣ () ∣ begin end ∣ [] ∣ [||] ∣ `tag-name
```

انظر أيضًا امتداد اللغة التالي: المكوّنات الحرفية للامتدادات.

يضمّ الصنف الصياغي للثوابت المكوّنات الحرفية من الأنواع الأساسية الأربعة (الأعداد الصحيحة، وأعداد الفاصلة العائمة، والمحارف، وسلاسل المحارف)، والمتغيّرات الصحيحة، والبواني الثابتة من المتغيّرات العادية والمتغيّرات متعدّدة الأشكال، إضافةً إلى الثوابت الخاصة `false` و`true` و`()` و`[]` و`[||]` التي تتصرّف كبوانٍ ثابتة، و`begin` `end` المكافئ لـ `()`.

الأنماط قوالب تتيح اختيار بنى بيانات ذات شكل معيّن، وربط معرّفات بمكوّنات بنية البيانات. وتُسمّى عملية الاختيار هذه مطابقة الأنماط؛ ونتيجتها إمّا «هذه القيمة لا تطابق هذا النمط»، وإمّا «هذه القيمة تطابق هذا النمط، وينتج عن ذلك عمليات ربط الأسماء بالقيم التالية».

#### أنماط المتغيّرات

النمط الذي يتكوّن من اسم قيمة يطابق أي قيمة، ويربط الاسم بالقيمة. والنمط `_` يطابق أي قيمة أيضًا، لكنه لا يربط أي اسم.

```ocaml
# let is_empty = function
    | [] -> true
    | _ :: _ -> false;;

val is_empty : 'a list -> bool = <fun>
```

الأنماط *خطّية*: لا يمكن ربط متغيّر واحد عدة مرات بنمط معيّن. وعلى وجه الخصوص، لا سبيل إلى اختبار تساوي جزأين من بنية بيانات باستعمال نمط وحده:

```ocaml
# let pair_equal = function
    | x, x -> true
    | x, y -> false;;

Error: Variable x is bound several times in this matching
```

غير أننا نستطيع استعمال حارس `when` لهذا الغرض:

```ocaml
# let pair_equal = function
    | x, y when x = y -> true
    | _ -> false;;

val pair_equal : 'a * 'a -> bool = <fun>
```

#### أنماط الثوابت

النمط الذي يتكوّن من ثابت يطابق القيم المساوية لهذا الثابت.

```ocaml
# let bool_of_string = function
    | "true" -> true
    | "false" -> false
    | _ -> raise (Invalid_argument "bool_of_string");;

val bool_of_string : string -> bool = <fun>
```

#### أنماط الكنى

النمط *pattern*₁ `as` *value-name* يطابق القيم نفسها التي يطابقها *pattern*₁. فإذا نجحت مطابقة *pattern*₁، رُبط الاسم *value-name* بالقيمة المطابَقة، إضافةً إلى عمليات الربط التي تجريها مطابقة *pattern*₁.

```ocaml
# let sort_pair ((x, y) as p) =
    if x <= y then p else (y, x);;

val sort_pair : 'a * 'a -> 'a * 'a = <fun>
```

#### الأنماط بين قوسين

النمط `(` *pattern*₁ `)` يطابق القيم نفسها التي يطابقها *pattern*₁. ويمكن أن يظهر قيد نوع في نمط بين قوسين، كما في `(` *pattern*₁ `:` *typexpr* `)`. ويفرض هذا القيد أن يكون نوع *pattern*₁ متوافقًا مع *typexpr*.

```ocaml
# let int_triple_is_ordered ((a, b, c) : int * int * int) =
    a <= b && b <= c;;

val int_triple_is_ordered : int * int * int -> bool = <fun>
```

#### أنماط «أو»

النمط *pattern*₁ `|` *pattern*₂ يمثّل «أو» المنطقية للنمطين *pattern*₁ و*pattern*₂. وتطابق القيمة *pattern*₁ `|` *pattern*₂ إذا طابقت *pattern*₁ أو *pattern*₂. ويجب أن يربط النمطان الفرعيان *pattern*₁ و*pattern*₂ المعرّفات نفسها بالضبط بقيم من الأنواع نفسها. وتجري المطابقة من اليسار إلى اليمين. وبدقّة أكثر: إذا كانت قيمة *v* ما تطابق *pattern*₁ `|` *pattern*₂، فعمليات الربط التي تجري هي عمليات *pattern*₁ عندما تطابق *v* النمط *pattern*₁؛ وإلا فإن القيمة *v* تطابق *pattern*₂ وتجري عمليات ربطه.

```ocaml
# type shape = Square of float | Rect of (float * float) | Circle of float

  let is_rectangular = function
    | Square _ | Rect _ -> true
    | Circle _ -> false;;

type shape = Square of float | Rect of (float * float) | Circle of float
val is_rectangular : shape -> bool = <fun>
```

#### أنماط المتغيّرات

النمط *constr* `(` *pattern*₁ `،` … `،` *pattern**n* `)` يطابق جميع المتغيّرات التي يساوي بانيها *constr* وتطابق وسائطها *pattern*₁ … *pattern**n*. ويُعدّ خطأ نوعًا أن لا يكون *n* هو عدد الوسائط التي يتوقعها الباني.

والنمط *constr* `_` يطابق جميع المتغيّرات التي بانيها *constr*.

```ocaml
# type 'a tree = Lf | Br of 'a tree * 'a * 'a tree

  let rec total = function
    | Br (l, x, r) -> total l + x + total r
    | Lf -> 0;;

type 'a tree = Lf | Br of 'a tree * 'a * 'a tree
val total : int tree -> int = <fun>
```

والنمط *pattern*₁ `::` *pattern*₂ يطابق القوائم غير الفارغة التي تطابق رؤوسها *pattern*₁ وتطابق أذنابها *pattern*₂.

والنمط `[` *pattern*₁ `;` … `;` *pattern**n* `]` يطابق قوائم طولها *n* تطابق عناصرها *pattern*₁ … *pattern**n* على الترتيب. ويتصرّف هذا النمط كالنمط *pattern*₁ `::` … `::` *pattern**n* `::` `[]`.

```ocaml
# let rec destutter = function
    | [] -> []
    | [a] -> [a]
    | a :: b :: t -> if a = b then destutter (b :: t) else a :: destutter (b :: t);;

val destutter : 'a list -> 'a list = <fun>
```

#### أنماط المتغيّرات متعدّدة الأشكال

النمط `````*tag-name* *pattern*₁ يطابق جميع المتغيّرات متعدّدة الأشكال التي يساوي وسمها *tag-name* ويطابق وسيطها *pattern*₁.

```ocaml
# let rec split = function
    | [] -> ([], [])
    | h :: t ->
        let ss, gs = split t in
          match h with
          | `Sheep _ as s -> (s :: ss, gs)
          | `Goat _ as g -> (ss, g :: gs);;

val split :
  [< `Goat of 'a | `Sheep of 'b ] list ->
  [> `Sheep of 'b ] list * [> `Goat of 'a ] list = <fun>
```

#### أنماط اختصار المتغيّرات متعدّدة الأشكال

إذا عُرّف النوع [`('a,'b,`…`)`] *typeconstr* = `[` `````*tag-name*₁ *typexpr*₁ `|` … `|` `````*tag-name**n* *typexpr**n*`]`، فإن النمط `#`*typeconstr* اختصار للنمط «أو» التالي: `(` `````*tag-name*₁`(_` `:` *typexpr*₁`)` `|` … `|` `````*tag-name**n*`(_` `:` *typexpr**n*`))`. وهو يطابق جميع القيم من النوع `[<` *typeconstr* `]`.

```ocaml
# type 'a rectangle = [`Square of 'a | `Rectangle of 'a * 'a]
  type 'a shape = [`Circle of 'a | 'a rectangle]

  let try_rectangle = function
    | #rectangle as r -> Some r
    | `Circle _ -> None;;

type 'a rectangle = [ `Rectangle of 'a * 'a | `Square of 'a ]
type 'a shape = [ `Circle of 'a | `Rectangle of 'a * 'a | `Square of 'a ]
val try_rectangle :
  [< `Circle of 'a | `Rectangle of 'b * 'b | `Square of 'b ] ->
  [> `Rectangle of 'b * 'b | `Square of 'b ] option = <fun>
```

#### أنماط الصفوف

النمط *pattern*₁ `،` … `،` *pattern**n* يطابق الصفوف ذات الرتبة *n* التي تطابق مكوّناتها الأنماط *pattern*₁ حتى *pattern**n*. أي إن النمط يطابق قيم الصفوف (*v*₁، …، *v**n*) بحيث يطابق *pattern**i* القيمة *v**i* لكل *i* = 1،…، *n*.

```ocaml
# let vector (x0, y0) (x1, y1) =
    (x1 -. x0, y1 -. y0);;

val vector : float * float -> float * float -> float * float = <fun>
```

#### أنماط السجلات

النمط `{` *field*₁ [`=` *pattern*₁] `;` … `;` *field**n* [`=` *pattern**n*] `}` يطابق السجلات التي تعرّف على الأقل الحقول *field*₁ حتى *field**n*، والتي تطابق فيها القيمة المرتبطة بـ *field**i* النمط *pattern**i*، لكل *i* = 1،…، *n*. والمعرّف الواحد *field**k* يقوم مقام *field**k* `=` *field**k*، والمعرّف المؤهَّل الواحد *module-path* `.` *field**k* يقوم مقام *module-path* `.` *field**k* `=` *field**k*. ويمكن أن تعرّف قيمة السجل حقولًا أكثر من *field*₁…*field**n*، ولا تُؤخذ القيم المرتبطة بهذه الحقول الإضافية في الحسبان أثناء المطابقة. ويمكن اختياريًا إنهاء نمط السجل بـ `;` `_` للإفضاء عن أن جميع حقول نوع السجل ليست مدرَجة في نمط السجل وأن ذلك مقصود. ويمكن إضافة قيود أنواع اختيارية حقلًا حقلًا بالصيغة `{` *field*₁ `:` *typexpr*₁ `=` *pattern*₁ `;`… `;`*field**n* `:` *typexpr**n* `=` *pattern**n* `}` لفرض أن يكون نوع *field**k* متوافقًا مع *typexpr**k*.

```ocaml
# let bytes_allocated
      {Gc.minor_words = minor;
       Gc.major_words = major;
       Gc.promoted_words = prom;
       _}
    =
      (Sys.word_size / 4) * int_of_float (minor +. major -. prom);;

val bytes_allocated : Gc.stat -> int = <fun>
```

#### أنماط المصفوفات

النمط `[|` *pattern*₁ `;` … `;` *pattern**n* `|]` يطابق المصفوفات التي طولها *n* بحيث يطابق العنصر ذو الرتبة *i* من المصفوفة النمط *pattern**i*، لكل *i* = 1،…، *n*.

```ocaml
# let matrix3_is_symmetric = function
    | [|[|_; b; c|];
        [|d; _; f|];
        [|g; h; _|]|] -> b = d && c = g && f = h
    | _ -> failwith "matrix3_is_symmetric: not a 3x3 matrix";;

val matrix3_is_symmetric : 'a array array -> bool = <fun>
```

#### أنماط المدى

النمط `'` *c* `'` `..` `'` *d* `'` اختصار للنمط `'` *c* `'` `|` `'` *c*₁ `'` `|` `'` *c*₂ `'` `|` … `|` `'` *c**n* `'` `|` `'` *d* `'`، حيث *c*₁، *c*₂، …، *c**n* هي المحارف الواقعة بين *c* و*d* في مجموعة المحارف ASCII. فمثلًا، النمط `'0'``..``'9'` يطابق جميع المحارف التي هي أرقام.

```ocaml
# type char_class = Uppercase | Lowercase | Digit | Other

  let classify_char = function
    | 'A'..'Z' -> Uppercase
    | 'a'..'z' -> Lowercase
    | '0'..'9' -> Digit
    | _ -> Other;;

type char_class = Uppercase | Lowercase | Digit | Other
val classify_char : char -> char_class = <fun>
```

#### أنماط الكسل

(أُدخلت في Objective Caml 3.11)

النمط `lazy` *pattern* يطابق قيمة *v* من النوع `Lazy.t`، بشرط أن يطابق *pattern* نتيجة إجبار *v* بـ `Lazy.force`. والمطابقة الناجحة لنمط يحوي أنماطًا فرعية من نوع `lazy` تُجبر الأجزاء المقابلة من القيمة المطابَقة، حتى تلك التي لا تتضمّن أي اختبار مثل `lazy` *value-name* أو `lazy` `_`. ومطابقة قيمة مع *مطابقة أنماط* تحوي بعض أنماطها أنماطًا فرعية من نوع `lazy` قد تؤدّي إلى إجبار أجزاء من القيمة، حتى عندما لا يحوي النمط المختار في النهاية أيّ نمط فرعي من نوع `lazy`.

```ocaml
# let force_opt = function
    | Some (lazy n) -> n
    | None -> 0;;

val force_opt : int lazy_t option -> int = <fun>
```

للمزيد من المعلومات، انظر وصف الوحدة `Lazy` في المكتبة القياسية (الوحدة `Lazy`).

#### أنماط الاستثناءات

(أُدخلت في OCaml 4.02)

يُسمح بشكل جديد من أنماط الاستثناءات، هو `exception` *pattern*، كنمط أعلى فقط، أو داخل نمط «أو» أعلى ضمن مطابقة أنماط `match`...`with` (وترفض مدقّق الأنواع أي ورود آخر).

وتُسمّى الحالات التي لها نمط أعلى من هذا القبيل «حالات استثناء»، في مقابل «حالات القيم» العادية. وتُطبَّق حالات الاستثناء عندما يطلق تقييم التعبير المطابَق استثناءً. وتُطابق قيمة الاستثناء حينئذ مع جميع حالات الاستثناء، ويُعاد إطلاقه إن لم يقبله أي منها (كما في كتلة `try`...`with`). ولأن أجسام حالات الاستثناء وحالات القيم كلها خارج نطاق معالج الاستثناء، فتُعدّ كلها في الموضع الذَّنَبي: فإذا كانت كتلة `match`...`with` نفسها في الموضع الذَّنَبي في الدالة الحالية، أدّى أي نداء دالة في الموضع الذَّنَبي في أحد أجسام الحالات إلى نداء ذَنَبي فعلي.

ويجب أن تحوي مطابقة الأنماط حالة قيمة واحدة على الأقل. ويُعدّ خطأً أن تكون جميع الحالات استثناءات، لأنه لن توجد شيفرة تعالج عودة قيمة.

```ocaml
# let find_opt p l =
    match List.find p l with
    | exception Not_found -> None
    | x -> Some x;;

val find_opt : ('a -> bool) -> 'a list -> 'a option = <fun>
```

#### الفتح المحلي للأنماط

(أُدخل في OCaml 4.04)

بالنسبة إلى الأنماط، يقتصر الفتح المحلي على البناء *module-path*`.(`*pattern*`)`. ويفتح هذا البناء محليًا الوحدة المشار إليها بمسار الوحدة *module-path* في نطاق النمط *pattern*.

وعندما يكون جسم نمط مفتوح محليًا محدَّدًا بـ `[` `]` أو `[|` `|]` أو `{` `}`، يمكن إهمال الأقواس. فمثلًا، *module-path*`.[`*pattern*`]` مكافئ لـ *module-path*`.([`*pattern*`])`، و*module-path*`.[|` *pattern* `|]` مكافئ لـ *module-path*`.([|` *pattern* `|])`.

```ocaml
# let bytes_allocated Gc.{minor_words; major_words; promoted_words; _} =
      (Sys.word_size / 4)
    * int_of_float (minor_words +. major_words -. promoted_words);;

val bytes_allocated : Gc.stat -> int = <fun>
```

### 11.7.2 التعابير الأساسية

#### الثوابت

التعبير الذي يتكوّن من ثابت يُقيَّم إلى هذا الثابت. مثلًا `3.14` أو `[||]`.

#### مسارات القيم

التعبير الذي يتكوّن من مسار وصول يُقيَّم إلى القيمة المرتبطة بهذا المسار في بيئة التقييم الحالية. ويمكن أن يكون المسار إمّا اسم قيمة، وإمّا مسار وصول إلى مكوّن قيمي في وحدة.

```ocaml
# Float.ArrayLabels.to_list;;

- : Float.ArrayLabels.t -> float list = <fun>
```

#### التعابير بين قوسين

للتعبيرين `(` *expr* `)` و`begin` *expr* `end` القيمة نفسها التي لـ *expr*. والبناءان متكافئان دلاليًا، لكن من الأسلوب الجيد استعمال `begin` … `end` داخل بنى التحكّم:

```text
        if … then begin … ; … end else begin … ; … end
```

و`(` … `)` في حالات التجميع الأخرى.

```ocaml
# let x = 1 + 2 * 3
  let y = (1 + 2) * 3;;

val x : int = 7
val y : int = 9
```

```ocaml
# let f a b =
    if a = b then
      print_endline "Equal"
    else begin
        print_string "Not Equal: ";
        print_int a;
        print_string " and ";
        print_int b;
        print_newline ()
    end;;

val f : int -> int -> unit = <fun>
```

ويمكن أن تحوي التعابير بين قوسين قيد نوع، كما في `(` *expr* `:` *typexpr* `)`. ويفرض هذا القيد أن يكون نوع *expr* متوافقًا مع *typexpr*.

ويمكن أن تحوي التعابير بين قوسين أيضًا إكراهات `(` *expr* [`:` *typexpr*] `:>` *typexpr*`)` (انظر القسم الفرعي 11.7.7 أدناه).

#### تطبيق الدوال

يُدلّ على تطبيق الدالة بمجاورة تعابير (قد تكون موسومة). والتعبير *expr* *argument*₁ … *argument**n* يقيّم التعبير *expr* والتعابير الظاهرة في *argument*₁ إلى *argument**n*. ويجب أن يُقيَّم التعبير *expr* إلى قيمة دالية *f*، تُطبَّق حينئذ على قيم *argument*₁ … *argument**n*.

والترتيب الذي تُقيَّم به التعابير *expr* و*argument*₁ … *argument**n* غير محدَّد.

```ocaml
# List.fold_left ( + ) 0 [1; 2; 3; 4; 5];;

- : int = 15
```

وتُطابَق الوسائط والمعاملات وفق وسومها الخاصة. وترتيب الوسائط غير ذي أثر، إلا بين وسائط لها الوسم نفسه أو ليس لها وسم.

```ocaml
# ListLabels.fold_left ~f:( @ ) ~init:[] [[1; 2; 3]; [4; 5; 6]; [7; 8; 9]];;

- : int list = [1; 2; 3; 4; 5; 6; 7; 8; 9]
```

وإذا حُدِّد معامل كاختياري (بوسم مسبوق بـ `?`) في نوع *expr*، فسيُلفّ الوسيط المقابل تلقائيًا بالباني `Some`، إلا إذا كان الوسيط نفسه مسبوقًا بـ `?` أيضًا، وفي هذه الحالة يُمرَّر كما هو.

```ocaml
# let fullname ?title first second =
    match title with
    | Some t -> t ^ " " ^ first ^ " " ^ second
    | None -> first ^ " " ^ second

  let name = fullname ~title:"Mrs" "Jane" "Fisher"

  let address ?title first second town =
    fullname ?title first second ^ "\n" ^ town;;

val fullname : ?title:string -> string -> string -> string = <fun>
val name : string = "Mrs Jane Fisher"
val address : ?title:string -> string -> string -> string -> string = <fun>
```

وإذا مُرِّر وسيط غير موسوم، وكان معامله المقابل مسبوقًا بمعامل اختياري واحد أو أكثر، فإن هذه المعاملات تُؤخذ *بقيمتها الافتراضية*، أي تُمرَّر لها القيمة `None`. وستُحفظ جميع المعاملات الناقصة الأخرى (التي لا وسيط مقابل لها)، الاختيارية وغير الاختيارية، وستكون نتيجة الدالة لا تزال دالة في هذه المعاملات الناقصة إلى جسم *f*.

```ocaml
# let fullname ?title first second =
    match title with
    | Some t -> t ^ " " ^ first ^ " " ^ second
    | None -> first ^ " " ^ second

  let name = fullname "Jane" "Fisher";;

val fullname : ?title:string -> string -> string -> string = <fun>
val name : string = "Jane Fisher"
```

وفي جميع الحالات عدا التطابق التام في الترتيب والوسوم دون معاملات اختيارية، ينبغي أن يكون نوع الدالة معروفًا عند موضع التطبيق. ويمكن ضمان ذلك بإضافة قيد نوع. ويمكن التحقّق من أصالة الاستنتاج في النمط `-principal`.

وكحالة خاصة، يدعم OCaml التطبيقات الكاملة `labels-omitted`: فإذا كانت للدالة رتبة معروفة، وكانت جميع الوسائط غير موسومة، وكان عددها يطابق عدد المعاملات غير الاختيارية، تُهمَل الوسوم وتُطابَق المعاملات غير الاختيارية بترتيب تعريفها. وتُؤخذ المعاملات الاختيارية بقيمها الافتراضية. ويُنصح بتجنّب إهمال الوسوم هذا، إذ يؤدّي إلى تحذير، انظر 13.5.1.

#### تعريف الدوال

تُقدَّم صيغتان صياغيتان لتعريف الدوال. الصيغة الأولى تُقدَّم بالكلمة المحجوزة `function`:

| `function`pattern₁`->`expr₁ `\|`… `\|`pattern*n*`->`expr*n* |
| --- |

يُقيَّم هذا التعبير إلى قيمة دالية بوسيط واحد. وعندما تُطبَّق هذه الدالة على قيمة *v*، تُطابَق هذه القيمة مع كل نمط من *pattern*₁ إلى *pattern**n*. فإذا نجحت إحدى هذه المطابقات، أي إذا طابقت القيمة *v* النمط *pattern**i* لبعض *i*، قُيِّم التعبير *expr**i* المرتبط بالنمط المختار، وأصبحت قيمته قيمة تطبيق الدالة. ويجري تقييم *expr**i* في بيئة مُثراة بعمليات الربط التي جرت أثناء المطابقة.

وإذا طابقت عدة أنماط الوسيط *v*، اختير النمط الأسبق ورودًا في تعريف الدالة. وإذا لم يطابق أيّ نمط الوسيط، أُطلق الاستثناء `Match_failure`.

```ocaml
# (function (0, 0) -> "both zero"
          | (0, _) -> "first only zero"
          | (_, 0) -> "second only zero"
          | (_, _) -> "neither zero")
  (7, 0);;

- : string = "second only zero"
```

وصيغة تعريف الدوال الأخرى تُقدَّم بالكلمة المحجوزة `fun`: `fun` *parameter*₁ … *parameter*ₙ `->` *expr*.

وهذا التعبير مكافئ لـ: `fun` *parameter*₁ `->` … `fun` *parameter*ₙ `->` *expr*.

```ocaml
# let f = (fun a -> fun b -> fun c -> a + b + c)
  let g = (fun a b c -> a + b + c);;

val f : int -> int -> int -> int = <fun>
val g : int -> int -> int -> int = <fun>
```

ويمكن إضافة قيد نوع اختياري *typexpr* قبل `->` لفرض أن تكون نتيجة الدالة متوافقة مع القيد *typexpr*: الصيغة `fun` *parameter*₁ … *parameter*ₙ `:` *typexpr* `->` *expr* مكافئة لـ `fun` *parameter*₁ `->` … `fun` *parameter*ₙ `->` `(` *expr* `:` *typexpr* `)`.

واحذر الفرق الصياغي الصغير بين قيد نوع على المعامل الأخير، `fun` *parameter*₁ … `(` *parameter*ₙ `:` *typexpr* `)` `->` *expr*، وقيد على النتيجة، `fun` *parameter*₁ … *parameter*ₙ `:` *typexpr* `->` *expr*.

```ocaml
# let eq = fun (a : int) (b : int) -> a = b
  let eq2 = fun a b : bool -> a = b
  let eq3 = fun (a : int) (b : int) : bool -> a = b;;

val eq : int -> int -> bool = <fun>
val eq2 : 'a -> 'a -> bool = <fun>
val eq3 : int -> int -> bool = <fun>
```

ونمطا المعامل `~`*lab* و`~(`*lab* [`:` *typ*]`)` اختصاران لـ `~`*lab*`:`*lab* و`~`*lab*`:(`*lab* [`:` *typ*]`)` على الترتيب، وكذلك نظيراهما الاختياريان.

```ocaml
# let bool_map ~cmp:(cmp : int -> int -> bool) l =
    List.map cmp l

  let bool_map' ~(cmp : int -> int -> bool) l =
    List.map cmp l;;

val bool_map : cmp:(int -> int -> bool) -> int list -> (int -> bool) list =
  <fun>
val bool_map' : cmp:(int -> int -> bool) -> int list -> (int -> bool) list =
  <fun>
```

```ocaml
# let open_file_for_input ?binary filename =
    match binary with
    | Some true -> open_in_bin filename
    | Some false | None -> open_in filename

  let open_file_for_input' ?(binary=false) filename =
    if binary then open_in_bin filename else open_in filename;;

val open_file_for_input : ?binary:bool -> string -> in_channel = <fun>
val open_file_for_input' : ?binary:bool -> string -> in_channel = <fun>
```

وبعد هذين التحويلين، تصبح التعابير على الشكل: `fun` [`label`₁] *pattern*₁ `->` … `fun` [`label*ₙ] *pattern*ₙ `->` *expr*.

وإذا أغفلنا الوسوم، التي لا تكون ذات معنى إلا عند تطبيق الدالة، كان ذلك مكافئًا لـ: `function` *pattern*₁ `->` … `function` *pattern*ₙ `->` *expr*.

أي إن تعبير `fun` أعلاه يُقيَّم إلى دالة مكارية بوسائط عددها *n*: فبعد تطبيق هذه الدالة *n* مرة على القيم *v*₁ … *v**n*، تُطابَق القيم على التوازي مع الأنماط *pattern*₁ … *pattern**n*. وإذا نجحت المطابقة، أعادت الدالة قيمة *expr* في بيئة مُثراة بعمليات الربط التي جرت أثناء المطابقات. وإذا فشلت المطابقة، أُطلق الاستثناء `Match_failure`.

#### الحُرّاس في مطابقات الأنماط

يمكن أن تحوي حالات مطابقة النمط (في البنى `function` و`match` و`try`) تعابير حُرّاس، وهي تعابير منطقية اعتباطية يجب أن تُقيَّم إلى `true` لاختيار حالة المطابقة. وتظهر الحُرّاس قبل الرمز `->` مباشرةً، وتُقدَّم بالكلمة المحجوزة `when`:

| `function`*pattern*₁ [`when` *cond*₁]`->`*expr*₁ `\|`… `\|`*pattern**n* [`when` *cond**n*]`->`*expr**n* |
| --- |

وتجري المطابقة كما وُصف سابقًا، إلا أنه إذا طابقت القيمة نمطًا ما *pattern**i* له حارس *cond**i*، قُيِّم التعبير *cond**i* (في بيئة مُثراة بعمليات الربط التي جرت أثناء المطابقة). فإذا قُيِّم *cond**i* إلى `true`، قُيِّم *expr**i* وأُعيدت قيمته نتيجةً للمطابقة، كالمعتاد. أما إذا قُيِّم *cond**i* إلى `false`، استُؤنفت المطابقة مع الأنماط التي تلي *pattern**i*.

```ocaml
# let rec repeat f = function
    | 0 -> ()
    | n when n > 0 -> f (); repeat f (n - 1)
    | _ -> raise (Invalid_argument "repeat");;

val repeat : (unit -> 'a) -> int -> unit = <fun>
```

#### التعريفات المحلية

تربط البنى `let` و`let` `rec` أسماء القيم محليًا. والبناء `let` *pattern*₁ `=` *expr*₁ `and` … `and` *pattern*ₙ `=` *expr*ₙ `in` *expr* يقيّم *expr*₁ … *expr**n* بترتيب غير محدَّد ويطابق قيمها مع الأنماط *pattern*₁ … *pattern**n*. فإذا نجحت المطابقات، قُيِّم *expr* في بيئة مُثراة بعمليات الربط التي جرت أثناء المطابقة، وأُعيدت قيمة *expr* قيمةً لتعبير `let` كله. وإذا فشلت إحدى المطابقات، أُطلق الاستثناء `Match_failure`.

```ocaml
# let v =
    let x = 1 in [x; x; x]

  let v' =
    let a, b = (1, 2) in a + b

  let v'' =
    let a = 1 and b = 2 in a + b;;

val v : int list = [1; 1; 1]
val v' : int = 3
val v'' : int = 3
```

وتُقدَّم صياغة بديلة لربط المتغيّرات بقيم دالية: فبدلًا من كتابة `let` *ident* `=` `fun` *parameter*₁ … *parameter*ₘ `->` *expr* في تعبير `let`، يمكن للمرء أن يكتب `let` *ident* *parameter*₁ … *parameter*ₘ `=` *expr*.

```ocaml
# let f = fun x -> fun y -> fun z -> x + y + z

  let f' = fun x y z -> x + y + z

  let f'' x y z = x + y + z;;

val f : int -> int -> int -> int = <fun>
val f' : int -> int -> int -> int = <fun>
val f'' : int -> int -> int -> int = <fun>
```

وتُقدَّم التعريفات العودية للأسماء بـ `let` `rec`: `let` `rec` *pattern*₁ `=` *expr*₁ `and` … `and` *pattern*ₙ `=` *expr*ₙ `in` *expr*.

والفرق الوحيد مع بناء `let` الموصوف أعلاه أن عمليات ربط الأسماء بالقيم التي تجريها مطابقة الأنماط تُعدّ قد جرت سابقًا عندما تُقيَّم التعابير *expr*₁ إلى *expr**n*. أي إن التعابير *expr*₁ إلى *expr**n* يمكن أن تشير إلى معرّفات يربطها أحد الأنماط *pattern*₁ … *pattern**n*، وتتوقع أن تكون لها القيمة نفسها كما في *expr*، جسم بناء `let` `rec`.

```ocaml
# let rec even =
    function 0 -> true | n -> odd (n - 1)
  and odd =
    function 0 -> false | n -> even (n - 1)
  in
    even 1000;;

- : bool = true
```

ويُضمن أن يتصرّف التعريف العودي كما وُصف أعلاه إذا كانت التعابير *expr*₁ إلى *expr**n* تعريفات دوال (`fun` … أو `function` …)، وكانت الأنماط *pattern*₁ … *pattern**n* مجرّد أسماء قيم، كما في: `let` `rec` *name*₁ `=` `fun` … `and` … `and` *name*ₙ `=` `fun` … `in` *expr*.

وهذا يعرّف *name*₁ … *name**n* كدوال عودية متبادلة محلية في *expr*.

وسلوك الأشكال الأخرى من تعريفات `let` `rec` يعتمد على التنفيذ. ويدعم التنفيذ الحالي أيضًا صنفًا معيّنًا من التعريفات العودية للقيم غير الدالية، كما هو مشروح في القسم 12.1.

#### تعليقات الأنواع متعدّدة الأشكال الصريحة

(أُدخلت في OCaml 3.12)

تتصرّف تعليقات الأنواع متعدّدة الأشكال في تعريفات `let` على نحو شبيه بالدوال متعدّدة الأشكال: `let` *pattern*₁ `:` *typ*₁ … *typ*ₙ `.` *typexpr* `=` *expr*.

وتفرض هذه التعليقات صراحةً أن تكون القيمة المعرَّفة متعدّدة الأشكال، وتتيح استعمال تعدّد الأشكال هذا في الورودات العودية (عند استعمال `let` `rec`). لكن لاحظ أن هذا نوع متعدّد الأشكال عادي، قابل للتوحيد مع أي تجسيد منه.

### 11.7.3 بنى التحكّم

#### التتالي

التعبير *expr*₁ `;` *expr*₂ يقيّم *expr*₁ أولًا، ثم *expr*₂، ويعيد قيمة *expr*₂.

```ocaml
# let print_pair (a, b) =
    print_string "(";
    print_string (string_of_int a);
    print_string ",";
    print_string (string_of_int b);
    print_endline ")";;

val print_pair : int * int -> unit = <fun>
```

#### الشرط

التعبير `if` *expr*₁ `then` *expr*₂ `else` *expr*₃ يُقيَّم إلى قيمة *expr*₂ إذا قُيِّم *expr*₁ إلى المنطقي `true`، وإلى قيمة *expr*₃ إذا قُيِّم *expr*₁ إلى المنطقي `false`.

```ocaml
# let rec factorial x =
    if x <= 1 then 1 else x * factorial (x - 1);;

val factorial : int -> int = <fun>
```

ويمكن إهمال الجزء `else` *expr*₃، وفي هذه الحالة يكون الافتراضي `else` `()`.

```ocaml
# let debug = ref false

  let log msg =
    if !debug then prerr_endline msg;;

val debug : bool ref = {contents = false}
val log : string -> unit = <fun>
```

#### تعبير الحالة

| `match` *expr* `with` *pattern*₁ `->` *expr*₁ `\|` … `\|` *pattern*ₙ `->` *expr*ₙ |
| --- |

يطابق هذا التعبير قيمة *expr* مع الأنماط *pattern*₁ إلى *pattern*ₙ. فإذا نجحت المطابقة مع النمط *pattern*ᵢ، قُيِّم التعبير المرتبط *expr*ᵢ، وأصبحت قيمته قيمة تعبير `match` كله. ويجري تقييم *expr*ᵢ في بيئة مُثراة بعمليات الربط التي جرت أثناء المطابقة. وإذا طابقت عدة أنماط قيمة *expr*، اختير النمط الأسبق ورودًا في تعبير `match`.

```ocaml
# let rec sum l =
    match l with
    | [] -> 0
    | h :: t -> h + sum t;;

val sum : int list -> int = <fun>
```

وإذا لم يطابق أيّ نمط قيمة *expr*، أُطلق الاستثناء `Match_failure`.

```ocaml
# let unoption o =
    match o with
    | Some x -> x ;;

Warning 8 [partial-match]: this pattern-matching is not exhaustive.
  Here is an example of a case that is not matched: None

val unoption : 'a option -> 'a = <fun>

# let l = List.map unoption [Some 1; Some 10; None; Some 2];;

Exception: Match_failure ("expr.etex", 2, 2).
```
#### المعاملات المنطقية

يُقيَّم التعبير *expr*₁ `&&` *expr*₂ إلى `true` إذا قُيّم كلٌّ من التعبيرين *expr*₁ و*expr*₂ إلى `true`، وإلا قُيّم إلى `false`. يُقيَّم المكوّن الأول *expr*₁ أولًا، ولا يُقيَّم المكوّن الثاني *expr*₂ إذا قُيّم الأول إلى `false`. ولهذا يتصرّف التعبير *expr*₁ `&&` *expr*₂ تمامًا كما يتصرّف `if` *expr*₁ `then` *expr*₂ `else` `false`.

ويُقيَّم التعبير *expr*₁ `||` *expr*₂ إلى `true` إذا قُيّم أحد التعبيرين *expr*₁ و*expr*₂ إلى `true`، وإلا قُيّم إلى `false`. يُقيَّم المكوّن الأول *expr*₁ أولًا، ولا يُقيَّم المكوّن الثاني *expr*₂ إذا قُيّم الأول إلى `true`. ولهذا يتصرّف التعبير *expr*₁ `||` *expr*₂ تمامًا كما يتصرّف `if` *expr*₁ `then` `true` `else` *expr*₂.

والمعاملان المنطقيان `&` و`or` مرادفان مهجوران للمعاملين `&&` و`||` على الترتيب.

```ocaml
# let xor a b =
    (a || b) && not (a && b);;

val xor : bool -> bool -> bool = <fun>
```

#### الحلقات

يُقيّم التعبير `while` *expr*₁ `do` *expr*₂ `done` التعبير *expr*₂ مرارًا ما دام *expr*₁ يُقيَّم إلى `true`. يُقيَّم شرط الحلقة *expr*₁ ويُفحص في بداية كل دورة. ويُقيَّم التعبير الكامل `while` … `done` إلى القيمة الواحدية `()`.

```ocaml
# let chars_of_string s =
    let i = ref 0 in
    let chars = ref [] in
      while !i < String.length s do
        chars := s.[!i] :: !chars;
        i := !i + 1
      done;
      List.rev !chars;;

val chars_of_string : string -> char list = <fun>
```

وكحالة خاصة، يُمنح التعبير `while` `true` `do` *expr* `done` نوعًا متعدّد الأشكال، ما يسمح باستعماله بدلًا من أي تعبير (في أحد فروع أي مطابقة أنماط مثلًا).

ويُقيّم التعبير `for` *name* `=` *expr*₁ `to` *expr*₂ `do` *expr*₃ `done` أولًا التعبيرين *expr*₁ و*expr*₂ (الحدّين) إلى قيمتين صحيحتين *n* و*p*. ثم يُقيَّم جسم الحلقة *expr*₃ مرارًا في بيئة يُربط فيها *name* تباعًا بالقيم *n*، *n*+1، …، *p*−1، *p*. ولا يُقيَّم جسم الحلقة أبدًا إذا كان *n* > *p*.

```ocaml
# let chars_of_string s =
    let l = ref [] in
      for p = 0 to String.length s - 1 do
        l := s.[p] :: !l
      done;
      List.rev !l;;

val chars_of_string : string -> char list = <fun>
```

ويُقيّم التعبير `for` *name* `=` *expr*₁ `downto` *expr*₂ `do` *expr*₃ `done` على نحو مشابه، إلا أن *name* يُربط تباعًا بالقيم *n*، *n*−1، …، *p*+1، *p*. ولا يُقيَّم جسم الحلقة أبدًا إذا كان *n* < *p*.

```ocaml
# let chars_of_string s =
    let l = ref [] in
      for p = String.length s - 1 downto 0 do
        l := s.[p] :: !l
      done;
      !l;;

val chars_of_string : string -> char list = <fun>
```

وفي كلتا الحالتين، يُقيَّم تعبير `for` الكامل إلى القيمة الواحدية `()`.

#### معالجة الاستثناءات

يُقيّم التعبير

| `try` *expr* `with` *pattern*₁ `->` *expr*₁ `\|` … `\|` *pattern*ₙ `->` *expr*ₙ |
| --- |

التعبير *expr* ويعيد قيمته إذا لم يُثر تقييم *expr* أي استثناء. أما إذا أثار تقييم *expr* استثناءً، فتُطابَق قيمة الاستثناء مع الأنماط من *pattern*₁ إلى *pattern*ₙ. وإذا نجحت المطابقة مع *pattern*ᵢ، يُقيَّم التعبير المرتبط *expr*ᵢ، وتصبح قيمته قيمة تعبير `try` كاملًا. ويجري تقييم *expr*ᵢ في بيئة تُثرى بالارتباطات التي أُنجزت أثناء المطابقة. وإذا طابق عدة أنماط قيمة *expr*، اختير النمط الأول ورودًا في تعبير `try`. وإذا لم يطابق أي نمط قيمة *expr*، أُثيرت قيمة الاستثناء من جديد، فتمرّ «عبر» بنية `try` بشفافية.

```ocaml
# let find_opt p l =
    try Some (List.find p l) with Not_found -> None;;

val find_opt : ('a -> bool) -> 'a list -> 'a option = <fun>
```

### 11.7.4 عمليات على بنى البيانات

#### الجداءات

يُقيَّم التعبير *expr*₁ `,` … `,` *expr*ₙ إلى الصفّ *n* من قيم التعبيرات من *expr*₁ إلى *expr*ₙ. وترتيب تقييم التعبيرات الفرعية غير محدّد.

```ocaml
# (1 + 2 * 3, (1 + 2) * 3, 1 + (2 * 3));;

- : int * int * int = (7, 9, 7)
```

#### المتغيّرات

يُقيَّم التعبير *constr* *expr* إلى قيمة المتغيّر الأحادي الذي بانيه *constr* ومعامله قيمة *expr*. وعلى المنوال نفسه، يُقيَّم التعبير *constr* `(` *expr*₁ `,` … `,` *expr*ₙ `)` إلى قيمة المتغيّر ذي الرتبة n الذي بانيه *constr* ومعاملاته قيم *expr*₁، …، *expr*ₙ.

ويُقيَّم التعبير *constr* `(` *expr*₁, …, *expr*ₙ `)` إلى قيمة المتغيّر الذي بانيه *constr* ومعاملاته قيم *expr*₁ … *expr*ₙ.

```ocaml
# type t = Var of string | Not of t | And of t * t | Or of t * t

  let test = And (Var "x", Not (Or (Var "y", Var "z")));;

type t = Var of string | Not of t | And of t * t | Or of t * t
val test : t = And (Var "x", Not (Or (Var "y", Var "z")))
```

وتُقدَّم للقوائم بعض السكر النحوي. فالتعبير *expr*₁ `::` *expr*₂ يمثّل الباني `(` `::` `)` مطبَّقًا على المعاملين `(` *expr*₁ `,` *expr*₂ `)`، ولذلك يُقيَّم إلى القائمة التي رأسها قيمة *expr*₁ وذيلها قيمة *expr*₂. والتعبير `[` *expr*₁ `;` … `;` *expr*ₙ `]` يكافئ *expr*₁ `::` … `::` *expr*ₙ `::` `[]`، ولذلك يُقيَّم إلى القائمة التي عناصرها قيم *expr*₁ إلى *expr*ₙ.

```ocaml
# 0 :: [1; 2; 3] = 0 :: 1 :: 2 :: 3 :: [];;

- : bool = true
```

#### المتغيّرات متعدّدة الأشكال

يُقيَّم التعبير `` ` ``*tag-name* *expr* إلى قيمة المتغيّر متعدّد الأشكال الذي وسمه *tag-name* ومعامله قيمة *expr*.

```ocaml
# let with_counter x = `V (x, ref 0);;

val with_counter : 'a -> [> `V of 'a * int ref ] = <fun>
```

#### السجلات

يُقيَّم التعبير `{` *field*₁ [`=` *expr*₁] `;` … `;` *field*ₙ [`=` *expr*ₙ] `}` إلى قيمة السجل { *field*₁ = *v*₁; …; *field*ₙ = *v*ₙ } حيث *v*ᵢ قيمة *expr*ᵢ من أجل *i* = 1، …، *n*. ويمثّل المعرّف المفرد *field*ₖ التعبير *field*ₖ `=` *field*ₖ، ويمثّل المعرّف المؤهَّل *module-path* `.` *field*ₖ التعبير *module-path* `.` *field*ₖ `=` *field*ₖ. ويجب أن تنتمي الحقول من *field*₁ إلى *field*ₙ جميعها إلى نوع السجل نفسه؛ ويجب أن يظهر كل حقل من هذا النوع مرة واحدة بالضبط في تعبير السجل، وإن جاز أن تظهر بأي ترتيب. وترتيب تقييم *expr*₁ إلى *expr*ₙ غير محدّد. ويمكن إضافة قيود نوع اختيارية بعد كل حقل، على الصيغة `{` *field*₁ `:` *typexpr*₁ `=` *expr*₁ `;` … `;` *field*ₙ `:` *typexpr*ₙ `=` *expr*ₙ `}`، لإلزام نوع *field*ₖ بأن يكون متوافقًا مع *typexpr*ₖ.

```ocaml
# type t = {house_no : int; street : string; town : string; postcode : string}

  let address x =
    Printf.sprintf "The occupier\n%i %s\n%s\n%s"
      x.house_no x.street x.town x.postcode;;

type t = {
  house_no : int;
  street : string;
  town : string;
  postcode : string;
}
val address : t -> string = <fun>
```

أما التعبير `{` *expr* `with` *field*₁ [`=` *expr*₁] `;` … `;` *field*ₙ [`=` *expr*ₙ] `}` فيبني سجلًا جديدًا تكون حقوله من *field*₁ إلى *field*ₙ مساوية لـ *expr*₁ إلى *expr*ₙ، وتأخذ جميع الحقوق الأخرى القيمة نفسها التي لها في السجل *expr*. وبعبارة أخرى، يعيد نسخة سطحية من السجل *expr*، باستثناء الحقول من *field*₁ إلى *field*ₙ التي تُهيَّأ بقيم *expr*₁ إلى *expr*ₙ. وكما سبق، يمثّل المعرّف المفرد *field*ₖ التعبير *field*ₖ `=` *field*ₖ، ويمثّل المعرّف المؤهَّل *module-path* `.` *field*ₖ التعبير *module-path* `.` *field*ₖ `=` *field*ₖ، ويمكن إضافة قيد نوع اختياري على كل حقل يُحدَّث بالصيغة `{` *expr* `with` *field*₁ `:` *typexpr*₁ `=` *expr*₁ `;` … `;` *field*ₙ `:` *typexpr*ₙ `=` *expr*ₙ `}`.

```ocaml
# type t = {house_no : int; street : string; town : string; postcode : string}

  let uppercase_town address =
    {address with town = String.uppercase_ascii address.town};;

type t = {
  house_no : int;
  street : string;
  town : string;
  postcode : string;
}
val uppercase_town : t -> t = <fun>
```

ويقيّم التعبير *expr*₁ `.` *field* التعبير *expr*₁ إلى قيمة سجل، ثم يعيد القيمة المرتبطة بـ *field* في هذه القيمة.

أما التعبير *expr*₁ `.` *field* `<-` *expr*₂ فيقيّم *expr*₁ إلى قيمة سجل، ثم يعدّلها في مكانها باستبدال القيمة المرتبطة بـ *field* في هذا السجل بقيمة *expr*₂. ولا يُسمح بهذه العملية إلا إذا كان *field* قد أُعلن `mutable` في تعريف نوع السجل. ويُقيَّم التعبير الكامل *expr*₁ `.` *field* `<-` *expr*₂ إلى القيمة الواحدية `()`.

```ocaml
# type t = {mutable upper : int; mutable lower : int; mutable other : int}

  let stats = {upper = 0; lower = 0; other = 0}

  let collect =
    String.iter
      (function
       | 'A'..'Z' -> stats.upper <- stats.upper + 1
       | 'a'..'z' -> stats.lower <- stats.lower + 1
       | _ -> stats.other <- stats.other + 1);;

type t = { mutable upper : int; mutable lower : int; mutable other : int; }
val stats : t = {upper = 0; lower = 0; other = 0}
val collect : string -> unit = <fun>
```

#### المصفوفات

يُقيَّم التعبير `[|` *expr*₁ `;` … `;` *expr*ₙ `|]` إلى مصفوفة من *n* عنصرًا تُهيَّأ عناصرها بقيم *expr*₁ إلى *expr*ₙ على الترتيب. وترتيب تقييم هذه التعبيرات غير محدّد.

ويعيد التعبير *expr*₁ `.(` *expr*₂ `)` قيمة العنصر ذي الرقم *expr*₂ في المصفوفة التي يدلّ عليها *expr*₁. رقم العنصر الأول 0، ورقم العنصر الأخير *n*−1 حيث *n* حجم المصفوفة. ويُثار الاستثناء `Invalid_argument` إذا كان الوصول خارج الحدود.

ويعدّل التعبير *expr*₁ `.(` *expr*₂ `)` `<-` *expr*₃ المصفوفة التي يدلّ عليها *expr*₁ في مكانها، باستبدال العنصر ذي الرقم *expr*₂ بقيمة *expr*₃. ويُثار الاستثناء `Invalid_argument` إذا كان الوصول خارج الحدود. وقيمة التعبير كاملًا `()`.

```ocaml
# let scale arr n =
    for x = 0 to Array.length arr - 1 do
      arr.(x) <- arr.(x) * n
    done

  let x = [|1; 10; 100|]
  let _ = scale x 2;;

val scale : int array -> int -> unit = <fun>
val x : int array = [|2; 20; 200|]
```

#### السلاسل

يعيد التعبير *expr*₁ `.[` *expr*₂ `]` قيمة المحرف ذي الرقم *expr*₂ في السلسلة التي يدلّ عليها *expr*₁. رقم المحرف الأول 0، ورقم المحرف الأخير *n*−1 حيث *n* طول السلسلة. ويُثار الاستثناء `Invalid_argument` إذا كان الوصول خارج الحدود.

```ocaml
# let iter f s =
    for x = 0 to String.length s - 1 do f s.[x] done;;

val iter : (char -> 'a) -> string -> unit = <fun>
```

ويعدّل التعبير *expr*₁ `.[` *expr*₂ `]` `<-` *expr*₃ السلسلة التي يدلّ عليها *expr*₁ في مكانها، باستبدال المحرف ذي الرقم *expr*₂ بقيمة *expr*₃. ويُثار الاستثناء `Invalid_argument` إذا كان الوصول خارج الحدود. وقيمة التعبير كاملًا `()`. **ملاحظة:** هذه الإمكانية معروضة لتوافق خلفي مع إصدارات OCaml الأقدم فقط، وستُزال في إصدار مستقبلي. وينبغي للشيفرة الجديدة أن تستعمل متتاليات البايتات ودالة `Bytes.set`.

### 11.7.5 المعاملات

يمكن أن تظهر الرموز من صنف *infix-symbol*، وكذلك الكلمات المحجوزة `*` و`+` و`-` و`-.` و`=` و`!=` و`<` و`>` و`or` و`||` و`&` و`&&` و`:=` و`mod` و`land` و`lor` و`lxor` و`lsl` و`lsr` و`asr`، في موضع وسيط (بين تعبيرين). ويمكن أن تظهر الرموز من صنف *prefix-symbol*، وكذلك الكلمات المحجوزة `-` و`-.`، في موضع بادئ (قبل تعبير).

```ocaml
# (( * ), ( := ), ( || ));;

- : (int -> int -> int) * ('a ref -> 'a -> unit) * (bool -> bool -> bool) =
(<fun>, <fun>, <fun>)
```

لا معنى ثابتًا للرموز الوسيطة والبائدة: فهي تُفسَّر ببساطة تطبيقاتٍ لدوال مرتبطة بالأسماء المقابلة للرموز. ويُفسَّر التعبير *prefix-symbol* *expr* تطبيقًا للصيغة `(` *prefix-symbol* `)` *expr*. وعلى المنوال نفسه، يُفسَّر التعبير *expr*₁ *infix-symbol* *expr*₂ تطبيقًا للصيغة `(` *infix-symbol* `)` *expr*₁ *expr*₂.

يسرد الجدول التالي الرموز المعرَّفة في البيئة الابتدائية ومعانيها الابتدائية. (راجع وصف وحدة المكتبة الأساسية `Stdlib` في الفصل 29 لمزيد من التفصيل.) ويمكن تغيير معانيها في أي وقت بالصيغة `let` `(` *infix-op* `)` *name*₁ *name*₂ `=` …

```ocaml
# let ( + ), ( - ), ( * ), ( / ) = Int64.(add, sub, mul, div);;

val ( + ) : int64 -> int64 -> int64 = <fun>
val ( - ) : int64 -> int64 -> int64 = <fun>
val ( * ) : int64 -> int64 -> int64 = <fun>
val ( / ) : int64 -> int64 -> int64 = <fun>
```

ملاحظة: تُعالَج المعاملات `&&` و`||` و`~-` معالجة خاصة، ولا يُنصح بتغيير معانيها.

ويمكن أن تظهر الكلمتان المحجوزتان `-` و`-.` معاملين وسيطين وبادئين معًا. وعندما تظهران معاملين بادئين، تُفسَّران على الترتيب بالدالتين `(~-)` و`(~-.)`.

### 11.7.6 الكائنات

#### إنشاء الكائنات

عندما يُقيَّم *class-path* إلى جسم صنف، يُقيَّم `new` *class-path* إلى كائن جديد يحوي متغيّرات النسخة ودوال الصنف.

```ocaml
# class of_list (lst : int list) = object
    val mutable l = lst
    method next =
      match l with
      | [] -> raise (Failure "empty list");
      | h::t -> l <- t; h
  end

  let a = new of_list [1; 1; 2; 3; 5; 8; 13]

  let b = new of_list;;

class of_list :
  int list -> object val mutable l : int list method next : int end
val a : of_list = <obj>
val b : int list -> of_list = <fun>
```

وعندما يُقيَّم *class-path* إلى دالة صنف، يُقيَّم `new` *class-path* إلى دالة تنتظر العدد نفسه من المعاملات وتعيد كائنًا جديدًا من هذا الصنف.

#### إنشاء الكائن المباشر

إن إنشاء كائن مباشرةً ببنية `object` *class-body* `end` يكافئ عمليًا تعريف صنف محليًا بالصيغة `class` *class-name* `=` `object` *class-body* `end` — انظر القسمين 11.9.2 وما يليهما لصياغة *class-body* — ثم إنشاء كائن واحد منه فورًا بـ `new` *class-name*.

```ocaml
# let o =
    object
      val secret = 99
      val password = "unlock"
      method get guess = if guess <> password then None else Some secret
    end;;

val o : < get : string -> int option > = <obj>
```

ويختلف تنميط الكائنات المباشرة عن تعريف صنف صراحةً من وجهين. أولًا، قد يحوي نوع الكائن المستنتج متغيّرات نوع حرّة. وثانيًا، بما أن جسم صنف الكائن المباشر لن يُمدَّد أبدًا، فيمكن توحيد نوع ذاتِه مع نوع كائن مغلق.

#### استدعاء الدوال

يستدعي التعبير *expr* `#` *method-name* الدالة *method-name* للكائن الذي يدلّ عليه *expr*.

```ocaml
# class of_list (lst : int list) = object
    val mutable l = lst
    method next =
      match l with
      | [] -> raise (Failure "empty list");
      | h::t -> l <- t; h
  end

  let a = new of_list [1; 1; 2; 3; 5; 8; 13]

  let third = ignore a#next; ignore a#next; a#next;;

class of_list :
  int list -> object val mutable l : int list method next : int end
val a : of_list = <obj>
val third : int = 2
```

وإذا كانت *method-name* دالةً متعدّدة الأشكال، فينبغي أن يكون نوعها معروفًا في موضع الاستدعاء. ويصحّ ذلك مثلًا إذا كان *expr* اسم كائن جديد (`let` *ident* `=` `new` *class-path* …) أو إذا وُجد قيد نوع. ويمكن التحقّق من أصلية الاستنتاج في النمط `-principal`.

#### الوصول إلى متغيّرات النسخة وتعديلها

لا تُرى متغيّرات نسخة الصنف إلا في جسم الدوال المعرَّفة في الصنف نفسه أو في صنف يرث من الصنف الذي يعرّف متغيّرات النسخة. ويُقيَّم التعبير *inst-var-name* إلى قيمة متغيّر النسخة المعطى. ويُسنِد التعبير *inst-var-name* `<-` *expr* قيمة *expr* إلى متغيّر النسخة *inst-var-name*، الذي يجب أن يكون قابلًا للتعديل. ويُقيَّم التعبير الكامل *inst-var-name* `<-` *expr* إلى `()`.

```ocaml
# class of_list (lst : int list) = object
    val mutable l = lst
    method next =
      match l with                            (* access instance variable *)
      | [] -> raise (Failure "empty list");
      | h::t -> l <- t; h                     (* modify instance variable *)
  end;;

class of_list :
  int list -> object val mutable l : int list method next : int end
```

#### تكرار الكائنات

يمكن تكرار كائن باستعمال دالة المكتبة `Oo.copy` (انظر الوحدة `Oo`). وداخل دالة، يعيد التعبير `{<` [*inst-var-name* [`=` *expr*] { `;` *inst-var-name* [`=` *expr*] }] `>}` نسخةً من الذات استُبدلت فيها متغيّرات النسخة المعطاة بقيم التعبيرات المرتبطة بها. ويمثّل اسم متغيّر النسخة المفرد *id* التعبير *id* `=` *id*. وللمتغيّرات الأخرى القيمة نفسها في الكائن المعاد كما في الذات.

```ocaml
# let o =
    object
      val secret = 99
      val password = "unlock"
      method get guess = if guess <> password then None else Some secret
      method with_new_secret s = {< secret = s >}
    end;;

val o : < get : string -> int option; with_new_secret : int -> 'a > as 'a =
  <obj>
```

### 11.7.7 الإكراهات

يمكن إكراه التعابير التي يحوي نوعها أنواع كائنات أو أنواع متغيّرات متعدّدة الأشكال (إضعافها) صراحةً إلى نوع أعلى. ويُكره التعبير `(` *expr* `:>` *typexpr* `)` التعبير *expr* إلى النوع *typexpr*. ويُكره التعبير `(` *expr* `:` *typexpr*₁ `:>` *typexpr*₂ `)` التعبير *expr* من النوع *typexpr*₁ إلى النوع *typexpr*₂.

وقد يفشل المعامل الأول أحيانًا في إكراه تعبير *expr* من نوع *typ*₁ إلى نوع *typ*₂ حتى لو كان النوع *typ*₁ نوعًا فرعيًا من *typ*₂: فهو لا يوسّع في التنفيذ الحالي إلا مستويين من اختصارات الأنواع الحاوية كائنات و/أو متغيّرات متعدّدة الأشكال، ولا يحتفظ بالعودية إلا حين تكون صريحة في نوع الصنف (بالنسبة إلى الكائنات). واستثناءً من الخوارزمية السابقة، إذا كان النوع المستنتج لـ *expr* و*typ* كلاهما أرضيًّا (*أي* لا يحوي متغيّرات نوع)، تصرّف المعامل الأول كالمعامل الثاني، آخذًا النوع المستنتج لـ *expr* نوعًا لـ *typ*₁. وفي حال الفشل بالمعامل الأول، ينبغي استعمال الثاني.

ولا يمكن إكراه تعبير *expr* من نوع *typ*₁ إلى نوع *typ*₂ إلا إذا كان نوع *expr* حالةً من *typ*₁ (كما في تعليمة النوع)، وكان *typ*₁ نوعًا فرعيًا من *typ*₂. ونوع التعبير المكرَه حالةٌ من *typ*₂. وإذا كانت الأنواع تحوي متغيّرات، فقد تُجزَّأ بخوارزمية النوع الفرعي، لكن ذلك لا يحدث إلا بعد تحديد ما إذا كان *typ*₁ نوعًا فرعيًا محتملًا لـ *typ*₂. وهذا يعني أن التنميط قد يفشل في خطوة التوحيد الأخيرة هذه حتى لو كان بعض حالات *typ*₁ نوعًا فرعيًا لبعض حالات *typ*₂. ونصف في الفقرات التالية علاقة النوع الفرعي المستعملة.

#### أنواع الكائنات

يقبل نوع الكائن الثابت، نوعًا فرعيًا، كل نوع كائن يحوي جميع دواله. ويجب أن تكون أنواع الدوال أنواعًا فرعية من نظيراتها في النوع الأعلى. أي إن:

`<` *met*₁ `:` *typ*₁ `;` … `;` *met*ₙ `:` *typ*ₙ `>` نوعٌ أعلى من `<` *met*₁ `:` *typ*′₁ `;` … `;` *met*ₙ `:` *typ*′ₙ `;` *met*ₙ₊₁ `:` *typ*′ₙ₊₁ `;` … `;` *met*ₙ₊ₘ `:` *typ*′ₙ₊ₘ [`;` `..`] `>`

وقد يحوي هذا الأخير علامة حذف `..` إذا كان كل *typ*ᵢ نوعًا أعلى من *typ*′ᵢ المقابل له.

ويمكن أن يكون نوع دالة أحادية الشكل نوعًا أعلى من نوع دالة متعدّدة الأشكال. أي إنه إذا كان *typ* حالةً من *typ*′، فإن `'` *a*₁ … `'` *a*ₙ `.` *typ*′ نوعٌ فرعي من *typ*.

وداخل تعريف صنف، لا تكون الأنواع المعرَّفة حديثًا متاحة للنوع الفرعي، لأن اختصارات الأنواع لم تُعرَّف تمامًا بعد. وثمة استثناء لإكراه الذات إلى النوع (المضبوط) لصنفها: يُسمح بذلك إذا لم يظهر نوع الذات في موضع معاكس التغاير في نوع الصنف، *أي* إذا لم توجد دوال ثنائية.

#### أنواع المتغيّرات متعدّدة الأشكال

يكون نوع المتغيّر متعدّد الأشكال *typ* نوعًا فرعيًا من نوع متغيّر متعدّد الأشكال آخر *typ*′ إذا كان الحدّ الأعلى لـ *typ* (*أي* أكبر مجموعة من البواني التي قد تظهر في حالة من *typ*) محتوىً في الحدّ الأدنى لـ *typ*′، وكانت أنواع معاملات بواني *typ* أنواعًا فرعية من نظيراتها في *typ*′. أي إن:

`[[<]` `` ` ``*C*₁ `of` *typ*₁ `|` … `|` `` ` ``*C*ₙ `of` *typ*ₙ`]`

الذي قد يكون نوعًا قابلًا للانكماش، نوعٌ فرعي من

`[[>]` `` ` ``*C*₁ `of` *typ*′₁ `|` … `|` `` ` ``*C*ₙ `of` *typ*′ₙ `|` `` ` ``*C*ₙ₊₁ `of` *typ*′ₙ₊₁ `|` … `|` `` ` ``*C*ₙ₊ₘ `of` *typ*′ₙ₊ₘ`]`

الذي قد يكون نوعًا قابلًا للتوسّع، إذا كان كل *typ*ᵢ نوعًا فرعيًا من *typ*′ᵢ.

#### التغاير

لا تُدخل الأنواع الأخرى علاقة نوع فرعي جديدة، لكنها قد تنقل علاقة النوع الفرعي لمعاملاتها. فمثلًا، *typ*₁ `*` *typ*₂ نوع فرعي من *typ*′₁ `*` *typ*′₂ عندما يكون *typ*₁ و*typ*₂ نوعين فرعيين من *typ*′₁ و*typ*′₂ على الترتيب. أما أنواع الدوال فالعلاقة فيها أدقّ: *typ*₁ `->` *typ*₂ نوع فرعي من *typ*′₁ `->` *typ*′₂ إذا كان *typ*₁ نوعًا أعلى من *typ*′₁ وكان *typ*₂ نوعًا فرعيًا من *typ*′₂. ولهذا تكون أنواع الدوال متغايرة طرديًا في معاملها الثاني (كالصفوف)، ومتغايرة عكسيًا في معاملها الأول. أما الأنواع القابلة للتعديل، مثل `array` أو `ref`، فليست طردية ولا عكسية، بل غير متغايرة، أي إنها لا تنقل النوع الفرعي.

وبالنسبة إلى الأنواع المعرَّفة من المستخدم، يُستنتج التغاير تلقائيًا: يكون المعامل متغايرًا طرديًا إذا كانت له ورادات طردية فقط، ومتغايرًا عكسيًا إذا كانت له ورادات عكسية فقط، وخاليًا من التغاير إذا لم تكن له ورادات، وغير متغاير فيما عدا ذلك. ويمكن للمعامل الخالي من التغاير أن يتغيّر بحرية عبر النوع الفرعي، فلا يلزم أن يكون نوعًا فرعيًا أو نوعًا أعلى. أما الأنواع المجرّدة والخاصة، فيجب إعطاء التغاير صراحةً (انظر القسم 11.8.1)، وإلا فالمعيار هو عدم التغاير. وهذا هو الحال أيضًا بالنسبة إلى المعاملات المقيَّدة في تعريفات الأنواع.

### 11.7.8 عناصر بنيوية محلية

(أُدخلت الحالة العامة في OCaml 5.5، أما `let` `open` و`let` `exception` و`let` `module` فقد كانت مدعومة قبل ذلك.)

تُدخل الصيغة `let` *local-definition* `in` *expr* العنصر البنيوي (انظر 11.11.2) *local-definition* في النطاق أثناء تقييم *expr*.

وتكافئ هذه البنية إدخال البنية

struct

local-definition

let

body

=

expr

end

محليًا في سياق تعبير `let`، وإعادة قيمة `body` نتيجةً.

وتحوي بقية هذا القسم ملاحظات وأمثلة خاصة بحالات معيّنة من هذه البنية.

#### الفتح المحلي

يتكافئ التعبيران `let` `open` *module-path* `in` *expr* و*module-path* `.(` *expr* `)` تكافؤًا تامًّا. وتفتح هاتان البنيتان الوحدة المشار إليها بمسار الوحدة *module-path* محليًا في نطاق التعبير *expr* المعني.

```ocaml
# let map_3d_matrix f m =
    let open Array in
      map (map (map f)) m

  let map_3d_matrix' f =
    Array.(map (map (map f)));;

val map_3d_matrix :
  ('a -> 'b) -> 'a array array array -> 'b array array array = <fun>
val map_3d_matrix' :
  ('a -> 'b) -> 'a array array array -> 'b array array array = <fun>
```

وعندما يكون جسم تعبير الفتح المحلي محدَّدًا بـ `[` `]` أو `[|` `|]` أو `{` `}`، يمكن إغفال الأقواس. وبالنسبة إلى التعابير، يمكن أيضًا إغفال الأقواس في حالة `{<` `>}`. فمثلًا، *module-path* `.[` *expr* `]` يكافئ *module-path* `.([` *expr* `])`، و*module-path* `.[|` *expr* `|]` يكافئ *module-path* `.([|` *expr* `|])`.

```ocaml
# let vector = Random.[|int 255; int 255; int 255; int 255|];;

val vector : int array = [|220; 90; 247; 144|]
```

#### الوحدات المحلية

يربط التعبير `let` *module-definition* `in` *expr* تعريف الوحدة *module-definition* محليًا أثناء تقييم التعبير *expr*، ثم يعيد قيمة *expr*. مثلًا:

```ocaml
# let remove_duplicates comparison_fun string_list =
    let module StringSet =
      Set.Make(struct type t = string
                      let compare = comparison_fun end)
    in
      StringSet.elements
        (List.fold_right StringSet.add string_list StringSet.empty);;

val remove_duplicates :
  (string -> string -> int) -> string list -> string list = <fun>
```

#### الاستثناءات المحلية

(أُدخلت في OCaml 4.04)

يمكن تعريف استثناءات محلية في التعابير: `let` *exception* *constr-decl* `in` *expr*.

```ocaml
# let map_empty_on_negative f l =
    let exception Negative in
    let aux x = if x < 0 then raise Negative else f x in
      try List.map aux l with Negative -> [];;

val map_empty_on_negative : (int -> 'a) -> int list -> 'a list = <fun>
```

النطاق النحوي لباني الاستثناء هو التعبير الداخلي، لكن لا شيء يمنع قيم الاستثناءات المنشأة بهذا الباني من الإفلات من هذا النطاق. وينتج عن تنفيذين للتعريف السابق بانيان غير متوافقين (كما في أي تعريف استثناء). مثلًا:

```ocaml
# let gen () = let exception A in A

  let () = assert(gen () = gen ());;

Exception: Assert_failure ("expr.etex", 3, 9).
```

ويمكن إدخال أنواع المتغيّرات القابلة للتوسّع (انظر 12.14) بالطريقة نفسها. ويُظهر المثال التالي دالةً تستعمل أثرًا محليًا لتحويل مكرِّر إلى متتالية («عكس التحكّم»).

```ocaml
# let invert (type a) ~(iter : (a -> unit) -> unit) : a Seq.t =
    let type _ Effect.t += Yield : a -> unit Effect.t in
    let yield v = Effect.perform (Yield v) in
    fun () -> match iter yield with
    | () -> Seq.Nil
    | effect Yield v, k -> Seq.Cons (v, Effect.Deep.continue k)
  ;;

val invert : iter:(('a -> unit) -> unit) -> 'a Seq.t = <fun>
```

#### الأنواع المحلية

تُدخل الصيغة `let` *type-definition* `in` *expr* نوعًا (أو مجموعة أنواع متبادلة العودية) في نطاق تعبير:

```ocaml
# let f x y =
    let type t = {x: float; y: float} in
    let norm p = p.x *. p.x +. p.y *. p.y in
    norm {x; y}
  ;;

val f : float -> float -> float = <fun>
```

ويتحقّق المترجم من أن القيم المنشأة من هذا النوع لا تفلت من هذا النطاق:

```ocaml
# let f x y =
    let type t = {x: float; y: float} in
    let twice p = {x = p.x +. p.x; y = p.y +. p.y} in
    twice {x; y}
  ;;

Error: This expression has type t but an expression was expected of type 'a
       The type constructor t would escape its scope
```

### 11.7.9 متفرّقات

#### فحص التأكيدات

يدعم OCaml بنية `assert` لفحص تأكيدات التنقيح. ويقيّم التعبير `assert` *expr* التعبير *expr* ويعيد `()` إذا قُيّم *expr* إلى `true`. وإذا قُيّم إلى `false`، أُثير الاستثناء `Assert_failure` مع اسم ملف المصدر وموضع *expr* معاملين. ويمكن إيقاف فحص التأكيدات بخيار المترجم `-noassert`. وفي هذه الحالة لا يُقيَّم *expr* إطلاقًا.

```ocaml
# let f a b c =
    assert (a <= b && b <= c);
    (b -. a) /. (c -. b);;

val f : float -> float -> float -> float = <fun>
```

وكحالة خاصة، يُختزل `assert false` إلى `raise` `(` `Assert_failure ...` `)`، ما يمنحه نوعًا متعدّد الأشكال. وهذا يعني أنه يمكن استعماله بدلًا من أي تعبير (في أحد فروع أي مطابقة أنماط مثلًا). ويعني أيضًا أن «تأكيدات» `assert false` لا يمكن إيقافها بالخيار `-noassert`.

```ocaml
# let min_known_nonempty = function
    | [] -> assert false
    | l -> List.hd (List.sort compare l);;

val min_known_nonempty : 'a list -> 'a = <fun>
```

#### التعابير الكسولة

يعيد التعبير `lazy` *expr* قيمةً *v* من النوع `Lazy.t` تغلّف حساب *expr*. ولا يُقيَّم المعامل *expr* في هذه النقطة من البرنامج؛ بل يجري تقييمه أول مرة تُطبَّق فيها الدالة `Lazy.force` على القيمة *v*، فتعيد القيمة الفعلية لـ *expr*. ولا تُقيّم التطبيقات اللاحقة لـ `Lazy.force` على *v* التعبير *expr* من جديد. وقد تكون تطبيقات `Lazy.force` ضمنية عبر مطابقة الأنماط (انظر 11.6).

```ocaml
# let lazy_greeter = lazy (print_string "Hello, World!\n");;

val lazy_greeter : unit lazy_t = <lazy>

# Lazy.force lazy_greeter;;

Hello, World!
- : unit = ()
```

## 11.8 تعريفات الأنواع والاستثناءات

### 11.8.1 تعريفات الأنواع

تربط تعريفات الأنواع بواني الأنواع بأنواع البيانات: إما أنواع المتغيّرات، أو أنواع السجلات، أو اختصارات الأنواع، أو أنواع البيانات المجرّدة. وتربط أيضًا بواني القيم وحقول السجلات المرتبطة بالتعريف.

```text
type-definition::= type [nonrec] typedef { and typedef } typedef::= [type-params] typeconstr-name type-information type-information::= [type-equation] [type-representation] { type-constraint } type-equation::= = typexpr type-representation::= = [|] constr-decl { | constr-decl } ∣ = record-decl ∣ = | type-params::= type-param ∣ ( type-param { , type-param } ) type-param::= [ext-variance] ' ident ext-variance::= variance [injectivity] ∣ injectivity [variance] variance::= + ∣ - ∣ +- ∣ -+ injectivity::= ! record-decl::= { field-decl { ; field-decl } [;] } constr-decl::= (constr-name ∣ [] ∣ (::)) [ of constr-args ] constr-args::= typexpr { * typexpr } field-decl::= [mutable] field-name : poly-typexpr type-constraint::= constraint typexpr = typexpr
```

انظر أيضًا امتدادات اللغة التالية: الأنواع الخاصة، وأنواع البيانات الجبرية المعمّمة، والسمات، وعقد الامتداد، وأنواع المتغيّرات القابلة للتوسّع، والسجلات المضمّنة.

تُقدَّم تعريفات الأنواع بالكلمة المحجوزة `type`، وتتألف من تعريف بسيط واحد أو عدة تعريفات بسيطة، قد تكون متبادلة العودية، تفصل بينها الكلمة المحجوزة `and`. ويعرّف كل تعريف بسيط باني نوع واحدًا.

ويتألف التعريف البسيط من معرّف يبدأ بحرف صغير، قد تسبقه معاملات نوع واحدة أو عدة، وتلحقه معادلة نوع اختيارية، ثم تمثيل نوع اختياري، ثم جملة قيد. والمعرّف هو اسم باني النوع المعرَّف.

```text
type colour =
  | Red | Green | Blue | Yellow | Black | White
  | RGB of {r : int; g : int; b : int}

type 'a tree = Lf | Br of 'a * 'a tree * 'a;;

type t = {decoration : string; substance : t'}
and t' = Int of int | List of t list
```

وفي الطرف الأيمن من تعريفات الأنواع، تُعدّ الإشارات إلى أحد أسماء بواني الأنواع المعرَّفة إشارات عودية، ما لم تتبع `type` الكلمة `nonrec`. وقد أُدخلت الكلمة المحجوزة `nonrec` في OCaml 4.02.2.

أما معاملات النوع الاختيارية فهي إما متغيّر نوع واحد `'` *ident*، لبواني الأنواع ذات المعامل الواحد، أو قائمة متغيّرات أنواع `('` *ident*₁, …, `'` *ident*ₙ `)`، لبواني الأنواع ذات المعاملات المتعددة. ويمكن أن يسبق كل معامل نوع قيد تغاير `+` (أو `-`) يدلّ على أن المعامل متغاير طرديًا (أو عكسيًا)، وتعليمة حقنية `!` تدلّ على أن المعامل يمكن استنتاجه من النوع كاملًا. ويمكن أن تظهر معاملات النوع هذه في تعابير الأنواع في الطرف الأيمن من التعريف، مقيَّدة اختياريًا بقيد تغاير؛ *أي* إن المعامل الطردي لا يظهر إلا في يمين سهم دالي (وبالأحرى في الفرع الأيسر من عدد زوجي من الأسهم)، والمعامل العكسي لا يظهر إلا في اليسار (الفرع الأيسر من عدد فردي من الأسهم). وإذا كان للنوع تمثيل أو معادلة، وكان المعامل حرًّا (*أي* غير مرتبط بقيد نوع بنوع مبنيّ)، فيُتحقَّق من قيد تغايره، لكن النوع الفرعي *وما إليه* سيستعمل التغاير المستنتج للمعامل، الذي قد يكون أقل تقييدًا؛ وإلا (*أي* في الأنواع المجرّدة أو المعاملات غير الحرّة)، فيجب إعطاء التغاير صراحةً، ويكون المعامل غير متغاير إذا لم يُعطَ تغاير.

وتجعل معادلة النوع الاختيارية `=` *typexpr* النوع المعرَّف مكافئًا لتعبير النوع *typexpr*: فيمكن استبدال أحدهما بالآخر أثناء التنميط. وإذا لم تُعطَ معادلة نوع، وُلّد نوع جديد: فيكون النوع المعرَّف غير متوافق مع أي نوع آخر.

ويصف تمثيل النوع الاختياري بنية البيانات الممثِّلة للنوع المعرَّف، بإعطاء قائمة البواني المرتبطة (إذا كان نوع متغيّر) أو الحقول المرتبطة (إذا كان نوع سجل). وإذا لم يُعطَ تمثيل نوع، لم يُفترض شيء عن بنية النوع عدا ما تنصّ عليه معادلة النوع الاختيارية.

وتمثيل النوع `=` [`|`] *constr-decl* { `|` *constr-decl* } يصف نوع متغيّر. وتصف تصريحات البواني *constr-decl*₁، …، *constr-decl*ₙ البواني المرتبطة بهذا النوع. ويصرّح تعريف الباني *constr-name* `of` *typexpr*₁ `*` … `*` *typexpr*ₙ بالاسم *constr-name* بانيًا غير ثابت، أنواع معاملاته *typexpr*₁ … *typexpr*ₙ. ويصرّح تعريف الباني *constr-name* بالاسم *constr-name* بانيًا ثابتًا. ويجب أن تبدأ أسماء البواني بحرف كبير.

وتمثيل النوع `=` `{` *field-decl* { `;` *field-decl* } [`;`] `}` يصف نوع سجل. وتصف تصريحات الحقول *field-decl*₁، …، *field-decl*ₙ الحقول المرتبطة بهذا النوع. ويصرّح تعريف الحقل *field-name* `:` *poly-typexpr* بالاسم *field-name* حقلًا نوع معامله *poly-typexpr*. ويتصرّف تعريف الحقل `mutable` *field-name* `:` *poly-typexpr* على نحو مشابه؛ ويزيد أنه يسمح بتعديل هذا الحقل فيزيائيًا. والحقول غير القابلة للتعديل متغايرة طرديًا، والحقول القابلة للتعديل غير متغايرة. ومنذ OCaml 5.4، يمكن وسم الحقول القابلة للتعديل بـ `[@atomic]` للوصول المتزامن، انظر 9.7.2. ويمكن أن يكون للحقول القابلة للتعديل وغير القابلة له أنواع متعدّدة الأشكال صريحة. ويُتحقَّق من تعدّد أشكال المحتوى ساكنًا كلما أُنشئت قيمة سجل أو عُدّلت. وقد تُجزَّأ أنواع القيم المستخرجة.

ويمكن دمج مكوّني تعريف النوع، المعادلة الاختيارية والتمثيل الاختياري، مستقلَّين، ما يعطي أربع حالات نموذجية:

****نوع مجرّد: لا معادلة ولا تمثيل.****

حين يظهر هذا التعريف في توقيع وحدة، فإنه لا يحدّد شيئًا عن باني النوع عدا عدد معاملاته: فتمثيله مخفيّ ويُفترض أنه غير متوافق مع أي نوع آخر.

****اختصار نوع: معادلة بلا تمثيل.****

يعرّف هذا باني النوع اختصارًا لتعبير النوع على يمين علامة `=`.

****نوع متغيّر أو نوع سجل جديد: لا معادلة، بل تمثيل.****

يولّد هذا باني نوع جديدًا ويعرّف البواني أو الحقول المرتبطة، التي يمكن من خلالها بناء قيم هذا النوع أو فحصها مباشرةً.

****نوع متغيّر أو نوع سجل معاد تصديره: معادلة وتمثيل.****

في هذه الحالة، يُعرَّف باني النوع اختصارًا لتعبير النوع المعطى في المعادلة، غير أن البواني أو الحقول المعطاة في التمثيل تبقى مرتبطة بباني النوع المعرَّف. ويجب أن يتوافق تعبير النوع في جزء المعادلة مع التمثيل: فيجب أن يكون من النوع نفسه (سجل أو متغيّر)، وأن يحوي البواني أو الحقول نفسها بالضبط، بالترتيب نفسه، وبالمعاملات نفسها. وعلاوةً على ذلك، يجب أن تكون لباني النوع الجديد الرتبة نفسها وقيود النوع نفسها التي لباني النوع الأصلي.

ويمكن أن تسبق متغيّرات الأنواع الظاهرة معاملاتِ نوعٍ ما بادئةٌ `+` أو `-` أو `+-` أو `-+` تدلّ على أن لباني النوع تغايرًا خاصًّا بالنسبة إلى هذا المعامل. فالمعامل المسبوق بـ `+` متغاير طرديًا، والمسبوق بـ `-` متغاير عكسيًا. ويمكن أن يكون المعامل طرديًا وعكسيًا معًا، أي متغايرًا في الاتجاهين، ببادئة `+-` أو `-+`. وتُستعمل معلومة التغاير هذه لتحديد علاقات النوع الفرعي عند التحقّق من صحة الإكراهات `:>` (انظر القسم 11.7.7).

فمثلًا، يصرّح `type +'a t` بأن `t` نوع مجرّد متغاير طرديًا في معامله؛ وهذا يعني أنه إذا كان النوع τ نوعًا فرعيًا من النوع σ، فإن τ`t` نوع فرعي من σ`t`. وعلى المنوال نفسه، يصرّح `type -'a t` بأن النوع المجرّد `t` متغاير عكسيًا في معامله: فإذا كان τ نوعًا فرعيًا من σ، فإن σ`t` نوع فرعي من τ`t`. وإذا لم تُعطَ تعليمة تغاير `+` أو `-`، فُرض أن باني النوع غير متغاير في المعامل المقابل. فمثلًا، يعني تصريح النوع المجرّد `type 'a t` أن τ`t` ليس نوعًا فرعيًا ولا نوعًا أعلى من σ`t` إذا كان τ نوعًا فرعيًا من σ.

ولا يُفرض التغاير المشار إليه بتعليمتي `+` و`-` على المعاملات إلا في الأنواع المجرّدة والخاصة، أو حين توجد قيود نوع. وفيما عدا ذلك، أي في الاختصارات وأنواع المتغيّرات والسجلات بلا قيود نوع، تُستنتج خصائص التغاير لباني النوع من تعريفه، ولا تُفحص تعليمات التغاير إلا من حيث مطابقتها للتعريف.

ولا تلزم التعليمات الحقنية إلا في الأنواع المجرّدة وأنواع الصفوف الخاصة، إذ يمكن عدا ذلك استنتاجها من تصريح النوع: فجميع المعاملات حقنية في تصريحات أنواع السجلات والمتغيّرات (بما فيها الأنواع القابلة للتوسّع)؛ وفي اختصارات الأنواع يكون المعامل حقنيًا إذا كانت له ورادة حقنية في معادلته المعرِّفة (سواء كانت خاصة أم لا). أما معاملات الأنواع المقيَّدة في اختصارات الأنواع، فهي حقنية إذا ظهرت في موضع حقني في الجسم، أو إذا كانت جميع متغيّرات أنواعها حقنية؛ وبوجه خاص، إذا حوى معامل نوع مقيَّد متغيّرًا لا يظهر في الجسم، فلا يمكن أن يكون حقنيًا.

وتسمح البنية `constraint` `'` *ident* `=` *typexpr* بتحديد معاملات الأنواع. ويجب أن تكون كل حجّة نوع فعلية تقابل معامل النوع *ident* حالةً من *typexpr* (وبالأحرى تُوحَّد *ident* و*typexpr*). ويمكن أن تظهر متغيّرات أنواع *typexpr* في معادلة النوع وتصريح النوع.

### 11.8.2 تعريفات الاستثناءات

```text
exception-definition::= exception constr-decl ∣ exception constr-name = constr
```

تضيف تعريفات الاستثناءات بواني جديدة إلى نوع المتغيّرات المدمج `exn` لقيم الاستثناءات. وتُصرَّح البواني كما في تعريف نوع متغيّر.

```ocaml
# exception E of int * string;;

exception E of int * string
```

وتولّد الصيغة `exception` *constr-decl* استثناءً جديدًا متميزًا عن جميع الاستثناءات الأخرى في النظام. وتمنح الصيغة `exception` *constr-name* `=` *constr* اسمًا بديلًا لاستثناء موجود.

```ocaml
# exception E of int * string

  exception F = E

  let eq =
     E (1, "one") = F (1, "one");;

exception E of int * string
exception F of int * string
val eq : bool = true
```

## 11.9 الأصناف

تُعرَّف الأصناف بلغة صغيرة تشبه لغة الوحدات.

### 11.9.1 أنواع الأصناف

أنواع الأصناف هي المكافئ على مستوى الأصناف لتعبيرات الأنواع: فهي تحدّد الشكل العام والخصائص النوعية للأصناف.

```text
class-type::= [[?]label-name:] typexpr -> class-type ∣ class-body-type class-body-type::= object [( typexpr )] { class-field-spec } end ∣ [[ typexpr { , typexpr } ]] classtype-path ∣ let open module-path in class-body-type class-field-spec::= inherit class-body-type ∣ val [mutable] [virtual] inst-var-name : typexpr ∣ val virtual mutable inst-var-name : typexpr ∣ method [private] [virtual] method-name : poly-typexpr ∣ method virtual private method-name : poly-typexpr ∣ constraint typexpr = typexpr
```

انظر أيضًا امتدادات اللغة التالية: السمات وعقد الامتداد.
#### تعابير الأصناف البسيطة

يكافئ التعبير *classtype-path* نوع الصنف المرتبط بالاسم *classtype-path*. وعلى المنوال نفسه، يكافئ التعبير `[` *typexpr*₁ `,` … `,` *typexpr*ₙ `]` *classtype-path* نوع الصنف ذا المعاملات المرتبط بالاسم *classtype-path*، بعد أن جُزِّئت معاملات نوعه إلى *typexpr*₁، …، *typexpr*ₙ على الترتيب.

#### نوع الدالة الصنفية

تعبير نوع الصنف *typexpr* `->` *class-type* هو نوع الدوال الصنفية (دوال من القيم إلى الأصناف) التي تأخذ معاملًا من النوع *typexpr* وتعيد نتيجةً صنفًا من النوع *class-type*.

#### نوع جسم الصنف

تعبير نوع الصنف `object` [`(` *typexpr* `)`] { *class-field-spec* } `end` هو نوع جسم صنف. ويحدّد متغيّرات نسخته ودواله. وفي هذا النوع، تُطابَق *typexpr* مع نوع الذات، فتوفّر بذلك اسمًا لنوع الذات.

ويطابق جسم الصنف نوع جسم صنف إذا قدّم تعريفات لجميع المكوّنات المحدّدة في نوع جسم الصنف، وكانت هذه التعريفات تحقّق شروط النوع المعطاة في نوع جسم الصنف. وعلاوةً على ذلك، يجب أن تكون جميع الدوال، المجرّدة أو العامة، الموجودة في جسم الصنف موجودة أيضًا في نوع جسم الصنف (أما بعض متغيّرات النسخة والدوال الخاصة الملموسة فقد تُغفَل). وتطابق الدالة المجرّدة دالةً ملموسة، ما يجعل من الممكن نسيان تنفيذها. ويطابق متغيّر النسخة غير القابل للتعديل متغيّر نسخة قابلًا للتعديل.

#### الفتح المحلي

الفتح المحلي مدعوم في أنواع الأصناف منذ OCaml 4.06.

#### الوراثة

تتيح بنية الوراثة `inherit` *class-body-type* ضمّ الدوال ومتغيّرات النسخة من أنواع أصناف أخرى. فتُضاف أنواع متغيّرات النسخة والدوال من *class-body-type* إلى نوع الصنف الحالي.

#### تحديد متغيّر النسخة

يُكتب تحديد متغيّر النسخة على الصيغة `val` [`mutable`] [`virtual`] *inst-var-name* `:` *typexpr*، حيث *inst-var-name* اسم متغيّر النسخة و*typexpr* نوعه المتوقّع. وتدلّ العلامة `mutable` على ما إذا كان هذا المتغيّر قابلًا للتعديل فيزيائيًا. وتدلّ العلامة `virtual` على أن هذا المتغيّر غير مهيّأ، ويمكن تهيئته لاحقًا عبر الوراثة.

ويخفي تحديد متغيّر النسخة أي تحديد سابق لمتغيّر نسخة بالاسم نفسه.

#### تحديد الدالة

يُكتب تحديد الدالة على الصيغة `method` [`private`] *method-name* `:` *poly-typexpr*، حيث *method-name* اسم الدالة و*poly-typexpr* نوعها المتوقّع، الذي قد يكون متعدّد الأشكال. وتدلّ العلامة `private` على أن الدالة لا يمكن الوصول إليها من خارج الكائن.

ويمكن إغفال تعدّد الأشكال في تحديدات الدوال العامة: فكل متغيّر نوع غير مرتبط بمعامل صنف ولا يظهر في موضع آخر داخل تحديد الصنف يُفترض أنه كلي، ويُجعل متعدّد الأشكال في نوع الدالة الناتج. وكتابة نوع متعدّد الأشكال صراحةً تعطّل هذا السلوك.

وإذا وُجدت عدة تحديدات للدالة نفسها، فيجب أن تكون أنواعها متوافقة. ويفرض أي تحديد غير خاص لدالة أن تكون عامة.

#### تحديد الدالة المجرّدة

يُكتب تحديد الدالة المجرّدة على الصيغة `method` [`private`] `virtual` *method-name* `:` *poly-typexpr*، حيث *method-name* اسم الدالة و*poly-typexpr* نوعها المتوقّع.

#### قيود على معاملات الأنواع

تفرض البنية `constraint` *typexpr*₁ `=` *typexpr*₂ تساوي تعبيري النوع. ويُستعمل هذا عادةً لتحديد معاملات الأنواع: إذ يمكن بهذه الطريقة ربطها بتعبيرات أنواع محدّدة.

### 11.9.2 تعابير الأصناف

تعابير الأصناف هي المكافئ على مستوى الأصناف لتعبيرات القيم: فهي تُقيَّم إلى أصناف، فتوفّر بذلك تنفيذات للتحديدات المعبَّر عنها في أنواع الأصناف.

```text
class-expr::= class-path ∣ [ typexpr { , typexpr } ] class-path ∣ ( class-expr ) ∣ ( class-expr : class-type ) ∣ class-expr { argument }⁺ ∣ fun { parameter }⁺ -> class-expr ∣ let [rec] let-binding { and let-binding } in class-expr ∣ object class-body end ∣ let open module-path in class-expr
```

```text
class-field::= inherit class-expr [as lowercase-ident] ∣ inherit! class-expr [as lowercase-ident] ∣ val [mutable] inst-var-name [: typexpr] = expr ∣ val! [mutable] inst-var-name [: typexpr] = expr ∣ val [mutable] virtual inst-var-name : typexpr ∣ val virtual mutable inst-var-name : typexpr ∣ method [private] method-name { parameter } [: typexpr] = expr ∣ method! [private] method-name { parameter } [: typexpr] = expr ∣ method [private] method-name : poly-typexpr = expr ∣ method! [private] method-name : poly-typexpr = expr ∣ method [private] virtual method-name : poly-typexpr ∣ method virtual private method-name : poly-typexpr ∣ constraint typexpr = typexpr ∣ initializer expr
```

انظر أيضًا امتدادات اللغة التالية: الأنواع المجرّدة المحلية، والسمات، وعقد الامتداد.

#### تعابير الأصناف البسيطة

يُقيَّم التعبير *class-path* إلى الصنف المرتبط بالاسم *class-path*. وعلى المنوال نفسه، يُقيَّم التعبير `[` *typexpr*₁ `,` … `,` *typexpr*ₙ `]` *class-path* إلى الصنف ذي المعاملات المرتبط بالاسم *class-path*، بعد أن جُزِّئت معاملات نوعه إلى *typexpr*₁، …، *typexpr*ₙ على الترتيب.

ويُقيَّم التعبير `(` *class-expr* `)` إلى الوحدة نفسها *class-expr*.

ويتحقّق التعبير `(` *class-expr* `:` *class-type* `)` من مطابقة *class-type* لنوع *class-expr* (أي من أن التنفيذ *class-expr* يحقّق تحديد النوع *class-type*). ويُقيَّم التعبير كاملًا إلى الصنف نفسه *class-expr*، باستثناء أن جميع المكوّنات غير المحدّدة في *class-type* تصير مخفيّة ولا يمكن الوصول إليها.

#### تطبيق الأصناف

يُشار إلى تطبيق الأصناف بمجاورة تعابير (قد تكون معنونة). ويدلّ على الصنف الذي بانيه التعبير الأول مطبَّقًا على المعاملات المعطاة. وتُقيَّم المعاملات كما في تطبيق التعابير، لكن الباني نفسه لا يُقيَّم إلا عند إنشاء الكائنات. وبوجه خاص، لا تحدث الآثار الجانبية الناتجة عن تطبيق الباني إلا في وقت إنشاء الكائن.

#### الدالة الصنفية

يُقيَّم التعبير `fun` [[`?`] *label-name* `:`] *pattern* `->` *class-expr* إلى دالة من القيم إلى الأصناف. وعندما تُطبَّق هذه الدالة على قيمة *v*، تُطابَق هذه القيمة مع النمط *pattern*، وتكون النتيجة نتيجة تقييم *class-expr* في البيئة الموسَّعة.

والتحويل من دوال ذات قيم معيارية إلى دوال بالأنماط فقط يعمل في الدوال الصنفية كما يعمل في الدوال العادية.

#### التعريفات المحلية

تربط بنيتا `let` و`let rec` أسماء القيم محليًا، كما في تعابير اللغة الأساسية.

وإذا حدث تعريف محلي في بداية تعريف الصنف تمامًا، فإنه يُقيَّم عند إنشاء الصنف (كما لو كان التعريف خارج الصنف). وإلا فإنه يُقيَّم عند استدعاء باني الكائن.

#### الفتح المحلي

الفتح المحلي مدعوم في تعابير الأصناف منذ OCaml 4.06.

#### جسم الصنف

```text
class-body::= [( pattern [: typexpr] )] { class-field }
```

يدلّ التعبير `object` *class-body* `end` على جسم صنف. وهذا هو النموذج الأوّلي للكائن: إذ يسرد متغيّرات النسخة ودوال كائن من هذا الصنف.

وجسم الصنف قيمة صنفية: فهو لا يُقيَّم دفعةً واحدة، بل تُقيَّم مكوّناته في كل مرة يُنشأ فيها كائن.

وفي جسم الصنف، يُطابَق النمط `(` *pattern* [`:` *typexpr*] `)` مع الذات، فيوفّر بذلك ارتباطًا للذات ولنوع الذات. ولا يمكن استعمال الذات إلا في الدوال والمهيّئات.

ولا يمكن أن يكون نوع الذات نوع كائن مغلق، حتى يبقى الصنف قابلًا للتوسّع.

ومنذ OCaml 4.01، يُعدّ خطأً تعريف الاسم نفسه لدالة أو متغيّر نسخة عدة مرات في جسم الصنف نفسه.

#### الوراثة

تتيح بنية الوراثة `inherit` *class-expr* إعادة استعمال الدوال ومتغيّرات النسخة من أصناف أخرى. ويجب أن يُقيَّم تعبير الصنف *class-expr* إلى جسم صنف. وتُضاف متغيّرات النسخة والدوال والمهيّئات من جسم الصنف هذا إلى الصنف الحالي. ووجود دالة يُلغي أي دالة سابقة معرَّفة بالاسم نفسه.

ويمكن ربط سلف بإلحاق `as` *lowercase-ident* ببنية الوراثة. وليس *lowercase-ident* متغيّرًا حقيقيًا، ولا يمكن استعماله إلا لاختيار دالة، أي في تعبير *lowercase-ident* `#` *method-name*. ويتيح ذلك الوصول إلى الدالة *method-name* كما عُرِّفت في الصنف الأب حتى لو أُعيد تعريفها في الصنف الحالي. ويقتصر نطاق ارتباط السلف هذا على الصنف الحالي. ويمكن استدعاء دالة السلف من صنف فرعي، لكن بشكل غير مباشر فقط.

#### تعريف متغيّر النسخة

يضيف التعريف `val` [`mutable`] *inst-var-name* `=` *expr* متغيّر نسخة *inst-var-name* قيمته الابتدائية قيمة التعبير *expr*. وتسمح العلامة `mutable` للدوال بتعديل هذا المتغيّر فيزيائيًا.

ولا يمكن استعمال متغيّر النسخة إلا في الدوال والمهيّئات التي تلي تعريفه.

ومنذ الإصدار 3.10، لا تنشئ إعادة تعريف متغيّر نسخة مرئي بالاسم نفسه متغيّرًا جديدًا، بل يُدمجان، وتُستعمل القيمة الأخيرة للتهيئة. ويجب أن يكون لهما النوعان نفسهما وقابلية التعديل نفسها. أما إذا حُجب متغيّر نسخة بإغفاله من واجهة، فسيبقى متميزًا عن متغيّرات النسخة الأخرى بالاسم نفسه.

#### تعريف متغيّر النسخة المجرّد

يُكتب تحديد المتغيّر على الصيغة `val` [`mutable`] `virtual` *inst-var-name* `:` *typexpr*. ويحدّد ما إذا كان المتغيّر قابلًا للتعديل، ويعطي نوعه.

وقد أُضيفت متغيّرات النسخة المجرّدة في الإصدار 3.10.

#### تعريف الدالة

يُكتب تعريف الدالة على الصيغة `method` *method-name* `=` *expr*. ويلغي تعريف الدالة أي تعريف سابق لهذه الدالة. وتكون الدالة عامة (أي غير خاصة) إذا نصّ على ذلك أي من تعريفاتها.

والدالة الخاصة، `method` `private` *method-name* `=` *expr*، دالة لا يمكن استدعاؤها إلا على الذات (من دوال أخرى للكائن نفسه، معرَّفة في هذا الصنف أو في أحد أصنافه الفرعية). ويجري هذا الاستدعاء بالتعبير *value-name* `#` *method-name*، حيث *value-name* مرتبط مباشرةً بالذات في بداية تعريف الصنف. ولا تظهر الدوال الخاصة في أنواع الكائنات. وقد تكون للدالة تعريفات عامة وخاصة معًا، لكن حالما يوجد تعريف عام تصبح جميع التعريفات اللاحقة عامة.

وقد يكون للدوال نوع متعدّد الأشكال صريح، ما يسمح باستعمالها استعمالًا متعدّد الأشكال في البرامج (حتى للكائن نفسه). ويجوز الإعلان الصريح بإحدى ثلاث طرق: (1) بإعطاء نوع متعدّد الأشكال صريح في تعريف الدالة، مباشرةً بعد اسم الدالة، *أي* `method` [`private`] *method-name* `:` { `'` *ident* }⁺ `.` *typexpr* `=` *expr*؛ (2) بإعلان مسبق للنوع متعدّد الأشكال الصريح عبر تعريف دالة مجرّدة؛ (3) باستيراد إعلان كهذا عبر الوراثة و/أو تقييد نوع الذات.

وثمة تعابير خاصة متاحة في أجسام الدوال للتعامل مع متغيّرات النسخة وتكرار الذات:

```text
expr::= … ∣ inst-var-name <- expr ∣ {< [ inst-var-name = expr { ; inst-var-name = expr } [;] ] >}
```

ويعدّل التعبير *inst-var-name* `<-` *expr* الكائن الحالي في مكانه، باستبدال القيمة المرتبطة بـ *inst-var-name* بقيمة *expr*. ويجب بطبيعة الحال أن يكون متغيّر النسخة هذا قد صُرِّح قابلًا للتعديل.

ويُقيَّم التعبير `{<` *inst-var-name*₁ `=` *expr*₁ `;` … `;` *inst-var-name*ₙ `=` *expr*ₙ `>}` إلى نسخة من الكائن الحالي استُبدلت فيها قيم متغيّرات النسخة *inst-var-name*₁، …، *inst-var-name*ₙ بقيم التعبيرات المقابلة *expr*₁، …، *expr*ₙ.

#### تعريف الدالة المجرّدة

يُكتب تحديد الدالة على الصيغة `method` [`private`] `virtual` *method-name* `:` *poly-typexpr*. ويحدّد ما إذا كانت الدالة عامة أو خاصة، ويعطي نوعها. وإذا كان المقصود أن تكون الدالة متعدّدة الأشكال، فيجب أن يكون النوع متعدّد الأشكال صراحةً.

#### الإلغاء الصريح

منذ Ocaml 3.12، للكلمات المحجوزة `inherit!` و`val!` و`method!` الدلالة نفسها التي لـ `inherit` و`val` و`method`، غير أنها تشترط إضافةً أن يكون التعريف الذي تُدخله ملغيًا. فـ `method!` تشترط أن يكون *method-name* معرَّفًا سابقًا في هذا الصنف، و`val!` تشترط أن يكون *inst-var-name* معرَّفًا سابقًا في هذا الصنف، و`inherit!` تشترط أن يلغي *class-expr* بعض التعريفات. وإذا لم يحدث إلغاء كهذا، أُشير إلى خطأ.

وكأثر جانبي، تتجنّب هذه الكلمات الثلاث التحذيرين 7 (إلغاء الدالة) و13 (إلغاء متغيّر النسخة). ولاحظ أن التحذير 7 معطَّل افتراضيًا.

#### قيود على معاملات الأنواع

تفرض البنية `constraint` *typexpr*₁ `=` *typexpr*₂ تساوي تعبيري النوع. ويُستعمل هذا عادةً لتحديد معاملات الأنواع: إذ يمكن بهذه الطريقة ربطها بتعبيرات أنواع محدّدة.

#### المهيّئات

يحدّد مهيّئ الصنف `initializer` *expr* تعبيرًا يُقيَّم كلما أُنشئ كائن من الصنف، بعد تهيئة جميع متغيّرات نسخته.

### 11.9.3 تعريفات الأصناف

```text
class-definition::= class class-binding { and class-binding } class-binding::= [virtual] [[ type-parameters ]] class-name { parameter } [: class-type] = class-expr type-parameters::= ' ident { , ' ident }
```

تعريف الصنف `class` *class-binding* { `and` *class-binding* } عودي. ويعرّف كل *class-binding* اسم صنف *class-name* يمكن استعماله في التعبير كاملًا باستثناء الوراثة. ويمكن استعماله في الوراثة أيضًا، لكن فقط في التعريفات التي تلي تعريفه.

ويربط ارتباط الصنف اسم الصنف *class-name* بقيمة التعبير *class-expr*. ويربط أيضًا نوع الصنف *class-name* بنوع الصنف، ويعرّف اختصارَي نوع: *class-name* و`#` *class-name*. الأول نوع كائنات هذا الصنف، والثاني أعمّ لأنه يتوحّد مع نوع أي كائن ينتمي إلى صنف فرعي (انظر القسم 11.4).

#### الصنف المجرّد

يجب وسم الصنف بأنه مجرّد إذا كانت إحدى دواله مجرّدة (أي تظهر في نوع الصنف، لكنها غير معرَّفة فعليًا). ولا يمكن إنشاء كائنات من صنف مجرّد.

#### معاملات الأنواع

تقابل معاملات نوع الصنف معاملات نوع الصنف واختصارَي النوع اللذين يعرّفهما ارتباط الصنف. ويجب ربطها بأنواع فعلية في تعريف الصنف باستعمال قيود النوع. ولكي تكون الاختصارات سليمة الصياغة، يجب أن تكون متغيّرات أنواع النوع المستنتج للصنف إما معاملات أنواع أو مرتبطة في جملة القيد.

### 11.9.4 تحديدات الأصناف

```text
class-specification::= class class-spec { and class-spec } class-spec::= [virtual] [[ type-parameters ]] class-name : class-type
```

هذا هو النظير في التوقيعات لتعريفات الأصناف. ويطابق تحديد الصنف تعريف صنف إذا كان لهما معاملات الأنواع نفسها وكان نوعاهما متطابقين.

### 11.9.5 تعريفات أنواع الأصناف

```text
classtype-definition::= class type classtype-def { and classtype-def } classtype-def::= [virtual] [[ type-parameters ]] class-name = class-body-type
```

يعرّف تعريف نوع الصنف `class` *class-name* `=` *class-body-type* اختصارًا *class-name* لنوع جسم الصنف *class-body-type*. وكما في تعريفات الأصناف، يُعرَّف أيضًا اختصارا نوع: *class-name* و`#` *class-name*. ويمكن أن يكون التعريف ذا معاملات أنواع. وإذا كانت إحدى دوال جسم نوع الصنف مجرّدة، فيجب وسم التعريف بـ `virtual`.

ويتطابق تعريفا نوع صنف إذا كان لهما معاملات الأنواع نفسها وكانا يتمدّدان إلى نوعين متطابقين.

## 11.10 أنواع الوحدات (تحديدات الوحدات)

أنواع الوحدات هي المكافئ على مستوى الوحدات لتعبيرات الأنواع: فهي تحدّد الشكل العام والخصائص النوعية للوحدات.

```text
module-type::= modtype-path ∣ sig { specification [;;] } end ∣ [functor] { ( module-name : module-type ) }⁺ -> module-type ∣ module-type -> module-type ∣ module-type with mod-constraint { and mod-constraint } ∣ ( module-type ) mod-constraint::= type [type-params] typeconstr type-equation { type-constraint } ∣ module module-path = extended-module-path
```

```text
specification::= val value-name : typexpr ∣ external value-name : typexpr = external-declaration ∣ type-definition ∣ exception constr-decl ∣ class-specification ∣ classtype-definition ∣ module module-name : module-type ∣ module module-name { ( module-name : module-type ) } : module-type ∣ module type modtype-name ∣ module type modtype-name = module-type ∣ open module-path ∣ include module-type
```

انظر أيضًا امتدادات اللغة التالية: استرجاع نوع وحدة، والاستبدال داخل توقيع، وكنى الوحدات على مستوى الأنواع، والسمات، وعقد الامتداد، والموصِّلات التوليدية، واستبدالات أنواع الوحدات.

### 11.10.1 أنواع الوحدات البسيطة

يكافئ التعبير *modtype-path* نوع الوحدة المرتبط بالاسم *modtype-path*. ويدلّ التعبير `(` *module-type* `)` على النوع نفسه *module-type*.

### 11.10.2 التوقيعات

التوقيعات تحديدات أنواع للبنى. والتوقيعات `sig` … `end` مجموعات من تحديدات الأنواع لأسماء القيم وأسماء الأنواع والاستثناءات وأسماء الوحدات وأسماء أنواع الوحدات. وتطابق البنية توقيعًا إذا كانت تقدّم تعريفات (تنفيذات) لجميع الأسماء المحدّدة في التوقيع (وقد تزيد عليها)، وكانت هذه التعريفات تحقّق شروط النوع المعطاة في التوقيع.

ويُسمح بـ `;;` اختيارية بعد كل تحديد في توقيع. وهي تعمل فاصلًا نحويًا لا معنى دلاليًا له.

#### تحديدات القيم

يُكتب تحديد مكوّن قيمة في توقيع على الصيغة `val` *value-name* `:` *typexpr*، حيث *value-name* اسم القيمة و*typexpr* نوعها المتوقّع.

وتشبه صيغة `external` *value-name* `:` *typexpr* `=` *external-declaration* ذلك، غير أنها تشترط إضافةً تنفيذ الاسم كالدالة الخارجية المحدّدة في *external-declaration* (انظر الفصل 23).

#### تحديدات الأنواع

يُكتب تحديد مكوّن نوع واحد أو عدة في توقيع على الصيغة `type` *typedef* { `and` *typedef* }، ويتألف من متتالية تعريفات متبادلة العودية لأسماء الأنواع.

ويحدّد كل تعريف نوع في التوقيع معادلة نوع اختيارية `=` *typexpr* وتمثيل نوع اختياريًا `=` *constr-decl* … أو `=` `{` *field-decl* … `}`. ويجب أن يكون تنفيذ اسم النوع في بنية مطابقة متوافقًا مع تعبير النوع المحدّد في المعادلة (إن أُعطي)، وأن يمتلك التمثيل المحدّد (إن أُعطي). وفي المقابل، سيتمكّن مستعملو هذا التوقيع من الاعتماد على معادلة النوع أو تمثيل النوع إن أُعطيا. وبالأحرى، لدينا الحالات الأربع التالية:

****نوع مجرّد: لا معادلة ولا تمثيل.****

يمكن تنفيذ الأسماء المعرَّفة أنواعًا مجرّدة في توقيع بأي نوع من تعريفات الأنواع (بشرط أن يكون لها العدد نفسه من معاملات الأنواع) في بنية مطابقة. وسيكون التنفيذ المضبوط للنوع مخفيًّا عن مستعملي البنية. وبوجه خاص، إذا نُفِّذ النوع نوع متغيّر أو نوع سجل، فلن تكون البواني والحقول المرتبطة متاحة للمستعملين؛ وإذا نُفِّذ النوع اختصارًا، فستُخفى عن مستعملي البنية المساواة النوعية بين اسم النوع والطرف الأيمن من الاختصار. ويعتبر مستعملو البنية هذا النوع غير متوافق مع أي نوع آخر: فقد وُلّد نوع جديد.

****اختصار نوع: معادلة `=` *typexpr*، بلا تمثيل.****

يجب أن يُنفَّذ اسم النوع بنوع متوافق مع *typexpr*. ويعلم جميع مستعملي البنية أن اسم النوع متوافق مع *typexpr*.

****نوع متغيّر أو نوع سجل جديد: لا معادلة، بل تمثيل.****

يجب أن يُنفَّذ اسم النوع بنوع متغيّر أو نوع سجل يحوي البواني أو الحقول المحدّدة بالضبط. ويتمكّن جميع مستعملي البنية من الوصول إلى البواني أو الحقول، واستعمالها لإنشاء قيم من ذلك النوع أو فحصها. غير أن مستعملي البنية يعتبرون هذا النوع غير متوافق مع أي نوع آخر: فقد وُلّد نوع جديد.

****نوع متغيّر أو نوع سجل معاد تصديره: معادلة وتمثيل.****

تجمع هذه الحالة الحالتين السابقتين: فيُجعل تمثيل النوع مرئيًا لجميع المستعملين، ولا يُولّد نوع جديد.

#### تحديد الاستثناء

يشترط التحديد `exception` *constr-decl* في توقيع أن تقدّم البنية المطابقة استثناءً بالاسم والمعاملات المحدّدة في التعريف، ويجعل الاستثناء متاحًا لجميع مستعملي البنية.

#### تحديدات الأصناف

يُكتب تحديد صنف واحد أو عدة في توقيع على الصيغة `class` *class-spec* { `and` *class-spec* }، ويتألف من متتالية تعريفات متبادلة العودية لأسماء الأصناف.

وتُوصف تحديدات الأصناف بمزيد من الدقة في القسم 11.9.4.

#### تحديدات أنواع الأصناف

يُكتب تحديد نوع صنف واحد أو عدة في توقيع على الصيغة `class` `type` *classtype-def* { `and` *classtype-def* }، ويتألف من متتالية تعريفات متبادلة العودية لأسماء أنواع الأصناف. وتُوصف تحديدات أنواع الأصناف بمزيد من الدقة في القسم 11.9.5.

#### تحديدات الوحدات

يُكتب تحديد مكوّن وحدة في توقيع على الصيغة `module` *module-name* `:` *module-type*، حيث *module-name* اسم مكوّن الوحدة و*module-type* نوعه المتوقّع. ويمكن تداخل الوحدات اعتباطًا؛ وبوجه خاص، يمكن أن تظهر الموصِّلات مكوّناتٍ للبنى وأنواع الموصِّلات مكوّناتٍ للتوقيعات.

#### تحديدات أنواع الوحدات

يمكن تحديد مكوّن نوع وحدة في توقيع إما كنوع وحدة ظاهر وإما كنوع وحدة مجرّد.

ويتيح تحديد نوع الوحدة المجرّد `module` `type` *modtype-name* تنفيذ الاسم *modtype-name* بأي نوع وحدة في توقيع مطابق، لكنه يخفي تنفيذ نوع الوحدة عن جميع مستعملي التوقيع.

أما تحديد نوع الوحدة الظاهر `module` `type` *modtype-name* `=` *module-type* فيشترط تنفيذ الاسم *modtype-name* بنوع الوحدة *module-type* في توقيع مطابق، لكنه يجعل المساواة بين *modtype-name* و*module-type* ظاهرةً لجميع مستعملي التوقيع.

#### فتح مسار وحدة

لا يحدّد التعبير `open` *module-path* في توقيع أي مكوّنات. فهو يؤثر فقط في تحليل العناصر التالية من التوقيع، فيتيح الإشارة إلى مكوّنات الوحدة التي يدلّ عليها *module-path* بأسمائها البسيطة *name* بدلًا من وصولات المسار *module-path* `.` *name*. وينتهي نطاق `open` بانتهاء تعبير التوقيع.

#### تضمين توقيع

يجري التعبير `include` *module-type* في توقيع تضمينًا نصيًا لمكوّنات التوقيع الذي يدلّ عليه *module-type*. وهو يتصرّف كما لو نُسخت مكوّنات التوقيع المضمَّن في موضع `include`. ويجب أن يشير المعامل *module-type* إلى نوع وحدة يكون توقيعًا، لا نوع موصِّل.
### 11.10.3 أنواع الموصِّلات

تعبير نوع الوحدة [`functor`] `(` *module-name* `:` *module-type*₁ `)` `->` *module-type*₂ هو نوع الموصِّلات (دوال من الوحدات إلى الوحدات) التي تأخذ معاملًا وحدةً من النوع *module-type*₁ وتعيد نتيجةً وحدةً من النوع *module-type*₂. ويمكن لنوع الوحدة *module-type*₂ أن يستعمل الاسم *module-name* للإشارة إلى مكوّنات أنواع المعامل الفعلي للموصِّل. وإذا لم يكن النوع *module-type*₂ يعتمد على مكوّنات أنواع *module-name*، فيمكن تبسيط تعبير نوع الوحدة بالصيغة المختصرة البديلة *module-type*₁ `->` *module-type*₂. ولا تُفرض أي قيود على نوع معامل الموصِّل؛ وبوجه خاص، يمكن للموصِّل أن يأخذ موصِّلًا آخر معاملًا («موصِّل عالي الرتبة»).

### 11.10.4 المعامل with

بافتراض أن *module-type* يدلّ على توقيع، يدلّ التعبير *module-type* `with` *mod-constraint* { `and` *mod-constraint* } على التوقيع نفسه بعد إضافة معادلات أنواع إلى بعض تحديدات الأنواع، وفقًا للقيود التي تلي الكلمة المحجوزة `with`. ويضيف القيد `type` [*type-parameters*] *typeconstr* `=` *typexpr* معادلة النوع `=` *typexpr* إلى تحديد مكوّن النوع المسمّى *typeconstr* في التوقيع المقيَّد. ويضيف القيد `module` *module-path* `=` *extended-module-path* معادلات أنواع إلى جميع مكوّنات أنواع البنية الفرعية التي يدلّ عليها *module-path*، فيجعلها مكافئة لمكوّنات الأنواع المقابلة في البنية التي يدلّ عليها *extended-module-path*.

فمثلًا، إذا كان اسم نوع الوحدة `S` مرتبطًا بالتوقيع

```text
        sig type t module M: (sig type u end) end
```

فإن `S with type t=int` يدلّ على التوقيع

```text
        sig type t=int module M: (sig type u end) end
```

و`S with module M = N` يدلّ على التوقيع

```text
        sig type t module M: (sig type u=N.u end) end
```

ويُكتب الموصِّل الذي يأخذ معاملين من النوع `S` يتشاركان مكوّن `t` على الصيغة

```text
        functor (A: S) (B: S with type t = A.t) ...
```

وتُضاف القيود من اليسار إلى اليمين. وبعد تطبيق كل قيد، يجب أن يكون التوقيع الناتج نوعًا فرعيًا من التوقيع قبل تطبيق القيد. وبهذا لا يستطيع المعامل `with` إلا إضافة معلومات على مكوّنات أنواع توقيع، لا إزالة معلومات أبدًا.

## 11.11 تعابير الوحدات (تنفيذات الوحدات)

تعابير الوحدات هي المكافئ على مستوى الوحدات لتعبيرات القيم: فهي تُقيَّم إلى وحدات، فتوفّر بذلك تنفيذات للتحديدات المعبَّر عنها في أنواع الوحدات.

```text
module-expr::= module-path ∣ struct [ module-items ] end ∣ functor { ( module-name : module-type ) }⁺ -> module-expr ∣ module-expr ( module-expr ) ∣ ( module-expr ) ∣ ( module-expr : module-type ) module-items::= { ;; } ( definition ∣ expr ) { { ;; } ( definition ∣ ;; expr) } { ;; } module-definition::= module module-name { ( module-name : module-type ) } [ : module-type ] = module-expr local-definition::= external value-name : typexpr = external-declaration ∣ type-definition ∣ exception-definition ∣ class-definition ∣ classtype-definition ∣ module-definition ∣ module type modtype-name = module-type ∣ open module-path definition::= let [rec] let-binding { and let-binding } ∣ include module-expr ∣ local-definition
```

انظر أيضًا امتدادات اللغة التالية: الوحدات العودية، والوحدات من الدرجة الأولى، والإلغاء في عبارات open، والسمات، وعقد الامتداد، والموصِّلات التوليدية.

### 11.11.1 تعابير الوحدات البسيطة

يُقيَّم التعبير *module-path* إلى الوحدة المرتبطة بالاسم *module-path*.

ويُقيَّم التعبير `(` *module-expr* `)` إلى الوحدة نفسها *module-expr*.

ويتحقّق التعبير `(` *module-expr* `:` *module-type* `)` من أن نوع *module-expr* نوع فرعي من *module-type*، أي من أن جميع المكوّنات المحدّدة في *module-type* منفَّذة في *module-expr*، وأن تنفيذها يحقّق الشروط المعطاة في *module-type*. وبعبارة أخرى، يتحقّق من أن التنفيذ *module-expr* يحقّق تحديد النوع *module-type*. ويُقيَّم التعبير كاملًا إلى الوحدة نفسها *module-expr*، باستثناء أن جميع المكوّنات غير المحدّدة في *module-type* تصير مخفيّة ولا يمكن الوصول إليها.

### 11.11.2 البنى

البنى `struct` … `end` مجموعات من التعريفات لأسماء القيم وأسماء الأنواع والاستثناءات وأسماء الوحدات وأسماء أنواع الوحدات. وتُقيَّم التعريفات بالترتيب الذي تظهر به في البنية. وتمتدّ نطاقات الارتباطات التي تُجريها التعريفات إلى نهاية البنية. ونتيجةً لذلك، يمكن لتعريف أن يشير إلى أسماء مرتبطة بتعريفات سابقة في البنية نفسها.

وللتوافق مع عبارات النظام التفاعلي (الفصل 14)، يُسمح بـ `;;` اختيارية بعد كل تعريف في بنية وقبله. ولا معنى دلاليًا لهذه `;;`. وعلى المنوال نفسه، يُسمح بعبارة *expr* مسبوقة بـ `;;` مكوّنًا من مكوّنات بنية. وهي تكافئ `let` `_` `=` *expr*، أي إن *expr* تُقيَّم من أجل آثارها الجانبية لكنها لا تُربط بأي معرّف. وإذا كانت *expr* المكوّن الأول في بنية، فيمكن إغفال `;;` السابقة.

#### تعريفات القيم

يربط تعريف القيمة `let` [`rec`] *let-binding* { `and` *let-binding* } أسماء القيم بالطريقة نفسها التي يربطها بها تعبير `let` … `in` … (انظر القسم 11.7.2). وتُربط أسماء القيم الظاهرة في الأطراف اليسرى للارتباطات بالقيم المقابلة في الأطراف اليمنى.

وينفّذ تعريف القيمة `external` *value-name* `:` *typexpr* `=` *external-declaration* الاسم *value-name* كالدالة الخارجية المحدّدة في *external-declaration* (انظر الفصل 23).

#### تعريفات الأنواع

يُكتب تعريف مكوّن نوع واحد أو عدة على الصيغة `type` *typedef* { `and` *typedef* }، ويتألف من متتالية تعريفات متبادلة العودية لأسماء الأنواع.

#### تعريفات الاستثناءات

تُعرَّف الاستثناءات بالصيغة `exception` *constr-decl* أو `exception` *constr-name* `=` *constr*.

#### تعريفات الأصناف

يُكتب تعريف صنف واحد أو عدة على الصيغة `class` *class-binding* { `and` *class-binding* }، ويتألف من متتالية تعريفات متبادلة العودية لأسماء الأصناف. وتُوصف تعريفات الأصناف بمزيد من الدقة في القسم 11.9.3.

#### تعريفات أنواع الأصناف

يُكتب تعريف صنف واحد أو عدة على الصيغة `class` `type` *classtype-def* { `and` *classtype-def* }، ويتألف من متتالية تعريفات متبادلة العودية لأسماء أنواع الأصناف. وتُوصف تعريفات أنواع الأصناف بمزيد من الدقة في القسم 11.9.5.

#### تعريفات أنواع الوحدات

يُكتب تعريف نوع وحدة على الصيغة `module` `type` *modtype-name* `=` *module-type*. وهو يربط الاسم *modtype-name* بنوع الوحدة الذي يدلّ عليه التعبير *module-type*.

#### فتح مسار وحدة

لا يعرّف التعبير `open` *module-path* في بنية أي مكوّنات ولا يُجري أي ارتباطات. فهو يؤثر فقط في تحليل العناصر التالية من البنية، فيتيح الإشارة إلى مكوّنات الوحدة التي يدلّ عليها *module-path* بأسمائها البسيطة *name* بدلًا من وصولات المسار *module-path* `.` *name*. وينتهي نطاق `open` بانتهاء تعبير البنية.

#### تضمين مكوّنات بنية أخرى

يعيد التعبير `include` *module-expr* في بنية تصدير جميع تعريفات البنية التي يدلّ عليها *module-expr* في البنية الحالية. فمثلًا، إذا عرّفت وحدة `S` كما يلي

```ocaml
module S = struct type t = int  let x = 2 end
```

فإن تعريف الوحدة `B` على الصيغة

```ocaml
module B = struct include S  let y = (x + 1 : t) end
```

يكافئ تعريفها على الصيغة

```ocaml
module B = struct type t = S.t  let x = S.x  let y = (x + 1 : t) end
```

والفرق بين `open` و`include` أن `open` يوفّر ببساطة أسماء قصيرة لمكوّنات البنية المفتوحة دون تعريف أي مكوّنات في البنية الحالية، أما `include` فيضيف أيضًا تعريفات لمكوّنات البنية المضمَّنة.

## 11.12 وحدات الترجمة

```text
unit-interface::= { specification [;;] } unit-implementation::= [ module-items ]
```

تجسر وحدات الترجمة بين نظام الوحدات ونظام الترجمة المنفصلة. وتتألف وحدة الترجمة من جزأين: واجهة وتنفيذ. وتحوي الواجهة متتالية تحديدات، كما في داخل تعبير توقيع `sig` … `end`. ويحوي التنفيذ متتالية تعريفات وتعبيرات، كما في داخل تعبير وحدة `struct` … `end`. ولكلوحدة الترجمة اسم *unit-name* مشتقّ من أسماء الملفات الحاوية للواجهة والتنفيذ (انظر الفصل 13 لمزيد من التفصيل). وتتصرّف وحدة الترجمة تقريبًا كما يتصرّف تعريف الوحدة
