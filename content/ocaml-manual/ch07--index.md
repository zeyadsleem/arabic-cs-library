# الفصل 7: أنواع البيانات الجبرية المعمّمة

توسّع أنواع البيانات الجبرية المعمّمة (GADTs) أنواع المجموع المعتادة من وجهين: فقد تتغيّر القيود على معاملات النوع بحسب باني القيمة، وقد تكون بعض متغيّرات النوع مكمَّمة وجوديًا. ويجري إضافة القيود بإعطاء نوع إرجاع صريح تُجزَّأ فيه معاملات النوع:

```ocaml
type _ term =
  | Int : int -> int term
  | Add : (int -> int -> int) term
  | App : ('b -> 'a) term * 'b term -> 'a term
```

يجب أن يستعمل نوع الإرجاع هذا باني النوع نفسه المستعمل في النوع المُعرَّف، وأن يكون له العدد نفسه من المعاملات. وتصبح المتغيّرات وجودية عندما تظهر داخل وسيط الباني دون أن تظهر في نوع إرجاعه. ولأن استعمال نوع الإرجاع يُغني غالبًا عن تسمية معاملات النوع في الطرف الأيسر من تعريف النوع، يمكن في تلك الحالة استبدالها بالأنواع المجهولة `_`.

ويمكن استعادة القيود المرتبطة بكل باني عبر مطابقة الأنماط. أي أنه إذا كان نوع المفحوص في مطابقة الأنماط يحتوي نوعًا مجرّدًا محليًا، أمكن تنقيح هذا النوع وفقًا للباني المستعمل. وهذه القيود الإضافية لا تكون صالحة إلا داخل الفرع الموافق من مطابقة الأنماط. وإذا كان للباني متغيّرات وجودية، تُولَّد أنواع مجرّدة محلية جديدة، ويجب ألا تفلت من نطاق هذا الفرع.

## 7.1 الدوال العودية

نكتب دالة `eval`:

```ocaml
let rec eval : type a. a term -> a = function
  | Int n    -> n                 (* a = int *)
  | Add      -> (fun x y -> x+y)  (* a = int -> int -> int *)
  | App(f,x) -> (eval f) (eval x)
          (* eval called at types (b->a) and b for fresh b *)
```

ثم نستعملها:

```ocaml
let two = eval (App (App (Add, Int 1), Int 1))

val two : int = 2
```

من المهم ملاحظة أن الدالة `eval` تستعمل الصيغة متعدّدة الأشكال للأنواع المجرّدة المحلية. وعند تعريف دالة عودية تتعامل مع GADT، ينبغي عمومًا استعمال العودية متعدّدة الأشكال الصريحة. فمثلًا، يفشل التعريف التالي بخطأ في النوع:

```ocaml
let rec eval (type a) : a term -> a = function
  | Int n    -> n
  | Add      -> (fun x y -> x+y)
  | App(f,x) -> (eval f) (eval x)

Error: The value f has type ($b -> a) term
       but an expression was expected of type 'a
       The type constructor $b would escape its scope
       Hint: $b is an existential type bound by the constructor App.
```

وفي غياب تعليمة متعدّدة الأشكال صريحة، يُستنتج للدالة العودية نوع أحادي الشكل. وإذا وقع نداء عودي داخل تعريف الدالة عند نوع يشمل متغيّر نوع وجوديًا من GADT، فإن هذا المتغيّر ينتقل إلى نوع الدالة العودية، وبذلك يفلت من نطاقه. وفي المثال أعلاه يحدث ذلك في الفرع `App(f,x)` حين تُنادى `eval` بالوسيط `f`. وفي هذا الفرع يكون نوع `f` هو `($App_'b -> a) term`، وهو نوع وجودي يسمّيه المترجم (انظر 7.5). ولأن نوع `eval` هو `'a term -> 'a`، فإن النداء `eval f` يجعل ذلك النوع الوجودي ينتقل إلى متغيّر النوع `'a` ويفلت من نطاقه. وهذا ما يُطلق الخطأ أعلاه.

## 7.2 استنتاج الأنواع

يُعرف عن استنتاج الأنواع في GADT أنه صعب. والسبب أن بعض الأنواع قد تصير مُلتبِسة عند الإفلات من فرع. فمثلًا، في حالة `Int` أعلاه، يمكن أن يكون نوع `n` هو `int` أو `a`، وهما غير متكافئين خارج ذلك الفرع. وكحلّ تقريبي أول، ينجح استنتاج الأنواع دائمًا إذا عُلّقت مطابقة الأنماط بأنواع لا تحتوي متغيّرات نوع حرّة (في المفحوص وفي نوع الإرجاع معًا). وهذا هو الحال في المثال أعلاه، بفضل تعليمة النوع التي لا تحتوي إلا أنواعًا مجرّدة محلية.

وفي الممارسة، يكون استنتاج الأنواع أذكى من ذلك بقليل: فتعليمات النوع لا يلزم أن تكون على مطابقة الأنماط مباشرة، ولا يلزم أن تكون الأنواع مغلقة دائمًا. ونتيجة لذلك، يكفي عادةً تعليق الدوال فقط، كما في المثال أعلاه. وتنتشر تعليمات النوع بطريقتين: أما بالنسبة إلى المفحوص، فتتبع مسار استنتاج الأنواع، على نحو شبيه بالدوال متعدّدة الأشكال؛ وأما بالنسبة إلى نوع الإرجاع، فتتبع بنية البرنامج، إذ تُجزَّأ على الدوال، وتنتشر إلى جميع فروع مطابقة الأنماط، وتعبر الأزواج والسجلات وأنواع المجموع. ثم إن مفهوم الالتباس المستعمل أقوى: فلا يُعدّ النوع مُلتبِسًا إلا إذا مُزج بأنواع غير متوافقة (وُحِّدت بقيود) دون تعليمات نوع تفصل بينها. فمثلًا، يُنمَّط البرنامج التالي بشكل صحيح.

```ocaml
let rec sum : type a. a term -> _ = fun x ->
  let y =
    match x with
    | Int n -> n
    | Add   -> 0
    | App(f,x) -> sum f + sum x
  in y + 1

val sum : 'a term -> int = <fun>
```

هنا لا يُخلط نوع الإرجاع `int` مع `a` أبدًا، فيُرى غير مُلتبِس، ويمكن استنتاجه. وعند استعمال تعليمات نوع جزئية كهذه نوصي بشدة بتحديد النمط `-principal` للتحقق من أن الاستنتاج أصلي.

ويكون فحص الشمول مدركًا لقيود GADT، فيستطيع أن يستنتج تلقائيًا أن بعض الحالات لا يمكن أن تقع. فمثلًا، تُرى مطابقة الأنماط التالية شاملة على نحو صحيح (إذ لا يمكن أن تقع حالة `Add`).

```ocaml
let get_int : int term -> int = function
  | Int n    -> n
  | App(_,_) -> 0
```

## 7.3 حالات الدحض

عادةً لا يحاول فحص الشمول إلا التحقق مما إذا كانت الحالات المحذوفة من مطابقة الأنماط قابلة للنمط أم لا. غير أنك تستطيع إجباره على بذل جهد أكبر بإضافة *حالات دحض*، تُكتب بنقطة كاملة. وفي حضور حالة دحض، يحسب فحص الشمول أولًا تقاطع النمط مع متمّم الحالات السابقة له. ثم يتحقق مما إذا كانت الأنماط الناتجة قادرة فعلًا على مطابقة قيم ملموسة، بمحاولة التحقق من نمطها. وتُعالَج الرموز العامة في الأنماط المولَّدة بطريقة خاصة: فإذا كان نوعها نوع متغيّر لا يحتوي إلا بواني GADT، قُسِّم النمط إلى البواني المختلفة للتحقق مما إذا كان أي منها ممكنًا (ولا يجري هذا التقسيم على وسائط هذه البواني، تجنّبًا لعدم الانتهاء). كما نقسّم الأزواج وأنواع المتغيّرات ذات الحالة الواحدة، لأنها قد تحتوي GADT في داخلها. فمثلًا، تُعدّ الشيفرة التالية شاملة:

```ocaml
type _ t =
  | Int : int t
  | Bool : bool t

let deep : (char t * int) option -> char = function
  | None -> 'c'
  | _ -> .
```

أي أن الحالة المتبقية المستنتجة هي `Some _`، وتُقسَّم إلى `Some (Int, _)` و`Some (Bool, _)`، وكلتاهما غير قابلتين للنمط لأن `deep` تتوقع `char t` غير موجود كعنصر أول في الزوج. ولاحظ أنه كان يمكن حذف حالة الدحض هنا، لأنها تُضاف تلقائيًا عندما تكون في مطابقة الأنماط حالة واحدة فقط.

ومن الإضافات الأخرى أن فحص التكرار صار مدركًا لـ GADT: فتُكتشف الحالة على أنها مكرّرة إذا كان يمكن استبدالها بحالة دحض تستعمل النمط نفسه.

## 7.4 أمثلة متقدّمة

النوع `term` الذي عرّفناه أعلاه نوع *مُفهرَس*، إذ يعكس معامل نوع فيه خاصية من محتوى القيمة. ومن استعمالات GADT الأخرى الأنواع *المفردة*، حيث تمثّل قيمة GADT نوعًا واحدًا بعينه. ويمكن استعمال هذه القيمة تمثيلًا وقت التشغيل لذلك النوع، ويمكن للدالة التي تتلقاها أن تسلك سلوكًا متعدّد الأنواع.

وهذا مثال على دالة متعدّدة الأشكال تأخذ تمثيل وقت التشغيل لنوع ما `t` وقيمة من النوع نفسه، ثم تطبع القيمة طباعة جميلة في صورة سلسلة:

```ocaml
type _ typ =
  | Int : int typ
  | String : string typ
  | Pair : 'a typ * 'b typ -> ('a * 'b) typ

let rec to_string: type t. t typ -> t -> string =
  fun t x ->
  match t with
  | Int -> Int.to_string x
  | String -> Printf.sprintf "%S" x
  | Pair(t1,t2) ->
      let (x1, x2) = x in
      Printf.sprintf "(%s,%s)" (to_string t1 x1) (to_string t2 x2)
```

ومن التطبيقات المتكررة لـ GADT كذلك شهود المساواة.

```ocaml
type (_,_) eq = Eq : ('a,'a) eq

let cast : type a b. (a,b) eq -> a -> b = fun Eq x -> x
```

هنا للنوع `eq` باني واحد فقط، وبمطابقته نضيف قيدًا محليًا يسمح بالتحويل بين `a` و`b`. وببناء شهود مساواة كهذه، يمكن جعل أنواع متساوية وهي مختلفة تركيبيًا.

وهذا مثال يستعمل الأنواع المفردة وشهود المساواة معًا لتنفيذ أنواع ديناميكية.

```ocaml
let rec eq_type : type a b. a typ -> b typ -> (a,b) eq option =
  fun a b ->
  match a, b with
  | Int, Int -> Some Eq
  | String, String -> Some Eq
  | Pair(a1,a2), Pair(b1,b2) ->
      begin match eq_type a1 b1, eq_type a2 b2 with
      | Some Eq, Some Eq -> Some Eq
      | _ -> None
      end
  | _ -> None

type dyn = Dyn : 'a typ * 'a -> dyn

let get_dyn : type a. a typ -> dyn -> a option =
  fun a (Dyn(b,x)) ->
  match eq_type a b with
  | None -> None
  | Some Eq -> Some x
```

## 7.5 أسماء الأنواع الوجودية في رسائل الخطأ

قد يولّد تنميط مطابقة الأنماط في حضور GADT أنواعًا وجودية كثيرة. وعند الحاجة، تشير رسائل الخطأ إلى هذه الأنواع الوجودية بأسماء يولّدها المترجم. وحاليًا يولّد المترجم هذه الأسماء وفق التسمية التالية:

- أولًا، الأنواع التي تبدأ أسماؤها بـ `$` هي أنواع وجودية.

- يدل `$a` على نوع وجودي أُدخل من أجل متغيّر النوع `'a` في باني GADT:

```ocaml
type any = Any : 'name -> any
let escape (Any x) = x

Error: The value x has type $name but an expression was expected of type 'a
       The type constructor $name would escape its scope
       Hint: $name is an existential type bound by the constructor Any.
```

- يدل `$'a` على الحالة التي وُحِّد فيها المتغيّر الوجودي مع متغيّر النوع `'a` أثناء التنميط:

```ocaml
type ('arg,'result,'aux) fn =
  | Fun: ('a ->'b) -> ('a,'b,unit) fn
  | Mem1: ('a ->'b) * 'a * 'b -> ('a, 'b, 'a * 'b) fn
let apply: ('arg,'result, _ ) fn -> 'arg -> 'result = fun f x ->
  match f with
  | Fun f -> f x
  | Mem1 (f,y,fy) -> if x = y then fy else f x

Error: This pattern matches values of type
         ($'arg, 'result, $'arg * 'result) fn
       but a pattern was expected which matches values of type
         ($'arg, 'result, unit) fn
       The type constructor $'arg would escape its scope
```

- يدل `$n` (حيث n عدد) على نوع وجودي مولَّد داخليًا تعذّرت تسميته بإحدى الطرق السابقة.

وكما يبيّن البند الأخير، فإن السلوك الحالي ناقص وقد يُحسَّن في إصدارات لاحقة.

## 7.6 التسمية الصريحة للأنواع الوجودية

كما شرحنا أعلاه، قد تُدخل مطابقة الأنماط على باني GADT أنواعًا وجودية. وقد أُدخلت صيغة تسمح بتسميتها صراحةً. فمثلًا، تسمّي الشيفرة التالية نوع وسيط `f` وتستعمل هذا الاسم.

```ocaml
type _ closure = Closure : ('a -> 'b) * 'a -> 'b closure
let eval = fun (Closure (type a) (f, x : (a -> _) * _)) -> f (x : a)
```

ويجب إدخال جميع متغيّرات النوع الوجودية للباني بالتركيب (`type` ...) وربطها بتعليمة نوع على خارج وسيط الباني.

ويمكن إضافةً إلى ذلك ربط الأنواع الوجودية التي أُدخلت حديثًا بتنقيح نوع وجودي آخر، إذا ظهرت في نوع الوسائط.

```ocaml
type _ ty =
  | Int : int ty
  | Pair : 'b ty * 'c ty -> ('b * 'c) ty
let rec default : type a. a ty -> a = function
  | Int -> 0
  | Pair (type b c) (b, c : b ty * c ty) ->
      (default b : b), (default c : c)
```

## 7.7 معادلات على أنواع مجرّدة غير محلية

قد تضيف مطابقة أنماط GADT معادلات نوع إلى أنواع مجرّدة غير محلية أيضًا. والسلوك هو نفسه في الأنواع المجرّدة المحلية. وباتّخاذ النوع `eq` أعلاه، يمكن كتابة:

```ocaml
module M : sig type t val x : t val e : (t,int) eq end = struct
  type t = int
  let x = 33
  let e = Eq
end

let x : int = let Eq = M.e in M.x
```

## 7.8 أنواع تُستعمل مؤشرات GADT

استعملنا في حديثنا عن حالات الدحض (7.3) المثال التالي:

```ocaml
type _ t =
  | Int : int t
  | Bool : bool t

let deep : (char t * int) option -> char = function
  | None -> 'c'
  | _ -> .
```

يستطيع مدقّق الأنواع التحقق من أن الحالة `Some _` مستحيلة لأن النوع `char t` خالٍ. وهذا يعتمد على أن الأنواع الواقعة في مؤشر GADT معروفة بأنها متمايزة: فالباني `Int` يُرجع `int t`، ونعلم أن `int` و`char` نوعان متمايزان، فـ `Int` مستحيل عند النوع `char t`، وكذلك الأمر في `Bool`. وبعبارة أخرى، يتطلب التحقق من استحالة حالة GADT (عند نوع بعينه) استدلالًا على المتباينات بين الأنواع.

ولهذا السبب لا يعمل استعمال الأنواع المجرّدة مؤشرات GADT كما هو مقصود. خذ مثلًا:

```ocaml
(* type-level natural numbers, in unary notation *)
module TypeNat = struct
  type zero
  type !'a succ
end

type ('a, _) sized_list =
  | Nil : ('a, TypeNat.zero) sized_list
  | Cons : 'a * ('a, 'n) sized_list -> ('a, 'n TypeNat.succ) sized_list
```

هذا التعريف لا يسمح باستبعاد حالات معيّنة على أنها مستحيلة كما قصدنا؛ فمثلًا يفشل التالي:

```ocaml
let of_singleton : ('a, TypeNat.(zero succ)) sized_list -> 'a = function
  | Cons (v, Nil) -> v
  | _ -> .

Error: This match case could not be refuted.
       Here is an example of a value that would reach it: Nil
```

ولأن `zero` و`succ` نوعان مجرّدان، يفترض المترجم أن تعريفهما غير معروف، وأنه قد يكونان في الواقع النوع نفسه. وعلى وجه الخصوص، بهذا التوقيع لا يُعرف أن النوعين `zero` و`zero succ` متمايزان (حتى لو كان تنفيذهما متمايزًا)، ولا يستطيع المترجم أن يوافق على أن حالة `Nil` مستحيلة عند النوع `zero succ`:[^1]

ومن طرق الاستدلال على ذلك أن وحدة بالتوقيع نفسه *كان يمكن* تنفيذها كما يلي، وحيث من الواضح أن `zero` و`zero succ` غير متوافقين:

```ocaml
module OtherTypeNat : sig
  type zero
  type !'a succ
end = struct
  type zero = unit
  type 'a succ = 'a
end
```

والطريقة الموصى بها لتجنّب هذه المشكلة إعطاء تعريف ملموس لأنواع مثل `zero` و`succ`، وهي أنواع لا يُقصد استعمالها إلا مؤشرات GADT. (وهذا مخالف للحدس، إذ لن نتعامل أبدًا مع قيم من هذا النوع.) ويمكنك استعمال:

```ocaml
module TypeNat = struct
  type zero = Zero
  type 'a succ = Succ
end
```

والأنواع الآن غير متوافقة لأن أسماء بوانيها مكشوفة ومتمايزة.

وكتحسين إضافي، يمكن تعريف أنواع المؤشرات هذه باستعمال تعليمة `private`، التي توضّح أنها لا يُقصد استعمالها لبناء القيم:

```ocaml
module TypeNat = struct
  type zero = private Zero
  type 'a succ = private Succ
end
```

ملاحظة: يُقصد عادةً استعمال `private` في الواجهات لا في التنفيذات؛ انظر توثيق الأنواع الخاصة في 12.3. ولا يمكن استعمال بواني نوع بيانات *مُعرَّف* بأنه `private` لبناء القيم، فيكون النوع خاليًا فعليًا. وهذا يجعل من الأوضح أن الأنواع لا يُقصد استعمالها إلا مؤشرات GADT.

### 7.8.1 السلوك القديم: الأنواع في الوحدة الحالية

كان للإصدارات المبكرة من OCaml، حتى OCaml 5.4، معالجة خاصة للأنواع المعرّفة في الوحدة الحالية. ولا تنطبق هذه الحالة الخاصة على تعريفي `succ` و`zero` اللذين ناقشناهما أعلاه، إذ يقعان في وحدتين فرعيتين منفصلتين.

لذا كانت التعريفات التالية تكفي لتعريف `sized_list`، لأن المترجم كان يقبل أن `zero` و`'a succ` متمايزان دائمًا:

```ocaml
type zero
type !'a succ
```

وكان الاستدلال أن الأنواع المجرّدة، وإن كان يمكن عمومًا تعريفها بأي شيء في مكان ما من البرنامج، فإن الأنواع المجرّدة التي أدخلناها للتوّ غير معرّفة أصلًا، فيصحّ افتراض أنها متمايزة. وعلى المنوال نفسه، كانت أنواع البيانات المعرّفة في الوحدة الحالية تُعدّ متمايزة حتى لو استعملت أسماء بواني أو حقول نفسها بالضبط.

وقد جعلت هذه الحالة الخاصة النظام أكثر تعقيدًا وأقل نمطية. فمثلًا، كانت أمثلة GADT تعمل جيدًا حين يُعرَّف كل شيء في الوحدة نفسها، لكن تعريفات الدوال الواقعة في وحدة أخرى تفشل، وهو أمر مربك جدًا للمستخدمين.

والبرامج التي تستعمل هذه الميزة المدعومة سابقًا يمكن إعادة كتابتها دائمًا باستعمال تعريفات صريحة بدلًا منها:

```ocaml
type zero = private Zero
type 'a succ = private Succ
```

[^1]: احتجنا أيضًا إلى تعليمة حقنية صريحة، `type !'a succ`، وإلا رُفض تعريف `sized_list` أيضًا لأن `succ` مجرّد.
