# الفصل 5: المتغيّرات متعدّدة الأشكال

*كتب هذا الفصل جاك غاريغ*

المتغيّرات كما عُرضت في القسم 1.4 أداة قوية لبناء بنى المعطيات والخوارزميات. غير أنها تفتقر أحيانًا إلى المرونة عند استعمالها في البرمجة المعيارية. والسبب أنّ كل باني يُنسب إلى نوع وحيد عند تعريفه واستعماله. فحتى لو ظهر الاسم نفسه في تعريف أنواع متعدّدة، فإنّ الباني نفسه ينتمي إلى نوع واحد فقط. ولذلك لا يمكن الحكم بأنّ بانيًا معيّنًا ينتمي إلى أنواع متعدّدة، ولا اعتبار قيمة من نوع ما تنتمي إلى نوع آخر ذي بوانٍ أكثر.

ومع المتغيّرات متعدّدة الأشكال يُرفع هذا الافتراض الأصلي. أي أنّ وسم المتغيّر لا ينتمي إلى أي نوع بعينه، بل يتحقّق نظام الأنواع فقط من أنه قيمة مقبولة بحسب استعماله. فلا حاجة إلى تعريف نوع قبل استعمال وسم متغيّر. وسيُستنتج نوع متغيّر مستقلًّا لكل استعمال من استعمالاته.

## 5.1 الاستعمال الأساسي

تعمل المتغيّرات متعدّدة الأشكال في البرامج عمل المتغيّرات العادية. ما عليك إلا أن تسبق أسماءها بعلامة الخلف.

```ocaml
# [`On; `Off];;

- : [> `Off | `On ] list = [`On; `Off]

# `Number 1;;

- : [> `Number of int ] = `Number 1

# let f = function `On -> 1 | `Off -> 0 | `Number n -> n;;

val f : [< `Number of int | `Off | `On ] -> int = <fun>

# List.map f [`On; `Off];;

- : int list = [1; 0]
```

النوع ``[>`Off|`On] list`` يعني أنه لمطابقة هذه القائمة، يجب أن تكون قادرًا على مطابقة `` `Off `` و`` `On `` على الأقل، من دون وسيط. والنوع ``[<`On|`Off|`Number of int]`` يعني أنه يجوز تطبيق `f` على `` `Off `` و`` `On `` (كلاهما من دون وسيط)، أو على `` `Number `` *n* حيث *n* عدد صحيح. وتُظهر علامتا `>` و`<` داخل أنواع المتغيّرات أنها قد تُصقَل بعد، إمّا بتعريف وسوم أكثر، وإمّا بالسماح بوسوم أقل. ومن ثمّ فهي تحتوي متغيّر نوع ضمنيًا. ولأنّ كلًّا من أنواع المتغيّرات هذه يظهر مرّة واحدة فقط في النوع كله، فلا تُعرض متغيّرات نوعها الضمنية.

كانت أنواع المتغيّرات أعلاه متعدّدة الأشكال، إذ تسمح بمزيد من الصقل. أمّا عند كتابة إضافات الأنواع، فسيصف المرء في الغالب أنواع متغيّرات مثبّتة، أي أنواعًا لا يمكن صقلها. وهذا هو الحال أيضًا في اختصارات الأنواع. فلا تحتوي مثل هذه الأنواع علامتي `<` أو `>`، بل مجرّد تعداد للوسوم وأنواعها المرتبطة، تمامًا كما في تعريف نوع معطيات عادي.

```ocaml
# type 'a vlist = [`Nil | `Cons of 'a * 'a vlist];;

type 'a vlist = [ `Cons of 'a * 'a vlist | `Nil ]

# let rec map f : 'a vlist -> 'b vlist = function
    | `Nil -> `Nil
    | `Cons(a, l) -> `Cons(f a, map f l)
  ;;

val map : ('a -> 'b) -> 'a vlist -> 'b vlist = <fun>
```

## 5.2 الاستعمال المتقدّم

فحص أنواع المتغيّرات متعدّدة الأشكال أمر دقيق، وقد تُنتج بعض التعابير معلومات نوع أعقد.

```ocaml
# let f = function `A -> `C | `B -> `D | x -> x;;

val f : ([> `A | `B | `C | `D ] as 'a) -> 'a = <fun>

# f `E;;

- : [> `A | `B | `C | `D | `E ] = `E
```

نرى هنا ظاهرتين. أولًا، بما أنّ هذه المطابقة مفتوحة (فالحالة الأخيرة تلتقط أي وسم)، نحصل على النوع ``[> `A | `B]`` بدلًا من ``[< `A | `B]`` كما في مطابقة مغلقة. ثم، بما أنّ `x` يُعاد كما هو، فنوعا المدخل والمخرج متطابقان. والتدوين `as 'a` يدلّ على هذا التشارك في النوع. وإذا طبّقنا `f` على وسم آخر `` `E ``، أُضيف إلى القائمة.

```ocaml
# let f1 = function `A x -> x = 1 | `B -> true | `C -> false
  let f2 = function `A x -> x = "a" | `B -> true ;;

val f1 : [< `A of int | `B | `C ] -> bool = <fun>
val f2 : [< `A of string | `B ] -> bool = <fun>

# let f x = f1 x && f2 x;;

val f : [< `A of string & int | `B ] -> bool = <fun>
```

هنا تقبل كل من `f1` و`f2` الوسمين `` `A `` و`` `B ``، لكنّ وسيط `` `A `` من النوع `int` في `f1` ومن النوع `string` في `f2`. وفي نوع `f` يختفي `` `C ``، الذي لا يقبله إلا `f1`، أمّا نوعا الوسيط فيظهران معًا لـ `` `A `` على شكل `int & string`. وهذا يعني أنه إذا مرّرنا الوسم `` `A `` إلى `f`، وجب أن يكون وسيطه `int` و`string` معًا في الوقت نفسه. ولأنّ مثل هذه القيمة غير موجودة، لا يمكن تطبيق `f` على `` `A ``، ويكون `` `B `` المدخل الوحيد المقبول.

وحتى إذا كان لقيمة نوع متغيّر مثبّت، يمكن إعطاؤها نوعًا أكبر عبر الإكراهات. وتُكتب الإكراهات عادةً بنوعي المصدر والهدف، لكن يمكن حذف نوع المصدر في الحالات البسيطة.

```ocaml
# type 'a wlist = [`Nil | `Cons of 'a * 'a wlist | `Snoc of 'a wlist * 'a];;

type 'a wlist = [ `Cons of 'a * 'a wlist | `Nil | `Snoc of 'a wlist * 'a ]

# let wlist_of_vlist  l = (l : 'a vlist :> 'a wlist);;

val wlist_of_vlist : 'a vlist -> 'a wlist = <fun>

# let open_vlist l = (l : 'a vlist :> [> 'a vlist]);;

val open_vlist : 'a vlist -> [> 'a vlist ] = <fun>

# fun x -> (x :> [`A|`B|`C]);;

- : [< `A | `B | `C ] -> [ `A | `B | `C ] = <fun>
```

ويمكنك أيضًا إكراه القيم إكراهًا انتقائيًا عبر مطابقة الأنماط.

```ocaml
# let split_cases = function
    | `Nil | `Cons _ as x -> `A x
    | `Snoc _ as x -> `B x
  ;;

val split_cases :
  [< `Cons of 'a | `Nil | `Snoc of 'b ] ->
  [> `A of [> `Cons of 'a | `Nil ] | `B of [> `Snoc of 'b ] ] = <fun>
```

وعندما يُغلَّف نمط «أو» مؤلَّف من وسوم متغيّرات داخل نمط مستعار، يُعطى الاسم المستعار نوعًا يحتوي فقط الوسوم المعدودة في نمط «أو». وهذا يسمح بأدوات مفيدة كثيرة، مثل التعريف التدريجي للدوال.

```ocaml
# let num x = `Num x
  let eval1 eval (`Num x) = x
  let rec eval x = eval1 eval x ;;

val num : 'a -> [> `Num of 'a ] = <fun>
val eval1 : 'a -> [< `Num of 'b ] -> 'b = <fun>
val eval : [< `Num of 'a ] -> 'a = <fun>

# let plus x y = `Plus(x,y)
  let eval2 eval = function
    | `Plus(x,y) -> eval x + eval y
    | `Num _ as x -> eval1 eval x
  let rec eval x = eval2 eval x ;;

val plus : 'a -> 'b -> [> `Plus of 'a * 'b ] = <fun>
val eval2 : ('a -> int) -> [< `Num of int | `Plus of 'a * 'a ] -> int = <fun>
val eval : ([< `Num of int | `Plus of 'a * 'a ] as 'a) -> int = <fun>
```

ولجعل هذا أيسر، يمكنك استعمال تعريفات الأنواع اختصاراتٍ لأنماط «أو». أي أنه إذا عرّفت ``type myvariant = [`Tag1 of int | `Tag2 of bool]``، فإنّ النمط `#myvariant` يكافئ كتابة ``(`Tag1(_ : int) | `Tag2(_ : bool))``.

ويمكن استعمال هذه الاختصارات وحدها،

```ocaml
# let f = function
    | #myvariant -> "myvariant"
    | `Tag3 -> "Tag3";;

val f : [< `Tag1 of int | `Tag2 of bool | `Tag3 ] -> string = <fun>
```

أو مقترنة بأسماء مستعارة.

```ocaml
# let g1 = function `Tag1 _ -> "Tag1" | `Tag2 _ -> "Tag2";;

val g1 : [< `Tag1 of 'a | `Tag2 of 'b ] -> string = <fun>

# let g = function
    | #myvariant as x -> g1 x
    | `Tag3 -> "Tag3";;

val g : [< `Tag1 of int | `Tag2 of bool | `Tag3 ] -> string = <fun>
```

## 5.3 مواطن ضعف المتغيّرات متعدّدة الأشكال

بعد أن رأينا قوة المتغيّرات متعدّدة الأشكال، قد يتساءل المرء لماذا أُضيفت إلى متغيّرات اللغة الأساسية بدلًا من أن تحلّ محلّها.

والجواب ذو شقّين. الشقّ الأول أنه رغم كونها فعّالة جدًّا، فإنّ غياب معلومات الأنواع الساكنة يسمح بتحسينات أقل، ويجعل المتغيّرات متعدّدة الأشكال أثقل قليلًا من متغيّرات اللغة الأساسية. غير أنّ الفروق الملحوظة لا تظهر إلا في بنى معطيات ضخمة.

والأهمّ أنّ المتغيّرات متعدّدة الأشكال، رغم كونها آمنة نوعيًا، تؤدّي إلى انضباط نوعي أضعف. أي أنّ متغيّرات اللغة الأساسية تفعل في الواقع أكثر بكثير من ضمان السلامة النوعية، فهي تتحقّق أيضًا من أنك لا تستعمل إلا البواني المعلنة، وأنّ كل البواني الحاضرة في بنية معطيات متوافقة، وتفرض قيود أنواع على وسائطها.

ولهذا السبب، يجب أن تكون أكثر حرصًا على جعل الأنواع صريحة عند استعمال المتغيّرات متعدّدة الأشكال. وحين تكتب مكتبة، يكون هذا سهلًا لأنك تستطيع وصف أنواع دقيقة في الواجهات، أمّا في البرامج البسيطة فالأرجح أن تكون متغيّرات اللغة الأساسية أفضل لك.

واحذر أيضًا أنّ بعض الأساليب تجعل الأخطاء التافهة صعبة الاكتشاف جدًّا. فمثلًا الشيفرة التالية خاطئة على الأرجح، لكن لا سبيل للمترجم إلى رؤية ذلك.

```ocaml
# type abc = [`A | `B | `C] ;;

type abc = [ `A | `B | `C ]

# let f = function
    | `As -> "A"
    | #abc -> "other" ;;

val f : [< `A | `As | `B | `C ] -> string = <fun>

# let f : abc -> string = f ;;

val f : abc -> string = <fun>
```

ويمكنك تجنّب مثل هذه المخاطر بإضافة نوع إلى التعريف نفسه.

```ocaml
# let f : abc -> string = function
    | `As -> "A"
    | #abc -> "other" ;;

Error: This pattern matches values of type [? `As ]
       but a pattern was expected which matches values of type abc
       The second variant type does not allow tag(s) `As
```
